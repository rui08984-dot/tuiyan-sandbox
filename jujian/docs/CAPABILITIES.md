# 局鉴 · 能力目录

> 每条能力写三栏：**它做什么 · 越界了怎么办 · 以及它明确不做什么**。
> 第三栏的「**不能做什么**」不是免责声明，是产品的定位声明——见 README 开头。
>
> 本目录的端点清单由 `test/readme.test.cjs` ③ 机械核对，与实际注册不一致即红。

## 一、建局与席（6 条）

| 端点 | 做什么 | 越界了怎么办 |
|---|---|---|
| `POST /api/games` | 建局并自动建席 1..N（默认名「N号」）。带 `script` 字段可挂 BOTC 剧本 | 类型不在枚举 → 400 并列出允许值；人数 >24 → 400。**同名幂等键重发只建一次** |
| `GET /api/games` | 局列表，含事件数、最大天数、剧本 | — |
| `GET /api/games/:id` | 局详情 ＋ 席位名单 | 局不存在 → 404；id 非整数 → 400 |
| `GET /api/games/:id/state?uptoDay=N` | 回放到第 N 天为止的完整状态（事件/声称/行动） | `uptoDay` 非 ≥1 整数 → 400。**这是复盘「当时看到了什么」的主入口** |
| `GET /api/games/:id/export` | 整局 JSON，带元信息与计数 | 局不存在 → 404 |
| `PUT /api/games/:id/seats` | 改席位昵称（仅 `players.name`，零 DDL） | 空数组/空名/席位不在名单 → 400，整批不生效 |

## 二、录入（3 条）

| 端点 | 做什么 | 越界了怎么办 |
|---|---|---|
| `POST /api/games/:id/events/macro` | 三宏直接结构化：**跳身份 / 查杀 / 金水**。不走 AI，产出待确认卡 | 未知 kind、缺席位、对象是自己、席位不在名单 → 400。**宏卡自报 `extracted_by: "macro"`，不冒充 AI 抽取** |
| `POST /api/games/:id/events/extract` | 自由文本 → 结构化声称。BOTC 局自动注入剧本上下文 | 空文本 → 400。MOCK 模式下 `meta.mode = "MOCK"` 如实标注，**绝不谎报为真实模型输出** |
| `POST /api/games/:id/events/confirm` | 确认入账：事件 ＋ 声称 ＋ 行动 ＋ BOTC 专属声称，**一个事务，全成或全不成** | 谓词/席位/引用任一不合法 → 400 且**零行写入**。BOTC 局未挂剧本却录阵营声称 → 400 |

### 确认入账时发生了什么（三条护栏）

原则：**能修的不拒，只有需要人确认的才拒。**降级不是丢弃——原词一定留在记录里。

| 情形 | 处置 | 留痕 |
|---|---|---|
| ① 阵营/状态词（恶魔/爪牙/醉酒/中毒）被当成角色名塞进 `claims_role` | 修复归入 BOTC 专属谓词，落私有表 | `warnings[]` |
| ② 角色名解析不出（口误、自然语言） | 降级为 `said` 留痕，原词完整保留 | `warnings[]` |
| ③ 角色能解析但**不属于本剧本** | **400 拒绝** | 错误信息说清「该角色属哪个剧本」 |

**②的存在理由**：一行说错话不该让整局录入失败，但也不能悄悄丢掉。降级留痕 + 警告 = 不拒、不丢、可复查。

## 三、改与撤（6 条）

| 端点 | 做什么 | 越界了怎么办 |
|---|---|---|
| `POST .../claims/:claimId/edit` | 改声称对象，改后自动标 `confirmed_by_user=1` | **已撤回 → 409**；空对象 → 400 |
| `POST .../claims/:claimId/retract` | 软删（`retracted=1`） | 重复撤回返回 true（终态幂等）；不存在 → false |
| `POST .../actions/:actionId/edit` | 改行动目标/结果 | 已撤回 → 409；patch 为空 → 400 |
| `POST .../actions/:actionId/retract` | 软删 | 归属错局 → 404 |
| `POST .../botc-claims/:claimId/edit` | 改 BOTC 声称备注 | 已撤回 → 409。**只允许改备注**：改谓词/主语会变更语义，须撤回重录 |
| `POST .../botc-claims/:claimId/retract` | 软删 | 重复撤回幂等 |

**账本纪律（写死在存储层）**：撤回是**软删**——行永远还在库里，只是从视图中消失。撤回后一律 409，不许改写。
理由：你会记错，但「你当时记成了什么」本身是复盘的事实。删掉它，复盘就失去了对象。

## 四、复盘（5 条 ＋ health ＋ adapters）

| 端点 | 做什么 | 越界了怎么办 |
|---|---|---|
| `POST /api/games/:id/day/:n/advise` | 天结算。**异步**：返回 202 ＋ task_id，录入不被阻塞 | 当天无事件 → 400，不产出空卡 |
| `GET /api/tasks/:taskId` | 轮询任务。`status ∈ running｜done｜failed` | 任务不存在 → 404 |
| `GET /api/games/:id/cards` | 按天倒序列出已存档的参谋卡（**读已落库数据，不重算**） | — |
| `GET /api/games/:id/cards/:day` | 单天卡 | 当天无存档 → 404 |
| `GET /api/adapters` | 游戏类型登记：内置三型 ＋ 扫 `adapters/` 目录 | 契约不齐 → `ready:false` ＋ 如实列出 `missing` |
| `GET /api/health` | 自报版本、定位、库路径、AI 模式、是否对外暴露 | — |

### 参谋卡上有什么

```
矛盾清单   每条：哪两句冲突 ｜ 欠定度(high/mid/low) ｜ 无辜解释(≥1) ｜ 原文引用
假设       当时怀疑谁、依据哪些发言、倾向强/中/弱
明日清单   明天该盯什么（不自动勾——只有你知道答案）
```

★**RD1 硬约束**：无辜解释为空的矛盾对**不得入库、不得展示**（`src/db/store.js` 的存储层校验，绕不过）。
没有「也可能不是矛盾」的理由，那就不是矛盾，只是解析器嘴硬。

★**同日重结算＝原子覆盖**：删旧与写新在同一个事务里。写失败整体回滚，旧卡原样还在。
（曾经是先删后写两步，中间失败会让当天存档凭空消失，而界面仍正常显示新卡。）

### 矛盾是怎么找出来的

| 来源 | 判据 |
|---|---|
| 纯代码比对器（`src/kernel/engine.js`） | 五类硬冲突：对跳 / 自相矛盾 / 同日行动声称 / 声称vs行动 / 死者活跃 |
| BOTC 剧本比对器（`src/kernel/botc/contradictions.js`） | 剧本数据驱动，认 130 个角色的唯一性与团队结构 |
| 阿瓦隆适配器 | 任务成败、队伍审批、刺杀的承诺兑现 |

**LLM 只负责补无辜解释与欠定度，不负责重新描述冲突。** 描述的唯一真源在代码比对器——
这样「冲突是什么」是确定的，「为什么也可能不是矛盾」才是模型的工作。

## 四·五、MCP 面（8 个工具 · `jujian-mcp`）

> 五条读 ＋ 三条只起草。**没有任何一条能往账本里写。**

| 工具 | 读/写 | 做什么 | 越界了怎么办 |
|---|---|---|---|
| `jujian_list_games` | 读 | 列出全部局（id／名字／类型／人数／天数／事件数） | 无参数，不会越界。空数组 ⇒ 这台机器还没有局 |
| `jujian_game_state` | 读 | 读整局事件、声称、行动。`upto_day` 可按天截断 | 局不存在 ⇒ isError ＋ 列出实际局号；`upto_day`<1 ⇒ isError |
| `jujian_review_card` | 读 | 读参谋卡：矛盾四件 ＋ 假设 | 当天无存档 ⇒ isError ＋ 说清「要人先跑天结算」 |
| `jujian_contradictions` | 读 | 只要矛盾清单 | 空清单 ⇒ **明说「不是这局没人撒谎」** |
| `jujian_game_types` | 读 | 支持哪些游戏 + 五方法契约进度 | 无参数 |
| `jujian_record_claim` | **只起草** | 跳身份/查杀/金水 → 落库草案 | 席位越界／枚举非法／BOTC 越剧本 ⇒ isError ＋ 说清错在哪 |
| `jujian_record_speech` | **只起草** | 自由文本抽取 → 待确认卡 | 未配 key ⇒ `mode:"MOCK"` 且人读文本里明说「不是真模型抽的」 |
| `jujian_review_day` | **只起草** | 天结算 → 可粘贴的命令 | 当天无事件 ⇒ isError，**不产空卡** |

### ★为什么三条写工具不给写权限

局鉴的全部价值是「矛盾清单里每一条都能回查到原始发言、每一条都说得出也可能不是矛盾的理由」。
这个价值完全建立在「账本里那句是谁说的」可信之上。

一条没人核对过的声称混进账本，矛盾检测就在编造上推理，**而它的输出看起来和有据可查的一模一样**。

所以三条写工具恒返回 `gate: 'NOT_CONFIRMED'` ＋ `do_not_retry: true` ＋ `how_to_record`，
人确认后自己跑那条命令。测试 `mcp.test.cjs` ⑩ 逐表核对：三条各调两次后，
各表计数与整局 JSON 必须**逐字节不变**。

### 协议兼容

新规范 2026-07-28 主路径 `server/discover`；老客户端只发 `initialize` / `ping` 也照样能连。
只支持新规范的话，老客户端会拿到 -32601，症状是「明明装上了却连不上」。

## 五、明确不做的事

| 不做 | 为什么 |
|---|---|
| 告诉你谁是狼 | 实测未证：结构化账本在某局里**输给**人工。协议预注册的定位是「复盘工具」 |
| 玄学排盘 / 判词 | 原系统的代码注释写着「绝不接入任何游戏研判功能」「梅花查狼实验已证判词无研判效力」。是赛后彩蛋不是复盘内核 |
| 自动勾选明日清单 | 答案只有你知道。自动勾等于替你下结论 |
| 出网写口 | 没有任何地方把你的对局发出去。唯一的出网是你自己配了 key 并发起分析 |
| 记录调用方身份 | 只保留不含身份的聚合统计 |

## 六、错误形状

所有错误统一为：

```json
{ "error": "人话说明，含允许值或原值", "status": 400 }
```

**400 = 你写错了；500 = 我这边出事了。** 两者对调用方的含义不同，不合并。
