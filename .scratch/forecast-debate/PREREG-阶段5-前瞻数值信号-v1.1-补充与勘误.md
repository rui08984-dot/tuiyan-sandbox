## §2 勘误 D-B：首次「冻结后确认跑」的脚本有**静默丢城**缺陷，所记读数取自**残缺样本**

### 2.1 事实

| 项 | v1 §3 冻结口径 | §44 所记「确认跑」实测 | 差异 |
|---|---|---|---|
| 配对 | **93 对 / 186 槽** | **72 对 / 144 槽** | **−21 对（−42 槽）** |
| `no_val` 题 | **12** | 66 | +54 |
| 上海覆盖 | 27 题 | **6 题** | **−21 题** |

**根因**：首次确认跑用的是一份**未入库的 `.tmp/stage5-final.cjs`**。其抓取错误路径为：

```js
const j = await g(u);
if (j.__err || !j.hourly) { console.log('  ERR'); continue; }   // ← 静默跳过整个分块
```

该次运行**恰逢上海 2024 分块 HTTP 失败**（运行日志首行 `fetch 31.23,121.47 2024: …` → `  ERR`），
于是**整块 24 道题被静默丢弃**，配对从 93 掉到 72 —— 而我在 §44/§43 把这份 72 对读数当作「冻结后确认达标」记录，
并声称「**完全相同代码重跑**」。**该声称不成立**：① 代码不同（`.tmp` 未入库副本 vs 探索性副本）；
② 样本被静默截断，与 §3 冻结口径不符。

**性质**：**工程缺陷 + 留痕失实**（读数方向未被推翻，见 §2.3；但「确认」二字的程序效力不成立）。

### 2.2 违反的条款

- v1 **§3**（冻结池＝105 道／有效配对 93 对／`no_val` 12 道）；
- v1 **§6**「previous-runs API 不可用 ⇒ **暂停并如实披露**（不换 API）」——分块失败应**暂停披露**，不得静默降级继续；
- v1 **§5.2-a** 必要件按 93×2 判定，残缺样品不足该口径。

### 2.3 修复（工程故障重跑 #1 · v1 §6 允许 ≤2 次）

新脚本入库：**`p1b/scripts/stage5-forecast-signal.cjs`**（可复现、可评审），相对旧 `.tmp` 副本的**唯一实质差异**＝硬失败语义：

```js
if (!j || j.__err || !j.hourly) {
  console.error('!! HARD FAIL: … 重试耗尽 -> ABORT 整批（不写结果）');
  process.exit(2);              // ← 不静默丢城
}
```

并加**池指纹硬门**：池 id 集合 sha256 ≠ 冻结锚 ⇒ `exit 3`（防冻结池静默漂移）。判据、映射公式、bootstrap 参数与 v1 §4/§5 逐字一致。

### 2.5 结论（**判据不变，结论不变，但依据换正**）

- 四条判据在**冻结口径的 93 对**上**全部 PASS** ⇒ **路线 (b) 达标结论维持**；
- §43/§44 所载 `Δ=0.1705 CI=[0.1348,0.2057]`（72 对）**作废为读数**（**保留为留痕**，如实记载其来自残缺样本）——正式读数以 §2.4 为准；
- **诚实边界**：这正是「静默降级」类缺陷 —— 残缺样本给出的 Δ（0.1705）比正样本（0.1587）**更大**，若只看数字反而更"好看"；
  即**该缺陷会系统性偏向"好看读数"**，故必须披露而非默默换数。
