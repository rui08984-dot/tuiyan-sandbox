# M-全拟真模拟方案（M 棒 · 单回合设计 · 2026-09-11）

> 任务：为 AI 推演沙盘积累带真值对局数据（L0 门禁 games≥30∧records≥200），回答两问：全拟真模拟怎么搞、除狼人杀还有什么。现状家底=3 局真人局转录（replay 格式已定型）+ p1a 账本（games/players/events/claims/actions，座位号语义）。证据基线：replay-werewolf-lyingman-s02e01.md（56 行，还原完整度≈85%，公开信息流盲测可读）、db.js 头注释（v1 对象式接口）、调研报告 §A（25+ 仓库实测盘点）。本方案只设计不实施。

## §0 三方案对比与推荐

### A. AI 自对局生成（LLM 多 agent 自跑）
流程：版型配置→角色随机分配→夜晚（LLM 决策或程序化）→白天发言（LLM）→声称提取→投票→结算→真值入库。
框架选型（调研报告 §A 实测）:
- AgentVerse（5.1k★，Apache-2.0）：通用多 agent 框架内置狼人杀——重，Python 生态与 p1a（Node/better-sqlite3）异构，出账本要写适配层，版型逻辑改造成本高。**不选**。
- wolfcha（701★，TS）：全 LLM 线上产品——玩法产品化固定，replay 抽取需逆向其存储，工程方向不匹配。**不选**。
- deepwolf（2★，MIT）：自对局 arena+belief model+calibrate 自跑 60 局出校准曲线——思路最同源但实现单薄，借鉴其「calibrate 对照真值」模式而非代码。
- **自研轻量 loop（推荐）**：AIWolf 协议思想（对局状态全枚举化消息）落地成 ~500 行 Node 脚本，与 db.js 同进程直调 v1 接口（createGame/addEvent/addClaims/addAction），**生成的局天然就是账本局，零适配**；游戏状态机（夜晚行动判定/死亡/投票结算/胜负）全部代码硬编码，LLM 只管两件事：发言文本+发言内声称。
优势：真值天然精确（程序结算）、量可批量、种子可复现、schema 原生对接。劣势：发言拟真度风险（AI 腔污染账本语义质量）、策略分布与真人局不同分布。

### B. 真实局转录管线（视频→replay）
流程：yt-dlp 拉片→字幕（whisper 本地）→LLM 按样板格式结构化（对齐 E-N 事件流+座位号表）→人工审核三态标注→真值层（复盘文+弹幕交叉验证）。
优势：语义质量天花板（真实博弈语言、真人话术、自带矛盾与噪声——正是矛盾检测器最稀缺的真考卷）。劣势：1 局 60-90min 视频约 2-4h 人工审核；优质公开复盘文有限（家底 3 局已筛过一轮）；瓶颈在人不在管线。
现状家底已证明管线可行（s02e01 样板含三处原文矛盾就地标注的完整先例），扩展是「复制劳动」而非「研发」。

### C. 混合双源（推荐）
games 表加 source 字段（sim/real），自对局批量供「量」（测管线、跑通 L0 门禁、暴露参谋卡系统性盲区），真实局精品供「质」（校准的分布锚点、矛盾检测器考卷）。两源分层报告，不做无标注混合统计。
选 C 的理由：A 单独跑会在第 30 局时发现校准曲线只对「LLM 对局分布」负责；B 单独跑在 L0 时限内凑不满量。C 的成本结构：A 的钱换时间，B 的人力换分布锚点，各取所长。

### §0.2 关键裁定：自对局算不算 L0 的 n≥30 局？

**建议：计入，但双口径分层 + 三个附带条件。**
1. 门禁防的是什么：L0 门禁（games≥30∧records≥200 前只记不评）的统计本质是防小样本噪声与事后选样（K 棒精读 F13：覆盖波动 ±0.05 需 n≈102；F61：debiased ECE 验证需 n∝√B/E²；F22：p 值粒度 1/(n+1)）。自对局预注册种子与参数后**天然不存在选样问题**（同 seed 可复现、生成后不可回填改参）——门禁的「防作弊」功能对 sim 局自动满足。
2. 门禁防不了什么：分布漂移。sim 局玩家全是 LLM（固定模型池），发言分布/策略分布与真人局**不同分布**；拿 sim 局校准出的 Brier/ECE 直接外推到真人局，等价于 K 棒 F58 说的「用错分布的评估」。**LLM 自对局的校准只对 LLM 对局分布负责。**
3. 附带条件：①games.source 必填（sim/real），报数永远分层（n_sim / n_real 分开）；②基于 sim 局产出的任何校准结论恒挂「模拟语料」标注；③真人局单列门槛 n_real≥10 前任何跨源结论降级探索性；④加一道分布差异哨兵：真人局 vs sim 局的 claims 谓词分布、发言长度分布做卡方/KS 对比，超阈值报警（分布哨兵实现约 30 行）。
4. 与既有纪律自洽：W2 防泄漏条款（created_at 前 200 禁事后选样）对 sim 局天然成立（种子+时间戳可查）。
一句话裁定：**sim 局算 n≥30 的「局」，不算「真人证据」；门禁过线放行「开始记分」，跨源结论分层到真人局攒够才解锁。**

## §1 推荐方案（C）详细设计

### §1.1 数据流与组件（自研轻量 loop）

组件四件（全部 Node，与 p1a 同栈）：
1. **版型配置器**（JSON）：人数/神职/狼数/发言轮转规则/警长规则——对应 replay 样板头的「版型」节；MVP 只做一个版型（9 人标准局：3 狼 3 民 3 神，或直接对齐家底 11 人屠城局）。
2. **游戏状态机**（纯代码，无 LLM）：夜晚行动收集（狼刀/女巫毒救/预言家验/守卫护/猎人枪）→死亡结算→白天发言轮转→投票→放逐→胜负判定。每一步落 addEvent/addAction，结算规则与真人局版型语义一致。**真值层**（角色分配+每夜全部行动）写 games.meta JSON，不进公开 events——对齐样板「公开信息流盲测可读」设计。
3. **LLM 玩家驱动**（唯一 LLM 环节）：每个存活席位一个带私有视角的 prompt（角色+夜间信息+历史公开事件流），输出=发言文本+结构化声称 JSON（同一次调用双输出，extracted_by 记 sim-llm）；狼人夜间刀人/预言家验人也走同结构输出（addAction）。**发言拟真度靠 prompt 侧注入真人语料风格锚**：prompt 里附 2-3 段家底 replay 的真实发言作 few-shot（用真人语言喂真人味，这是最便宜的拟真手段）。
4. **落库直通层**：loop 直接调 db.js v1 对象式接口，一局结束即 exportGame 出 JSON 归档到 docs/sandbox/sim-replays/（文件名 sim-ww-XXXX-seedYYYYY.md+json，附生成参数头）。

数据流：版型 JSON+seed → 状态机建局 → 循环{夜晚：LLM 行动→程序结算→system 事件；白天：LLM 发言+claims→投票→程序结算} → 胜负 → exportGame 归档 →（批量模式）下一局。

成本预估：11 人局×4 天×(11 发言+11 投票+夜行) ≈ 150-250 次 LLM 调用/局；30 局 ≈ 6000-8000 次——用低成本模型跑发言、关键决策同模型，MVP 先 5 局实测单价再定批量预算。

### §1.2 账本 schema 对接（逐字段映射）

- games：name=sim-ww-XXXX；game_type='werewolf_sim_11p_tuicheng'（前缀 sim_ 与真人局 game_type 区分）；player_count=11；**新增列 source TEXT NOT NULL DEFAULT 'real' + meta TEXT**（seed/model/prompt_version/版型 JSON）——一处 ALTER TABLE，其余表零改动。
- players：seat 1..11（座位号语义原样），name=「sim-{seat}号」或注入拟人昵称（MVP 用座位号，昵称二期）。
- events：day=天数；phase∈night|day|dusk 原语义；type：夜晚死亡公布=system、发言=statement、投票结果=vote、遗言/宣称=claim；seq 自动单调。
- claims：same-call 双输出的结构化部分直接映射——谁说的 seat、说谁 subject_seat、谓词七选一（is_wolf/is_good/is_role/claims_role/voted/did_action/said）、object=对象座位号或「动词:目标」格式（check:8）。**声称与发言同源生成，天然对齐真人局「E-3: 公开宣称+报查验」的事件-声称二元组结构**。
- actions：夜行动直接映射（kill_target/poison_target/protect_target/check_target），投票=vote/abstain——枚举零扩展（狼人杀版型完全够用）。
- contradictions/hypotheses：不写！这两个表是参谋卡的**输出**，sim 局只喂输入（公开层），参谋卡照常跑，其输出与 sim 真值对照产生校准数据——deepwolf calibrate 模式。
- exportGame 已有：loadGameState+meta 直接复用，sim 局归档与真人局同格式（追加 source/meta 字段）。

### §1.3 质量护栏（AI 腔检测 + 预注册条款）

**护栏一：发言拟真度三道检测（每局跑，结果写进 meta.qc）**
1. 程序化分布哨兵（零 LLM）：发言长度分布、句长方差、口语/语气词频、claims 密度（每条发言的结构化声称数）——与 3 局真人家底对比分位数，越界打标。~30 行。
2. LLM AI 味抽样：**复用本机已有 aidetect 能力**（中文 AI 味量化：指数 0-10+八项指标），每局抽 10% 发言，AI 味指数>6 的占比写 meta.qc.ai_flavor_rate。
3. 博弈有效性：身份一致性矛盾率（sim 局的 claims 自相矛盾率 vs 真人家底）——本身是矛盾检测器的输入，顺带当拟真度指标：真人局矛盾率是锚，sim 局显著偏低（太理性）或偏高（乱说）都打标。
**护栏二：预注册条款（防 prompt 过拟合，L0 同构纪律）**
1. 每局生成前冻结五元组（seed、模型 id、温度、版型 JSON、prompt_version）写 meta——生成后不可改。
2. prompt 迭代必须升 prompt_version 且**新版本只影响新局**，禁止对旧局回填重跑；比较不同 prompt_version 的局时视为不同分布层。
3. 禁止「跑完参谋卡发现表现不好→回去调 prompt 重生成同一批」——这是校准欺骗的模拟版（与「事后选样」同罪）。要调参，预注册新一轮 batch。
4. 批量报告附 QC 汇总表（每局：调用数/发言数/AI 味率/矛盾率/局长），不达标的局标记但不删除（保留完整记录，报告分层呈现）。

## §2 领域扩展矩阵（除狼人杀还有什么）

复用率定义：账本五原语（座位号玩家/事件流 phase+type/声称谓词七种/行动枚举/矛盾检测语义）在目标游戏中可直接使用而不需语义扭曲的比例；②号适配器门槛=复用率≥70%（任务书裁定）。

| 领域 | 复用率 | 真值可得性 | 改造工时 | 值不值 | 判定 |
|---|---|---|---|---|---|
| 阿瓦隆 Avalon | ~80%：座位号✓/events✓（轮次映射 day）/vote✓（队列表决）/claims_role✓（宣称梅林/派西维尔/莫德雷德）/行动枚举需加 nominat_team 任务提名（system 事件可顶） | 角色分配即真值+任务成败天然已知 | 低（1-2 天，主要是任务轮状态机） | **值**：隐藏角色+团队博弈，语义最贴近，且「梅林视角信息不对称」是参谋卡验证点的绝佳考卷 | **②号适配器首选** |
| 一夜终极狼人 | ~85%：版型是狼人杀子集（单夜+一天讨论），schema 全兼容 | 天然 | 低（半天，砍掉多夜循环即可） | 中：边际信息少（与已支持版型重叠高），但**做 MVP 管线冒烟测试最便宜**（6 人×1 夜≈40 次调用） | MVP 冒烟用，不算主力语料 |
| 血染钟塔 | 已支持（家底） | — | — | — | 不动 |
| 剧本杀 | ~55-60%：座位号✓/statement✓/claims 部分✓（said/claims_role），vote 与行动枚举大半废（搜证/技能结构差异大） | 剧本自带凶手 | 中（剧本结构差异大，一剧本一适配） | 低-中：结构松、口径难统一 | **缓**（二期看需求） |
| 逆转裁判 | ~60%：座位号+statement+claims 高复用，vote/action 基本废；「威慑/出示证据」需新 event type | 剧本固定真值 | 中高（章节结构+证物系统） | **特殊价值**：证言/指认/矛盾密度极高——是矛盾检测器（engine.findContradictions）的高质量压力测试考卷，不走 L0 主粮口径、单列「矛盾检测器考卷库」 | **支线特批**（不走 70% 门禁，理由=用途不同） |
| 德州扑克 | ~45%：座位号✓/actions 核心是下注序列（bet/call/raise/fold 全不在枚举）/claims 谓词几乎全废（牌桌话术弱声称） | 牌面全公开 | 中 | 分：**「下注=真金白银的置信声明」对预测卡独特**，但 schema 语义扭曲大 | **砍**（YAGNI；将来若做独立「下注即预测」线再启） |
| 围棋/象棋 | ~20%：PGN/SGF 真值完美但无多人座位/声称/发言语义，账本五原语废四个 | 完美 | 低（解析器简单） | 不值：复用率远低于 70% 门槛 | **明确砍**（任务书点名 gate 不达标） |

矩阵结论：②号适配器=阿瓦隆（80% 过线）；MVP 冒烟=一夜狼；支线考卷库=逆转裁判；其余全部砍或缓。

## §3 失败长相与砍件清单

### §3.1 五种失败长相（提前验尸）
1. **AI 腔污染**：发言全是同一模板腔 → claims 分布同质化 → 校准曲线假好。检测=护栏一三道；发生时处置=prompt 版本升级（few-shot 换真人语料权重加大），新版本只跑新局。
2. **策略塌缩**：LLM 狼人永远悍跳预言家/女巫对跳 → 真值分布退化，参谋卡「见怪不怪」。检测：开局策略分类统计（首夜刀位分布/首跳率/对跳率）跨局对比真人家底；发生时：升温度/换角色 prompt 骨架/注入随机人设。
3. **自嗨循环**：LLM 席位互相秒懂，3 天速推结束 → 局内事件数远低于真人局（家底 31 事件/3 昼）。护栏：版型最小时长下限（如≥3 昼≥25 事件），不达标局记 qc.short=1。
4. **prompt 过拟合**（最阴险）：跑完参谋卡表现不好→回去调 prompt 重生成同批 → 校准欺骗的模拟版。防=预注册条款（§1.3 护栏二），违反=该 batch 作废重预注册。
5. **成本失控**：30 局×200 调用×长 prompt——先 5 局实测单价，超预算的降级路径：小版型（6 人一夜狼）当批量主力+11 人局当精品层，报数时注明版型分层。

### §3.2 砍件清单（YAGNI）
- 砍：AgentVerse/wolfcha 框架引入（自研 500 行 loop 直连 db.js）。
- 砍：语音/视频输入的自动管线（MVP 只做文字 replay；视频转录半自动+人工审核，yt-dlp+whisper 只当素材工具）。
- 砍：围棋/象棋/德扑适配器（复用率不达标）。
- 砍：多版型并发（MVP 单版型；版型配置器留了 JSON 口子但不多做）。
- 砍：LLM 记忆/长期人设系统（席位间不共享私有状态以外的任何东西，prompt 即全量——加记忆系统会把分布搞得更不可控）。
- 缓：剧本杀（二期）、昵称拟人化（二期）、自动扩量调度（手动跑 batch 就够）。

## §4 分期路线（MVP→扩量）

**M0 管线冒烟（0.5-1 天）**：一夜狼 6 人版 1 局端到端——版型 JSON→loop→落库→exportGame→参谋卡能吃公开层。验收判据：1 局完整落库、exportGame JSON 过 schema 校验、真值层与公开层分离正确、QC 报告产出。
**M1 批量 30 局（2-3 天）**：11 人标准局，预注册五元组→跑满 30 局 sim（AI 腔哨兵全程开）→ L0 门禁「games≥30」达成（sim 口径）→ 预测卡开始记分（只记不评，恒挂模拟语料标注）。验收：30 局 QC 汇总表+分布哨兵报告+参谋卡对照真值的首份分层校准曲线（sim 层）。
**M2 真人局扩容（并行长期）**：真实局 3→10 局（每局半自动转录+人工审核 2-4h）→ n_real≥10 解锁跨源对比 → 双源分层 ECE/矛盾率报告 + 分布哨兵卡方检验出第一份「sim vs real 分布差异」报告。验收：分层报告+差异量化结论（决定 sim 校准曲线能否外推）。
**M3 领域扩展（按需）**：②号适配器=阿瓦隆（复用率 80% 过 70% 门槛，1-2 天状态机改造+few-shot 语料补充）→ 双版型混合账本 → 逆转裁判考卷库支线（走矛盾检测器压力测试，不走 L0 主粮）。

各期共同验收铁律：只记不评过线前 UI 恒挂参考标注；所有 sim 局产物带 source+seed+prompt_version 三元组；报告永远分层（sim/real、版型、prompt_version）。
