**成立怎么改**：裁 B1(a) 的三路信息差为准——每条路径新旧对比恰好单变量（v1 只变证据、v3 只变基率、v2 不变），归因干净。A1 文字改「注入点在 buildUserPrompt 内按 variant 分流」。

### 攻击 4｜对 S1：「predictions 账本一行不动」被自己的 runner 违反 【重（自评可降轻-中）｜站得住】

S1 §2 步骤②承诺「predictions 账本一行不动」；但 judge-runner.cjs L31 对每条 `UPDATE predictions SET assigned_prob = median`——重跑会把 90 条 assigned_prob 全部覆写成新条件的中位数，旧条件写回值丢失（可从 verdicts 归档重算，但计划没写恢复路径）。更深一层：assigned_prob 的 schema 语义是「落注时的数值概率」，已被 runner 劫持为「判词中位」，`calibration()` 端点现在把判词中位当落注概率输出——语义冲突无人认领。

**成立怎么改**：重跑前把旧 assigned_prob 快照进归档并在 §2 写明；中期把判词概率从 assigned_prob 拆出（落 verdicts 表聚合或独立列）。

### 攻击 5｜对结构深查员：「飞轮量产劣于基线的判词」事实错误 + 源头断点没排优先级 【重｜站得住】

**证据**：grep 实测 sim-loop.cjs、batch-runner.cjs 零 verdict/判词调用——飞轮产的是题＋真值＋replay，不产判词；判词是独立手动 runner。同一轮调查又说「飞轮缺调度器」——不产判词又没调度器的东西不可能「量产劣质判词」，两条发现自相矛盾。依赖方向：更多带真值的题＝TS 重校准的更多标注数据，题源生产与判词修复**解耦**。保留一个合理内核：飞轮的真正前置不是判词质量，而是 **checklist v2(Q0-3)＋模板多样性**（现在 3 条固定模板×N 局＝同题重复灌水，200 门会被重复刷线）。另抓一处倒挂：他把四族列排 TOP1，却没把 evidence_json 回填排进任何位置——**先修不存在的新列，不修已坏的旧列**。

**成立怎么改**：排序改为 模板库扩建＋checklist v2 → 飞轮（调度器最后）；判词修复与飞轮并行不阻塞；若将来飞轮挂自动判词，前置条件是模型版本戳先落。

### 攻击 6｜四族列等重跑完再加？——一大半站不住 【站不住（弱化为「捆绑回填」）】

additive 可空列中途加的先例就在本表（七审计列是 p12 中途加的），NULL=遗留语义有成例；重跑只读 statement/layer/evidence_json，不读新列，加列不污染重跑。「两代 schema 行混析」靠 NULL 语义＋checklist_hash 式版本化即可。**站得住的残余**：①90 条旧行 anchor_uri 无法回填（evidence_json 空，锚点信息已丢）——anchor_uri 依赖攻击 1 的回填；②template_id 回填要一次拍板（3 个隐式模板命名）。结论：不等重跑，但回填（evidence_json＋template_id＋tautology）**捆成同一次账本迁移**，避免对不可变账本 UPDATE 三轮。

### 攻击 7｜S1+S2 都没接的盲区（6 个）

1. **git 缺位不在任何批次**【重｜站得住】。实测非 git 仓库。p12 自己记载 SCHEMA 行级 edit 六轮才绿＋修复脚本用完即删——无版本控制的代价已付过一次；重跑要动 verdicts.js/judge-runner/sim-titles 三个文件，零回滚。批次 0：git init＋.gitignore＋基线 commit，≤1 小时。
2. **D-裁决 方案 5 仪表盘「立即」档悬空**【重｜站得住】。D-裁决 L57 明文「立即｜方案 5 仪表盘｜1-2 天」，理由「上线后静默劣化，仪表盘=监测件」。现状：calibration()＋路由已在，p1b\web\src grep 零预测相关文件——**UI 半件无人接**，S1/S2 都没排。TS 重校准落地期恰是漂移监测最需要的窗口。
3. **verdicts 无模型/批次版本戳**【重｜站得住】。PRAGMA 实测 7 列（id/prediction_id/prompt_variant/temperature/verdict_text/implied_prob/created_at）。重跑的「新」数据靠「清表」与归档隔离——归档到重跑之间任何误 POST /verdicts（公开路由）静默混入不可分辨。additive 两列＋runner 带戳，半小时，**必须赶在重跑前**。
4. **红队漏报#2（judge-runner 选题 SQL 无域过滤）无归属批次**【中｜站得住】。L12 无 source_type/game_id 过滤。现状潜伏，但 convertCheckpointsToPredictions 随真实局天结算自动落卡，layer 一并补录即被卷入。15 分钟加过滤，挂进批次 1。
5. **3 条/局对「预测万物」的支撑是虚的**【中｜站得住】。一夜狼单版型下 L2 系综/L4 自反/L5 随机结构性出不了题，S2③ 写「sim 源 0（已有）」低估了缺口；不扩模板库（≥10 非重言模板、跨版型），飞轮之夜只是同题复读，200 门=注水达标。
6. **口径小漂移（脚注级）**：S1 引「70 条 implied_prob∈[0.6,1.0]」，DB 实测 ≥0.6=68 条，70 是 ≥0.55 档的数。另 INDEX L1 写「11 篇」实为 12 篇，S2 L66「11 篇里最大缺口」连带继承此错，G v1.2 更正时一起扫。

### 攻击 8｜预注册「防跑到好看」实际防不住的三处缝 【中｜站得住】

①判据只冻了阈值没冻 endpoint（median 还是 per-path 没写死，事后选有利的＝forking paths）；②无噪声条款（n=60 的 1σ≈0.06，两个方向的结论都可能由噪声决定）；③烟测门「verdict_text 必须引用事件内容」没按路径分标——v2 纯题面路径照字面必挂，执行者会被迫临场改规则，而临场改规则正是预注册要防的事。S1 尾注 3「判定者双人背对背」是好人条款，不是规格。
