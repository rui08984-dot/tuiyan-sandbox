## 二、有争议点的三方对照

**争议 1：14 天 DNA 回溯读数实验（E1）该不该跑、以什么形态跑**
- 正方（07）：纯读侧、失败零损伤，一次实验定 v3.0 全部可救组件的生死，值得 14 天包干。
- 反方（08）：三处硬伤——未控制既有 layer×domain 分层（A/R/S 通过＝重发现既有分层＝假阳性）、五日包干成本低估、L2 基率主导误差结构致信息上限极低；跑赢也只得一列。
- **裁决：跑，但收编为「加列制首列」而非独立 14 天项目。** S 维先行，判据＝控制 layer×domain 后条件化 ΔCI 不含 0 且格 n≥30；放弃条件＝ΔCI 含 0，该维永久降为文档标签，姿态门与路由主张一并放弃。理由：取正方「一次实验定生死」之魂，用反方的控制变量修理其身；14 天换 1-2 人日/列，产能省给天气主攻。改判：规则版标注一致率 <85% 或事视角污染不可控 → 连加列制也停。

**争议 2：记账语言统一是实质还是修辞**
- 正方（07）：给归因以语义槽位（错在先验还是似然），是公开报告与文献对话的通用语；批评者自己采纳即其不可替代性之证。
- 反方（08）：行为测试不过——标签不改任何门/阈值/路由；槽位归因＝换算子重算＝消融，已判负；真内容只是更整洁的报告模板。
- **裁决：反方胜半——采纳但降预期为零精度增量的文档层语言。** 其实质收益只认两件有行为后果的事：Wilson→Beta 升级（表#6）与 operator_runs 归因表（P1 消融配套）。改判：出现争议 2 改判条件实例（表#2）→ 升级为机制层。

**争议 3：8 产品收缩到哪两个、API 何时上**
- 正方（07）：日历＋报告＋API 三件近期；批评成立于次序不成立于愿景。
- 反方（08）：只做日历＋报告，API 后置；放行门＝分域 n≥30＋首份报告。
- 对标棒（04）：API 是 8 形态中唯一有成熟先例、最先可做的。
- **裁决：近期两件＝日历＋公开校准报告；API 后置。** API 工程最易恰是陷阱——产能是一人团队最高风险资源（01-P3），放行门优先于工程可行性。改判：天气域连续 4 周前瞻 ΔCI 为正＋报告已发布＋产能有余 → API 提前立项。

## 四、给用户的一句话建议

**最小采纳（按 v3.1 修订，不整案、不封存）**：v3.0 的真正价值不是「统一框架」——那已被四次负结果与 KK516 null 判了缓刑——而是它逼出了这份可证伪的分期清单；据此采纳四件内核（文档层记账语言、DNA 加列制、Beta 共轭先验、公开验证骨架＋日历/报告两产品）与天气主攻，迁移纪律六件套为不可协商前置，乘法公式/MCMC/类比/专家网络/三条「唯一」即日删除或封存，路由/因果/缓存/其余产品各持预注册门票待验——每张票都写好了放弃条件，输得起才配赢。
