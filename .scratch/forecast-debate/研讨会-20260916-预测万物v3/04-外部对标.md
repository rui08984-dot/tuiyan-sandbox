## 一、验证/排行榜机制先例

| 平台 | 核心机制（一句话） | 对 v3.0 第6层「公开排行榜+校准报告」可直接借鉴 |
|---|---|---|
| **Metaculus** | 众包概率预测平台：用户出题+预测，社区预测聚合，按分辨力积分，长期追踪校准（存在与定位已核验；细部未联网核验） | ①校准公开页：按预测区间分桶画「声称概率 vs 实际频率」曲线，而非只发文字报告；②排行榜按题目类别分组（对应你的按 DNA 分组），用相对分数而非绝对 Brier，避免跨题不可比；③「已关闭待揭晓」题目单独展示，管理验证延迟 |
| **Manifold / Kalshi / Polymarket** | 市场定价：交易价格即概率（Manifold 玩具货币 AMM、Polymarket 真金 AMM、Kalshi 受 CFTC 监管的限价订单簿），存在已核验、细部未联网核验 | 第6层「系统 vs 预测市场」对比列可直接取三家公开 API 的收盘价做基准线；注意市场价只能当**对手参照**，不能当真值源 |
| **Good Judgment / Samotsvety** | 超预测者团队：筛选+训练+组队出预测，公开 track record（Samotsvety 官网红队已核验） | 人类专家对比的**最小可行版**：不必拉人进场，先引用 Samotsvety/ForecastBench 已公开的人类分数做对照行 |
| **ForecastBench** | AI 预测动态基准（arXiv 2409.19839，本轮直核）：1000 题自动生成、定期更新；**只收提交时无已知答案的未来题**，从根源防训练数据泄漏；N=200 子集收人类专家预测，公开榜在 forecastbench.org | **最值得抄**：①防泄漏设计——题目信息必须晚于 LLM 训练截止（对 AI 似然算子的每轮调用都成立）；②动态换题池+公开榜；③人类专家仍显著强于最强 LLM（p<0.001）——给 v3.0「超越人类专家」提供了真实基线刻度 |
| **FutureX** | LLM 未来预测 live 基准，动态实时更新题目防污染（arXiv 2508.11987，红队已核验；futurex.live 本轮可访问但页面 JS 化，机制未联网核验） | 借鉴其「持续出新题、旧题揭晓即归档」的滚动机制，对应你已有的 PREREG 冻结+verdicts 回填——你的基础设施已等价，缺的只是对外公开面 |

## 二、8 个产品形态逐个对照

| 形态 | 先例判定 | 一句现实性判断 |
|---|---|---|
| 预测编译器 | 部分先例（ForecastBench 题目自动生成管线、Chronulus「AI agents 预测万物」） | 最小版＝把自家六层管线包成「问题→DNA+配方+概率」入口，一人+AI 一周可成，本质是门面工程 |
| **预测配方市场** | 无通用先例；部分先例＝Numerai（模型质押按真实表现结算+合成 meta model，本轮直核）、量化策略市场 QuantConnect（未联网核验） | **单向发布可行、双向市场不可行**：发布自家配方的公开目录+归因数据可做；吸引第三方上传需双侧冷启动+防作弊评分，超出一人团队——建议改名「配方公开库」 |
| **结构搜索引擎** | 未检索到通用先例；最近类比＝学术因果图库/数据集搜索引擎（未联网核验） | 对内可行：在你 1972 题账本上做 DNA/配方/因果结构检索是现成数据的增值；对外无供给方，作产品无先例支撑，建议降级为内部功能 |
| 预测API | 成熟先例（Metaculus/Manifold/Kalshi/Polymarket 均有公开 API，未联网核验；open-meteo 即此范式） | 完全可行：现有管线加 HTTP 层即可，且是 8 形态中唯一有直接成熟先例的，宜最先做 |
| **反事实沙盒** | 部分先例＝Guesstimate（费米估算蒙特卡洛沙盒，网站本轮可达但机制未联网核验）、Causal.app 类决策建模（未联网核验） | 窄版可行：基于情景算子+因果图缓存输出「若 X 则分布如何变」；硬约束：反事实**不可验证**，必须标注「模拟非预测」并挡在铁律（UI 禁「预测」）之外表述 |
| 预测竞技场 | 有成熟先例（ForecastBench 的 AI vs 人类公开榜本轮直核；Metaculus 锦标赛、Hypermind 冠军面板红队已核验） | 无需真人版可行：自家系统 vs 市场收盘价 vs ForecastBench 公开人类分数的三行对比榜；拉真人进场成本高、且与 8787 零接触纪律冲突，发布须走独立渠道 |
| 预测日历 | 部分先例（经济日历 ForexFactory/Trading Economics、Kalshi 按日组织的事件页，均未联网核验） | 工程量最小、最贴合你已有资产：结算 daemon 的日历+PREREG 队列直接变成公开页，建议与校准报告合并为第一个对外产物 |
| 预测地图 | 部分先例（垂直成熟：选举概率地图、气象地图 Windy，均未联网核验；通用概率地图无先例） | 只在天气域有意义（openmeteo 本身带地理维度），通用版无供给与需求，建议缩为天气域一张图 |

**总评**：8 形态中 API、竞技场（对比榜版）、日历三个有直接可抄先例且一人+AI 可落地；三个最 novel 的（配方市场/结构搜索/反事实沙盒）都应从「对外产品」降级为「对内功能/单向发布」，因缺乏先例+双边市场/验证性硬伤。

## 三、先窄后广：领域切入建议

对照标准（结果明确、数据丰富、可验证）与现有管线：

**最优先：天气域加深（主攻「超越专家」主张）**。理由：①唯一已有达标前瞻信号（阶段 5b Δ=0.1587）；②openmeteo 档案管线+真值自动回填现成，验证零人工；③无监管争议、与 UI 禁词纪律无冲突；④ForecastBench/WeatherNext 证明天气是 AI 预测最被认可的垂直域，对标资源最全。
**次优先：经济数据发布预测**。dbnomics/frankfurter 管线现成，发布日历固定→与「预测日历」产品天然咬合；数据发布不是市场定价对象，避开有效性难题。
**可选：加密货币做校准练习场**（kraken 管线在，但真金市场定价强（Polymarket/Kalshi 先例），别指望超越市场，只练校准）。
**暂缓**：体育（无管线+对抗强，第二梯队）；选举（监管+低频，红队已警示）；票房/财报/科技发布（验证延迟、真值口径模糊）；彩票（已有强域但属可预测性下限，只宜作「校准诚实」展示，不宜对外主打）。

一句话：**v3.0 清单里真正该动的棋是「天气主攻+经济数据日历」，其余六域先上黑名单而非路线图。**
