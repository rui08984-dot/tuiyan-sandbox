## 二、DB/账本影响

- predictions 表 23 列已含 layer/engine/gate/metric_version/backtest_batch 等元数据列，**additive 加列有先例且可行**；回改历史行一律不可行（账本不可变）。
- verdicts 10 列：判词行不可改；算子级细粒度归因如需逐算子行 → **旁路新表 operator_runs**（prediction_id, operator, output_json, version），不动 verdicts。
- 「问题DNA标签」给存量 1972 行打标：**唯一合规路径是读侧派生**——照 truthBasis.js/domain.js 既定范式：派生规则写死、改动=版本递进、零账本写、披露计数。写端 UPDATE/物化进 predictions＝违账本不可变，禁。若派生计算太重需物化：additive 新表 dna_tags（prediction_id, dims_json, extractor_version, created_at），照 predictionsStore「共享库禁 DDL 改既有表、私有表 CREATE TABLE IF NOT EXISTS」先例建 p1b 私有表，只 INSERT 不 UPDATE 历史行。
- 缓存（四层/语义）：旁路新表 cache_entries（key_hash, payload_json, ttl, hit_count）；校准参数（ACI α、等渗映射）读侧即时计算，无需 schema 变化。
- p1a-terminal/src/db.js 是禁改面：p1b 只经 predictionsStore/verdictsStore 读复用，一切 DDL 走 p1b 私有表 additive 路径。

## 三、LLM 成本与角色合规

铁律④（LLM 四角色＋不出概率）在 verdictsStore 已落为硬约束：verdict_text 是唯一产出，implied_prob 由末行 `P=0.xx` 正则机械抽取（两次负结果均死于 LLM 直出数字）。逐算子判定：

- 合规（照旧）：AI似然=多路角色；基率注记=基率角色；校准报告生成=校准角色（且现有 ACI 校准零 LLM，更稳）。
- 可辩护但需裁定：分解/情景/反事实/类比——若 LLM 只产**结构化文本**（子问题、情景清单、因果结构、类比案例），概率仍由多路判词出＋机械抽取，可归入「多路」角色的输入准备；若 LLM 直接给后验概率＝违铁律④，必须改设计。因果图生成同理（只产结构不产概率），自产文案须过 l5_certified 的 assertion_guard 黑名单扫描先例。
- 零 LLM：最大熵、统计似然、贝叶斯更新、保形、等渗、beta calibration、路由决策（规则版）。

成本量级（相对参照：命题 A 全量 2158 行×3 臂≈6474 次判词调用/轮；金额未核验，交接件无数字）：一次「DNA→算子→后验」全流程，若 DNA 用规则版＝0 次；LLM 算子（类比+情景+因果+反事实各 1-3 次）＋多路判词 3 变体≈**每题 7-13 次调用**，约为命题 A 单行 3 臂的 2-4 倍。v3.0 §十「下周 10 题手动跑全流程」≈70-130 次，不足命题 A 一轮的 2%。注意：全量 1972 行 LLM 打 DNA 标≈1972 次虽也不贵，但违铁律④，不做；规则版打标零成本。

## 四、分期落地方案（去伪后清单：剔除 Decitron/ForecastAgent/Lynx/BBC 生造名，BBC→beta calibration）

**P0（零风险 additive，无需 PREREG）**：①等渗回归 PAVA 纯函数＋在 4766 verdicts/1972 行上与 ACI 离线 A/B；②DNA 规则版八维读侧派生器（照 domain.js 单一真源范式，存量 1972 行读侧打标或 additive dna_tags 表）；③校准报告 additive 扩展（g2-report 分 DNA 披露）。验收：金样回放零读数变化；既有 373/318 测试不红；零账本写。

**P1（需 PREREG 冻结）**：①算子路由最小版（DNA→固定配方映射；立项前置=答辩 D2 model≡base 负结果）；②情景/分解算子按「多路变体＋机械抽取」改造；③beta calibration（Kull 2017）对照实验；④最大熵算子。验收：PREREG sha 冻结＋池指纹硬门（stage5Pool 范式）＋泄漏审计 0＋负结果止发。
