## §2 ★根因（实测锁定）

**不是网络问题，是 daemon 的请求头策略触发目标站反爬。**

### 2.1 实测矩阵（同一 URL，同一时刻）

| 请求头组合 | 结果 |
|---|---|
| curl 默认（无 UA） | **200** ✓ |
| node fetch 默认（无 UA） | **200** ✓ |
| `User-Agent: Mozilla/5.0 ...`（浏览器 UA，**裸**） | **567** ✗ |
| 浏览器 UA + `Accept: application/json, text/plain, */*` | **567** ✗ |
| **浏览器 UA + `Referer: https://static.sporttery.cn/`** | **200** ✓ |
| 浏览器 UA + `Origin: ...`（无 Referer） | **567** ✗ |
| `User-Agent: curl/8.0` | **200** ✓ |
| `User-Agent: corpus-resolve/1.1 (+node)` | **200** ✓ |

### 2.2 规则归纳

> **sporttery 对「浏览器 UA」要求完整浏览器头上下文（含 Referer）；对「非浏览器 UA」不做此检查。**

即：**自称是浏览器却拿不出浏览器该有的头 ⇒ 判爬虫 ⇒ 567**。

### 2.3 为什么只有 daemon 踩中

| 调用路径 | 是否注入 UA | 结果 |
|---|---|---|
| `corpus-resolve.cjs` **直跑** | 否（`getJson(u)` 不传 headers） | **200** ✓ |
| `corpus-resolve-daemon.cjs` | **是**——L74 强制 `Object.assign({ 'User-Agent': UA_DEFAULT, Accept: ... }, headers)` | **567** ✗ |

`UA_DEFAULT` = `'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36'`（**浏览器 UA，裸**）

⇒ **daemon 的「善意」UA 注入，恰好把 dlt 推进反爬规则里**。

## §3 为什么之前没被发现

- 既有记忆记为「**dlt 567 老问题**」⇒ 被当作**外部环境问题**接受，未追根因
- 该域**从无成功样本**（38/38 未解）⇒ 没有"以前能结、现在不能"的对照，**缺少触发排查的信号**
- daemon 的 UA 注入是**全局行为**（对所有 kind 生效），但只有 sporttery 一家对此敏感

## §4 修复选项

| 选项 | 做法 | 影响面 | 评价 |
|---|---|---|---|
| **A（推荐）** | **dlt resolver 显式传 `Referer`**（`getJson(u, { Referer: 'https://static.sporttery.cn/' })`） | **仅 dlt 一个 kind** | ★最小改动、零口径变更、有实测支撑 |
| B | daemon 去掉浏览器 UA（改 `corpus-resolve/1.1`） | **全局所有 kind** | 风险：其他站可能依赖该 UA（未验证）——**改全局默认值须评估全部 61 kind** |
| C | daemon 对 sporttery 域特殊处理 | 全局代码加分支 | 比 A 复杂，收益相同 |
| D | 不修，dlt 域作废 | — | 该域 38 题**全部**不可结，但**不触门**；作废须拍板 |

**推荐 A 的理由**：
1. **影响面最小**（只改一个 resolver 的一次调用）
2. **零口径变更**（不碰判据、不碰统计、不碰全局默认）
3. **实测支撑**（Referer 方案已测 200，且是 4 组对照中唯一生效的浏览器头）
4. **可回归**：可写测试锁「dlt resolver 必须传 Referer」
