> 触发：决策清单 ② 的后续（dlt 已修，cta/elexon 待诊——它们在（四十一）批报 HTTP 403）
> 性质：**只读诊断**，零代码改动 ｜ 结论：**地域/IP 层封禁**（与 dlt 的 UA 策略问题**机制不同**）

## §1 现象

| 域 | 未解 | 总 | 最后成功 | 报错 |
|---|---|---|---|---|
| `cta_daily_total_rides` | 3 | 7 | **09-13**（8 天前） | HTTP 403 |

★ **elexon 两天前还能成功** ⇒ 不是永久封锁，是**近期开始的拦截**。

## §2 诊断矩阵（实测）

### 2.1 elexon

| 测试 | 结果 |
|---|---|
| 原 URL（curl 默认 UA） | **403** |
| curl + `User-Agent: Mozilla/5.0` | **403** |
| 换日期参数 | **403** |
| 去掉参数（仅 `?format=json`） | **403** |
| **`/api/v1/health`（健康检查端点）** | **403** |
| 完整浏览器头（UA+Accept+Referer+Origin） | **403** |

★ **连 `/health` 都 403** ⇒ **整个域名被网关封**（非参数/headers/限流问题）。
响应体含 `Microsoft-Azure-Application-Gateway/v2` ⇒ 拦截发生在 **Azure 网关层**。

### 2.2 cta（Socrata 平台）

| 测试 | 结果 |
|---|---|
| 原 URL | **403** |
| `/api/views.json`（平台元数据端点） | **403** |
| **站点首页 `data.cityofchicago.org/`** | **403** |
| **`data.seattle.gov`（另一 Socrata 站点）** | **403** |

★ **连首页都 403**，且**跨站点**（chicago + seattle）⇒ 是 **Socrata 平台级**对本机 IP 段的封禁。

### 2.3 对照（排除"本机网络全断"）

| 站点 | 结果 |
|---|---|
| `api.github.com` | **200** ✓ |
| `api.crossref.org` | **200** ✓ |
| `ipinfo.io` | **200** ✓ |

⇒ 本机网络正常；**是特定站点/平台对本机 IP 的封禁**。

## §4 与 dlt 的根本区别（★重要）

| 维度 | dlt（已修） | cta／elexon（本件） |
|---|---|---|
| 报错 | HTTP **567** | HTTP **403** |
| curl 默认 UA | **200** ✓ | **403** ✗ |
| 换 headers 能否解 | **能**（加 Referer） | **不能**（全试过） |
| 根因层 | **应用层反爬策略**（UA 检查） | **网关/平台层地域封禁** |
| 代码能否解决 | **能**（已修） | **不能** |

⇒ **dlt 的经验不能套用**：dlt 是"自称浏览器但头不全"，cta/elexon 是"整个 IP 被拒"。

## §5 修复选项

| 选项 | 做法 | 可行性 | 评价 |
|---|---|---|---|
| **A（推荐）** | **接受现状**：这两域标记为「地域受限」，不作为待办 | — | ★诚实——这是**环境事实**，非缺陷 |
| B | 用代理绕过 | 需可用代理 | 本机**无可用代理**（实测 7897/7890/10809/1080 全不通）；且代理绕过地域限制**可能违反服务条款** |
| C | 换数据源（如 cta 改用其他开放数据镜像） | 需调研 | 可考虑，但**改数据源＝口径变更**，且新源同样可能被拦 |
| D | 出题器暂停这两域 | 小改动 | 与 A 效果接近，但**已出的题仍需处置**（作废须拍板）|

**推荐 A 的理由**：
1. **是环境事实，不是缺陷**——诊断已证明代码无问题（连首页都访问不了）
2. **不触任何门**（cta n=4、elexon n=17，均 <30 不出结论）
3. **B 有合规风险**（代理绕地域限制可能违反 ToS）
4. **C 须调研**（且新源未必更好）——可作为**将来的选项**，不是现在的
