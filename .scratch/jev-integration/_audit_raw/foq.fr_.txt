The 4 Superpowers of Foq

Mathematically built for deterministic decision-making and seamless integration in mission-critical software pipelines.

[ PILLAR 01 ]

Zero generated tokens (Prefill-Only)

Traditional LLMs waste 95% of their compute in sequential token-by-token decoding loops. Foq evaluates context in a single feed-forward pass (autoregressive short-circuiting) and immediately projects the internal state onto allowed typed classes.

[ PILLAR 02 ]

Mathematical Calibration via RLCD (ECE 0%)

Uncalibrated LLMs claim 99% confidence even when completely hallucinating. Foq incorporates Temperature Scaling T* and RLCD: when it reports 80% confidence, the verdict is factually accurate in exactly 80% of real-world trials.

[ PILLAR 03 ]

The only engine that knows when to say 'I don't know'

Below your programmable confidence threshold (e.g. 85%), Foq never guesses blindly. It automatically triggers needs_review = True to escalate the case to human oversight or a tier-2 deliberation agent.

[ PILLAR 04 ]

Auditable weight patches (patched_by)

Every edge-case failure or production regression becomes a documented, auditable patch in weights and projection rules, accompanied by automated regression tests in the benchmark suite.

// TECHNICAL FAQ

We give a FAQ

Direct engineering answers, zero buzzwords.

What is a 'System 1' Model?
+

Referring to Daniel Kahneman’s dual-process theory, System 1 denotes fast, instinctive, and automatic decision-making, in contrast to System 2 (slow, deliberative, step-by-step reasoning). Traditional conversational LLMs (GPT, Claude) are forced to deliberate word-by-word. Foq is trained specifically to classify and decide in a single feed-forward compute pass (prefill-only), dropping latency to ~25 ms.

Is Foq just a compressed small LLM?
+

No. A small quantized LLM still sequentially decodes text tokens and still suffers from hallucination and JSON syntax breaks. Foq completely bypasses the autoregressive decoding loop: output heads project internal representations directly onto typed primitives (Choice, Score) calibrated via RLCD (ECE 0.23%).

How is this different from JSON Mode or Structured Outputs?
+

Cloud API structured outputs force a generative model to generate a JSON syntax character by character: you pay for every bracket and quote, wait 2 to 3 seconds of network and decoding latency, and receive uncalibrated probabilities. Foq returns the typed object directly in memory in 24 ms with zero syntax overhead.

What hardware is required?
+

The reflex model Foq 8B (ternary PQ2_0 quantization) takes only 2.2 GB of storage and runs smoothly on any consumer GPU with 4 GB of VRAM (or even directly on x86/ARM CPU). For complex arbitration, the judge model 27B requires ~7.2 GB VRAM (runs on RTX 3060, 4060, or Apple Silicon Macs).

Why is statistical calibration (RLCD) critical?
+

In automated software pipelines, if an AI predicts an action with 95% confidence, it must be correct in exactly 95% of cases. Without calibration, LLMs output 99% confidence on wildly inaccurate predictions. With RLCD, Expected Calibration Error (ECE) drops to 0.23%, enabling safe, automated decision thresholds.

Is Foq an open-source alternative to Jev (TypeSafe.ai)?
+

Yes. Foq is designed as the direct, 100% local, open-source alternative to Jev by TypeSafe AI. It provides the exact same typed decision primitives (Choice, Boolean, Score) running locally on your hardware with 25 ms latency, 0 generated tokens, zero cloud subscriptions, and fully inspectable Apache 2.0 weights.

Can I migrate existing Jev code to Foq?
+

Yes. Foq maintains 1:1 conceptual compatibility with Jev primitives. Instead of sending API calls to a remote cloud, you query the local Foq daemon via REST (port 8089) or Python SDK (from foq import FoqEngine, Choice). The payload formats, typed results, and confidence scores are immediately familiar.

Why choose Foq 8B over lightweight BERT-based routers like Laya?
+

While sub-billion models (like Laya's 420M ModernBERT) look lightweight on paper, empirical testing shows they collapse on negations (14.6% confidence), fail critical emergency triage with 100% false confidence, and are vulnerable to prompt injections (7.9% confidence). Foq's 8B base model retains human-level linguistic comprehension and immunity to prompt attacks, operating with 100% accuracy on operational benchmarks.

What is the 'Memory Paradox' between Foq and multi-model routers?
+

Multi-domain routers like Laya require keeping separate FP16 models resident in PyTorch for each classification task, consuming ~8.6 GB total memory (3.35 GB system RAM + 5.31 GB GPU VRAM). In contrast, Foq uses 1.58-bit ternary quantization (PQ2_0) within a single native C++ binary, using only ~4.8 GB total (2.54 GB RAM + 2.25 GB VRAM). Foq is 44% lighter in total memory while having 19x more parameters.
