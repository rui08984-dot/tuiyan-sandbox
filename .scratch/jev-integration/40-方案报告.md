## 一、结论先行

**这套东西不该以「能力」身份进这个项目**——不接生产引擎、不立新层、不进账本、不上产品面、不接 Jev 托管 API 做依赖。

**它只能以「一次测量对象」身份进，而且现在推荐只做零成本纸面前置**：先出一页预注册（含判死线），技术测量（≤293.1 MiB、零安装、只落 `.scratch/` 工件）排在第 4 期放行门与 I1 之后、由用户拍板触发（触发条件含 G0 单回签，见 §5.2 与 §八）。

三句直给的理由：
1. **Jev 本体买不到、搬不动**——未发布权重、无自托管、未公布参数量与架构（六路交叉否证，§3.1），"引入 Jev"等于引入一个不可复算的第三方 SaaS 依赖；且它不产文本、只出数字，在本项目铁律④下没有合法落点。
2. **本地开源同类 25 条里确有 4 条达到「可信」（kev／decider／Verdict／Laya），9 条有明确的本机落地路径**；但它们唯一可能有价值的**概率源类**落点只剩「在读侧补上第二路可比较的独立读数（p 只落工件、永不进账本）」这一格——而这一格上，**同形实证 8 条全部为负**（H1／H2／H3／H5／H6／H7／H8／H10），其中**最窄的「文本读取型概率源」三连尝试 H1／H2／H8 = 0/3 成功**，另有 2 条设计层拒绝（D1／D4）；且按修正后的功效算术，同形历史效应量（0.0014–0.0088）在现有样本量下大多**读不出来**（§七 攻击 A1）。
3. 所以正确动作不是"整合"，是"**把它当一次可失败的测量**"——先零成本纸面、再条件触发一次小刀，**预期产出是第 16 条负结果或"未判定"**，而不是一次性赢面。

### 3.3 一条本机实测的硬边界（对"要不要调 API"承重）

### 5.2 我推荐哪一种、为什么

**推荐 丁（旁路读数）作为唯一的第一步身份**，理由四条：

1. **它是唯一不碰任何已收口资产的形态**：零迁移、零账本写、零引擎槽位改动、零冻结件改动——甲/乙/戊/己 四个身份全部要动某些不可逆或需拍板的东西。
2. **它按定义就是「测」而不是「接入」**（架构师术语表），因此不改变任何读数或判据。**但"不是接入"≠"免检"——本报告的显式裁决是**：
   - **0 号刀（纸面，不产生任何 p）不需要 G0**；
   - **1 号刀（要落盘产生 p）需要 G0 单回签或用户明示"按 §十-1 推荐默认执行"**（§八 8.2 触发条件④）；
   - **任何 p 进入数值列的动作：永久禁止，与 G0 答案无关**。
   这一裁决同时回应了 20-铁律守门人（要 G0）与另三席（要纸面先行）：纸面与 G0 单同批出，技术动作在回签后。
3. **它是六席在"技术侧第一步"上的最大公约数**：20-引擎架构师 §8、20-证据充分性审判员 §8 的 0-A/0-B、20-校准与统计专家 §9、20-产品与机会成本负责人 §5、20-本地部署工程师 §7 全部指向它（只有样本量与 G0 顺序的差异，已在 §八 定死）。
4. **它覆盖唯一有决策意义的结果区间**：即时判死（冗余/不可用/劣）与"在该 n 分辨率下可读出的大效应"；而历史同形的小效应（0.0014–0.0088）本来就**读不出、也不改任何决策**（功效修正见 §七 攻击 A1）。

**同时明确说三条"不推荐"**：
- **不推荐现在直接上 丙（挑战者臂）**：臂定义改动＝PREREG 版本递进＝新增冻结件＋用户拍板队列；而它的判据上限（在该 n 与借用的 σ̂_d 下）大概率是"只披露"（角色③先例）。
- **不推荐任何以"提升五层读数／推进第 4 期门"为由的方案**：**加模型不产生一格里的一条结算题**——第 4 期门是数据事件。
- **不推荐"再来一个模型也许就有增益"作为立项理由**：本项目的同形实证 8 条全部为负（§2.5 归并口径）。

**并且设定期望**：这条线**默认预期是第 16 条负结果或"未判定"**；如果用户不能接受"花一次小刀换一个大概率为负的结论"，**那就应该选择连 0 元纸面也不做**——这也是一个合法答案（本项目纪律：说"不该做"和说"该做"同样有价值）。

> **判据成本一栏的术语澄清（回应读者 U9）**：本报告把「**生存判据（gate）**」定义为"判定某源是否优于/不劣于基线的成对判据（C1/C2、TOST、MDE 义务）"，「**止损线（KILL）**」定义为"预先写死的、命中即停的条件（如出数率<80%）"。丁 身份**没有前者**（不设通过门），**有后者**（K1–K4）——两者不是一回事，早稿把二者混写成"零判据成本"，此处更正。

### 6.2 分歧点（6 处）

1. **第一步是什么（程序分歧，最大）**：守门人要"先拍板单、技术侧零动作"；架构师要"旁路读数"；审判员/产品/部署要"纸面"；校准要"影子预检"。**红队 攻击 A5 指出四席的第一步互相冲突**（在"要不要先拍板"上直接对立）；主编在 §七 A5 把它裁定为一条顺序（纸面与 G0 单同批出、产生 p 的动作须回签），**不是"四席互斥所以无解"，而是"冲突已被合并"**。
2. **④ 是否覆盖「非 LLM 的原生概率」**（原文空白；守门人要求"两问两答"：问 A 覆盖性＋问 B"不得直出"是否随问 A 失效）。
3. **功效墙的算术**：六席全部引用同一个数「判非劣需 n≈4704」（且全部沿用锚 p29:29 的二手转述）——**红队证明这是误用**（§七 攻击 A1；主编亲验源码并复算修正）。

11. **六席"分数"是什么？可比吗？** 是各席自评的"值得投入整合"（0–10），三席给分、三席空缺；**只在给分席之间可读，不可跨席比较、更不能当投票权重**（§6.1 注）。
