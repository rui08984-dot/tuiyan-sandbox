## 0. 我攻击的是什么、不攻击什么

**攻击对象**＝六份专家表态的**结论与承重前提**，不是它们的语气。**不攻击**＝我已实测证实为真的部分（见 §2，那些我逐条丢弃）。

判定严重度按"这条攻击打掉之后，面板的结论还剩什么"来定：
- **fatal**：该主张被证伪，且它是多席共同的地基（抽掉它，面板的"只做一次读数"这一步失去正当性）。
- **major**：该主张被证伪或从未被验证，但换一个理由结论仍站得住。
- **minor**：成立但分量小，或属于过程卫生。

### A1 ★fatal｜「判非劣需 n≈4704」是错公式——**六席全部引用了同一个数，没有一席读过判据原文**

**攻击点**：判据原文写的是**单侧上界**，4704 却是**双侧检出**公式（MDE，80% 功效）反解的；两者不是同一件事，差了 1.27×–15.5×。

**证据链（我本次逐条亲取）**：

1. 判据原文（角色③ PREREG，白纸黑字）：
   `.scratch/forecast-debate/PREREG-角色③情景分支合成器-v1-20260920.md:47`
   > **主判据 C1（非劣）**：配对 bootstrap（B=1000、seed=987654321，对**题**重采样保留配对）Δ 的 95%CI **上界 ≤ +0.005**。
2. 代码实现与原文一致（两处独立）：
   - `p1b/scripts/role3-replay.cjs:56` `const NONINF_MARGIN = 0.005;`

### A2 ★major｜那台"便宜的判死仪器"（ρ̂）**按构造不可能触发**——四个席位的第一步都建在它上面

**攻击点**：判死线写作"点阈值 0.95"，实现却是"**CI 下界** ≥ 0.95"。对置信下界用点阈值，等于把有效阈值抬到 0.97–0.98；"ρ̂ 没判死"因此几乎不携带信息。

**证据**：
- `p1b/scripts/e2-combo-precheck.cjs:35` `const RHO_KILL = 0.95;          // §3.1 写死`；`:191` `decision: (point !== null && ci.lo !== null && ci.lo >= RHO_KILL) ? '该域组合臂判死（ρ̂ CI 下界 ≥ 0.95）' …`
- 项目自己唯一的实读：`p1b/sim/out/e2-combo-precheck-20260920.json`（我读值）`L1×L6 n=240 rho_hat=0.011469… ci95=[-0.075330, +0.107695]` —— **240 对样本上 95%CI 宽 0.183**。
- **我本次仿真**（命令与输出见 §5-2；numpy 2.5.1，seed=987654321，B=1000 百分位法，与脚本口径同）：

  ```
  n=240  rho_true=0.90 -> ci95=[+0.871, +0.918]  判死触发=False
  n=240  rho_true=0.95 -> ci95=[+0.940, +0.963]  判死触发=False
  n=240  rho_true=0.98 -> ci95=[+0.970, +0.981]  判死触发=True
  n=1005 rho_true=0.95 -> ci95=[+0.940, +0.953]  判死触发=False
  n=1532 rho_true=0.95 -> ci95=[+0.943, +0.953]  判死触发=False
  ```
  ⇒ **真值恰好等于判死线（ρ=0.95）时，面板提出的任何 n 上都不会触发**；只有 ρ≳0.97–0.98（几乎逐位相同）才触发——而那种情形已经由另一个布尔量 `identical_outputs`（`L2×L3` 那次就是 `True`）抓到了。

**这条打掉了什么**：
- 架构师 §4.2（`:218`）：「若 ρ̂ CI 下界 ≥0.95 ⇒ **当场判死，省下后面全部预算**」——实际省不下来。
- 校准与统计 §1.3：「有便宜的『判死』仪器（ρ̂，n≈1000 时很可信）」、§11「把这次只读影子预检当作…一次收据化实验」——**该实验最可能的输出是"不停用"，而"不停用"会被下一步读成"存活"**。
- 守门人 §11、审判员 §8 的第一/第二刀同样把 `RHO_KILL` 当预算阀门。
⇒ 这不是"门太严"，是**门在最需要它的那一侧没有功效**（真要判死的对象恰恰在 0.8–0.95 区，而那一区永远放行）。

**严重度：major**。

### A3 ★major｜三个席位反复引用的「state 没有原料／必重演 H11」**从来没有被查库验证过**；我查了：方向对，但它是抽样的反面案例

**攻击点**：这是"所有六位共同默认、其实没人验证"的典型——而它的风险不是结论错，是**方法错到差点得出相反结论**（我自己第一抽就中了）。

**证据**：
- 三处主张：校准与统计 §5-2「H11 Granger 因为『账本不存序列历史值』而封存。**新模型救不了不存在的字段**」；本地部署 §4.4(2)「数值域的 state 因此**没有原料**」；引擎架构师 §5.3「L2/L3 行的 state 基本等于『一条序列 URL ＋ 一个阈值』」。
- **我本次只读实测**（`immutable=1`，零侧写；命令见 §5-3）：先抽 2 行 → L2 的第 452 行带 `reference_tail = {"2026-06":1.1518,"2026-07":1.1417,"2026-08":1.1593}`，L3 的第 451 行带 `forecast = {"endpoint":…,"date":"2026-09-14","temperature_2m_max_c":30.2,"fetched_at":"2026-09-12T15:02:08+08:00"}` ——**看起来"state 明明在库"**。
- **全量计数推翻了这 2 行的代表性**：L2+L3 共 **1434** 行里，`reference_tail` 只有 **1** 行、`forecast` 只有 **17** 行；典型行只有 `resolve / baseRate / baseRateNote / kind / slug / meta / phase`。
- ⇒ **正确的可核说法是**："1433/1434 的 L2/L3 行没有序列历史字段（我实测）"——比三席写的更强、可复算；但他们写的是**推断**（从 H11 外推，而 H11 的适用范围是"Granger 需要长滞后序列"，另一回事），**没有一个人查过库**。我的 2 行抽样演示了这个推断有多脆：抽 2 行会得出完全相反的面板结论。

**严重度：major**（对方法论；对结论本身是支持）。

## 3. 失败模式：如果这东西最终白干，最可能是怎么白干的

**最可能的一条（"第 16 条负结果"，但比角色③ 更贵）**：探针按方案跑了，`ρ̂` 因为 A2 的门无功效而**必然报"不停用"**（真 ρ=0.95 都不触发），`RES` 在 30–50 题上同样没有功效，于是读数长成"未判死 ＋ 无增益证据"；**"未判死"被下一步读成"存活"**（这正是架构师 §4.2 设计时担心的形态），于是走 PREREG 版本递进＋用户拍板＋影子臂接线；影子臂的 C1 上界落在边际附近（我复算：n≈1000 时 95%CI 半宽 0.0076，n≈1532 时 0.0061——**贴着 0.005**），最终照角色③ 先例收口为"只披露"。半年后回看：账上多了一条负结果、多了一件需要长期维护的冻结件、多了一次用户拍板，而**没有任何一个决策因此改变**。

**第二条（更羞辱的那条）**：真正决定"要不要"的实验是 *Jev 在中文数值题上有没有信息优势*，而唯一能触及 Jev 的动作（API 烟测）卡在"没人有 key、要用户注册"（A4）。于是整条产出的实际内容变成"**一个 151M/421M 社区克隆在中文数值题上打不过统计基率**"——用架构师自己的话，这一步"产出的是管线通，不是源能用"。**它既不是用户的问题的答案，也不是 Jev 的答案**；而因为 Laya 自曝零样本近随机（0.362 < 多数类 0.461），这个负结果几乎是开跑前就写好的。

## 4. 点名：**最自信、证据最薄**的那一个判断

> **「本项目的判据尺在现 n 下结构上读不出任何模型的贡献——判非劣需 n≈4704，而历史效应只有 0.0014–0.0030。」**
> ——六席里 **6/6** 引用（A1 表逐行可查），并且它是"不做整合／只做一次读数"的**唯一硬理由**。

**为什么说它最薄**：
1. **数字用错了公式**：判据原文是**单侧上界 ≤+0.005**（`PREREG-角色③…-v1:47`、`role3-replay.cjs:56/:146`），而 4704 来自 `MDE = 2.802·SE`，代码自注是「α=.05 **双侧**、80% 功效、**§4 M4 义务用**」（`e2-shadow-score.cjs:134`）——**披露义务被当成了判定阈值**。我复算：正确值是 2305（Δ=0）／3711（80% 功效）／303（按角色③ 实测 Δ̂=−0.008787）——与 4704 差 **1.27×–15.5×**。
2. **同一批产物里还有第三个互不相容的数**：校准与统计专家自己打印了 `n_for_90CI_within_eps 1621.2`（我复算 1623.5），正文却只用 4704，**没有对账**。
3. **σ̂_d 是借的，而且是借错的量**：六席用的 σ̂_d 全部来自**角色③**（0.122470，一个在 60 题狼人杀域上、其差异被项目自己诊断为"**离散度 vs 位置**主导"的臂）或 **H5**（0.0881，由一条 CI 反推，而那条 CI 是 90% 还是 95% 口径未定）。**没有任何一席测量过"新源 vs L2 在数值格上的配对差"的离散度**——包括审判员，他把"零测量"明确写在了 §5 表里。
4. **n 随论证需要浮动**：同一份 JSON 提供 240 / 1005 / 1532，部署工程师用 240（得 4.4×，最惨），校准与统计用 1532（得"唯一可能是例外"），**谁也没说评估人口应该是哪一个**（A8）。
5. **它的结论比它的证据宽松**：即使按最保守的 3711，正确表述也只是"**现 n 不够、差 1.2–1.9 倍**"，而不是"**结构上不可达**"。面板把"不够"说成了"不可能"，而这两者在对"要不要花一次零成本读数"的决策上**方向相反**。

**最难堪的一点**：这条判断的六个引用者里，**没有一个去读过判据原文那一行**（`PREREG-角色③情景分支合成器-v1-20260920.md:47` 与 `role3-replay.cjs:146`），全部沿用锚 `p29:29` 的二手转述。**项目纪律里写死了"禁凭记忆编、必给一手证据"——这条最硬的数字，恰恰是六席一致豁免的。**
