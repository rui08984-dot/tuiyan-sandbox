## 2. ★ 本次会话最该记住的五条

① **C14 判据错在 spec，脚本只是照抄。** 原写「N号+昵称=0 行」，而机械模式在合成局里 100% 命中模板盘话
   （种子库里还剩 **168 行合法示范数据**）。照原判据＝要求「把 90% 示范数据也删光才准发」。
   ⇒ 改成「真名一个都不许出现」，机械串降为报告项。真名**运行时从源库推出、不落盘不进 git**；
   源库读不到 ⇒ **fail-closed 判红**。

② **「测试全绿」≠「测试在检查东西」。** 本次共出现**四次**：6 个变异里 3 个没咬住（G7 字节闸零覆盖、
   n-gram 粒度无人钉、claims 外键清理无人钉）；README 归属条只断言「这个数在句子里」，
   mine/corpus 标签对调照绿；跨文件守卫被同节的诚实说明遮住。
   ⇒ **每次补锁后都要原样重放那个变异，确认它会红。**

③ **闸门会抓自己的注释。** 三次因为在注释里写形如 `<scheme>://<addr>:<port>` 的示例端点而被 C3 照红。

④ **文件在盘上 ≠ 已入 git。** visitor.ts、audit-release.cjs、firstRun.ts… **每批都出现「新文件未 add」**，
   闸门照样全绿（文件在盘上所以绿），但他人 clone 即缺文件。
   ⇒ 收尾逐件核已做成**工作流里的固定阶段**（每批都真抓到了东西）。

⑤ **★看到闸门输出里的「绿?」不要当绿灯。** 那表示首跑红、复跑才绿。第 4 批实测踩到过一次——

## 4. 环境备忘

- **`python` 是商店占位符**，用全路径 `C:/Users/crx/AppData/Local/Programs/Python/Python313/python.exe`
- **`git ls-files` 会把中文路径输出成八进制转义** ⇒ 批量脚本必须加 `-c core.quotepath=false`
- **做变异测试用 `cp` 备份，★不要用 `git checkout -- <file>`**（会连未提交的改动一起退掉；我自己翻过一次车）
- **注释里不许写看起来像真端点的串**（发行闸 C3 照红）
- GitHub 令牌在 **Windows 凭据管理器**（`git credential fill` 读得到），无 `gh` CLI
- ★**curl 传中文 JSON 会坏** ⇒ payload 写成 UTF-8 文件后 `--data-binary @file`
