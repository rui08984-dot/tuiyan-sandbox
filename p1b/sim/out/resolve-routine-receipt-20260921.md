## §4 ★★新发现：frankfurter 预筛过度保守 ⇒ 19 条「可结题」被拦死（**须拍板**）

**发现过程**：§3 分析第 4 期门时，注意到 22 条 frankfurter 未解全部被判 pending「ECB 发布窗口尚未走完（接口对未来区间 404）」。手工打网复核 ⇒ **数据其实已经存在**。

**证据链（逐条实测）**：

1. **接口能通**：`https://api.frankfurter.app/2026-09-16..2026-09-23?from=USD&to=CNY` ⇒ **HTTP 301 → .dev 域 ⇒ HTTP 200**，返回 `{"2026-09-16":{"CNY":6.7071},...}`。
2. **resolver 其实能工作**：跟随重定向后字段对得上（`j.rates['2026-09-16']['CNY'] = 6.7071`）；resolver 读法 `j.rates[ks[0]][r.quote]` **正确命中**。
3. **被拦在预筛**（`corpus-resolve-daemon.cjs:156`）：
   ```js
   if (k === 'frankfurter_rate_range') { if (d10(r.date_plus7) > t) return 'ECB 发布窗口 ' + r.date + '~' + r.date_plus7 + ' 尚未走完（接口对未来区间 404）'; }
   ```
   ⇒ 判据是「**窗口终点**是否已过」，但题面判据只需要「**窗口内第一个 ECB 发布日**」的数据——**两者不等价**。
4. **影响面（逐条核）**：

| 窗口 | 条数 | 预筛 | 首个发布日 |
|---|---|---|---|
| 2026-09-16~09-23 | 3 | 拦截 | **数据已存在** ⇒ 可结 |
