# asr-replay-integration —— 本地 ASR 接入推演沙盘 replay 管线 · 实测报告（R-ASR 棒，2026-09-11）

> 结论先行：**ASR 路径跑通且成本可控**——一局 55 分钟综艺音频从 yt-dlp 到带时间戳文稿全程 8 分 21 秒（其中模型首次下载占 5 分余，二次运行降为约 3 分钟级），CPU、零云 API、零费用。无复盘帖的局（PandaKill/GodLie/Lyingman 大部分单集）这是**唯一**转录路径，且逐句原文的还原完整度天然高于文字复盘帖的概述级。主要短板不在转写在**结构化**：座位→ID 绑定与说话人轨需要「声纹初分+文本回填+外部锚点」三段式，见 §4。

## 2. 踩坑实录（每条含根因与修法，均已闭环）

1. **asr_pipeline.ps1 现状不可用**：其转写引擎 transcribe_v2.py 硬编码 IIC 路径（asr-hub/model/asr/models/models/iic），而该目录是空壳（模型实体曾存在后被清，modelscope 断点残留在 ._____temp），funasr 报 is not registered。管线失败分支行为正确（m4a 移「待查」+清段）。→ 本次绕行走 asr_worker.py；管线修复建议见 §5。
2. **asr_worker.py --dump-raw 只写 raw JSON**（模型返回原样 list，无 elapsed_seconds、无格式化文本）——不构成失败但产物不可读。→ 本棒补 merge_asr_raw.py 后处理（从 sentence_info 提取 [mm:ss]/spk/句文本合并成带段分隔文稿）。若重跑建议去掉 --dump-raw 让其直接产 JSON+TXT（会重付转写电时，故本次选后处理）。
3. **模型缓存空**是本机现状事实（全盘搜 seaco 模型目录零命中），首次运行现场下载 ~1GB（modelscope CDN，约 5 分钟）——**一次性成本**，缓存已归位，后续 job 直接受益。
4. run_code 沙箱无 require、内联多行 python 转义不可行 → 多行逻辑一律落 .py 文件再 pwsh 执行（临时脚本用后即删）。

## 3. ASR 文稿噪声类型清单（实测归纳，按对 replay 结构化的杀伤力排序）

| # | 噪声类型 | 实测实例 | 对策 |
|---|---|---|---|
| 1 | **座位→ID 无锚**：音频只有「几号」与真名混称，无字幕/画面 | 全局 12 人仅 9号=申屠（遗言并列）、7号=风行云（解说锚）实锤 | ①开场报名/座位字卡专项转写+字幕 OCR ②同集内互称回填 ③LLM 结构化时未定 ID 一律标【待考】禁止硬猜 |
| 2 | **同音字错写**（游戏术语/ID 重灾区） | 「针对言家」→预言家、「贾冤家」→假预言家、「司警徽」→撕警徽、「酒神」↔「九号」 | hotwords 预热名单（asr_worker.py 原生 --hotwords-file：预言家/查杀/金水/悍跳/退水/归票/警徽流+全员真名）——本棒实测未启用，集成后首选项 |
| 3 | **声纹聚类缺陷**：合并（法官×12号同簇）/分裂（9号 警上 spk9、警下 spk2）/大杂烩（spk0=2号遗言+11号发言+解说） | 11 簇 vs 真实 13+ 声部 | 放弃「声纹直出说话人轨」；改「声纹初分+文本座位号回填」两段式：自报「我 X号」/被称「X号」优先于 spk 标签 |
| 4 | **插播解说混入公开信息流** | 30:05-34:11 上帝视角复盘（十一号跳女巫挡刀/白狼王战术） | 分层纪律：解说段识别（口吻+上帝信息）→归真相层；可作 ID/事件旁证锚点（本棒 7号=风行云 即此法） |
| 5 | **句子碎片化+语气词**（VAD 切句过细） | 平均 10.4 字/句，「呃/好吧/对吧」高密度 | 结构化时按连续段+语义合并；LLM 汇总阶段天然吸收 |
| 6 | **同音数字/绰号混淆** | 「三号和八号警长」实为「三号和『王』（6号）警长」 | 数字+绰号互证：与唱票/法官点名交叉核对，冲突即标噪声 |
| 7 | **断言缺失**（发言未完整转出） | 11号「跳女巫」关键句缺失（解说有旁证） | 与文字帖路径同样标【缺口】；高危段（投票前后）可降 VAD 阈值重转 |
| 8 | 片头花絮/正文无边界 | 00:00-02:31 采访闲聊 | 锚点定界：「游戏开始天黑请闭眼」/法官规则段为 Day 起点 |

## 4. 结构化示范（ASR→E-N）

示范文件：docs/sandbox/p0-replay/asr-structured-demo-pandakill-s1e6-day1.md（PandaKill S1E6 第一局 Day1，E-1~E-23，还原完整度 70%）。
与 P 棒文字帖样板的差异实测：
- **升档**：发言逐句原文（文字帖多为概述级、票型几乎全缺）；本次警长选举 6 票逐票唱票完整转出——正是 P 棒 s2e2 档案 60% 完整度的最大缺口项。
- **降档**：ID 映射（文字帖自带全名单；ASR 需额外绑定工序）。
- 声称提取/票型识别在示范内均落 E-N 行并标证据等级（实锤/推定/噪声/缺口），方法与 P 棒完全兼容。

## 5. 集成进 P 棒（replay 产线）的建议

1. **管线修复**（asr_pipeline.ps1 两处）：①转写引擎换 asr_worker.py（句级时间戳+声纹+hotwords，CPU 兼容）或修 transcribe_v2.py 的 IIC 路径指向实际缓存（并确认模型已归位）；②产物落点参数化（现为 horror-teller/samples 硬编码）。
2. **半自动 Day 切分**：以法官「天黑请闭眼/天亮了/昨晚死亡的是」为锚点切夜/昼，LLM 逐昼出 E-N——本次 Day1 切片按时间戳手切，锚点法可脚本化（merge_asr_raw.py 已带时间戳，加约 30 行即可）。
3. **hotwords 名单先行**：对已知 IP（PandaKill/GodLie/Lyingman）把全员真名+术语表写 --hotwords-file，预期同音字错写（噪声#2）大幅下降，直接改善 ID 绑定。
4. **ID 绑定工序**（人工+LLM 协同，每局约 20-40 分钟）：开场报名/字卡 OCR → 发言互称回填 → 解说锚点 → 剩余标【待考】。**不建议**追求全自动：一局 12 人，错绑一座位即污染整局声称链。
5. **路线取舍**：有文字复盘帖的局仍优先文字帖（成本 1-2 人×分钟级，ID/票型自带）；ASR 路径用于①无帖局（绝大多数单集）②文字帖关键缺口补全（票型/遗言原文——ASR 逐句恰是补票型细节的武器）。
6. **成本模型**（本机 CPU 实测外推）：音频时长×(0.9-1.4)≈转写秒数（55min→7m43s 含下载；纯转写估 3-5min）+首局一次性模型下载 ~1GB。一季 PandaKill S1（12 期×3 局口径）≈ 30-40 小时 CPU 后台分夜跑，零费用。
