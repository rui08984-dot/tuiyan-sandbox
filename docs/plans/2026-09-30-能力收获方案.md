# 能力收获方案：把已有的东西全部变成「能被调用的」

> **日期**：2026-09-30 · **接替** `2026-09-30-基座对外交付方案.md` 的执行细节
> **创始人定的方向**：「把我们项目这些已经有的东西都开发完全一下，能用的都基本上都用上了」
> 「细化一下方案的落实」

---

## 〇、这一版相对上一版改了什么

上一版把方案窄化成「**补三个 MCP 工具**」。那是补漏，不是收获。

★**盘完之后的实情**：

| 形态 | 已有能力数 | 外面知道的有几个 | 有文档吗 |
|---|---:|---:|---|
| **HTTP 端点** | **58** | 0 | ❌ 一份都没有 |
| **CLI 命令** | **23** | 约 5 | ❌ 只在 `--help` 里 |
| **MCP 工具** | **18** | 0 | ❌ 名字还是机器名 |
| **取数源登记** | **53** | 0 | ⚠️ 只有一张内部表 |
| **六层算子** | **6** | 0 | ❌ 完全不露 |
| | **158** | | |

★**58 个 HTTP 端点**是这个最大发现：**服务本来就在跑，接口本来就能调，只是没有任何人知道它能干什么。**
上一版一个字都没提它。

## 一、这套系统能干什么（**四组能力**，不按代码目录分，按「用户会问什么」分）

### 组 1 · 记账（记一道判断，让它进不可改的账本）

| 已有 | 在哪 | 外面能用吗 |
|---|---|---|
| 写一道题 + 你的确信度 | `POST /api/predictions`（6 个端点） | ❌ 无文档 |
| 真值锚（答案去哪查、什么时候能结） | 拒收门三问，逻辑在 `revealClass.js` | ❌ 无 MCP 工具 |
| 归属（这道题是谁的） | `ownershipStore` ＋ 三桶 | ❌ 无 MCP 工具 |
| 到期未结的清单 | `GET /api/disclosure/resolve-queue` | ❌ 无 MCP 工具 |

### 组 2 · 打分（我准不准，我在哪类事上偏）

| 已有 | 在哪 | 外面能用吗 |
|---|---|---|
| 分层读数（每层 n / Brier） | `GET /api/audit/summary` ＋ CLI `分层` | ❌ 无 MCP 工具 |
| 判词（复盘文字） | `GET /api/predictions/:id/verdicts` | ❌ 无 MCP 工具 |
| 偏差分析（你在哪类事上说大了） | `p1b/web` 的 WhereOffPage 算过 | ⚠️ **只在网页里算过，没抽成接口** |
| 诚实区间（n<30 只给区间不给点估计） | `p1b/mcp/exitMap` ＋ baseline 页面 | ❌ 无 MCP 工具 |

★**第 3 行是这一组最值钱的能力，而它现在只活在网页里**——
「你在哪类事上偏」是整个项目的核心价值，**它没有被抽出来成任何可调用的东西**。

### 组 3 · 裁决（这事能不能自动结，该归哪一层）

| 已有 | 在哪 | 外面能用吗 |
|---|---|---|
| 六层分类 | `revealClass.js` ＋ 6 个算子 | ❌ 不露，且**没有独立接口** |
| 自动揭晓（机器能自己查的到期就自己结） | `settle` ＋ `corpus-resolve-daemon` | ❌ 无 MCP 工具 |
| 53 个取数源 | kind 目录表 ＋ resolver | ❌ **调用方不能指定用哪个源** |

### 组 4 · 审计（数据被改过吗，有没有真值混进判断题）

| 已有 | 在哪 | 外面能用吗 |
|---|---|---|
| 冻结哈希 | `冻结哈希` ＋ `p1b_audit_prereg_freeze` | ✅ **唯一形态齐的** |
| 泄漏扫描 | `p1b_doctor_leak_scan` | ✅ 有 |
| 锚点闸（**候选 0 条 ⇒ exit 3**） | `p1b_audit_anchor_gate` | ✅ 有 |
| 契约一致 | `p1b_audit_g2_contract` | ✅ 有 |
| 异地备份 / 恢复演练 | `p1b_backup_*` | ✅ 有 |

★**四组里，只有「审计」这一组是形态齐的**——因为它本来就是给机器用的。
另外三组（记账／打分／裁决）是给人用的，**从来没被抽成接口**。

## 二、★「联动」怎么落成可测的东西

创始人要的是「互相融洽、互相耦合、互相联动」。落地成**四条端到端链**，
每条都必须能**一串跑完**，且**中途失败要停对位置**。

### 链 A · 记一道判断（对应组 1）

```
说「帮我记一道：明天会不会下雨」
 → ① 归层（六层分类：L3 短窗混沌）
 → ② 找真值（53 个取数源里挑能用的）
 → ③ 拒收门三问（真值锚可机检？cutoff 早于决定性时点？结果随实例变化？）
 → ④ 落账（只写不改）
 → ⑤ 告诉你这类题历史上多少次对了
```
★**第 3 步不通过就停在那一步**，且明确说「拒收门第 2 问没过：cutoff 晚于决定性时点」。
**不许**降级放行。

### 链 B · 到期结算（组 3）

```
说「这批题到期了」
 → ① 逐条问六层：能自动结的 / 要人答的 / 永远结不了的
 → ② 能自动结的去取真值
 → ③ 要人答的列出来（★「永远结不了」的不给按钮——给假按钮是欺负人）
 → ④ 每条结算都变成一条判词（挂 PREREG 指纹）
```

### 链 C · 打分与偏差（组 2）★**这是项目的核心价值所在**

```
说「我准不准」
 → ① 按题型分开算（★不分层的总平均没有意义）
 → ② 每类给 n / 偏差 / 够不够下结论（n<30 只说方向不给比例）
 → ③ 指出「你在哪类事上系统性偏」
 → ④ 给一句诚实的收尾：「1 道题什么都不说明」
```

### 链 D · 审计（组 4，已有，补联动）

```
说「这批数据可信吗」
 → 冻结哈希对不对 → 锚点闸过不过 → 契约一不一致 → 有没有真值混进判断题
```

★**四条链的共同纪律**：任一步不满足前提 ⇒ **停在那一步**，
前几步的写入**如实报告、不回滚**（账本不可变是硬边界，不能假装没发生过）。

## 三、四种形态各干什么（**不只 MCP**）

| 形态 | 给谁 | 现在 | 本轮要做 |
|---|---|---|---|
| **HTTP** | 任何能发请求的东西（网页、小程序、别的服务） | **58 个端点，零文档** | ★**逐端点补文档**；补组 1–3 缺的端点 |
| **MCP** | 所有 AI 工具 | 18 个，偏审计；名字是机器名 | 补组 1–3 的工具；★**名字改成人能读的** |
| **CLI** | 人、脚本、CI | 23 条，完整 | 只补**能力索引**，不改功能 |
| **当库用** | 想把它嵌进自己程序的人 | `require('p1b/…')` 能用，没文档 | ★**这是最被忽略的一种**：给一份「怎么 require 它算我的分」 |

★**「当库用」这一条上一版完全没写**。它其实最轻——不需要任何新接口，
只要把几个模块的调用方式写清楚，任何语言能 require 的地方都能用。

**Skill（`p1b/skill/SKILL.md`）** 已经存在，作为 AI 技能的分发形态保留。

## 四、执行序（每步都有可核产物，**上一步没验完不许进下一步**）

### A · 收获对账（**不做完这步，后面全是猜的**）

产出**一张能力对账表**，每行五栏：

| 能力 | 现有形态 | 缺的形态 | 结论 |
|---|---|---|---|
| 写一道判断 | HTTP 有 | MCP 无 / 库无文档 | 补 MCP + 库文档 |
| 分层读数 | HTTP 有 / CLI 有 | MCP 无 | 补 MCP |
| 偏差分析 | ★只有网页 | HTTP 无 / MCP 无 / CLI 无 | ★**抽成接口**（最要紧） |
| 六层分类 | 内部 | 全部无 | 抽 HTTP + MCP |
| … | | | **158 行逐行填** |

★**判据：158 个能力面，表里每一行都有结论。**
「没提到」不算结论，「忘了」是最大的漏洞。
—— 这就是上一版说的「覆盖率对账」，现在**落到具体行数**了。

### B · 补三组缺口（组 1 记账 / 组 2 打分 / 组 3 裁决）

优先补 **偏差分析**（它现在只在网页里，是核心价值却最不可用）。

### C · 能力目录（四组 × 五栏，每条带**能跑的**调用示例）

第四栏「不能做什么」与第五栏「越界了怎么办」**不许空**——
这是本项目独有的，市面同类没有。

### D · 四条联动链 ＋ **中途投毒测试**

对每条链破坏第 k 步的前提 ⇒ 必须停在第 k 步，且前 k−1 步的写入被如实报告。

### E · 对外发布

GitHub 上必须有：**能力目录** ＋ **安装说明**（MCP / HTTP / 当库用 三种装法）＋ **README 补一节能力摘要**。

## 五、诚实交代

1. **「已经在做」不等于「能用」**。58 个端点、6 个算子、53 个取数源都「已经在做」，
   但**对外面的人来说它们等于不存在**。这正是这一版要做的事。
2. **最值钱的能力（在哪类事上偏）现在只活在网页里**——这是本次盘点最要紧的发现。
3. **这一轮可能要把一些网页里的逻辑抽成接口**，那是「减」不是「加」，
   但为了让别人能调，必须抽。★**抽的时候不许改判据**（同一个口径不许出两份实现）。

---

## 六、这一轮不做（继承上一版，划死）

继续做页面 ／ Electron ／ 桌面壳 ／ 找普通用户 ／ 自建数据源 ／ 远程托管
—— **界面那条线到此为止**，只有「网页里已有但没抽成接口的逻辑」才允许动。
