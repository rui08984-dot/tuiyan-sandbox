# 游戏模块独立化 · 可行性质检（2026-10-03）

> 触发：创始人一句「社交类推理游戏的那个模块可以单独独立出来做营销、丰富、完善」。
> 本文回答三个问题：**它现在有多真 · 能营销的是什么 · 独立出来要付什么代价**。
> 全部结论出自 2026-10-03 实跑，不含估计值。凡"未验证"一律写"未验证"。

---

## 〇、结论先行

**能独立，而且盘上的东西比预想的完整——但独立出来能卖的那个东西，和这个项目的招牌承诺是反的，除非换定位。**

三句话：

1. **技术上完全可独立**：游戏面是一块 2137 行的自闭环内核（三种游戏、23 个端点、~105 个测试用例），不依赖推演沙盘的预测账本。
2. **★盲测已经给出裁决：能卖的是「复盘器」，不是「破案器」。** 预注册评分协议第 3 节自己写死了三档结局，其中第二档原文是「砍概率层保留账本＋矛盾检测，**产品＝复盘工具**」。而实测落在这一档。
3. **★真正的坑不是技术，是定位**：项目 B-slogan 是「把判断力做成契约，让任何 agent 都无法替你下结论」。若游戏模块以「AI 帮你找出狼人」为卖点营销，卖的是这句招牌的反面。

推荐路径见 §五，代价清单见 §四。

## 一、盘上到底有什么（2026-10-03 实测）

### 1.1 三种社交推理游戏都在

| 游戏 | 实现位置 | 规模 | 状态 |
|---|---|---|---|
| **血染钟楼 BOTC**（3 个剧本：tb 暗流／bmr 暗流+红教堂／snv 疯狂） | `p1b/src/botc/` 5 个文件 | **869 行** | 完整：剧本数据驱动角色表、声称、矛盾检测、prompt 注入 |
| **狼人杀** | `p1b/src/detectors/werewolf-contradictions.js` | **443 行** | 完整：词表＋矛盾检测＋对跳识别 |
| **阿瓦隆** | `p1b/src/adapters/avalon.js` | **681 行** | 完整：适配器形态，加新游戏**只需落一个文件** |

`routes/games.js:39-47` 明写扩展点：**「可用游戏类型 = 内置 GAME_TYPES ∪ `adapters/` 目录登记 id（加新游戏只需落适配器文件，前后端零改）」**。
这条注释本身就是"基座"形态的证据——游戏模块天生就是一个可插拔基座。

### 1.2 能力面

- **HTTP 端点 23 个**挂在 `/api/games*` 下（建局／局列表／详情／状态回放／导出／改座位名／事件录入／宏结构化／LLM 抽取／声称与动作的改撤／剧本声称／天结算参谋卡／参谋卡存档／预言盘），另 3 个 `/api/oracle/*`。
- **前端 642 行**：建局向导（`NewGameWizard` 113 + `Steps` 119）、对局中三区（`AdvisorZone` 参谋 77 ／ `LiveEmpty` 102 ／ `OracleZone` 预言 126）、局详情 88。
- **★MCP 覆盖 = 0**。21 个 MCP 工具里没有任何一个碰游戏（`p1b_note_record` / `p1b_where_i_bias` / `p1b_which_layer` 三条用户工具全是账本侧）。而 ADR-001 已定「主分发形态＝MCP」。

### 1.3 测试覆盖：扎实（★这里更正我自己的一个误判）

我第一遍扫文件名得出「没有以游戏模块为对象的测试文件」，**那是错的**——测试写在 `server.test.cjs` 的集成层里。

- `server.test.cjs` 共 **82 个用例，其中 66 个是游戏面**（建局自动建席、宏卡结构化、声称改撤、409 账本纪律、剧本声称、botc-only 对跳检测、prompt 注入逐字节零改动回归…）
- `oracle.test.cjs` 13 + `oracleCast.test.cjs` 18 + `oracleInterpret.test.cjs` 8 = **39 个预言盘用例**
- 合计 **~105 个游戏面用例**，在四道闸门的 backend 门内受覆盖。

四道闸门本次实跑：**backend 111.45s / build 1.98s / frontend 1.33s / types 1.95s，全 exit 0。**

### 1.4 真实对局盲测资产（★这是最值钱的一块）

`docs/sandbox/p0-replay/` 下 **5 局真实对局档案，每局都是双层的**：

| 档案 | 公开层 | 真值层 |

## 二、★能营销的是什么 —— 盲测已经投过票了

### 2.1 实测读数（`score-lyingman-s02e01.md` / `score-botc-rulebook.md`）

| 局 | 实验轨（结构化账本） | 基线轨（裸聊） | 判定 |
|---|---|---|---|
| lyingman-s02e01 | 3 分 / 3 切片 = **1.00** | 4 分 / 3 切片 = **1.33** | **基线赢** |
| botc-rulebook | 0% | 0% | H1 **不过**（双轨同脱靶） |

### 2.2 但机制层是过的

botc-rulebook 的终判原文：

- **H2 过** —— 全部结论引用 E-1..E-17 内真实事件，抽查**零虚构**
- **H2' 过** —— 硬矛盾 4 条复核成立，抽查通过率 100%
- **H3 过** —— 有 1 次由新事件触发的**归因翻转**
- **H1 不过** —— 「嫌疑排序优于基线」未证明

### 2.3 根因分析是全文最值钱的一段

> 真相 hinges on 完全不可见的私密信息（投毒）。公开层下，「Julian 说 Sarah=Drunk」与「Julian 撒谎」两种解释在证据上**欠定**，实验轨选了证据上更自洽的错误支。**这不是引擎缺陷，而是设计输入。**

### 2.4 ★所以预注册协议自己早就写好了出路

`score-protocol-realgames.md` §3 三档结局，第二档原文：

> **H1 不过但确定层达标**：实验轨矛盾清单经抽查有效率 ≥80% 且基线轨无此产出 → 砍概率层保留账本＋矛盾检测，**产品＝复盘工具**。
> **杀项目**：确定层有效矛盾也产不出（抽查有效率 <50%）。

实测落在第二档，**距"杀项目"档还有明确距离**（抽查有效率 100% vs 门槛 50%）。

★**结论：协议在点火前就预注册了"这一档的产品是什么"，而实测正好落在这一档。这个模块的诚实定位是「对局复盘／审计器」，不是「实时破案器」。**

这与预测侧的结论**同构**：Brier 0.2259 显著优于 0.2500，但与「拿 p 当权重掷骰子」0.2267 不可区分。**项目在两条业务线上得出的是同一句话：机制可信，价值增量未证。**

## 三、★独立出来能营销的／不能营销的

| 能说（每句都有盘上证据） | 不能说（会被打脸） |
|---|---|
| 「它把每句话拆成结构化声称，并抓出互相矛盾的地方」——H2' 抽查 100% | 「它比人更会找狼」——H1 不过，且实测**输给**基线 |
| 「它推翻了谁翻了、因为哪句话翻了」——H3 有归因翻转 | 「它能帮你赢」——价值层未证，且协议预注册口径不覆盖 |
| 「它引用的事件全部可回查，零虚构」——抽查 E-1..E-31 全中 | 「AI 破案助手」——项目自己的裁决文档否定这个说法 |
| 「复盘用：局后自动出矛盾清单＋假设收窄轨迹」 | 「实时提示」——欠定根因使实时承诺必然失约 |

## 四、独立出来的真实代价

### 4.1 耦合：只耦合 p1a，不耦合 p1b 账本

游戏面唯一的跨模块依赖是 `p1b/src/deps.js` → `p1a-terminal/src/{db,llm,engine}.js`，共用到 **20 个 db 函数**（`createGame/loadGameState/saveAdvisorCard/exportGame/getPlayers/…`）。

- ✅ **好消息**：`deps.js` 的文件头把它定为「引擎复用**唯一入口**，施工铁律：零复制零修改」。**耦合是干净的、单点的。**
- ⚠️ **代价**：`p1a` 是整个 p1a-terminal 的 db＋LLM 适配层。独立出去要么**依赖 p1a**（就不是独立包了），要么**重写一层持久化**（违反零复制铁律，且 20 个函数的重写是真实工作量）。

### 4.2 ★红线张力（这是最需要拍板的一条）

README 红线第 2 条：**「工具描述与返回文本中，不出现荐下注语义」**。

`routes/advise.js` 生成的就是**参谋卡：嫌疑排序 ＋ 假设 ＋ 矛盾清单**。

- 在**账本语境**里这站得住：参谋卡复盘的是**你自己下的判断**，正是 B-slogan 说的事。
- 在**消费者营销语境**里，若宣传为「AI 帮你判断谁是狼」，它就从"记录你的判断"变成了"替你下结论"——**恰是招牌承诺的反面**，且触碰红线第 2 条。

★**这不是可以两头讨好的技术问题。它要求先选定位。**

### 4.3 缺口三条

| # | 缺口 | 影响 |
|---|---|---|
| 1 | **MCP 覆盖 = 0** | ADR-001 定的主分发形态完全够不到游戏面 |
| 2 | 无游戏侧 CLI（账本侧有 18 个 CLI） | 脚本化／agent 化无入口 |
| 3 | 无独立启动路径（`server.js` 158 个面混在一起） | 「游戏模式」不存在 |

## 五、三条路径

### 路径 A · 同仓新身份（**推荐**）

游戏模块在本仓内长成独立的**分发身份**（独立 README 段 + 独立 npm 包名/入口 + 独立 landing），共用同一套闸门与账本内核。

- 代价最低（无需拆 p1a 依赖），可逆性最高（不新建远端仓库）
- 能吃到全部现成资产：105 个用例、5 局盲测材料、botc/avalon/werewolf 内核
- 定位按 §2 收窄为「复盘器」，**不触碰红线第 2 条**

### 路径 B · 拆成独立仓库

需先解 p1a 依赖（重写持久化层或把 p1a 一并抽出），再定品牌与 licence 归属。
★**不建议现在做**：代价集中在无收益的工程上，且品牌／商标是创始人决定，不该由我先斩。

### 路径 C · 只补 MCP 面，不动定位

在 p1b 内给游戏面加 MCP 工具（建局／录事件／查矛盾／出参谋卡），让游戏能力能被 agent 调。
- 与 ADR-001 完全同向，**与是否独立出去无关**——三条路径都需要它
- 是**唯一零分叉的零后悔动作**

## 七、零后悔动作（无论拍哪条都要做）

1. **补游戏侧 MCP 面**（路径 C）——主分发形态目前完全够不到这块，是纯亏。
2. **把 5 局盲测资产从 `.md` 档案升级成可复跑的评测命令**——现在评分手工执行，套件本身没进闸门。这套预注册材料是全项目最独特的资产，**现在只躺在文档里，没有一条命令能复现它**。
