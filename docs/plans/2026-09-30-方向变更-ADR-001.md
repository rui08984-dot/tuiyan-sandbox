# 方向变更标注文档 · ADR-001：主线从「界面」切到「接口」

> **状态**：Accepted · **日期**：2026-09-30 · **决策者**：创始人
> **取代**：本项目 2026-09-07 至 2026-09-30 期间「以界面交付为主线」的隐含方向
> **本文件是标记，不是记录**——它存在的唯一目的，是让**以后任何人**看一眼就知道：
> **为什么突然不做页面了，以及再提议做页面时该先读哪段。**

---

## 一句话

**这个项目是基座，不是应用。基座的价值在接口层，「双击即用」做完一次就够了。**

---

## 一、变更内容

| | 之前 | 之后 |
|---|---|---|
| **主线** | 让人能用起来（页面 ＋ 打包） | 让别人能**当零件用**（接口 ＋ 分发） |
| **完成判据** | 陌生人双击能打开 | 别人装上 MCP 就能用 |
| **投入分布** | 四批全在页面 | 页面线**停止排期**；接口线投入 |
| **首个用户** | 会用网页的人 | **会装 MCP 的开发者** |

---

## 二、★为什么变（依据：盘出来的数，不是感觉）

| 形态 | 已有能力数 | 外面知道的有几个 | 有文档吗 |
|---|---:|---:|---|
| **HTTP 端点** | **58** | 0 | ❌ 一份都没有 |
| CLI 命令 | 23 | 约 5 | ❌ 只在 `--help` 里 |
| MCP 工具 | 18 | 0 | ❌ 名字是机器名 |
| 取数源登记 | 53 | 0 | ⚠️ 只有内部表 |
| 六层算子 | 6 | 0 | ❌ 完全不露 |
| **合计** | **158** | **约 5** | |

★**158 个能力面，外面知道的不到 5 个。** 这不是「宣传不足」，是**能力根本没被抽成接口**。

★**最要紧的一条**：
**「你在哪类事上偏」——整个项目的核心价值——现在只活在一个网页组件里**，
没有抽成任何接口（HTTP 无 / MCP 无 / CLI 无）。
按「所有功能都能被调用」的标准，**项目最值钱的那件功能，眼下最不可用。**

---

## 三、★我的偏差（写在这里是为了不再犯）

最近四批（`0e5db61` / `3340b62` / `0982be1` / `32b426c` / `13a4a78`）
**全是页面 ＋ 打包，没有一批在做接口与开源分发。**

**根因**：我照着《产品化交付方案》做的。
★**那份方案对「做一个好用的软件」是正确的判断**——它通篇讲「陌生人双击就能用」。
★**但它回答的是「怎么让别人用得上」，没回答「让别人拿它当零件」。**
对一个**基座**来说，那一半才是主线。

⇒ **记在这里，是因为下一次还会犯**：
**做了 23 天的东西，最容易的错觉是「它需要什么，我就补什么」**，
而不是「它是什么，就该以什么形态交出去」。

---

## 四、现在的样子（比喻，供解释给外人）

**它是一个公证处。**

- 法院告诉你**谁有道理**（那是律师和法官的事）
- 公证处只做一件事：**如实记录，记录之后不许改**，再给你一张「这份记录没被动过」的证明

它**不预测**（那是专家的事），**不建议你**（那是理财顾问的事）。
它只做一件别人不做的事：**记下你的判断，然后证明你没事后改口。**

围绕它搭了三层：

```
【底座】六层分类 ＋ 六个算子 ＋ 53 个取数源 ＋ 只写不改的账本
   ↓
【接口】23 条 CLI ＋ 18 个 MCP 工具 ＋ 58 个 HTTP 端点   ← ★现在的主战场
   ↓
【皮】  五个网页页面 ＋ 绿色 zip                            ← 已够用，不急
```

★**对一个基座来说，皮做得再好，别人也接不进来**——他没法让你的网页给他算分。

---

## 五、界面线的例外（唯一一条）

**网页里已有、但没抽成接口的逻辑，允许动。**

例如「你在哪类事上偏」那段计算现在住在网页组件里，
它**必须被抽成接口**——但抽取时**不许改判据**（同一口径不许出两份实现，
否则哪天两边对不上，你连查哪边是真都不知道）。

除此之外，**不再做任何页面改动**。

---

## 六、明确不做（划死，免得又跑偏）

Electron ／ 桌面壳 ／ 移动 App ／ Docker ／ 找普通用户 ／ 自建数据源 ／ 远程托管
／ 把「为你推荐」做成引导

---

## 七、转向之后的执行序

| 段 | 做什么 | 阻断判据 |
|---|---|---|
| **1** | **收获对账**：158 行逐行填，每行多一栏「**是否幂等**」 | ★**表没填完不许进第 2 段** |
| **2** | 补三组缺口（记账／打分／裁决）＋ 四条工程要求 | 重复调用同一次记账，结果不变 |
| **3** | 能力图 ＋ 能力目录 ＋ 三种组合（直线／回溯／回环） | 每种都能真跑通 ＋ 中途投毒测试 |
| **4** | 发布：GitHub 三份文件 ＋ 挂 MCP registry | 有人从零装成功，且能**说出「它能帮我干什么」** |

★**为什么是这个顺序**：不知道就写目录＝写出假的目录；没有目录就做链＝造出调不通的链；
**没验就发布＝把坏接口发出去**。

### ★第 1 段里那条「幂等」为什么是阻断项

AI 客户端**默认会重试**超时的调用；而账本**不可改** ⇒
**重试一次 = 多一条预测，用户的准确率立刻被污染。**
⇒ **幂等不是优化项，是「没有就不能对外」。**

另三条工程要求（现在一条都没有）：
**可续**（中断能从断点接着，不从头重写）／
**部分失败可见**（停在哪一步如实报告，**不回滚**）／
**同一口径只有一份实现**。
