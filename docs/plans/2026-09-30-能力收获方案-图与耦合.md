# 能力收获方案 · 二版：真实调用路径与模块组合

> **日期**：2026-09-30 · **修正** `2026-09-30-能力收获方案.md` 里「四条链」的写法
> **创始人追问**：「除 HTTP 之外，别人接入这些智能体里到底怎么调用？」
> 「四个模块之间 A→B→C，或者 A→B→再回 A，这种复杂的耦合怎么调试？」

---

## 〇、先认账：那四条链**太八股了**

链是**线性**的：A 做完给 B，B 做完给 C。
★**但真实用法不是线性的。** 有三种形态会让链条立刻崩：

| 形态 | 线性链会怎么死 |
|---|---|
| **回环** | 「打完分发现你在某类事上偏得厉害」→ 要**回写一条新判断** → 再打分 → A→B→**A** |
| **回溯** | 「归层判成 L3，但取数源取不到真值」→ **退回换层/换源重试** → 不是往下走，是回头 |
| **分叉** | 「n<30」→ 只报方向；「n≥30」→ 给比例。**同一个模块按数据量走两条路** |

⇒ **正确的抽象不是「链」，是「有环的图 + 明确的收敛条件」。**
这一版把链条降级为**图上的四条最常用路径**，并把耦合的工程要求单独立一节。

## 一、别人到底怎么调它（**四条真实路径，按上手难度排序**）

### 路径 1 · AI 智能体接进来（MCP）—— 最推荐

**实际发生的事**，以 Claude / Cursor / 任何 MCP 客户端为例：

```jsonc
// 客户端配置里加一段，AI 进程启动时自动握手
{
  "mcpServers": {
    "p1b": {
      "command": "node",
      "args": ["/绝对路径/p1b/mcp/index.cjs"],
      "env": { "P1B_DB_PATH": "~/我的判断账.db" }
    }
  }
}
```

握手之后发生的事：
1. 客户端启动 `index.cjs`，它回一份**工具清单**（现在 18 个）＋ 每个工具的说明 ＋ 每个工具的**输入结构**
2. 之后每次对话，客户端把清单塞给模型
3. 用户说「帮我记一道：明天会不会下雨」→ 模型**自己挑工具**、自己填参数、发请求
4. 返回值进对话历史，模型据此组织回答

★**AI 侧完全不需要知道有 53 个取数源、6 个算子。** 它面对的是 18 个名字和说明。
**⇒ 所以工具名与说明就是 AI 的全部感知层——这就是「名字要人话」的真正原因。**

**当前能不能跑**：✅ 能。**但**没人知道、没发布、名字是机器名。

### 路径 2 · 自己的程序调（HTTP）—— 最通用

```bash
# 起服务（本地，默认 127.0.0.1:8787）
cd p1b && node src/server.js

# 读健康与就绪
curl http://127.0.0.1:8787/api/health

# 读账本总览
curl http://127.0.0.1:8787/api/audit/summary
```

**适合**：小程序、别的后端服务、任何能发 HTTP 请求的东西。
★**58 个端点已经在跑**，但**零文档**——这是最大的浪费。

### 路径 3 · 脚本/流水线（CLI）—— 最省事

```bash
node p1b/cli 体检 看板      # 人在终端看
node p1b/cli 体检 看板 --json > board.json    # 脚本里取
```

**适合**：CI、cron、你自己的 shell 习惯。23 条已经完整。

### 路径 4 · 嵌进别的程序（当库用）—— 最被忽略

```js
const { classifyReveal } = require('p1b/src/evidence/revealClass.js');
// 直接调判定，不用起服务、不用 MCP
```

★**这一条最轻、也最被忽略**：不需要任何新接口，把几个模块的调用方式写清楚就完事。
对「想把打分逻辑塞进自己产品」的人，这是最短的路。

## 二、模块之间到底怎么组合（**图，不是链**）

### 2.1 先把模块摆出来

```
        ┌──────────────┐
        │  M1 归类     │  六层分类（revealClass）
        └──┬────────┬──┘
           │        │
     ┌─────▼──┐  ┌──▼─────┐
     │M2 取值  │  │M3 拒收门│  真值锚可机检/cutoff/随实例变化
     │53 源   │  └────┬────┘
     └─────┬──┘       │不通过 ⇒ 停
           │通过      │
     ┌─────▼──────────▼───┐
     │   M4 记账（只写不改） │
     └─────┬──────────┬───┘
           │          │
     ┌─────▼──┐  ┌────▼─────┐
     │M5 结算  │  │M6 审计    │
     └─────┬──┘  └───────────┘
           │
     ┌─────▼──────┐
     │M7 打分/偏差 │ ← ★核心价值，现在只活在网页里
     └─────┬──────┘
           │
           └──→ 回到 M1（回环：发现偏差 → 补一条判断 → 再记）
```

### 2.2 三种真实组合（★这才是用法，链只是它的特例）

**组合 ① · 直线（最常见）**
```
归类 → 取值 → 拒收门 → 记账        「帮我记一道」
```
这是链 A。

**组合 ② · 回溯（取不到真值时）**
```
归类(L3) → 取值(53 源里挑不到) → ★退回 → 归类(L5 认证随机) 或 ★要求人工填
                                            ↑ 不往下走，是回头
```
★**线性链在这里会死**：它没有「回头」这个动作。
**要补的是**：每个节点声明**能否回溯、回溯到哪、试几次**。

**组合 ③ · 回环（核心价值所在）**
```
记一道 → 结算 → 打分 → 发现「你在汇率这类题上说了 0.19」
     → ★回写一条针对该偏差的新判断 → 重新记账 → 再结算 → 再打分 → 偏差缩小
```
★**这就是你说的「A→B→再回 A」，而且它是整个项目的目的**：
不是让你答得更准，是让你**知道自己哪儿不行，然后有针对性地练**。
**线性链表达不了这个，因为它不是一次性的。**

### 2.3 所以要交付的不是链，是**这三样**

| 交付物 | 是什么 | 为什么必须有 |
|---|---|---|
| **能力图** | 模块 ＋ 谁调谁 ＋ 哪些边可回溯 | 让调用方知道能怎么组合 |
| **组合契约** | 每个组合的**前提 / 产出 / 失败时停在哪** | 否则调用方只能试错 |
| **收敛条件** | 回环**什么时候停**（几轮？偏差不再缩小？） | ★没有它，回环会无限跑 |

★**收敛条件是这个项目特有的难题**：一般软件里「写—评估—再写」是自愈；
但**账本不可变**，写进去就拿不回来 ⇒ 回环**必须是纯增量**，
每轮只追加、不改写历史。**这条纪律不写清楚，回环就是个坑。**

## 三、耦合要「调得动」，需要四条工程要求（现在一条都没有）

| # | 要求 | 为什么 | 现在状态 |
|---|---|---|---|
| **E1 幂等** | 同一个调用重复执行，结果相同 | AI 会重试；不幂等＝重复记账（**账本不可变，重试就是多写一条**） | ❌ |
| **E2 可续** | 中断后能从断点接着跑，不从头 | 长链跑到第 5 步断了，从头重来会把前 4 步重写一遍 | ❌ |
| **E3 部分失败可见** | 链跑到第 4 步失败 ⇒ 说清「1–3 步已写入、第 4 步没成」 | ★**不回滚**（账本不可变），但**不许假装没发生过** | ⚠️ 部分 |
| **E4 同一口径只有一份实现** | 打分只有一个算法，网页与接口共用 | 抽出接口时最容易出两份实现，**哪天对不上你连查哪边是真都不知道** | ❌ |

★**E1 是最要命的**：AI 客户端**默认会重试**超时的调用。
在「只写不改」的账本上，重试一次 = 多一条预测，**分数立刻被污染**。
⇒ 这不是优化项，是**上线前的阻断项**。

## 四、后续完整推进方案（**四段，每段有阻断判据**）

### 第 1 段 · 收获对账（**1 段，不写代码**）

把 **158 个能力面**（58 HTTP / 23 CLI / 18 MCP / 53 源 / 6 算子）逐行填：

| 能力 | 现形态 | 缺什么形态 | 结论 | 是否幂等 |
|---|---|---|---|---|

★**多填一栏「是否幂等」**——这是 E1 的前置盘点。
**判据：158 行，每行都有结论。「没提到」不算结论。**

**阻断判据**：表没填完，不许进第 2 段。

### 第 2 段 · 补三组缺口 ＋ 四条工程要求

按优先级：
1. ★**偏差分析抽成接口**（核心价值，现在只活在网页里）
2. ★**E1 幂等**（上线阻断项：AI 会重试，不可改账本经不起）
3. 组 1 记账 / 组 3 裁决 的缺失端点与工具
4. E3 部分失败可见 / E2 可续 / E4 单一实现

**阻断判据**：四道闸门全绿 ＋ **「重复调用同一次记账，结果不变」有测试证明**。

### 第 3 段 · 能力图 ＋ 能力目录 ＋ 三种组合

- **能力图**：模块与边，含哪些边可回溯
- **能力目录**：四组 × 五栏（用户这么说 / 调什么 / 得到什么 / **不能做什么** / 越界怎么办）
- **组合契约**：直线 ① / 回溯 ② / 回环 ③ 各自的**前提、产出、停在哪、收敛条件**

**阻断判据**：★**四条链 + 三种组合，每种都能真跑通**；
且每种的**中途投毒测试**都停在正确的那一步（破坏第 k 步 ⇒ 停第 k 步，前 k−1 步如实报告）。

### 第 4 段 · 发布

GitHub 上三份文件：**能力目录** ＋ **安装说明（三种装法）** ＋ **README 补能力摘要**。
先挂 MCP registry；npm 与 HTTP 文档随后。

★**发布前的阻断判据**：有一个人**按安装说明从零装成功**，并且**说出了一句「它能帮我干什么」**
（不是「它有什么接口」，是「我能用它做什么」）——说不出来就是能力目录没写好。
