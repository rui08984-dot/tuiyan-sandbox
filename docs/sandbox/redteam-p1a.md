# AI 推演沙盘 P1a 终端版施工方案 — 红队对抗性审查报告

> 日期：2026-09-07 ｜ 审查对象：design.md §14（P1a 施工方案，主对象）＋§13（gate 终判）＋§10（数据模型/研判实现）＋§11.2（极简交互）
> 方法：red-team 反编造门——每条发现必须给出完整失败路径（入口→步骤→影响），给不出完整路径的推测一律丢弃，不凑数。分级：红线=会杀死产品／黄线=会显著伤产品／提示。
> 与上轮审查关系：adversarial-review-v3.md 的 R1（gate 三档结局）已落 §9.4/§13.3、R2（评分协议预注册）已落 score-protocol-realgames.md——本轮不重复报告，仅在其上攻击 P1a 新增面。

## 目标/范围
- 包含：§14 全部组件——SQLite 三主表（events/claims/actions）、CLI（add/day/list/export）、参谋卡三件套（纯代码矛盾比对+欠定度标注／LLM 竞争假设／LLM 验证点）、假设/排序机械自洽校验、meihua.js 彩蛋挂载、DeepSeek 适配、三条 gate（录入 ≤30 秒实测／比对器单测 100%／试用无感回炉）。
- 排除：P1b 网页版、P2 玄学引擎内部实现、DeepSeek 服务端自身可靠性（无在本代码/配置上的利用路径）。
- 授权依据：自有产品设计文档自检，工作目录 E:\music player。

## 威胁模型
行动者=未来自己的三类化身（非外部黑客）：①快节奏局中时间被挤压的录入者（无脑回车、速记失真、把转述当断言）；②自证动机下的测量者（gate 自测既是运动员又是裁判）；③首次把项目搬进独立 git 仓库的开发者（习惯性 git add -A）。对手赢的标志：垃圾数据入账产出权威假矛盾／gate 假阳性放行／秘钥泄漏／卡片在关键期外到达。
信任边界：用户速记文本→LLM 抽取→claims 表（一切下游结论的唯一源头）；比对器输出→参谋卡（设计文档 §2.2 自认「带引用的结论反而更易取信」——输出自带镀金效应，此边界的过滤必须从严）。

## 攻击面（入口+信任边界）
①比对规则语义层（claims×claims、claims×actions 冲突判定＋欠定度归属）；②回显确认流（人机接口，唯一垃圾过滤点）；③「思路非答案」标签（说服面，锚定与习惯化）；④录入 ≤30 秒 gate 的测量法；⑤施工拆分 A-E 的契约边界；⑥key 存放与 export 面；⑦天结算时序（18 分钟实测延迟×局内真实节奏）。

## 发现
### RD1｜欠定度/无辜解释层在「纯代码比对」重构中失去归属——P0 的 100% 实证不迁移 ｜ 红线
- 入口：§14.2①「矛盾清单=纯代码比对（claims×claims、claims×actions 冲突对）+欠定度标注」——标注的归属主语缺失；§10.1 contradictions 表有欠定度/无辜解释字段但无人填。
- 步骤：① P0 的 29 条矛盾与全部欠定度标注是 LLM 生成+人工核验形态（证据：runs/lyingman day1-exp.md 逐条标注全是语义论证，如「低（档案注记定性该安排为对狼队友的行动指令，反讽读法牵强）」——且该条还依赖 P1a 实时局不存在的档案注记）；② 比对换纯代码后，代码只会机械配对（同人 A 与 ¬A 并存），产出不了「真女巫被迫对跳可解释，不单独定罪」这类无辜解释；③ 若标注也归代码：botc 首发局含毒/醉合法谎言（§9.3 根因明文：声称冲突≠撒谎）→ 合规矛盾被当硬冲突上卡 → 用户在桌上拿「系统显示你矛盾」冤枉朋友；④ 若归 LLM：与「确定层可单测、可离线」（§10.2）的架构声称断裂，且实时局输入是 30 秒速记而非档案级上下文，LLM 标注在此条件下零实测（同模型语义判断在信息稀疏处出错有实证：PK昼2 把 E-18 白狼王自爆误读为对 8号 有利）。
- 影响：产品唯一被实证的资产（矛盾层 29/29 零虚构、有效率 100%）换形态后失效甚至反向——系统性冤枉好人正是 §9.3 预警的失败模式，桌上社交性死亡比不准更致命。
- 绕过尝试：「试用 gate（复盘无感则回炉）」→ 部分守住：冤枉型矛盾用户会有感；但「回炉 prompt」不解决归属未定，可能被错误地归给代码侧加规则，越修越冤。
- 缓解：§14.2 补一段钉死边界——比对器只输出「冲突对+机械冲突类型」，欠定度+无辜解释明确指派给 LLM 侧（可并入验证点调用），强校验加「每条矛盾必须带非空欠定标注」；同时把 P0 的 29 条矛盾做成 golden 回归集。
- 复测：golden 集 29 条上重跑，联合输出语义有效率 ≥80%（P0 阈值）且零虚构引用；另构造 3 条毒/醉合法谎言用例，欠定层必须全部标「不单独定罪」。

### YD1｜「比对器单测 100%」gate 是循环论证——通过≠语义正确 ｜ 黄线
- 入口：§14.4 gate「单测通过率 <100% 不准接 CLI（比对器是产品核，零容忍）」。
- 步骤：① 测试作者=比对器作者，单测只证明「实现符合作者自己写的测试预言」；② 测试用例来自作者对冲突的想象，真实局输入（改口/转述/绰号别名如「女巫/药婆/巫」）超出测试集 → 比对器 100% 通过后在真实局漏报或误报；③ P0 最有价值的恰是「E-12 遗言刀序」这类需要游戏规则库支撑的深矛盾，规则库不完整时漏报的正是高价值矛盾；④ gate 被错误信号放行。
- 影响：产品核质量门失效，坏比对器直接接 CLI；漏报型失败在桌上表现为「工具没话说」，用户流失于无声。
- 绕过尝试：try 试用 gate 兜底 → 漏报型恰好表现为「无感」，单靠它守不住；两条 gate 联合才闭环。
- 缓解：单测 gate 之外加 golden 集 gate（同 RD1）；比对规则逐条列成规则表，每条规则=一条单测+一条真实局例证（29 条矛盾逐条标注由哪条规则命中，命中不了的规则缺口显形）。
- 复测：golden 集通过率；规则表对 29 条矛盾的覆盖审查留档。
### YD2｜E 任务计时方法测不出真实录入节奏——gate 可被无意作弊 ｜ 黄线
- 入口：§14.3 E「用 botc 官方局数据灌账计时，gate=单条 ≤30 秒」。
- 步骤：① botc 官方局数据=已写好的预制文本（切片/档案是作者预压缩的要点句，非原始口语）；照稿录入测的是转录速度，不是实时局「听 30-45 秒口语→现场压缩成结构化速记，同时下一人已在说话」的压力节奏；② 计时口径未定义：含不含 LLM 抽取往返（2-5s）与回显确认键击？不含则 gate 系统性偏松；③ 自计时无对照、无疲劳曲线（第 1 条 vs 第 25 条的手感衰减不测）。
- 影响：gate 假阳性放行（如 25s/条）→ 首次真人局实测 90s+/条 → 录入断供（§5 头号死亡路径）延迟到 P1b 朋友局才爆雷，P1a 三天工程建立在假前提上。
- 绕过尝试：try 换更难的素材自测——恰好可行：sources/werewolf-lyingman-s02e01-raw.txt 存有原始口语节奏，忠实测试的素材已在本机。
- 缓解：预注册计时协议（延续 R2 预注册纪律）：条=原始局一名玩家完整发言（看视频或按 raw.txt 真实节奏念出）；计时从发言开始到入账确认完成，含抽取+确认；≥10 连续条目并记录疲劳衰减；lyingman/pandakill 两局各测一轮。
- 复测：协议落盘后重测；>30s 即触发 §14.4 既定失败处置（改纯复盘导入工具）。

### YD3｜「天结算时生成一次」×18 分钟延迟：卡片在关键期外到达 ｜ 黄线
- 入口：§14.2「day（天结算→参谋卡）」+ §14.1④「研判延迟 15-18 分钟→参谋卡仅天结算时生成一次」。
- 步骤：① 18 分钟是 §9.1 实测值；② 首发场景 botc 夜阶段无狼队夜谈（恶魔独走+神职行动），真实耗时约 3-5 分钟；③ 时序推演：昼 N 放逐→生成启动（18min）→昼 N+1 讨论已进行 10+ 分钟卡片才到→用户对前几人的第一印象已成型，且正忙 30s/条录入无暇读卡；④ 卡片价值密度最高的验证点（如「看夜 N 刀口是否兑现遗言刀序」）恰在到达时已半失效；⑤ 生成失败重试若同步阻塞 CLI，用户连录入（主功能）都被卡住。
- 影响：卡片错过采纳窗口→中段被弃用；生成期录入断供。
- 绕过尝试：try「狼人杀夜谈 5-10 分钟够长」→ 部分场景守得住，但 botc 首发场景守不住（其夜阶段最短）。
- 缓解：①触发点从「天结算」提前到「入夜」（放逐+遗言入账即触发）；②生成异步化（后台子命令/进程），结果写文件落盘+终端响铃，永不阻塞 add；③重试封顶（3 次退避）+失败明示，支持当天手动补生成。
- 复测：快节奏局实测「卡片文件生成时刻 vs 昼 N+1 首个关键发言时刻」先后；生成期间 add 全程可用。
### YD4｜「可并行派单」隐藏串行依赖：claims schema 是 A/B/C/D 共同契约，且类型枚举依赖 C 的实测行为 ｜ 黄线
- 入口：§14.3「施工拆分（可并行派单）」A-E。
- 步骤：① B 的回显确认流要渲染 C 的抽取输出，D 要渲染 A 的矛盾对+C 的假设 JSON——四方都绑在 events/claims 的 JSON 契约上；契约未先冻结则各写各的，集成日返工；② 更深一层：比对规则决定 claim 类型枚举（身份声称/指控/信息报告…），类型枚举决定抽取 prompt——而抽取在真实速记文本上可靠产出哪些类型是经验事实非设计事实，A 的比对器要等 C 在真实文本上实测后才能定型规则集，A↔C 天然是迭代回路不是并行件；③ E 名为并行实为终端任务（A+B+C 未合无法计时全链路），排期若按并行预期会空等。
- 影响：并行派单在集成日撞车；或各方各建隐式契约靠转换层硬接——有损转换=抽取归一化信息丢失→比对漏报（与 YD1 叠加）。
- 绕过尝试：无现有控制可绕——契约缺失本身就是敞开的门。
- 缓解：派单前先落一页「schema 契约 v0」：字段名、类型枚举、supersede/改口字段、证据类型字段（self-claim/heard，防转述当断言）、假设 per-player stance 字段（见 PD1）；D/E 用 golden fixtures 开发不等人；契约变更须版本号+四方知会。
- 复测：A/B/C/D 四方产物在契约 v0 上互导零转换层（或仅一层显式 adapter）。

### YD5｜回显确认流可被无脑回车穿透，且 CLI 无 edit/retract——垃圾入账不可逆 ｜ 黄线
- 入口：§14.2 B「add→LLM 抽取→回显人工确认→入账」+ §14.2 CLI 命令集（add/day/list/export）无修正命令。
- 步骤：① 快节奏局 30s/条，「回车确认」恒为默认键→用户肌肉记忆化全确认；② 抽取错归因（「10号怀疑6号」被抽成 claim(6号, 怀疑10号)）入账；③ 比对器拿假 claim 配出假矛盾→参谋卡带事件 ID 引用上卡（§2.2 自认镀金效应：带引用的结论更易取信）→用户桌上据此质疑 6号；④ 用户事后发现错录，CLI 无 fix/retract，SQLite 手改超出 CLI 接口约定，错 claim 持续污染此后每天参谋卡。
- 影响：单条垃圾全链路放大为权威假矛盾且接口层不可撤销；错归因类污染还直接伤桌面社交。
- 绕过尝试：try「提醒用户仔细核对」——非结构性防护，时间压力下无效，不采纳。
- 缓解（结构性、低成本）：①上下文确认——新抽取与既有 claim 同人同题/冲突时，确认提示变体+高亮既有条目，需显式键（y）而非回车；②高险字段（说话人归属/目标/身份）逐条键控，低险字段（day/phase）才可批量确认；③补 edit/retract 命令，retract 软删留审计痕，参谋卡引用已 retract 事件时降权显示。
- 复测：构造错归因用例灌账，确认流必须拦截并展示冲突上下文；retract 后次日参谋卡不再引用该事件。
### YD6｜「key 环境变量/本地配置文件」双选项+即将独立建仓：误提交路径开放 ｜ 黄线
- 入口：§14.2「key 环境变量/本地配置文件，不入库不入 git」。
- 步骤：① 本机现状实测（本轮核验）：E:\music player 无 .git、无 .gitignore；设计文档自述「如需挪到独立项目目录可直接搬走」——独立建仓是既定方向；② 若走「本地配置文件」选项（config.json/.env 存 key），搬目录+git init 后习惯性 git add -A → key 进初始提交 → push（哪怕私有仓）→ 泄漏面=所有仓库可见者+未来误转公开；③ 泄漏后果：DeepSeek key 直接计费损失+配额被刷爆→参谋卡生成断供。
- 影响：财务损失叠加核心功能中断。
- 绕过尝试：try「不入库不入 git」自我纪律 → git add -A 恰是纪律失效时的动作，防护不能建立在纪律上。
- 缓解：砍掉「本地配置文件」选项，key 只读环境变量（DEEPSEEK_API_KEY），缺失即报错并打印设置指引（密钥永不落盘）；建仓首日 .gitignore 即含 *.db、exports/；export 命令输出做单测断言不含任何凭据字段。
- 复测：全新克隆+未设 env → CLI 拒启且不读写任何本地密钥文件；git 全量历史 grep 无 key。

### PD1｜假设/排序自洽校验的「机械可查」前提缺失：假设是自由文本则校验空转 ｜ 提示
- 入口：§14.2「新增机械校验：假设/排序自洽检查（H1 认定 X 为好人则 X 不得入嫌疑 Top，机械可查）」。
- 步骤：① 机械校验需要逐玩家 stance 字段（defends/accuses）；若假设 JSON 是自由文本叙述（P0 产出即此形态，如「9号大概率为真预言家但不排除悍跳」），代码无从解析「认定」；② 校验对模糊表述空转放行→LY昼2 脱节（信 9号 真预言家却押其最大嫌疑）原样穿过，系统还给出「已自洽」的假信心。
- 影响：为修 LY昼2 脱节而新增的机制名存实亡（提示级：若按 YD4 落 stance 字段即顺手解决）。
- 绕过尝试：try 试用 gate → 空转型失败（校验从未触发）恰恰无感，守不住。
- 缓解：假设 JSON 强制 per-player stance 枚举字段，自洽校验只读结构化字段；校验必须带负例测试——喂 LY昼2 脱节原始数据必须报警（从未触发过的校验=坏校验）。
- 复测：LY昼2 数据回归必须报警；正例数据不误报。
## 汇总
- 保留发现 8 条：红线 1（RD1 欠定层归属缺失）、黄线 6（YD1 gate 循环论证／YD2 计时方法失真／YD3 天结算时序耦合／YD4 并行契约缺失／YD5 确认流穿透+无修正命令／YD6 key 误提交路径）、提示 1（PD1 自洽校验空转前提）。
- 丢弃的无完整路径推测 4 条（反编造门执行记录）：① better-sqlite3 Windows 原生编译失败——未实际安装验证，无复现路径（建议 E 任务首日花 5 分钟装库试证，证实后再升级为发现）；② DeepSeek 服务不可用/限流——外部依赖，无在本代码/配置上的路径，YD3 异步化缓解已覆盖其局内后果；③ 多对局并发写冲突——P1a 单用户单库，无入口；④ 语音转写错误——P1a 范围未含语音，§11.2 已限定语音仅草稿+回显确认。

## 裁决：修后开工
架构（账本+机械比对+LLM 附件层）扛住了全部七面攻击，无需重设计——七条攻击面均打在边界与 gate 上，未打穿承重墙（P0 实证的矛盾层价值主张在 RD1 边界钉死后依然成立）。开工前必须完成三项文档级前置（合计约半天）：
1. §14.2 补欠定层归属段落（RD1）：比对器出冲突对，欠定度/无辜解释归 LLM 侧，强校验加非空约束；P0 29 条矛盾固化为 golden 回归集（同时满足 YD1）。
