> 产出：子代理「AI 推演沙盘调研员」（2026-09-09）。任务：盘点开源"预测所有东西"类项目，提炼本项目参谋卡引擎（矛盾区/假设区双栏对峙/验证点 checklist + LLM 判词）可学习的内功。
> 方法：先本地（botc-research-report.md §3 已盘先例不重复）后联网；repo 事实（star/语言/许可）经 GitHub API 核验，标 URL；未核验项如实标注。

## 0. 结论先行

本次共经 GitHub API 实测核验 25+ 仓库（star/语言/许可均为 2026-09-09 实测值）。三条结论：

1. **"预测所有东西"没有单一开源神库，而是一条管线内功**：问题类型化（Metaculus）→ 多路独立研究×多预测（forecasting-tools 3×5）→ 聚合（中位/市场出清）→ 落注记账（fatebook/brierly）→ 解决后校准（Brier，ForecastBench 对人类对照组）。五环每一环都有 MIT/BSD 开源实现可直接借鉴。
2. **社交推理侧定位最同源的是 deepwolf**：透明"贝叶斯风味" belief model 给每个存活玩家 P(狼)，LLM 只作第二意见，且 `deepwolf calibrate` 自对局对照真值出校准——与本项目"假设双栏对峙+验证点 checklist"几乎同构，MIT 许可可直接抄。反讽的是它 2 star 没人看见。
3. **参谋卡的差异化机会 = 把预测管线五环嫁接到对局账本**：验证点升级为可评分预测卡（Brier 记账），矛盾区升级为谓词互斥+论证攻击图（Argdown），LLM 判词从单 prompt 改为多路独立+聚合。Top5 见 §C。

### B2 机制深挖：假设表示 / 概率更新 / 校准 / 对冲

1. **假设如何表示**：Metaculus 每个问题自带类型（binary / multiple-choice / numeric / date）+ resolution date + 判定标准；ForecastBench 题目强制可判定（resolution criteria）；Squiggle 把"分布"而非点估计作为一等公民。共同点：**每个预测必须是可判定真伪的原子命题**——这正是"验证点 checklist"应达到的形式化程度。
2. **概率如何随证据更新**：主流 bot 路线不是贝叶斯增量微调，而是**重跑**——metac-bot 每 20 分钟对全部未解决题重新走完整研究管线；forecasting-tools 每题固定多路独立研究（源码 `research_reports_per_question=3, predictions_per_research_report=5`，即 15 个独立概率再聚合）。**更新 = 到点全量重算 + 聚合**，工程便宜且天然防锚定。社交推理侧 deepwolf 则是逐事件更新（发言/投票/死亡后刷新每玩家 P(狼)）。
3. **如何校准**：三层范式——个人层（fatebook/brierly：落注带置信度→解决→Brier 记账→校准曲线）；基准层（ForecastBench：对 superforecaster 人类对照组算分）；自对局层（`deepwolf calibrate` 自跑多局，把 copilot 的 P(狼) 对照真值出曲线）。第三层对本项目最有价值：**不依赖外部基准，自对局即可测参谋卡可靠度**。
4. **如何对冲多个竞争假设**：forecasting-tools 的多路独立研究就是结构化对冲——单路幻觉被聚合淹没（TemplateBot 3 个预测方法+1 个研究方法均可覆写）；metaforecast 跨平台中位聚合+分歧展示；Manifold 用连续交易出清群体信念。共同点：**对冲不靠一个更聪明的大脑，靠独立视角的多样性**。

## C. Top5 可落地借鉴点（对照参谋卡：矛盾区 / 假设区双栏 / 验证点 checklist）

| # | 技术名 | 出处 repo | 一句机制 | 在本项目落点 | 成本 | 许可 |
|---|---|---|---|---|---|---|
| 1 | **多路独立判词+聚合**（3 份研究×5 预测→中位） | [Metaculus/forecasting-tools](https://github.com/Metaculus/forecasting-tools) | 同一问题强制 N 路独立推理再聚合，单路幻觉被中位淹没、防锚定 | **LLM 判词流程**：参谋卡生成从"单 prompt 单判词"改为"多路独立判词→聚合"；假设区每张假设卡的置信度=聚合值而非一次性输出 | S | MIT |
| 2 | **透明 belief 栏 × LLM 判断栏双栏对峙** + 自对局校准 | [JuneQQQ/deepwolf](https://github.com/JuneQQQ/deepwolf) | 程序化贝叶斯概率与 LLM 第二意见分离显示，各说各话；`calibrate` 自跑 60 局对照真值出曲线 | **假设区双栏**：左栏=claims 统计/谓词互斥推出的程序化概率栏，右栏=LLM 判断栏；两栏分歧最大的席位=验证点 checklist 优先条目来源 | M | MIT |
| 3 | **验证点升级为可评分预测卡**（Brier 记账+校准曲线） | [Sage-Future/fatebook](https://github.com/Sage-Future/fatebook) · [tcballard/brierly](https://github.com/tcballard/brierly) · [ForecastBench](https://github.com/forecastingresearch/forecastbench) | 预测必须带置信度+到期日+判定标准，解决后按 Brier/log score 记账，长周期看校准曲线 | **验证点 checklist**：每条验证点变成"先验概率+判定标准+到期事件"的预测卡，事件账本新事件入账即自动回填评分；复盘报告输出参谋卡长期校准曲线（第 1 环到第 5 环闭环） | S | MIT |
| 4 | **矛盾区二阶化：论证攻击图**（supports/undermines） | [argdown/argdown](https://github.com/argdown/argdown) | 轻量 DSL 把论证建成"主张→支持/攻击"的有向图， rebuttal 关系一等公民 | **矛盾区**：从平铺冲突列表升级为二阶论证图——既有 contradictions.js 的互斥结果=一阶边；说书人裁量（醉酒/中毒=合法假信息）作为一等 attack 边挂在"该声称可信"上 | M | MIT（package.json 核验） |
