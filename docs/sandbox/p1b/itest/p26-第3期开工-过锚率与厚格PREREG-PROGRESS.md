## ★阻断点（本棒开工前的实测发现）

**「过锚率」当前在账上根本算不出来**——它同时卡住**蓝图里最值钱的两张票（角色③、I1）**。三处实测证据：

1. **拒收留痕表全空**：p1b 私有表 `intake_rejects` **0 行**、`intake_questions` **0 行**（只读查库）⇒ 拒收门（Q0-1/2/3）**在生产从未留下一条记录**。
2. **出题器只落「通过」的行**：`p1b/scripts/corpus-sources-b4.cjs` 的红线注释写了 Q0-2／Q0-3 过滤，但实现是 `continue` **静默跳过**（第 53/55/92/97/100/158/161/210/213/246/247/277 行等）⇒ **被丢掉的候选零留痕**。
3. **拿现成候选池算出来的永远是 100%**：`p1b/sim/out/corpus-sources-b4.rows.json` **420 条候选 ⇒ 420 条全在账本**（statement 逐条比对）⇒ 该件是「已入账集」而非「候选全集」⇒ 用它算过锚率是**构造性的 100%**，无信息量。

⇒ **结论**：角色③／I1 的「≥80%」前置**不是「未测」，而是「按现有仪器测不了」**。要让这两张票能开，必须先有**仪器**（Q0 门可执行判定 ＋ 候选留痕），否则任何「过锚率」读数都是编的。

**同族登记**：这是「**判据可靠但测量通道不存在**」类（承 §88 缺陷二「守卫绕过 ⇒ 静默走到网络层」的同类：都是**该留痕的地方没留痕**）。**可复用纪律**：**凡写「前置＝某率 ≥X」的票，必须同时指定该率的测量通道与留痕落点**；否则该前置＝永久未测。
