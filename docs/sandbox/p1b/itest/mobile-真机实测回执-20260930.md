## 一、为什么代理做不了（别再派一次）

| 要素 | 代理有无头浏览器 | 创始人有真手机 |
|---|---|---|
| 真实触控（手指遮挡、系统级手势） | ❌ 合成的 `element.click()` | ✅ |
| 真实视口（刘海、圆角、安全区、DPR） | ❌ `Emulation.setDeviceMetricsOverride` 能改宽高与 DPR，**但改不出刘海、圆角、真实安全区、真实文字渲染差异** | ✅ |
| 真实网络路径（走 Wi-Fi、经路由器与防火墙） | ❌ 走回环 | ✅ |
| 防火墙入站规则 | ❌ 无头请求不经入站规则 | ✅ 需手动放行一次 |
| 「好不好看」「看不看得见右边」 | ❌ 只能给像素，不能给眼睛 | ✅ |

★第 5 行是关键：p5 报告第 4 行已经写明，**本机自连 `127.0.0.1:8787` 成功不等于手机能连上**
（自连不穿越防火墙入站规则）。

### 放行前必须知道的三件事

1. 后端要监听**全部网卡**而不是只听回环，否则同网段也连不上。
   启动后用 `netstat` 确认 `0.0.0.0:<端口>` 是 LISTENING 状态。
2. 手机与电脑必须在**同一个 Wi-Fi**（不是手机流量、不是访客网络、不是 VPN 网段）。
3. 电脑本机的 Wi-Fi 网络类别若是「公用」，Windows 会默认拦入站 ⇒ 这是最常见的失败原因。

### 放行与回滚（**由创始人手动执行，代理不代劳**）

管理员 PowerShell 里放行（把 `<端口>` 换成后端实际监听端口）：

```powershell
New-NetFirewallRule -DisplayName "推演沙盘 dev" -Direction Inbound -Protocol TCP -LocalPort <端口> -Action Allow -Profile Private
```

测完**回滚**（不留规则在机器上）：

```powershell
Remove-NetFirewallRule -DisplayName "推演沙盘 dev"
```

★放行期间只开 `Private` 档，不要开 `Any`/`Domain`；测完立即删。

  且桌面端不在本轨目标内）。已在 CSS 注释与测试里如实标注。手机目标（Chromium／WebKit）
  走的是 3px 那条。
