## 2. 判定口径

**抽取层（沿用狼人杀基线 7 谓词口径）**：✅ 正确=核心语义全捕获无编造无冲突；⚠️ 可疑=核心语义在但含无标注推断或归属丢失；❌ 有误=事实错误/关键遗漏/编造角色或座位/上下文冲突。

**映射层（本报告独有价值；逐 claim 由 splitBotcClaims 同构逻辑机械分类）**：

| 类别 | 判定条件 | 去向 |
|---|---|---|
| botc | predicate ∈ is_demon/is_minion/status_drunk/status_poisoned | botc_claims（B2 扩展表） |
| 角色入账 | claims_role/is_role 且角色可解析且属本剧本 | 主表 claims（object=角色 id） |
| 通用透传 | said/voted/did_action/is_good | 主表 claims 原样 |
| 狼错位 | is_wolf（BOTC 无统一狼阵营，语义错位但代码透传） | 主表 claims（错位） |
| 不可入账 | claims_role/is_role 但角色不可解析/越剧本 → confirm 抛 400 | **整批失败**（splitBotcClaims 首遇即 throw） |

- **机械入账率** = 落库 claims / 总 claims（含狼错位——代码事实上账）；
- **对齐可用率** = 对齐入账（botc+角色+通用）/ 总 claims（剔除狼错位，反映「记对账本」的口径）。

## 8. Prompt 调整建议（只建议不改——调整由队长定）

1. **注入剧本角色清单+明示 BOTC 专属谓词（或立替身规范）——最高优先级**：实测 botc 专属谓词产出 0/29：状态声称 6 条全部丢失、阵营声称靠 is_wolf/is_role 硬塞且三本行为不一致（is_wolf×2、is_role×1 触发 400）。建议二选一由队长定：①botc 局 payload 注入本局剧本角色清单并扩 4 谓词说明；②不扩谓词，prompt 明示「阵营/状态口播统一落 is_wolf/said，object 必须保留原词」，配合映射层做替身翻译。
2. **发言席位进 payload——修第一人称归属黑洞**：speakerSeat 已在 ctx 但 buildExtractUserPayload 从不输出：6 条第一人称/状态样本 4 条 0 claims；且 actor_seat/action.seat 一律按 claims[0].subject_seat 回填（llm.js:744/747），提名句把行动人错指成被提名者（tb-05/bmr-05/snv-05 全中）。payload 增一行【发言席位】即可让「我」可归属，成本极低。
3. **反例注入：阵营词不是角色名；转述指控必须保留归属**：snv-02 的 is_role(14,恶魔) 直接让 splitBotcClaims 抛 400 整批拒入（对的 claims 也陪葬）；tb-07/snv-07 指控归属丢失成裸断言（同 prompt 下 bmr-07 做对了，说明可教）。建议在 EXTRACT_SYSTEM_PROMPT 铁律区增两条反例：①「恶魔/爪牙」等阵营词禁止入 is_role；②「X号说/反咬」的归属（谁说的）必须写进 object。
4. **（代码侧护栏，非 prompt）400 整批失败降级 + 零声称机械复查**：splitBotcClaims 对不可解析角色现为首遇即 throw（p1b/src/botc/claims.js），一条坏 claim 让整批 confirm 拒入；建议降级为 said+warning 收集（改动属 B2 代码，归队长定）。另建议抽取后机械校验：原话含醉酒/中毒/恶魔/爪牙关键词但 claims 为空 → 触发重试或警告（对应本次 6 条状态丢失）。
