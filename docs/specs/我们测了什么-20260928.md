# 我们测了什么、什么没成立

> **这一页的用途**：对外沟通的第一页，或任何场合被问到「所以你们到底做成了什么」时递过去的这一页。
>
> 写法说明：这一页**故意**把没成立的部分写得和成立的部分一样详细。
> 理由不是谦虚——**能把自己证伪的东西列出来的人，别人才会信他剩下的话。**
> 一份只有好消息的清单，读者会自动按「他在挑着说」折价；一份带负结果的清单，读者会认为其余条目可信。
>
> 配套页：[《对外口径 · 2026-09-28》](./对外口径-20260928.md) —— 每个数字的 file:line 与禁用清单。
> 本页所有读数于 2026-09-28 只读核对（生产库 `p1a-terminal/data/p1a.db`，SQLite 只读查询）。

## 一、测成了的（可复现、有出处、经得起追问）

### 1. 一条干净的端到端质量读数

| 项 | 值 |
|---|---|
| 样本 | 已结算且有落注概率的题 **n = 1700** |
| 观测 Brier | **0.2259** |
| 正态近似 95% CI | **[0.2194, 0.2324]** |
| 对照：永远报 50% | 0.2500 —— **不落在上面的 CI 内** |

为什么这条干净：它只读账本里**真实发生**的结算，不掺自证、不掺泄漏、不掺外部预报技巧。

**但我们没说的话**：这不等于「优于随机」。评审报告里另有「纯随机理论值 0.2300」这个基线，
**我们没有复算它**，所以对外只声称「显著优于永远报 50%」，不声称「优于随机」。

### 2. 一套会自己承认失败的机制

这些不是成绩，是**装置**，但它们决定了这个项目的数字可不可信：

- **n<30 一律不给结论**，只记方向。`p1b/src/routes/auditKpi.js:81` 置信区间不足 30 时直接给 `null`，
  披露件门面同一口径 `p1b/src/routes/disclosure.js:285`。
- **G2 过程能力门**：题进不了账本就先拒收，拒收原因落 `intake_rejects` 表（`p1b/src/db/intakeStore.js`）。
- **判定不清不许硬判**：`ambiguous` 强制附注，判据不清本身进负结果账本。
- **数据快照件全部落盘、纯只读、零 LLM**：任何人可以打开 `p1b/sim/out/` 逐个复核。

### 3. 一次被主动叫停的缺陷

阶段 5 首次「冻结后确认跑」用的是一份**未入库的临时脚本**，其中抓取失败的错误分支是
`console.log('ERR'); continue;` —— **静默丢掉整个分块**。恰逢某城某年 HTTP 失败，
配对从冻结口径的 93 对掉到 72 对，而当时**已经把它当达标读数记下了**。

处置：把该错误路径改成**硬失败**（重试耗尽即 `exit 2`，不写任何结果），
并把抓取逻辑落成仓库内可复现脚本 `p1b/scripts/stage5-forecast-signal.cjs:9-14`（脚本头注即此事）。

> **为什么把这件事写进对外页**：因为它证明我们的「达标」判据不是事后凑的——
> 样本掉了就是掉了，宁可那次不算数，也不用残缺样本出一个更好看的数。

## 二、没成立的（全部列出，附证据）

### 1. 两个会被一击而破、已从对外材料删除的数字

| 数字 | 它其实是什么 | 证据 |
|---|---|---|
| L1 Brier = **0.0000** | 真值与答案读同一张表，零误差是**构造出来的** | `stage4-run-five-layers-20260926.json:519`（`brier_engine: 0`）＋ `:534`（`accuracy: 1`）；引擎出参 `p: value ∈ {0,1}` 见 `p1b/src/engines/l1_proc.js:97` |
| L6 Brier = **0.1755** | 同一族口径问题；且判词层在**时间上根本不合法** | `stage4-run-five-layers-20260926.json:735`；判词 100% 晚于结算（5156/5156） |

（完整机制与 file:line 见《对外口径》① ②。）

### 2. 判词层：目前**没有任何**可对外引用的质量读数

这是本项目最实质的负结果，值得整段讲：

- 评审说的「判词在结算后平均 1.547 天生成」**精确复现**：实测 **1.5465 天 / n=5156**。
- 更糟的一条（本次新测）：**100.0%（5156/5156）**的判词写于结算之后。
  没有一条判词是在答案揭晓前写的。
- **123/5156（2.4%）**的判词正文直接引用终局事件。实例判词原话：
  「**#38 为系统级终局事件，直接宣告狼人胜利**」
  （`.scratch/forecast-debate/verdicts-archive-rb-pre-20260912.json:11`）。

**结论**：判词层在方法上尚未合法，其质量读数**不可用、不可报**。
要修复需要「判词生成时点 < 结算时点」这个硬门，这道门目前**不存在**。

### 3. 阶段 5 那个唯一达标的信号，**不属于我们**

Δ = 0.1587 CI[0.1221, 0.1901]（`p1b/sim/out/stage5-forecast-signal-20260915.out:3`）测的是
**Open-Meteo 的 1/3 日数值预报相对气候基线的优势**：
signal 臂来自 `previous-runs-api.open-meteo.com`（`p1b/scripts/stage5-forecast-signal.cjs:84-86`），
量纲是 4 城日最高气温（同文件 `:108-117`），是**追溯回放**；
base 臂则是**本项目账本自带的基率**（`p1b/src/evidence/stage5Pool.js:97-103`）。

> **被它打败的那个臂，本来就是我们自己的产出。**
> 换句话说：这个项目做到的事，在这件事上等于「输给了公开气象服务」。

### 4. 全局规模：这是一份**没有用户**的账本

- 1994 道题**全部**由脚本批量灌入，**真人手写 0 道**。
- 接题表 `intake_questions` 仅 2 行，且都是护栏测试。
- 拒收日志 `intake_rejects` **0 行**——拒收门在生产从未留痕。
- 账本没有任何一行的 `gate='scored'`；`baseline_brier` 全部为 `NULL`。

**这些必须在对外第一页自己说。** 等别人发现的成本，比自己说的成本高一个数量级。

### 5. 一个方法论盲区（我们自己写下的）

`docs/specs/推演沙盘-投资级评审报告-20260928.md:377` 的原话：

> 「判词层泄漏未被工具覆盖：sim 行的 LLM 判词在游戏结束后 1.55 天才写、且直接引用终局事件；
> leak-scan 只查 meta.cutoff vs 事件窗口，**查不到『判词生成时点 vs 预测结算时点』**。这是方法论盲区。」

即：**我们的防泄漏工具本身有覆盖缺口**，而且这个缺口恰好放过了我们最需要防的那一类泄漏。
一个工具会漏，不算大问题；**不知道它会漏**才是。

## 三、为什么这一页本身就是最好的销售材料

1. **它是可证伪的。** 每一行都带 file:line 或可复现的数字，当场就能验。
2. **它证明了我们在用同一套标准对自己。** 那些坏数字**是我们自己先算出来、先删掉的**——
   这比「我们没有这些数字」可信一个量级。
3. **它暴露的是判断力，不是运气。** 运气只能给出一个好数字；判断力表现为
   「知道好数字为什么出现、并且在它最漂亮的时候把它删掉」。
4. **它让剩下的承诺变得可信。** 读完这一页，对方会相信「0.2259」，
   也相信下一次我们说「这条不成立」时是认真的。
5. **它把风险从"被发现"变成"已披露"。** 演示崩盘的代价是全部信誉；
   主动交出一个坏数字的代价，是一次点头。

## 四、当前的一句话定位（如实版）

> 「一个人做了 16 天的预测纪律系统：1994 道题全部记账、1700 道真实结算、
> 一条干净的整体读数（Brier 0.2259，CI [0.2194, 0.2324]），
> **外加两件我们主动删掉的漂亮数字**——
> 一个自证的 0.0000，一个泄漏来的 0.1755。
> 判词层还没合法，账本里还没有一条人写的题。
> **这些都是我们自己查出来、写在这一页上的。」

## 五、维护

- 本页读数与《对外口径》同源，**任一落盘件重新生成即须重新核实**。
- 新增负结果请**追加**，不要删改旧条目——这份清单的价值在于它的**累积长度**。
- 若某条负结果后来被修好（如判词时点门落地），**保留原文并加一行「已修复：<证据>」**。
  只写好消息的负结果页，三页之后就没人信了。
