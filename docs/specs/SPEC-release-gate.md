# Spec: release-gate · 发行体检脚本（第 5 道闸）

> 能力地图模块 id `release-gate` · 依赖：`privacy-seed` · 规模 1.5 人日
> **它是唯一一道能挡住「发布」的闸。** 前四道闸管代码质量，这道管「能不能发出去」。

## Objective

写一个 `audit-release.cjs`，对**一棵待发行的目录树**跑 14 项机械检查，任何一项不过就以门禁码 3 退出。

**给谁用**：打包的人（可能是我，也可能是你）。
**成功的样子**：把一棵含真密钥、含真人昵称、含绝对路径、含 6.5 MB 数据库的树丢给它，**它会红**并说清红在哪一项；一棵干净的树丢给它，**它会绿**。

## Commands

```bash
# 体检一棵发行树
node p1b/scripts/audit-release.cjs --tree <发行树目录>

# 只跑隐私与结构那几项（privacy-seed 迭代期用）
node p1b/scripts/audit-release.cjs --tree seed --only C9,C10,C11,C14
```

## Project Structure

```
p1b/scripts/audit-release.cjs   ← 本模块唯一新增文件
p1b/test/audit-release.test.cjs ← 新建（含变异注入自证）
```

## Code Style

**照抄 `p1b/scripts/secret-preflight.cjs` 的三条硬纪律**：

1. **绝不打印密钥本体**（只打印计数与文件路径）
2. **绝不联网**
3. **默认只读**（`--tree` 指哪扫哪，绝不写）

CLI 不收它——理由照 `commands.cjs:264-270` 的 `EXCLUDED` 范式：它是「库不是 CLI」。

## Testing Strategy

★**本模块的测试必须包含变异注入**，且这是它区别于其他模块的地方：

1. **正向**：一棵构造好的干净树 ⇒ exit 0
2. **反向锁**：逐项注入 14 类缺陷 ⇒ 对应项必须红（**逐项单独注入，不许一次全注**——否则只知道「整体会红」，不知道是哪一项在咬）
3. **★变异注入自证**：把某一项的检查逻辑破坏掉，确认对应测试变红。**空跑的检查在变异下不会红**——这是分辨真闸与假绿的唯一可靠办法
4. **空树不崩**：目标目录不存在 ⇒ 可读错误 ＋ 非 0，**不许静默通过**

## Boundaries

- **Always**：每项检查独立可定位（报「第几项 ＋ 哪个文件 ＋ 为什么」）；逐项退出码
- **Ask first**：扩展检查项（那是改发布标准）
- **Never**：为了让发行包通过而放宽任何一项；静默跳过扫不到的项（**扫不到必须报红**，否则「没扫到」被读成「没问题」）

## 14 项检查与退出码

| # | 检查 | 判据（机械可复现） | 失败码 |
|---|---|---|---|
| C1 | 密钥 | 发行树内 `config/*.json` 存在即红（**存在即红，不管是不是空串**——空模板应是 `config.example.json`） | 11 |
| C2 | 绝对路径 | 匹配 `[A-Za-z]:\\` 计数 = 0（`node_modules` 除外） | 12 |
| C3 | 内网 IP | 匹配 IPv4 且不是 `127.0.0.1` / `0.0.0.0` ⇒ 红 | 13 |
| C4 | 原生模块可达 | **真 require**（不是 grep）：发行树内 require `p1a-terminal/node_modules/better-sqlite3` 成功 | 14 |
| C5 | `db.js` 可 require | 真 require 成功 | 15 |
| C6 | 包体积 | 发行树总字节 < **12 MB**（不含便携 node） | 16 |
| C7 | 无 node_modules 外泄 | `config/` 目录数 = 0 | 17 |
| C8 | 无 wal/shm | `*.db-wal` / `*.db-shm` 文件数 = 0 | 18 |
| C9 | 种子库表数 | `sqlite_master` 表数与视图数 = 种子声明值 | 19 |
| **C10** | **种子库隐私** | ★见下 | 20 |
| C11 | 种子库五层齐全 | `layer ∈ {L1,L2,L3,L5,L6}` 各 ≥1；`outcome='true'` ≥1；未到期 ≥1 | 21 |
| C12 | 契约表 | 契约冻结件存在且 sha256 与 kind 表一致 | 22 |
| C13 | 启动无残留 | `start*.bat` 的 `cd /d` 行**不含任何盘符**；`package.json` 有 `start` | 23 |
| **C14** | **无真人数据** | ★见下 | 24 |

**退出码表**：
```
0   全部通过
1   用法错
3   ★门禁码：某项不通过（与 anchor-gate / prereg-freeze 同族）
11-24  逐项失败码（可多报）
其它  原样透出
```

★**选 3 而不是 1 的理由**（照 `p1b/cli/index.cjs:18-20` 原文）：「这不是『错误』，是项目最核心的防 Goodhart 设计在说话……**CLI 绝不抹平它**」。发布闸就是最大的 Goodhart 面。

## ★C10 与 C14 的判据（★这一节是对上游方案的实质修正）

上游方案写的判据是「`events.raw_text` 含中文且含'号'的行数 = **0**」。**这个判据不可用**，实测三层：

| 口径 | 行数 | 说明 |
|---|---:|---|
| 机械匹配（含中文 + 含「号」） | **458** | 绝大多数是合法数据（如「3号查杀5号」）。剔完 5 行仍红 453 行 ⇒ **那道闸永远过不去，等于没有闸** |
| 含「N号+昵称」模式 | **173** | 多数只有编号没有昵称 |
| ★**真正带真人昵称** | **5** | 1号【昵称已打码】／8号【昵称已打码】／5号【昵称已打码】／12号【昵称已打码】 等 |

⇒ **本模块的判据**：

- **C14**：`events.raw_text` 按「N号+昵称」模式匹配的行数 **= 0**
- **C10**：`hypotheses` 行数 = 种子声明值（本期 0）；`analytics_*` ＋ `question_owners` 行数 = 0

**不做「按 458 机械剔除」**——那会删掉 90% 的合法示范数据，种子库的可信度就没了。
**判据与剔除名单必须同源**（都来自 `make-seed-db.cjs` 导出的那个 `NICK_RE`），不许两处各写一份。

## Success Criteria

- [ ] 14 项检查全部实现，每项独立可定位（报项号 ＋ 文件 ＋ 原因）
- [ ] 干净树 ⇒ exit 0；**14 类缺陷逐项单独注入 ⇒ 对应项红**（不许一次全注）
- [ ] **变异注入自证通过**：破坏任一项检查逻辑，对应测试变红
- [ ] 目标目录不存在 ⇒ 可读错误 ＋ 非 0，**不静默通过**
- [ ] C10/C14 的判据与 `make-seed-db.cjs` 的 `NICK_RE` 同源
- [ ] 绝不打印密钥本体；绝不联网；默认只读
- [ ] 某一项不通过时整体退出码 = 3（门禁码），且逐项失败码可多报
- [ ] 四道闸门 exit 0
