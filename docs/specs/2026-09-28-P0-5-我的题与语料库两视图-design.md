## 2. 三个桶（互斥且完备）

| 桶 | 定义 | 列行？ | 为什么要这么切 |
|---|---|---|---|
| `mine` 我的题 | 归属当前访客的题 | ✅ | 第一屏该看的就是自己的题 |
| `corpus` 语料库 | **无归属记录**的题（批量灌入那些） | ✅ | 一条没删，只是归在这里 |
| `others` 别人的题 | 有归属但不属于我 | ❌ **只报数** | 混进语料库等于把 A 的题面显示给 B |

- 恒等式：`mine + corpus + others == 账本总数`（测试里逐次断言，可自校验）。
- ★「语料库」按**无归属**定义，**不是**按「不是我的」定义——这两个定义在有第二个访客时
  结果完全不同，用错会导致 A 的题面出现在 B 的语料库里。
- `view=all` = 前两桶的并集（复核用），**仍不含他人题面**：隐私优先于「给个全量」。

## 3. 归属怎么来（两条路，都幂等）

1. **建题即归属**：P0-4 的 `question_created` 事件上报时，同一请求顺带落一行
   （`how='created'`）。前端零额外操作；**漏报也只是进语料库，不丢题**。
2. **显式认领**：`POST /api/analytics/claim { prediction_id }`（`how='claim'`），
   给「先有题、后有归属」的历史题补一条。

归属**不可抢**：已归属他人 ⇒ 409（不静默改写归属记录）。
同一人重复认领 ⇒ 幂等（`duplicate:true`，不产生第二行）。
题不存在 ⇒ 404（不凭空造归属行）。访客 id 不认识 ⇒ 400（身份只由服务端铸造，见 P0-4 §1.5）。

## 4. ★三条不可让步的纪律

1. **绝不删除、绝不隐藏**。每个视图都同时返回 `counts.{mine,corpus,others,total}`，
   前端不需要切视图就知道语料库有多少条。界面文案固定带一句
   「语料库还有 N 条（一条都没删，只是不在这儿列）」——
   因为「筛掉了 N 格」最容易被读成「数据没了 N 格」。
2. **归属不改变结算口径**。本模块**只读** `predictions`，零写账本、零写审计与真值表。
   语料库里的题照旧由守护进程自动揭晓、照旧进 G2 审计——把它归进语料库**不是把它搁置**。
3. **取不到时不假装**。两视图端点不可用时，`WhereOffPage` 显示
   「下面是账本里最近已揭晓的题——它们**不分归属**，不是『你的题』」，
   **绝不**把整片语料库挂在「我的题」标题下（那正是本改动要消灭的那件事）。

## 5. ★「已自动揭晓 N 条」怎么不互相矛盾

不变量是：**对同一个访客，两个视图报的已揭晓拆解必须逐字段相同**。

`auto_revealed = { mine, corpus, others, total }` 是**账本的性质**，与当前看的是哪个视图无关；
`total` 恒等于账本里真·已揭晓的条数。测试用 `assert.deepEqual` 卡住这一点：

```
actual:   { mine: 0, corpus: 1, others: 1, total: 2 }   ← 不带 visitor_id 查语料库
expected: { mine: 1, corpus: 1, others: 0, total: 2 }   ← 带 visitor_id 查我的题
```

`mine` 桶天然是**相对的**（「我的已揭晓」），所以不变量必须写成「**同一个访客**下的两个视图」，
而语料库视图也要接受 `visitor_id`——它列的是语料库题，但计数拆解要按这个人来拆。
界面文案固定写明：语料库里的题也在自动结算（并给出其中的条数）。

## 6. n<30 纪律

`shares.{mine,corpus,others}` 是比例读数：分母（账本总数）< 30 ⇒ `share:null` + 人话 `note`，
**原始计数照给**。与 `auditKpi.brierCi`、披露件 compiler 门面同口径。
界面在 `counts.total < min_n` 时追加一句「只记条数、不给任何比例」。

## 7. 覆盖范围（如实记）

- 归属只覆盖 `predictions`。**`intake_questions`（「记一笔」那条路）未接**：
  它不在 294 这一屏上，且本轮可改文件里没有它的写入路径。
- `question_revisited` 之类埋点事件不参与归属判定。
- 归属**不**回写 `predictions` 任何一列（`game_id` / `source_type` 等一律不碰）。
