## 2. 协议怎么用（三步）

```js
const { protocol, validator } = require('./p1b/src/protocol');

// ① 把问卷摊给模型（题面 + 取值域 + 后果，一次给全，别让模型猜格式）
const p = protocol.getProtocol();
const questionnaire = p.questions.map(q => ({
  key: q.key, prompt: q.prompt, domain: q.value_domain, required: q.required,
}));

// ② 模型答完 → 过机械门（纯函数，零网络零 LLM 零写库）
const v = validator.validateIntakeAnswers(modelOutput);
if (!v.ok) return v.errors;          // 不合规就别发——发出去是 400，白跑一趟
if (v.warnings.length) review(v.warnings);   // 告警不拦路，但要看

// ③ 过了再发。v.outcome 是**本协议算出**的落层/拒收，发完拿真响应 diff 一遍
const res = await classify(v_ok_submission);
diff(res, v.outcome);
```

**别跳第 ②步。** 机械门存在的全部理由就是：模型的产物在**离开模型之后、进账本之前**，
要有一个不靠模型判断的检查点。跳过它，纪律②就只剩一句话。

### 校验器返回什么

```js
{
  ok: false,                       // 无 error 才 true
  errors:   [ {code, key, message} ],   // 拦路
  warnings: [ {code, key, message} ],   // 不拦路，但要看（如「合法但零判断」）
  per_question: { 'Q0_1': {given, normalized, effect}, … },
  outcome: { rejected, reason, first_failing_question, computed_layer, layer, secondary, gate_eligibility },
  summary: '3 条不合规（…）'
}
```

## 3. 模型该怎么答

### 3.1 取值域（逐项投影自冻结件，不是约定的）

| 规范值 | 接受的写法 |
|---|---|
| `true` | 布尔 `true`、数字 `1`、`yes` / `y` / `true` / `是` / `1` |
| `false` | 布尔 `false`、数字 `0`、`no` / `n` / `false` / `否` / `0` |
| `unknown` | `unknown` / `未知` / `n/a` / `na` |

- 归一时 `trim + 小写`，所以 `'Yes'`、`' YES '` 都收。
- **以上没列出的写法一律 `E_DOMAIN`（400）。** `'maybe'`、`2`、`'是是'` 都不是「当成 unknown」，
  是非法。**「大概是」不是取值域里的一项**——判据的可判定部分交代码，判不了的走第 4 节。

### 3.2 必答与形状

```jsonc
{
  "checklist": {
    "Q0_1": true, "Q0_2": true, "Q0_3": true,   // 拒收门 3 问（标量）
    "L5": [true, true, true],                    // 决策树 5 层：定长数组
    "L6": [true, true, true, true],
    "L1": [false, true, true, false],
    "L3": ["unknown", false, true, true],        // 「答不出」是合法取值，见第 4 节
    "L2": [false, false, false, false],
    "L4": [true, true, false]                    // 可选；不发也行，发了就必须定长 3
  }
}
```

- 决策树五层**逐层必填**。缺键 ⇒ 400（`checklist.<层> 必填`），不是拒收。
- 层答案**只收定长数组**，长度必须等于该层问数。
- L4「可选」只指**键可以不发**；一旦发，长短不对照样 400。
- 键名严格区分大小写与下划线：`L1`、`L1_`、`l1` 是三个不同的东西。
  拼错的那一个会被**静默忽略**（校验器给 `W_UNKNOWN_KEY` 告警点名），
  而账本上「没答 L1」和你以为的「答了 L1」从此对不上号。

### 3.3 可选覆盖（谨慎）

- `decided_layer`：取值须 ∈ `PRIMARY_LAYERS`（**不含 L4**——L4 永不作 primary）。
  给了就**覆盖**决策树结果（`outcome.computed_layer` 仍保留树算的那个，可 diff）。
- `secondary`：取值须 ∈ `ALL_LAYERS` 或不发。给了就覆盖 L4 全绿的自动判定。
- ⚠ 这两个是**绕过**决策树的旋钮。模型用它们之前，先想清楚是在纠正还是在偷懒。

## 4. 答不出时怎么办 ★三条纪律的核心

三态里那个 `'unknown'` 不是「随便填填」，它在不同位置后果完全不同。**分三处看**：

| 位置 | 填 `unknown` 的后果 | 判据 |
|---|---|---|
| **拒收门 Q0** | **拒收**，reason = 该问的 reason | 判据是 `!== true`，与「否」同一条路 |
| **决策层某问** | 该层**非全绿**（树继续往下走） | 逐项 `=== true` 比 |
| **L4 叠加** | 不记 secondary，不影响 primary | 同上 |

所以「答不出」的正确表达分两种，**别混**：

- **整层答不出**（这一层我一个都判不了）→ 该层全填 `'unknown'`。
  这是诚实的：它和「全填 false」在**落层结果**上相同，在**账本是否诚实**上完全不同。
- **一题都判不了、这道题不该收** → **不提交**。
  拒收门没有「不答」这个选项，填 `unknown` 只会被记成一条拒收留痕，
  而那条留痕说的是「判为否」，不是「判不了」。这两件事在拒收原因分布里长得一样，**那就是失真**。

### ★逃逸形态（本协议专门点名，因为它合法）

一份**每个必答项都填 `'unknown'`** 的提交：
值域全合法、必答全齐、**不会被拒收门挡住**（拒收门与「否」同路），
一路走到底层非全绿、落 `layer='unknown'`、**照常入账**。

它不是错误，是一份**零判断**的提交。校验器给 `W_UNKNOWN_ESCAPE_TOTAL`。
人看见这条告警，就知道账本里那行是模型什么都没干留下的——而不是它真判了一遍。

> 判据不写死在这儿：这份提交的**唯一**可判定性来自「`unknown !== true`」和「逐项 `=== true`」两条代码，
> 投影自 `intake.js` 的拒收门循环与 `layerGreen`。

## 5. 三条纪律

### 纪律① 可判定的交给代码

- 问数、决策树顺序、拒收原因、三态词表、primary 合法值、gate 转移表，
  **全部由 `p1b/src/protocol/intakeSource.js` 在加载时从冻结件读出**，协议里一个数字都没手写。
- 读不到、形状不对、代码与清单对不上 ⇒ **抛错拒绝加载**，不发半份问卷。
- 题面原文从冻结清单 `docs/specs/万物分类清单-v2.md` 读；代码说 4 问、清单说 3 问 ⇒ 加载即响。
- 依据：同一口径被手抄成两份、本项目反复吃亏。活例子就在旁边——
  `web/src/lib/noteChecklist.ts:36` 手抄了一份 `QUESTION_COUNT`，今天还对，但**没有机制拦着它漂**。
- **两道反向锁**（`test/intake-protocol.test.cjs` ①）：
  ①-1 把投影与**活模块真导出**逐字比对；
  ①-2 `QUESTION_COUNT` **根本没导出**，用 `classifyIntake` 的 400 路径**探**出真值再对账。
  ⇒ 静态读法一旦读歪，红的是测试，不是模型手里的问卷。

### 纪律② 模型的产物必须过机械门

- 校验器是**纯函数**：零网络 · 零 LLM · 零写库 · 不 require 应用代码。
- ③ 是它的**零副作用源码锁**（照 `test/leak-scan.test.cjs:51-57` 的零写库锁范式）。
- 机械门自己不许比模型聪明：它不判断题面对不对，只判断**这份答案合不合协议**。

### 纪律③ 拒答必须与答不出严格区分

- 键缺省 = **400**（请求非法，账本无痕）——「我没答」
- 填 `unknown` = **合法提交**（会入账/会留痕）——「我答了，判不了」
- 两者在账本上长得完全不一样。**模型不许拿 `unknown` 当「我没答」用**，
  也不许拿「我没答」当「判不了」用。校验器把后者点成名（`W_GATE_UNKNOWN_REJECTS`），
  把全表弃权点成名（`W_UNKNOWN_ESCAPE_TOTAL`）。

## 6. 本协议比冻结件严的一处（如实登记）

冻结件的 `layerGreen` 接受**对象**形式，而那个分支**不校验长度**：

```js
checklist.L2 = { only: true }     // 4 问的层，用 1 键
// 真端点：200，layer = 'L2'   ← 一票就把四问的层判成全绿
```

实测见 `test/intake-protocol.test.cjs` ②-5（不是推理，是打出来的）。

**本协议只收定长数组**，对象形式判 `E_SHAPE`。
理由与方向：primary 仍由冻结件的决策树算，本协议**只收紧、不放松**——
收紧为「拒」，绝不悄悄放过。冻结件那条分支是既有实现的已知形状，
**本件不改它**（PREREG 冻结），只在此登记，等另立项。

## 7. 协议不管的事（如实划界）

- **第 -1 步实验场域门**（`game_id`/`game_type` → 真实局即拒 `reason='other'`）：
  它的判定要查 `games` 表，**不在本协议内**。带了局标识时校验器给
  `W_LAB_BOUNDARY_UNCHECKED` 点名「它会先于拒收门跑」，不假装自己评过。
- **引擎与概率**：校验器只给 `gate_eligibility`（够不够格进 `scored` 通道），
  真出不出数还要看引擎 `ok`——**概率只在 `scored` 后出现**，未达标一律 `descriptive`。
- **L4 第 3 问的文本是废条款**：清单 v3 注记已废止「无法归入 L1-L3/L5」那条互斥条款
  （原条款使 L4 永远不可达），但 `QUESTION_COUNT.L4` 仍是 3、层答案仍要 3 条。
  协议照实投影现状，**不改判据**（冻结件与清单都不许动）。
- **`normTri` 是复刻的**（它没导出）。复刻就有漂的风险，账在 ②-3：
  投影词表每个词 + 布尔 + `0|1` + 各种大小写空格写法，逐个打真端点对拍。

## 8. 自查清单（发请求前逐条过）

```
[ ] checklist 是对象，键名无拼错（看有没有 W_UNKNOWN_KEY）
[ ] 决策树五层键齐全，每层是定长数组
[ ] 拒收门三问都是 true（否则是拒收，不是通过）
[ ] 有没有 W_UNKNOWN_ESCAPE_TOTAL？（有 ⇒ 这次归层等于没判）
[ ] 有没有 W_LAYER_UNKNOWN？（有 ⇒ 落 unknown，不是归层）
[ ] v.outcome 与发出去之后的真响应一致？（不一致 ⇒ 投影漂了或引擎差异）
[ ] 没有靠 decided_layer 绕开决策树
```
