## §1 ★必写行（逐字，不许改写、不许省）

每份结算收据的「到期面」一节**必须**原样出现这一行（N 填本轮实际数字）：

> 本次因到期口径推不出而未处理 **N** 条（口径＝round#N 汇总行『无法定到期』＝`corpus-resolve-daemon.cjs:400` `R.undatable`；**非** `--report-due` 的 `distribute():465`）

- **为什么必须逐字**：口径一旦被自由改写，「N 到底是哪来的」就又回到人脑里——09-22→09-27 这 7 天
  正是这样丢掉的（§2.2 复盘）。
- **N 的来源只有一个**：`corpus-resolve-daemon.cjs:526` 那行 `round#N … 无法定到期=R.undatable`，
  计数器在 `:400`。**不许**用 `--report-due` 的数顶替（两者锚不同，见 §4）。
- 数字为 0 时**照样写这一行**（写 0）。省掉＝读者无法区分「0 条」与「忘了记」。

## §2 与 v1 方案的四项撤回（如实登记）

v1 方案曾提四件，本次**全部撤回**，理由逐条如下。核实方式：`grep -rn "KNOWN_UNDATABLE\|undatableCoverage\|baseline_n"`
于 2026-09-27 全仓执行，**零命中**（唯一命中在 `_session_extract/` 的历史会话归档 JSONL 里，与本仓代码无关）
⇒ 四件**从未落地为代码**，撤回不产生任何代码删除动作，只是「不写」。

| 撤回项 | 为什么撤回 |
|---|---|
| ① `KNOWN_UNDATABLE` 例外名单 | 名单登记的是「今天哪几个没实现」，而要抓的是「明天多了哪个没实现」。**手抄快照登记不了增量。** 替代物＝§3 的契约覆盖断言。 |
| ② `undatableCoverage` 覆盖断言 | 同 ①：数字快照会随结算自然漂移，漂移即转红 ⇒ 要人回来改数字 ⇒ 改着改着就没人看了（Goodhart）。 |
| ③ `baseline_n` 单调性 | 账本**只增不删**，「基线不得下降」会把**每一次正常结算**都报成事故。 |
| ④「8-vs-5」头注 | 那个反例**已不可复现**：实测 id 821/833 已 `outcome=false, resolved_at=2026-09-26 17:09:45`；`inferIssue('2026110')` 两锚同解 2026-09-22；`corpus%` 集内 `outcome IS NULL` == `resolved_at IS NULL` == 292，两向零分歧。**收据不许挂不可复现的反例。** |

## §3 ★可复现锚（取代不可复现的反例）

收据的「到期面」一节**必须**同时给出下面两条锚，缺一条视为体例不合规。

### 3.1 锚 A — 本次改动自身的前后对

写法：`落地前 <X> 条 / <K> kind 全量 undatable → 落地后 <Y> 条 / <M> kind`，并附**跑它的日期**与**完整命令**。

- 2026-09-27 实测值（本次「结算通道欠账告警」那一轮的**前**态，可作体例样板）：
  **8 kind / 86 条全量 undatable**（64 条已解 + 22 条未解）→ 待 A3–A6 分支落地后应为 0/0。
- 为什么钉这条而不钉「22→24」：前者**任何人重跑都能得到同一个数**（读的是只读契约 + 合成夹具），
  后者依赖账本当时的快照，隔一天就变了。

### 3.2 锚 B — 读者可当场复跑的一行探针

```bash
node -e "const {db}=require('E:/music player/p1b/src/deps');db.init();const D=require('E:/music player/p1b/scripts/corpus-resolve-daemon.cjs');const B=require('E:/music player/p1b/src/evidence/dueBranches');const {DatabaseSync}=require('node:sqlite');const a=D.distribute();const c=new DatabaseSync(db.DEFAULT_DB_PATH,{readOnly:true});let cov=0;for(const r of c.prepare('SELECT evidence_json FROM predictions').all()){let ev=[];try{ev=JSON.parse(r.evidence_json||'[]')}catch(e){ev=[]};if(B.DATE_DERIVATIONS[String(((ev[0]||{}).resolve||{}).kind)]&&!(D.dueOf(ev[0]||{})||{}).due)cov++}c.close();console.log('①收据口径='+a.undatable+' ②覆盖面='+cov)"
```

- 2026-09-27 实跑输出：`①收据口径=22 ②覆盖面=86`。
- **读法（这一条要抄进收据，否则探针白给）**：
  - **① ＝ §1 那行的 N**。不相等 ⇒ 收据写错了，或有人换了口径。
  - **② 与 ① 不等是常态，不是分叉**：① 是结算面（`corpus%` ∧ 未解），② 是覆盖面（契约登记的 kind ×
    **全量行**，含已解）。覆盖面**恒 ≥** 结算面。2026-09-27 差 64 ＝ 那批**已解**的饿死题。
  - **真正的口径分叉信号**是第三个数：`matures_at <= 今天`（09-22 收据 §1 用的就是它）。
    它既不是 ① 也不是 ②。**收据里若出现未经标注的第三口径，视为不合规**——这正是 09-22 漏掉
    31 条饿死题却无人察觉的机制（`resolve-routine-receipt-20260927.md` §2.2）。

> ★**对 v1 方案的一处修正（如实登记）**：v1 把锚 B 写成「两者不等即口径分叉」。
> 实测该判据**恒成立**（覆盖面本就 ≥ 结算面），会变成天天报警的狼 ⇒ 无效告警。
> 本文改成上面三条读法：**N 取 ①、不等即收据错；②≠① 是常态；第三口径出现才是分叉。**

## §4 口径根治留档（本轮**不改**，只登记）

**机制**（不是某一次的实例）：

```
corpus-resolve-daemon.cjs:513   if (args.indexOf('--report-due') !== -1) { initDb(); return await reportDue(); }
corpus-resolve-daemon.cjs:519   await refreshCals();
```

`--report-due` 的早退**在** `refreshCals()` **之前** ⇒

- **报表恒用内置锚**：cwl `2026105@2026-09-10`（`:34`）、dlt `26104@2026-09-12`（`:35`）；
- **结算轮用刷新锚**：`refreshCals()`（`:328`/`:333`）从官方列表拉最新期/日后覆盖 `CALS`。

⇒ 凡到期日靠 `inferIssue()` 从期号推的 kind（`cwl_*` / `dlt_draw_result`），
**同一个未解题在报表与结算轮可能被判出不同的 due**（锚较旧时 `inferIssue` 回推会落在不同日期，
极端情形下回推出 `null`）。这正是 §1 那行要求「口径＝`R.undatable`（:400），**非** `distribute():465`」
的机械原因。

**为什么本轮不修**：改顺序**会动读数**（报表的到期分布会变），属须拍板事项，不夹带在告警施工里。
**何时修**：任何一次要改 `CALS` 刷新顺序的施工，必须同批把 §1 固定行与 §3.2 探针一起复跑并更新本节。

## §5 测试门（体例，保留）

每份收据的「测试门」一节写**前后两个数字**（不是只写「全绿」），
体例照 `resolve-routine-receipt-20260922.md:59-61`：

```
**<前> → <后> pass / <后> fail**（`cd p1b && npm test`）
```

- 2026-09-27 本轮实测：**643 → 645 pass / 0 fail**。
- 门内若有红：**如实写红**，并在下一行写带注更新（注明「读数前进，非口径变更」），不得只写绿。

> ★**同一条纪律的延伸：写清楚跑的是哪条命令**。本仓有两条测试命令，**覆盖面不同、数字必然不等**：
>
> | 命令 | 收哪些件 | 2026-09-27 实测 |
> |---|---|---|
> | `cd p1b && npm test`（＝`node --test`，从 `p1b` 起递归发现） | `p1b/test/*.test.cjs` **76 件** ＋ `p1b/web/**/*.test.mjs` **17 件** | 645 |
> | `cd p1b && node --test test/*.test.cjs` | 只有 `p1b/test/*.test.cjs` **76 件** | 552 |
>
> 差 93 例**不是**漏跑，是 web 侧的 `.test.mjs` 不在第二条命令的通配里。
> 收据里**必须写全命令**（`npm test` 还是 `node --test test/*.test.cjs`），否则 645 与 552 并列出现时，
> 读者无从判断是回归还是口径差——本文 §3.2 治的正是同一类病，这里不给自己开一个新口子。
