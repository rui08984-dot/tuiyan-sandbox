## 二 · 功能映射表（立项书 §二-第一步 · 必做前置）

> 目的（评审 F4）：说清 LLM 在 `retrieval` 臂的输入/输出 schema、是否产出概率、与 design §2 逐层角色矩阵的对应；
> 并**援引**项目内部先例（立项书原文要求「援引或反驳，不得回避」）。

### 2.1 内部先例援引（评审 F4 指其缺失）

`.scratch/forecast-debate/H-发散收敛架构.md` §五「铁律对齐自查」原文（L76）：

> | LLM 四角色（聚合/基率/多路/校准） | 低温=信息聚合…；高温=多路推理（发散候选，R-b 明文归入此角色）；聚合=机械中位非 LLM 读判词…；校准=ECE 仪表盘… |
> **✓ 无第五角色**；玄学臂是安慰剂基线（被测对象）非新角色 |

**援引结论**：H 件对「基率检索 ＋ fact-check」同类架构判过「**✓ 无第五角色**」——其归位方式是「低温=信息聚合 / 高温=多路推理」。本立项 `retrieval` 臂的 LLM 用途（**对检索到的证据行抽取结构化字段**）恰属该先例的「**信息聚合**」用法 ⇒ **有内部先例支持 (b)，不需新增第五角色**。此即对评审 F4「未援引」的补正。

### 2.2 retrieval 臂的 LLM 输入/输出 schema（写死，PREREG 冻结）

| 项 | 内容 |
|---|---|
| **输入（prompt 变量）** | ① 题面 statement ② **检索结果行**（每条：URL ＋ 抓取时间 ＋ 原文片段，**均已过 §四-3 三层时点审计**）③ 固定指令模板（含「禁使用 cutoff 之后信息」硬约束） |
| **输出（结构化，非自由文本）** | JSON 行数组：每条 `{ url, published_at, event_at, quote, direction('for'|'against'|'neutral'), strength(0–1) }`；**LLM 不直接输出最终概率** |
| **概率来源** | **固定规则聚合**（PREREG 附件的纯函数）：`p = Σ(strength_i × sign_i) / Σ(strength_i)` 之类**写死**规则 + 兜底 0.5；**非 LLM 出数** |
| **角色归属** | ＝「**信息聚合**」（把无序证据整理成结构化行），与 H 先例「低温=信息聚合」同型；聚合出概率一步**不是 LLM**，故不落「多路」也不落「校准」 |
| **是否产出概率** | **否**（LLM 只出结构化证据行；概率由固定规则算出）——这是 (b)「措辞与实现都在四角色内」的**实现级证据** |

### 2.3 与 design §2 逐层矩阵的对应（**实验臂声明**）

| design §2 行 | 现有 LLM 角色 | retrieval 臂是否触碰 | 说明 |
|---|---|---|---|
| L2 系综 | 基率（整理/核对来源） | **否（实验臂）** | 本臂**不写入** L2 生产路由；L2 引擎（`l2_baseline.js`）一字不改 |
| L3 短窗 | 校准（出同化/特征代码） | **否（实验臂）** | 同上，L3 引擎（`l3_aci.js`）一字不改 |
| L6 对抗 | 多路 + 校准 | **否（实验臂）** | 本臂输出存**独立容器**（§四-5），不进判词聚合 |
| 其余层 | — | **否** | 不触碰 |

**「实验臂」声明的确切含义（写死）**：`retrieval` 臂的 LLM 调用**只发生在实验运行期**，其结果落**独立 run-state 容器**（`run_id` 命名空间，见 §四-5），
**零写** `predictions`／`truth_vault`／`intake_questions`，**不改动**任何生产引擎的输入/输出契约，**不新增**任何生产路由。故 design §2 矩阵**无需开列**「多路用于 L2/L3」。
> 评审 F4 要求「(b) 的代价写清」：本声明即代价形式——代价＝**本臂证据永远只能作实验读数，不得回流生产路由**（若日后要回流，须另走 (a) 铁律修订 + design 版本递进）。

### 3.2 覆盖域结论（回答「retrieval 臂能覆盖哪些题」）

- **可入本立项实验池的层 = {L2, L3}**（立项书 §四-2 资格谓词）。对应 **48 个 kind**；账本 `g2_regime='R4'` 下 L2 625 行 ＋ L3 752 行 = **1377 行**，其中**已解（outcome∈{true,false}）= 783 行**（L2 302 ＋ L3 481）——此即立项书 §四-2 与评审实测的**池 783 行**（一致）。
- **L5（3 kind，彩票/体彩）明确排除**：认证随机源，`retrieval` 无力（且触碰即「泄漏信号」反例，见铁律备注）。
- **限制项（如实披露）**：
  1. **时点合规是命门**：本清单里的源多数是**历史 archive**（可回填查），但 retrieval 臂用的是**cutoff 前可得**的信息 —— 须逐条过 §四-3 三层时点审计；archive 端点是否保留「当时版本」需在 PREREG 冻结前**逐源验证**（部分官方源只给最新快照）。
  2. **`resolve.url_template` 主机禁访**（防「抓真值锚冒充找证据」，评审 F1 实测 `id=473` 即此形态）⇒ 检索用的**检索式证据源**须与 `resolve` 源**分离**（如天气题：resolve 用 archive-api 真值，retrieval 用 cutoff 前的预报表/新闻）。
  3. **成本/限速未知**：本件只列源，成本走立项书 §六 公式（含 A 实测 42% 首轮成功率）；限速需在 PREREG 冻结前逐源标（`api.github.com` 无 token 60/h 已知）。
