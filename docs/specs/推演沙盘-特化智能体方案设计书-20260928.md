## 0. 一页结论

### 0.1 定位（一句话）

> **它是 LLM 的上游闸门，不是 LLM 的下游助手。**
> 一个只做减法的题面准入判定器：给定一句待问的问题和它的证据规格，它用纯代码机械判定这道题值不值得进账本，并给出**可复核的、不会被模型改写的**拒绝理由。
>
> **广告语：不是让它更会猜，是让它先证明这道题有资格被猜。**

### 0.2 四个岗位独立收敛到的同一形态

| 岗位 | 结论 |
|---|---|
| CTO | 18 条 CLI 命令就是 tool registry；**MCP over stdio 手写 405 行，1 人日可验**；**exit 3 走成功通道是唯一不能做错的地方** |
| 数据 | **agent 出题合法，agent 给概率不合法**（三重锁）；**3 张新表全是私有表，predictions 零改动**；**三门全红** |
| 产品 | 人的位置在**押注时、认账时、决定相不相信一份报告时**——三个位置一个都不能自动化 |
| 商业 | **MCP 免费全功能 + 付费层卖「审计导出与合规报告」**；**别喊 51 类取数器，那是规模指标不是价值指标** |

### 0.4 三条不可让步的协议纪律

> **D1 · 空集永不等于通过。** `candidates=[]` 必须返回 `{verdict:"empty_set", gate_exit:3}`，禁止 throw、禁止返回 pass、禁止被模型总结为"未发现问题"。依据 `anchor-gate.cjs:209`。
>
> **D2 · LLM 不产出任何进入数值列的值。** 8 个首发工具的返回里不存在 `my_prob`/`implied_prob`/`confidence` 字段。agent 出的 `layer`/`engine` 是 kind 的**确定性映射**，不是模型的判断。
>
> **D3 · 每个工具结果必须带"这不是错误"的元信息。** `gate_exit:3` 是**正常返回字段**，不是错误码。**任何 tool 都不得让 MCP 层返回 `isError: true`（门禁场景）。**

### 0.5 最关键的一处设计

**`index.cjs:26-28` 那段注释是整个 agent 化的原型：**

> 「把它们抹平成 1，等于把『防空集被读成通过』和『普通报错』归成同一类，**CI 与人都再也分不出来**。」

**agent 会犯同样的错，而且错得更快**——它会把"锚点门判定 57 条不可用"读成"这个工具坏了"，于是改用别的工具或编一个结论。**这恰好是 Goodhart 定律要求系统防的那种事。** agent 版只是把这段注释复制到协议层：

```jsonc
// exit 3 的返回体
{ "verdict": { "gate": "FAIL", "exit": 3,
    "meaning": "门禁判定不通过——这是防 Goodhart 机制在说话，不是程序崩溃",
    "do_not_retry": true } }   // isError: false
```

**这是整个设计里唯一一处「不做就等于把项目最核心的资产接到一根线上短路」的地方。**

## 1. 传输层与基座选型

### 1.1 决策：**MCP over stdio，手写 JSON-RPC 2.0，不引 SDK**

| 选项 | 裁决 | 理由 |
|---|---|---|
| **MCP over stdio** | **采用** | 唯一被所有 MCP 客户端开箱支持的传输；进程模型与「双击 bat 起一个进程」完全吻合；**不监听端口 ⇒ 不新增网络暴露面**（对一个刚修完 P0-2 的项目是决定性的） |
| MCP over HTTP+SSE | 否决 | 需常驻服务 = 需进程守护；需监听端口 = 新暴露面，与 P0-2 修复方向相反；与已注册的 Fastify 争同一生命周期 |
| Streamable HTTP | 否决 | 为远端服务设计，本项目是单机本地工具。**在 0 个远程消费者时引入远程传输，是为不存在的需求付运维成本** |
| 纯 HTTP + 手写 JSON-RPC | 否决 | 丢失「任何 MCP 客户端零配置接入」这唯一实际收益，等于自造私有协议 |
| 裸 function-calling | 降级为 M2 的一部分 | 它是"模型调本项目"，本轮命题是"别人用现成 agent 调本项目"。但不该丢弃——M2 之后它就是 MCP 的实现细节 |

### 1.2 手写 405 行的分解

| 模块 | 行数 | 内容 |
|---|---:|---|
| `mcp/framing.cjs` | 55 | 按行切分、JSON.parse 包裹 try、**stdout 写锁**（防并发交错） |
| `mcp/protocol.cjs` | 70 | initialize / notifications/initialized / ping / 未知方法回 -32601 |
| `mcp/tools.cjs` | 95 | tools/list（含 nextCursor 分页）、tools/call 分派、未知工具回 -32602 |
| `mcp/cliBridge.cjs` | 85 | 组装 argv、**spawnSync 带 pipe**、捕获 stdout/stderr/exit code、超时 |
| `mcp/exitMap.cjs` | 60 | `3 的退出码映射表 |
| `mcp/index.cjs` | 40 | 引导、握手、require 清单 |
| **合计** | **≈405** | **只需实现 5 个方法** |

**⚠️ 最硬的约束（CTO 实测）**：`index.cjs:271` 是 `stdio:['ignore','inherit','inherit']` —— **CLI 不捕获子进程输出，直接写父进程 stdout**。**所以 MCP 不能复用 `main()`，必须抽一个带 stdio 选项的 spawn。** 这是 `index.cjs` 唯一的一处改动（`main()` 仍传 `inherit`，行为逐位不变）。

### 1.3 为什么不用 SDK（决定性理由不是省事）

| 维度 | 手写 405 行 | `@modelcontextprotocol/sdk` |
|---|---|---|
| **退出码映射** | 自定义 40 行 | **仍需自定义** —— SDK 不提供 exit 3 语义 |
| 传递依赖 | **0** | zod + 事件总线 + 可选栈（清单待核验） |
| 供应链风险 | 无 | 1 人 + 0 CI 的项目多一条无审计依赖链 |
| 1 人可维护性 | 高 | 中（黑盒 + 升级长尾） |

**用了 SDK，那 40 行还是要写，同时还多一个黑盒。**

### 1.4 「零新依赖」铁律的重新划界

【事实】这条铁律事实上已不成立：`p1b/package.json` 有 4 个运行时依赖，`p1a-terminal` 有原生模块 better-sqlite3，`web/` 有 3+6 个。

**建议改写为**：

> **铁律 v2：MCP server 运行时零新依赖；devDependencies 不受限。**

理由：保留原关切（405 行自己写）**应该**保留；放行 devDependencies 是因为 CI 需要的东西比测试框架多，**把 CI 建立在「零 dev 依赖」上，是在为一个已经破产的假设付成本**。

### 2.3 W 档与 confirm 的处理：**复用现有确认闸，零新增代码**

【事实】`index.cjs:232-246` 的确认闸在 **spawn 之前** return EXIT.USAGE，**子进程一次都不起**。

**做法：MCP spawn 时永不带 `--确认`。** 于是：

| 方案 | 做法 | 新增代码 | 模型看到 |
|---|---|---:|---|
| **A（推荐）** | 正常注册；MCP 永不带 --确认 | **0 行** | 完整预览文本 + `gate_not_confirmed` |
| B | 不注册，只做 resource | ~30 行 | 只有一句"此操作需人工" |

**推荐 A。** 它把**人机共用的同一道闸**复用了——模型拿到完整预览，人拿同一段预览去终端执行。**信息量更大，且不新增任何绕过面。**
**配套铁律**：`corpus-resolve` 是唯一的 `net:true`，**MCP 层必须能整体关掉打网工具**（`P1B_MCP_ALLOW_NET=1` 才注册），默认离线。

【事实】18 条里**只有 6 条支持 `--json`**：board / exp-health / leak-scan / g2-report / stage4-run / kind-table。

| 方案 | 适用 | 做法 | 工作量 |

## 3. 数据面设计

### 3.1 三张新表（全部 p1b 私有表 additive，**predictions 零改动**）

【事实】范式依据 `predictionsStore.js:9-10`：「共享库禁 DDL → p1b 私有表启动时 CREATE TABLE IF NOT EXISTS 的 additive 新表」。

#### ① `agent_tool_calls` —— 工具调用轨迹（第一优先）

**为什么第一**：它是 agent 化后**唯一无法事后重建**的数据。工具返回值会消失、模型会变、prompt 会改，但"当时调了什么、拿到什么、判成什么"只有落盘才保得住。

```sql
CREATE TABLE IF NOT EXISTS agent_tool_calls (
  id            INTEGER PRIMARY KEY,
  run_id        TEXT    NOT NULL,              -- 批次指纹，照 verdicts.run_id 范式
  turn_index    INTEGER NOT NULL,              -- agent 决策回合序号
  actor_type    TEXT    NOT NULL DEFAULT 'agent'
                CHECK(actor_type IN ('agent','human','script')),
  tool_key      TEXT    NOT NULL,              -- ★用 commands.cjs 的 key，不用脚本名
  tool_tier     TEXT    NOT NULL CHECK(tool_tier IN ('R','F','W')),  -- 从命令表抄
  argv_sha256   TEXT    NOT NULL,              -- ★只存 argv 哈希，绝不存原文
  net_requested INTEGER NOT NULL DEFAULT 0 CHECK(net_requested IN (0,1)),
  confirmed     INTEGER NOT NULL DEFAULT 0 CHECK(confirmed IN (0,1)),
  target_host   TEXT,
  allowlist_verdict TEXT CHECK(allowlist_verdict IS NULL OR
                allowlist_verdict IN ('allow','block_host','block_tier','block_no_confirm')),
  started_at    TEXT    NOT NULL,
  latency_ms    INTEGER,
  exit_code     INTEGER,                       -- ★原样存，3=门禁码不许抹平
  result_sha256 TEXT,                          -- ★只存 stdout 哈希
  result_bytes  INTEGER,
  verdict_json  TEXT,                          -- 机器可读结论（非原文）
  run_frozen    INTEGER NOT NULL DEFAULT 0 CHECK(run_frozen IN (0,1)),
  created_at    TEXT DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_atc_run  ON agent_tool_calls(run_id, turn_index);
CREATE INDEX IF NOT EXISTS idx_atc_gate ON agent_tool_calls(exit_code) WHERE exit_code = 3;
```

**绝对不能存**：任何 api_key / 共享令牌；`argv` 原文（含绝对路径 = 个人信息）；`stdout` 原文（判词正文可能含题面片段）；题面 statement（埋点表一列都不记题面是既有纪律，工具调用表必须同款）。

#### ② `prediction_actor` —— 预测的作者身份（1:1 独立表，不 ALTER predictions）

```sql
CREATE TABLE IF NOT EXISTS prediction_actor (
  prediction_id  INTEGER PRIMARY KEY REFERENCES predictions(id),
  actor_type     TEXT NOT NULL CHECK(actor_type IN ('user','engine','agent','unknown')),
  actor_proof    TEXT NOT NULL CHECK(actor_proof IN (
                  'human_key_match','human_no_key','engine_frozen_id',
                  'agent_run_id','agent_ungated','legacy_backfill')),
  declared_model TEXT,                    -- 声明的批次标签（配对键，不得改动）
  resolved_model TEXT,                    -- 事实层：usageSink 回填的实际模型
  run_id         TEXT,
  prompt_sha256  TEXT,
  -- ★结构上锁死
  CHECK(actor_type <> 'user'   OR actor_proof IN ('human_key_match','human_no_key')),
  CHECK(actor_type <> 'agent'  OR run_id IS NOT NULL),
  CHECK(actor_type <> 'engine' OR actor_proof = 'engine_frozen_id')
);
CREATE INDEX IF NOT EXISTS idx_pa_type ON prediction_actor(actor_type);
```

#### ③ `agent_decisions` —— 决策记录（可复算的物理载体）

```sql
CREATE TABLE IF NOT EXISTS agent_decisions (
  run_id          TEXT PRIMARY KEY,
  created_at      TEXT NOT NULL,
  frozen_at       TEXT,
  status          TEXT NOT NULL DEFAULT 'running'
                  CHECK(status IN ('running','frozen','aborted','expired')),
  manifest_sha256 TEXT NOT NULL,   -- ★六元组指纹（见 §3.4）
  system_sha256   TEXT NOT NULL,   -- 生效源全文哈希
  tools_sha256    TEXT NOT NULL,   -- ★commands.cjs 全文哈希（改工具表则旧 run 自动失效）
  engine_sha256   TEXT NOT NULL,   -- engines/ 目录哈希
  contract_sha256 TEXT NOT NULL,
  model_declared  TEXT NOT NULL,
  model_resolved  TEXT,
  n_turns         INTEGER NOT NULL DEFAULT 0,
  n_tool_calls    INTEGER NOT NULL DEFAULT 0,
  decision_json   TEXT NOT NULL,   -- ★结构化决策节点（thought 只存哈希）
  out_sha256      TEXT,
  replay_status   TEXT CHECK(replay_status IS NULL OR
                    replay_status IN ('not_attempted','match','mismatch','skipped_external')),
  replay_detail   TEXT
);
```

**「宁缺勿错」三判据**：
1. **反向证明优先**——允许的证明只有三种：`engine` 非空 / checklist_hash 命中冻结名册 / 密钥命中。**不允许**"应该是脚本出的吧"这种推断。
2. **一次性 + 幂等 + 可对账**——`predictions` 行数 − `prediction_actor` 行数必须恒等于 0。
3. **冻结 + 禁改判**——回填规则先写成 `PREREG-actor-backfill-v1.md` 冻结，sha256 记进 manifest；改判据必须版本递进 + 全量重跑 + 显式 diff。

### 3.4 可复算性：manifest 六元组 + 三种快照等级

```
manifest = sha256(JSON.stringify({
  run_id,
  system:   sha256(生效源全文),
  tools:    sha256(commands.cjs),   ★工具表进指纹 ⇒ 改工具表旧 run 自动失效
  engine:   sha256(engines/ 目录),
  contract: sha256(g2-contract-frozen-r4.json),
  model:    declared_model + ':' + temperature,
}, null, 0))
```

**外部 API 会变 ⇒ 三种快照等级必须显式标级**：

| 等级 | 做法 | replay_status | 可对外？ |
|---|---|---|---|
| **S 自足** | 返回值全部落盘，重放只读盘 | match | ✅ |
| **R 可重取** | 只落哈希，重放时重取并比对 | match/mismatch | ⚠️ 仅 match |
| **E 外部漂移** | 外部源已变 | mismatch | ❌ **必须如实标 mismatch 并附 diff** |

**硬规则**：`result_sha256` 必须先写哈希再判等；重放 mismatch 时**禁止**自动改哈希重跑（那就是"跑完改答案"）。

### 3.5 ★★ 三条必须先做的"行号重锚"与技术债

**【事实·本轮新发现】ADR-002 的行号已经漂移：**

| ADR-002 记录 | **实测真实行号** | 漂移 |
|---|---|---|
| :356 | **:434** | +78 |
| :499 | **:580** | +81 |
| :519 | **:600** | +81 |

**三处全漂移。任何照 ADR 施工的人会改错地方。** 好的一面：`grep "UPDATE predictions"` 在整个 `p1b/src` 下**只有这 3 处命中，没有第 4 处**——这是可回滚性分析的基础。

**★ P7（最危险的一条）**：`assigned_prob` **不在任何一处 UPDATE 里**（实测三处 UPDATE 的列是 resolved_at/outcome/resolve_note、批量审计列、tautology）。**不是因为设计上不许，而是因为还没人写那行代码。** ⇒ 必须把"agent 不得写 assigned_prob"从约定升级为**三重**：写入层只读 + `prediction_actor` 的 CHECK + `process_roles.forbidden`。

**★★ 物理隔离只能靠独立只读 surface DB 文件**

【事实】`process_roles` 4 行的 `enforcement` **全为 `'contract'`**；`gd2-0-accept.cjs:7` 自陈「SQLite 单库单进程没有内核级角色」；`merged-migration-receipt:130` 自陈「只是声明，任何能打开 p1a.db 的进程都不受它约束」；**grep 证实无任何运行时组件读取它**。
⇒ **唯一真实的隔离是 `predictions_public` 视图**（shadow DB 里 predictions/truth_vault 确实 no such table）。**这 1 个文件是整个 agent 沙箱的地基。**

**★★★ 沙箱逃逸（现成的，0.5 人日可堵）**

【事实】`index.cjs:214`：`--` 之后全部 token **原样透传**。【事实】`commands.cjs:57-61`：`WRITE_FLAGS = ['--write','--out','--json',...]`，且注释明写「**CLI 不拦（拦了会改子脚本行为）**」。【事实】实测 **8/10 条 R 档脚本自身有 writeFileSync 调用点**。

⇒ 漏洞：`node p1b/cli 体检 泄漏 -- --md <任意路径>` ⇒ **一条标称"R 档只读"的命令把文件写到任意路径**。
**对人是"我不替你做主"的合理设计；对 agent 是沙箱逃逸。**

**修法（0.5 人日）**：加 `--as-agent` 入口——① 对 tier:R 拒绝透传 WRITE_FLAGS ② 透传路径必须落在 `.scratch/agent/<run_id>/` 前缀下 ③ 每次拒绝落 agent_tool_calls（`allowlist_verdict='block_tier'`）**拒绝本身是数据不是错误** ④ **不动 index.cjs 默认行为**。

## 4. 产品形态

### 4.1 三类用户（各含可证伪假设 + 最小实验）

**① 开发者/团队：要把"我们的口径纪律"接进自己的 LLM 工作流**（唯一有预算的）
- 痛点不是模型不够聪明，是**他们无法证明输出是干净的**——老板/客户/监管问"你怎么知道它没抄答案"，没人答得出
- 最小实验：把 `leak-scan` + `anchor-gate` 包成 GitHub Action，对 10 个公开的 LLM-eval 仓库发 PR
- **判定线：≥2 个 PR 被 merge ⇒ 成立；全部被无视 ⇒ 证伪**
- 成本 4 人日（包装 2 + 触达 2）。**这是 ROI 最高的验证**，因为目标用户已经在用 CI，不需要教育

**② 独立研究者/评测者：要审计一个预测系统**
- 最小实验：做成"喂一个 SQLite 文件给我，我告诉你这套系统哪些读数不可信"的只读工具，发到 arXiv forecasting 板块 + 2 个 Discord
- 判定线：30 天内 ≥1 个外部 PR/issue ⇒ 成立
- **【事实】这是唯一一个用户和作者利益完全一致的画像**——不存在"服务评审者 vs 服务使用者"的取舍

**③ 赌徒/交易员/风控**（排第三，且承认最弱）
- 在 agent 形态下唯一成立的样子不是"算你的强弱"，是**"先告诉你这道题能不能判"**
- 但需要 `no_anchor` 命中率足够高才有价值，**先把命中率做实再谈卖给谁**

### 4.2 两条关键旅程

**旅程 A：外部开发者在自己的 LLM 客户端里接这个 agent**

| 步 | 发生什么 | 底层 |
|---|---|---|
| A0 | MCP 配置加一行（**无需 clone、无需 node_modules、无需 p1a.db**） | — |
| A1 | 他问"我要问『明天下不下雨』这个问题，合规吗？" | — |
| A2 | **agent 第一个动作不是回答，是拆 spec** | `admit_question` |
| A3 | 返回 `{verdict:"no_anchor", why:"kind 未在现役 RESOLVERS 注册", remedy:[候选]}` | anchor-gate 的纯 judge() |
| A4 | **agent 的回答**："不行。你这个问法到期后没有唯一答案可查。而且你写的不是阈值命题（超过多少毫米？）。" | 工具结果转述 |
| A5 | 他改问"改成『明天上海日降水量 ≥ 10mm，2026-09-29』" | 命中 kind |
| A6 | 三问全过 | |
| A7 | **agent 主动给下一步**（本产品独有动作）："合规。顺便：同类题账本里已有 37 条，21 条已结算，观测发生率 21.3%（n=37<30，按纪律**只记方向、不出结论**）。你要押多少？" | get_base_rate |
| A8 | **他说 60%。此刻这个数由人给，不由 agent 给。** | myProb 的 agent 版 |

**A4 那一屏，任何通用 LLM 框架都给不出来。** Claude/Cursor 会说"这个问题可以预测，我帮你估算概率"。本 agent 说"不行，你这个问法到期后没有唯一答案可查"。**前者是概率，后者是事实。这就是全部的差异化。**

**旅程 B：研究者在 CI 里跑，审一批题面**——**全程不开网页**

| 步 | 她看到什么 |
|---|---|
| B0 | CI 3 行配置 |
| B1 | **空集保护**：candidates=[] ⇒ 门禁码 3，**禁止被总结成"未发现问题"** |
| B2 | 三列表：verdict（8 值枚举）/ why / remedy |
| B3 | 七类计数 + 严格口径 vs 候选口径双分母 |
| B4 | 全库泄漏扫描——**这一步她的系统还没有**（没存 meta.cutoff 就查不了） |
| B5 | 三个退出码：0 全过 / 3 有 leak 或空集 / 4 预检失败 |
| B6 | 打开落盘报告对照 PR |

> **纪律类工作的正确交付物是退出码 + 落盘报告，不是界面。CI 里没有鼠标。**

### 4.3 25 个页面逐页裁决（**全部保留，0 删除**）

裁决词汇：**R** 保留主交互 / **o** 只读报告 / **M** 工具承载 + 页面降级为 demo / **F** 冻结（agent 不触碰）

| 裁决 | 页数 | 行数 | 占比 |
|---|---:|---:|---:|
| R 保留主交互 | 4 | 1,536 | 33% |
| o 只读报告 | 7 | 2,283 | 48% |
| M 工具承载 + 页面降级 | 3 | 876 | 19% |
| F 冻结（agent 不触碰） | 4 | 982 | 21% |

**R 的四页**：`NotePage`（人写题面+人押数，唯一起点）、`ResolvePage`（人认账，唯一起点）、`QuestionPage`（逐条核对 agent 干了什么，**防撒谎的唯一界面**）、`HomePage`

**o 的七页**：WhereOff / NegativeResults / Overview / Audit / CalibrationReport / BayesLens / Arena / Calendar —— **"agent 产出结论，界面承载『人要相信它』这一步"**

**M 的三页**：IntakePage / CompilerPage / ——（它们的唯一功能已被工具完整承载，**页面保留为该 tool 的人工回执面**）

**F 的四页**：LivePage / ManagePage / MysticPage / OracleZone
- **玄学显式封禁是保护不是审查**：agent 是会对外说话的东西，让一个 LLM 驱动的产品生成算命断语，等于把"娱乐参考"横幅的法律效力归零

**8 个"死页面"（2,348 行）不是被删，是被映射**——每一个都有对应的 CLI 命令或 HTTP 端点。agent 形态下，页面是落盘件的一种渲染，不是唯一入口。

### 4.4 八条交互反模式（agent 形态特有）

| # | 反模式 | 后果 | 缓解 |
|---|---|---|---|
| **AP1** | **好判决被 LLM 念坏**（no_anchor 被说成"基本靠谱但有小问题"） | **本产品唯一的产品单位是"拒绝"。拒绝一旦被软化，产品就没了。** | verdict 枚举由 MCP 层直出到 UI，**不经 LLM**；散文只允许追加不允许改写枚举 |
| **AP2** | **好问题被 LLM 拒掉**（52 个 kind 里挑错） | 假阴性 ⇒ 用户从此不信任这个闸门 | 返回必须带 `remedy: ["试试这几个已注册的 kind"]` |
| **AP3** | **agent 造 spec** | 账本里出现没人问过的题——**这正是 1994 条的成因** | `admit_question` 与落库**分成两个工具**，后者必须带 `authored_by:"human"` |
| **AP4** | **跨库越权**（工具链有一环能读 truth_vault） | **整个"事前"纪律归零。唯一会毁掉产品根的反模式** | 走 `ATTACH predictions_public`；只读 surface DB |
| **AP5** | **agent 复读坏数字**（p=null 被讲成 0） | **这正是 `QuestionPage.tsx:18` 写下的「null 就是当时没给，绝不显示成 0」** | schema 层把 `p:null` 与 `p:0` 做成两个不同枚举，note 必填 |
| **AP6** | **确认闸被 agent 绕过** | 不可逆写库 | `preflight` 启动时扫描全表，W 档一律拒注册（结构性拒绝） |
| **AP7** | **exit 3 被 LLM 咽掉** | 工具失败 ⇒ 模型重试或编结论 | 工具**永不 throw**，gate_exit 是正常返回字段 |
| **AP8** | **娱乐线泄漏进 agent** | "娱乐参考"横幅是全部免责设计的地基 | preflight 黑名单 `oracle*` |

### 4.5 人在哪里 —— 明确站队

**人保留三件事，agent 一件都不许碰：**

| # | 人的动作 | 为什么 agent 不能做 | 对应件 |
|---|---|---|---|
| 1 | **写题面** | 题面必须由人事前确定，否则"事前"这个词没有意义 | NotePage |
| 2 | **押注** | 整个产品的价值来自"我押了多少 vs 基率多少"。agent 押 = 无人在场 | myProb |
| 3 | **认账** | 真值的价值来自"我事后承认我错了"。agent 认账 = 账本退化成流水 | ResolvePage |

**会不会变成"只有 agent 在用的系统"？会。而且我认为——对纪律引擎这一半是好事。**

> **纪律引擎（agent + engines + evidence + scripts）应该是"只有 agent 在用"的东西，这正是它的正确形态。linter、SAST、provenance checker 没有人的产品经理希望自己的 linter 有个漂亮的 UI。**
>
> **判断账本（NotePage + ResolvePage + QuestionPage + predictions 表）必须永远保留人工界面，而且 agent 越强，它越重要。**

**一句话：人在三个地方——押注时、认账时、以及决定相不相信一份 agent 报告时。这三个位置一个都不能被自动化，不是技术做不到，是自动化之后这个产品就没有存在的意义了。**

### 5.4 定价建议：**$29–49/席位/月**

- 下限锚 LangSmith $39；**建议先定 $29** 打入，绕过"没人知道这是什么"
- 上限受 Confident AI $200/月不限席位约束——**若能证明"替客户省下人工审计时间"，可上探到 $200+/月不限席位**
- **绝不能定 $200+/席位/月**：那要求有品牌、有案例、有销售团队，单人 + AI 代理做不到

**按用量计分的备选（更贴形态）**：参照 Monte Carlo 的 credit 模式 + Context7 的 calls 模式，**"$29/月含 N 次 + 超量 $0.01/次"**。理由：可证明交付价值、不会因用量预测错误亏本。

### 5.5 走「免费开源 + 咨询转化」，但要加一条 MCP 付费层

**四条理由（按权重）**：
1. **购买决策人不是 agent 开发者。** 真正掏钱的是合规/风险负责人——**这类人不会从 npm 上订阅一个陌生 MCP server**，他不会写 MCP client。直接订阅转化率趋近 0。
2. **Context7 的成功条件本项目不满足**：它的买家就是开发者本人。
3. **Apple/Styra 类比指向"被集成件"而非"被直接购买件"**。
4. **MCP 免费层的真正作用是获客，不是收入**——外部 agent 能调用 → 产生使用数据与案例 → 案例转咨询。**这与 CTO 的 ADR-001「C → B」排序完全一致，两份独立分析收敛到同一结论。**

**具体形态**：
- **MCP server 完全免费、全功能、无限制**（含 18 条中可安全暴露的全部）→ 最大化分发与案例产出
- **付费的是"托管版 + 审计导出 + 合规报告生成"**——这一层**无法自助购买，必须人卖**，收入规模受创始人产能限制

### 5.6 合规：三条线红线清单

**线一 · AI 生成合成内容标识（2025-09-01 施行，强制性国标）**
- 🔴 红线 1：agent 生成的任何面向人类文本，**元数据隐式标识必须在生成时写入，不可延后**（agent 输出自动流向用户，事后补标识无法回溯生成时刻）
- 🔴 红线 2：MCP tool 的 description 与返回文本中**不得出现"预测建议/推荐下注/信号"**；返回一律限定为"账本中已结算的历史统计事实"，固定携带 `disclaimer` 字段
- **触发判断**：只返回结构化 JSON 不面向终端用户"发布"→ 不触发；一旦做人类可读报告页/landing page 展示 agent 生成文字 → 触发

**线二 · 彩票/博彩**
- 🔴 红线 3：server **默认 openWorldHint:false**，N 档命令**必须显式确认**（沿用 `commands.cjs:18`），**不允许 agent 自行决定打网**
- 🔴 红线 4：server 侧**强制注入 SSRF 白名单**，禁止任何绕过反爬路径；做成**代码层硬约束**——外部调用者不受 README 约束
- 🔴 红线 5：返回体中任何价格/赔率字段**必须原样标注为"市场共识数据"并附源与时间戳**，禁止加工成"建议"
- **新风险**：MCP server 一旦发布，**调用者是匿名的、不可控的**。现有 CLI 的"薄包装 + 只 spawn"纪律**假定调用者是作者本人**；对外发布后这个假定失效

**线三 · 数据出境（本轮新增）**
- 【事实】真值来自境外 API 是**数据流入**，不是出境，本身不触发评估
- 🔴 红线 6：**默认本地部署，不托管境外**。若提供托管版，**托管区域必须在中国境内**
- 🔴 红线 7：**不要为了做"团队版"往账本塞姓名/邮箱/工号**——一旦塞入，本项目从"个人工具"变成"个人信息处理者"，出境义务与标识义务同时触发。**agent 形态下默认单租户单用户**，多租户留到有真实 B2B 客户时
- 🔴 红线 8：MCP server **默认不记录调用方身份**，只留聚合统计

### 5.7 三层可见性（「保留」是对你说的，「分级」是对市场说的，两者不矛盾）

| 层 | 内容 | 面向 |
|---|---|---|
| **L1 对外首屏** | 8 条最安全的 R 档 + 1 条 W 档演示 + README 首屏 | 陌生人 |
| **L2 完整能力** | 全部 18 条命令 + 完整表格 + 档位图 | 有兴趣的开发者 |
| **L3 内部** | 狼人杀 / 玄学 / Playwright 脚本 / .scratch | 创始人自己 |

**对外命名映射**（现有 5 组是给作者用的，不是给市场用的）：契约→commitment、结算→settle、校准→calibrate、体检→inspect、运维→audit。

**狼人杀与玄学是资产，不是杂质**：它们在"预注册 + 不可篡改 + 自动结算"上与主项目同构——狼人杀是一局有真值、有结算、有校验的对局，**恰恰是"契约化对局"的实验场**。建议对外不列为独立功能，列为"方法论的验证场"，**写进 README 的 Architecture 段，不写进 Features 段**。

**但玄学出现在商业材料里会直接损伤可信度**：一个把 Brier 分数和塔罗牌放在一起的品牌，**卖不进 ISO 42001 预算**。这不是价值判断，是客群匹配判断。

### 5.8 三个候选 slogan

| 候选 | 判定 |
|---|---|
| **A「记录你的判断，然后证明它没有说谎」** | 成立——直击唯一不可被免费品替代的资产（对比 OpenAI 自述 memory 可单独删除、不可承诺）。**减分：不含"AI"、不含"agent"** |
| **B「把判断力做成契约，让任何 agent 都无法替你下结论」** | **成立**——同时命中三条证据：MCP 生态真实存在且官方渠道就位 / Apple acqui-hire 证明判定能力值钱 / 与创始人自陈意图 100% 对齐。**减分：听众窄**——"契约"对合规/采购有强吸引力，对开发者是抽象词。**作 landing page 首句会劝退开发者，作 MCP registry 描述反而合适** |
| **C「51 类取数器，一个能算 Brier 分的账本」** | **建议弃用**——① 已被一个 GitHub 项目用 4 个源证伪 ② **"51 类"是规模指标不是价值指标**，会把叙事从"判断力不可篡改"拉回"我抓了很多数据"，**主动降级定位** ③ 把它拉进 Metaculus/Polymarket 同一条赛道，而对面站着 Radiant 免费 + 20 万级校准数据 |

**推荐：候选 B 作定位主线，候选 A 作价值证明句，候选 C 弃用。**

> **定位（B）**：把判断力做成契约，让任何 agent 都无法替你下结论。
> **证据（A）**：预测入账即冻结，概率由正则机械抽取，结算不可改写——并且可被第三方复算。
> **形态**：一个 18 条命令的 MCP server，**档位即权限**：只读的随便调，写库的必须显式确认。
