## 0. 一句话

把 P1b 薄 CLI 的 18 条命令包成 stdio 上的 MCP 工具；`p1b/mcp/` 全部模块只 spawn 子进程，
**进程自身对 `p1a.db` 零接触**；门禁码（exit 3）走成功通道，不抹平、不冒充崩溃。

**核对带来的一处实现决策（与设计书不同，理由记录在此）**：

设计书 §2.5 原方案把 exit 1 映射成 **JSON-RPC 协议级 error `-32603`**。
本层**不这么做**，改用 `isError:true` ＋ `structuredContent`。理由是规范自己写的 ——
`CallToolResult.isError` 的注释原文：「originate from the tool 的错误 **SHOULD** 在 result 里用
`isError:true` 报，**而不是**协议级 error response，否则 LLM 看不到错误发生过、无法自我纠正」。
协议级 error 会让整条 `tools/call` 失败、模型拿不到 stdout。
同理，**协议级 error 在本层只留一种用法：叫了一个不存在的工具**（`-32602`）——那是本层没满足调用。

**一处未做**：`ttlMs` 本层**不填**。`ListToolsResult extends CacheableResult` 且 `ttlMs` 必填，
但本层 18 条工具表是编译期常量、进程生命周期内不变，填 `0`（永不过期）语义上正确，
却会让响应形状绑死在一个将来可能改的字段上。**这是本层对规范的一处已知偏离**，
接真实客户端前应补 `ttlMs: 0`。

## 3. 三条最要紧的裁决

### 3.1 exit 3 走成功通道（本层唯一不能做错的地方）

```
exit 3  ⇒  isError 缺席（即 false）  +  verdict.gate='FAIL'  +  do_not_retry:true
```

`isError:true` 会让客户端把它读成「调用失败，换个参数重试」。
而 `门禁 锚点` 的 exit 3 是**一次成功的裁决** —— 程序正确地得出了「候选 0 条，
不许被读成通过」（`p1b/scripts/anchor-gate.cjs:209`）。标成失败 = 把结论从输出里删掉。

**★ exit 3 的含义随命令而变，本层逐条登记在 `toolTable.EXIT3`**，不笼统映射：

| 工具 | kind | 含义 | 出处 |
|---|---|---|---|
| `p1b_audit_anchor_gate` | `VERDICT` | 候选 0 条（防空集被读成通过） | `anchor-gate.cjs:209` |
| `p1b_doctor_file_map` | `GUARD` | 生成物含 NUL（防二进制泄漏进仓库） | `file-map.cjs:185` |
| `p1b_backup_restore_drill` | `VERDICT` | 这份备份不可用 | `restore-drill.cjs:246` |
| `p1b_audit_prereg_freeze` | **`CRASH`** | ★**解析异常 —— 这一次是真崩溃，不是裁决** | `prereg-freeze.cjs:66` |

最后一行是「同一个码，一个是结论一个是故障」的实例。
把它笼统映射成「门禁 FAIL」就是在造第三种读法（`p1b/skill/SKILL.md:272`：只写「exit 3」等于没写）。

### 3.2 W 档永不带 `--确认`，且**不靠新代码保证**

`p1b/cli/index.cjs` 的确认闸在 **spawn 之前** return，子进程一次都不起。
⇒ 「永不带 `--确认`」**不需要任何新代码**：只要 argv 拼装**是白名单式的**就成立。
本层 `buildArgv` 只从登记过的 4 个位置参数键里取值，调用方塞进来的 `--确认` / `out` /
`extra` 全部进不了命令行（`mcp-no-ledger-write.test.cjs` 最后一条用例机械验证了这一点）。
`cliBridge` 另有一道**拼完再扫**的保险，命中即抛。

W 档与 `备份 异地` 拿到的返回是 `isError:false` ＋ `verdict.gate='NOT_CONFIRMED'`
＋ `will_execute`（完整命令行）—— 模型拿到预览，人拿着同一段预览去终端执行。**同一道闸。**

### 3.3 exit 2 必须再分一次

CLI 的 `EXIT.USAGE` 有两个来源，语义相反：`index.cjs:219`（缺位置参数 = **用法错**）
与 `:245`（确认闸 = **一道设计好的闸在正常工作**）。都是码 2。
本层按 CLI 自己打印的那行确认标记（`:242`）嗅探分开，**不改 CLI、不猜**。
宁可误判成用法错（模型重试一次），也不能误判成闸放行（模型以为要写库了）。

## 4. `p1b/cli/index.cjs` 的唯一改动

抽出 `runChild(scriptPath, childArgs, stdio)`，`stdio` 缺省 = 老的 `['ignore','inherit','inherit']`。
`main()` 里的调用点**显式**传同一组。三条性质由 `mcp-cli-parity.test.cjs` ④机械验证：

1. 缺省 stdio 就是老的 inherit；
2. `main()` 的调用点显式传 inherit（不靠缺省 —— 靠缺省等于未来改缺省值会静默变更行为）；
3. 全文件 `spawnSync(` 只剩 `runChild` 内部那一处。

**为什么不把 stdio 做成 `main()` 的参数**：`main()` 的返回码、确认闸、位置参数分流、outDir 生成顺序
全都在那一条语句之前，任何签名改动都会把「MCP 调用 = 人工调用」这条等式变成两条路径。

**`p1b/cli/commands.cjs` 一行未改**（设计书 §2.1 原方案是 +4 行给 4 个 `pos` 加 ASCII key/type）。
两个理由：① 本批的授权写入面不含 `commands.cjs`；② ASCII 工具名是 **MCP 侧的传输关切**，
塞进人类 CLI 的单一真源里是污染。代价是要自己断言 18 条对得上 ——
`toolTable.assertCoverage()` 在**模块加载时**双向对表，对不上**拒绝启动 server**。
事后回归锁（`mcp-golden` ①②）发现晚，启动即拒是当场发现。

## 6. ★ 一处必须更正的前提：验收项 ① 的字面形式不成立

验收写的是「`体检 看板` 的 stdout **sha256 逐位不变**」。
**实测：未改动的 CLI 自己就不是逐位稳定的。** 同一条命令连跑两次：

```
stock run1  c416f96d8aa59fa8e9a278e2d7cc91bf7d0e4635c8b6931dd3a1db291c3118ce
stock run2  3e4a16a5160642600c51e757a41eae3a999958d250eccb47be8404e09a2e4dec
```

差的只有第一行：`推演沙盘 · 一页看板（<ISO 时间戳>）`。
`门禁 契约`（`…:719Z`）、`读数 G2门`（`生成 … | 库 …`）同样带时间戳；
`体检 泄漏`、`体检 跑批` 等则稳定。

⇒ **这不是 MCP 改了它，是这条命令每次都重新报时。** sha256 判据对这类命令在数学上不可能成立。
设计书第 689 行早已把这条列为未知（「12 条无 --json 命令的输出稳定性」），
本轮把它**从未知变成实测结论**，并给出两条可用的判据（`mcp-cli-parity.test.cjs` ②③）：

* **原始 sha256**：给输出本来就稳定的命令（`体检 泄漏`）做**逐字节**比对 —— 更强的形式；
* **归一化 sha256**：抹掉 ISO 时间戳后比对，覆盖全部命令；并额外断言
  「归一化后两次直跑即相同」，确保归一化没有把实质差异一起洗掉。

`mcp-cli-parity.test.cjs` ① 把「未改动 CLI 本身不稳定」这件事本身**写成一条断言** ——
哪天 `体检 看板` 不再打时间戳了，这条会红，提醒复核另外两条判据的依据是否还成立。

## 8. 本层的已知边界（如实列，不粉饰）

1. **`ttlMs` 未填**（见 §2）：`ListToolsResult` 要求它。接真实客户端前补 `ttlMs: 0`。
2. **18 条全部只给 `content[0].text`，没有 `structuredContent` 里的业务数据**。
   根因实测在 `commands.cjs`：18 条的 `build()` **只返回 argv 字符串数组**，
   且 CLI 用 `stdio:'inherit'` 不捕获子进程输出 ⇒ 父进程拿不到数据，只有文本。
   想要原生 JSON 需另开一条路（给子脚本加 `--json` 注入层，或 M2 的纯函数工具）。
   本层的 `structuredContent` 只承载**退出码裁决**（本层能确知的部分），不假装承载业务读数。
3. **R 档透传写盘 flag 的攻击面未封**：`index.cjs` 会把 `--` 之后的 token 原样透传，
   而子脚本认 8 个写盘 flag。**本层没有 `--` 透传能力**（argv 白名单拼装），
   所以从 MCP 这条路进不来；但**从终端进来依旧能进** —— 那是既有 CLI 的既有行为，
   本轮不改（改了会改变 `node p1b/cli` 行为，违反第一纪律）。
   彻底封堵需要 `commands.cjs` 加 `--as-agent` 入口，**不在本轮范围内**。
4. **无分页**（18 条一次返回完）。
5. **无 `resources` / `prompts`**：本层只做 tools。设计书 M2 的 3 个 Resources 未做。
6. **`kind_table` 偶发 exit 1 未定位**（见 §7）。

## 10. 合规

* **禁词**：面向模型的文案（18 条 description/title/inputSchema ＋ `server/discover` 的
  `instructions` ＋ 整份 `tools/list` 载荷）**零「预测」**。
  18 条描述全部在 `toolTable.cjs` **重写**、**不转发** `commands.cjs` 的 `cmd.desc`
  ——因为 `读数 分层` 那条的原 desc 含该词。
  ★子进程 stdout **逐位透传**，其中该有的字一个都不改（改了就是第二套口径）。
  由 `mcp-golden.test.cjs` ④机械检查。
* **`disclaimer` 字段**：每条工具返回的 `structuredContent` 固定携带
  「本工具只返回账本中已结算的历史统计事实，不构成任何对未来结果的判断或建议」。
* **默认不联网**：唯一的 net 工具可被 `P1B_MCP_ALLOW_NET=0` 整体下线（18 → 17）。
  默认开着是因为它结构上就发不出网（确认闸在 spawn 之前 return）。
* **不记录调用方身份、不托管**：本层零持久化，只在内存里跑一次 spawn。
