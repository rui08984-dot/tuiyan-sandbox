## 0. 三句话版本（背下来就够用）

1. **不能说**「L1 的 Brier 是 0」——那是拿同一张表既当真值又当答案，不是能力。
2. **不能说**「L6 的 Brier 是 0.1755」——同一族的问题，而且判词层在时间上根本不合法。
3. **不能说**「我们把 Brier 压低了 0.1587」——那个数是**公开数值预报打败气候基线**的教科书差距，
   而被它打败的那个基线臂，本来就是我们自己的。

## 1. 逐个数字的完整口径与出处

### ① L1 Brier = 0.0000 —— 循环论证，**删除**

**出处（逐位可查）**

| 项 | 位置 | 值 |
|---|---|---|
| Brier | `p1b/sim/out/stage4-run-five-layers-20260926.json:519` | `"brier_engine": 0` |
| 命中率 | 同文件 `:534` | `"accuracy": 1` |
| 样本量 | 同文件 `:498` | `"scored_n": 180` |
| 分域块（同一数） | 同文件 `:73` / `:79` | `"layer": "L1"` / `"brier_engine": 0` |
| 对照基线 | 同文件 `:80` | `"brier_const_half": 0.25` |

**为什么它必然是 0（机制，不是巧合）**

- L1 引擎的出参写死是 0/1：`p1b/src/engines/l1_proc.js:97` —— `{ value: value, p: value }`。
- `p` 的来源是**该局记录本身**。例：规则① `first_night_peace`
  （`p1b/src/engines/l1_proc.js:16`）的口径就是「day=1 无 type=death」；
  抽一条真实题面是「本局首夜平安（无人死亡）」，`evidence` 只有一个事件 id（`[30]`）。
- 引擎喂进去的就是那张表：`p1b/scripts/stage4-run.cjs:157`
  `procCalc({ ..., events: eventsOf(r.game_id), claims: claimsOf(r.game_id), ... })`。
- 命题本身（「首夜平安」）与真值（「首夜有没有 death 事件」）是**同一件事**，
  于是 `p` 与 `y` 逐行相等，**Brier ≡ 0、accuracy ≡ 1 是构造出来的，不是测出来的**。

> 一击即破的一句话：*「这 180 道题的真值和答案都从 events 表读，引擎算的是自己刚写进去的东西。
> 要证明它，请把真值换成 events 表以外的东西再算一次。」*

**处置**：对外材料**删除**该数字。若必须谈 L1，只能说「L1 是决定论层，n=180，
它的读数是程序复算的正确率，与概率层的 Brier 不同量纲，**不可与 L2/L3/L6 并列比较**」。

### ② L6 = 0.1755 —— 判词层泄漏，**删除**（并修正评审报告的构成说法）

**出处（逐位可查）**

| 项 | 位置 | 值 |
|---|---|---|
| Brier | `p1b/sim/out/stage4-run-five-layers-20260926.json:735` | `"brier_engine": 0.17545467076550367` |
| 分域块（同一数） | 同文件 `:440` / `:446` | `"layer": "L6"` / 同值 |
| 样本量 | 同文件 `:710` / `:714` | `ledger_rows` / `scored_n` 均 270 |

**⚠ 本次核实修正了评审报告的一处构成错误（`docs/specs/推演沙盘-投资级评审报告-20260928.md:572`）**

评审报告写「L6 的 0.1755 来自泄漏臂（v1_evidence 0.1525 / v2_skeptical 0.2600 /
v3_baserate 0.2507）」。**三个臂的数一字不差，但归属说错了**：

- 那三个数复现为 **「全体（不限层）判词池化 Brier」**，不是 L6 臂：
  `v1_evidence n=1727 → 0.1525` / `v2_skeptical n=1710 → 0.2600` / `v3_baserate n=1716 → 0.2507`。
- **L6 单层**的同口径数是 `0.1649 / 0.2696 / 0.2554`（n≈1050/变体）。
- 且 `(0.1525+0.2600+0.2507)/3 = 0.2211 ≠ 0.1755` ⇒ **这三个臂在算术上根本不构成 0.1755**。

**准确的表述应是**：0.1755 与 L1 的 0.0000 **是同一族的读数——都是引擎 Brier**
（`brier_engine`），而 ① 那一族的口径问题（程序自证）同样适用；
**判词层另有一组独立且更严重的问题**（下列时间证据），两组数不要互相解释。

**判词层时间不合法的证据（可复现，只读）**

- 评审的「平均 1.547 天」**精确复现**：
  `AVG(julianday(verdicts.created_at) − julianday(predictions.resolved_at))` = **1.5465 天，n=5156**。
- **比它更强的一条（本次新测）**：已结算题的判词中，
  `verdicts.created_at > predictions.resolved_at` 的比例 = **5156/5156 = 100.0%**。
  即**没有一条**判词是在结算之前写的。
- 判词正文直接引用终局事件：`verdicts` 表 5156 行中 **123 行（2.4%）**含
  「终局 / 游戏结束 / 胜利 / 获胜」措辞。实例：
  `.scratch/forecast-debate/verdicts-archive-rb-pre-20260912.json:11`
  判词正文原话：「**#38 为系统级终局事件，直接宣告狼人胜利**」。

> 一击即破的一句话：*「你们的判词是在结果出来之后写的，而且直接引用了宣布胜负的那个事件。
> 用它算出来的任何分数，都是在读答案。」*

**处置**：对外材料**删除** 0.1755，也**不要**把 0.1525/0.2600/0.2507 当作成绩引用
（它们既非 L6、又是泄漏臂）。判词层目前**没有任何可对外引用的质量读数**。

### ③ Δ = 0.1587 CI[0.1221, 0.1901] —— 属于 Open-Meteo，不属于本项目，**必须加口径标注**

**出处（逐位可查）**

| 项 | 位置 | 值 |
|---|---|---|
| Δ 精确值 | `p1b/sim/out/stage5-forecast-signal-20260915.json:139` | `"delta_all": 0.15871992353643954` |
| CI / 两臂 / n | `p1b/sim/out/stage5-forecast-signal-20260915.out:3` | `n=186 base=0.2644 signal=0.1057 Δ=0.1587 CI=[0.1221,0.1901] PASS` |
| 配对题数 | 同 JSON `:17` | `"n_paired": 93` |
| 四城 | 同 JSON `:39–70`（coverage 的四个键） | `31.23,121.47` / `39.9,116.41` / `23.13,113.26` / `30.57,104.07` |
| 判据全 PASS | 同 `.out:10` | Δ≥0.02 ∧ CI 下界>0 ／ n≥30 ／ 4 城方向一致 ／ lead 单调 |

**完整口径（一句话）**

> **Δ = 0.1587 是「Open-Meteo 的 1/3 日数值预报技巧」相对「本项目账本自带的气候基率」的优势，
> 样本 n=93 对 × 2 lead、中国 4 城日最高气温、**追溯回放**（题目的成熟日是 2024 年的历史日期，
> 预报取自 previous-runs 归档）。**

**为什么它不属于本项目的预测能力（三条可查）**

1. **signal 臂是外部服务**：`p1b/scripts/stage5-forecast-signal.cjs:84-86` 请求
   `https://previous-runs-api.open-meteo.com/v1/forecast?...&hourly=temperature_2m_previous_day1,temperature_2m_previous_day3`。
   `previous-runs` 是**预报归档**，取的是当年真实发出的预报。
2. **量纲是日最高气温**：`p1b/scripts/stage5-forecast-signal.cjs:108-117`
   从 2 米气温逐日取 `max` 聚合而成。
3. **base 臂是我们自己的**：`p1b/src/evidence/stage5Pool.js:97-103`
   的 `parseBaseRate` 读的是账本行内 `evidence.baseRate.p` / `evidence.baseRateNote` 的「占 x%」。
   ⇒ **被 0.1587 打败的那个臂，就是本项目的基线产出。**
   这个 Δ 衡量的是「公开数值预报 > 气候基线」这条教科书差距，**不是**本项目做了什么。

> 一击即破的一句话：*「把 Open-Meteo 的预报和气候平均值比，
> 谁都能拿到这个 0.16。这跟你们的系统有什么关系？」*

**处置**：若必须提到，**只能**写成
「阶段 5 前瞻信号 Δ=0.1587 CI[0.1221,0.1901]（n=93 对、4 城、**Open-Meteo 数值预报 vs
本项目自带气候基率**，追溯回放）」。**禁止**简写成「我们的 Brier 改善了 0.1587」。

**未复现项（如实记）**：我没有复算 `base=0.2644` 这个具体值——它来自冻结名册的 105 道题；
我抽样 400 行账本基率得均值 0.4502，但那不是同一人群（全体层 vs 冻结名册），不构成证据。
0.2644 的权威出处仍是上面那份 `.out:3`。

## 2. 对照表：可以说什么 / 不可以说什么

### ✅ 可以说（附口径）

1. 「账本里有 **1994** 道题、**1700** 道已结算，全部由脚本批量灌入，**没有一条是真人手写**。」
   —— 这是实话，且说完会加分（它同时说明你在诚实盘点）。
2. 「在 1700 道已结算题上，整体 Brier = **0.2259**，95% CI [0.2194, 0.2324]，
   明显优于『永远报 50%』的 0.2500。」
3. 「我们把 n<30 的格一律不给结论，只记方向。」——展示的是纪律，不是数字。
4. 「我们的读数件全部落盘、可复现、纯只读。」——可当场打开 `p1b/sim/out/` 给人看。
5. 「阶段 5 有一个前瞻信号 Δ=0.1587，但**它衡量的是 Open-Meteo 预报技巧相对气候基线的优势，
   不是我们的能力**。」（自己先说，比被问出来强十倍。）

### ❌ 不可以说

| 不能说 | 为什么 | 出处 |
|---|---|---|
| 「L1 Brier = 0.0000」/「我们有一层做到了零误差」 | 程序自证，p 与 y 逐行相等是构造出来的 | ① |
| 「L6 Brier = 0.1755」 | 同一族口径问题；判词层 100% 在结算后生成 | ② |
| 「三条判词臂 0.1525 / 0.2600 / 0.2507」 | 既不是 L6 的数，又是泄漏臂 | ② |
| 「我们把 Brier 改善了 0.1587」 | 是 Open-Meteo vs 气候基线，被打败的臂是我们自己 | ③ |
| 任何**不带 n 的 Brier** | n<30 必须标注（项目既有铁律） | `p1b/src/routes/auditKpi.js:81` |
| 把 L1 与 L2/L3/L6 的 Brier 放同一张表比较 | 不同量纲（错误率 vs 概率分） | `p1b/src/engines/l1_proc.js:5-6` |
| 「判词质量已验证」 | 判词层目前**没有任何**可对外引用的质量读数 | ② |

## 3. 被质询时的标准回答

> **Q：你们最大的成绩数字是什么？**
>
> 「1700 道已结算题，整体 Brier 0.2259，95% CI [0.2194, 0.2324]。
> 我不报 L1 那个 0.0000——那 180 道题的真值和答案来自同一张表，零误差是构造出来的。
> 我也不报 L6 那个 0.1755——我们的判词是在结算之后才写的，其中 100% 晚于结算时刻，

答完这一段，对方基本不会再追：**主动交出坏数字，比守住好数字更让人相信剩下的每一个。**

## 4. 本次核实做了什么、没做什么

**做了**

- 三个数字**逐位定位到 file:line**，含复现命令。
- 复现了评审的「1.547 天」：`1.5465 天 / n=5156`。
- 复现了三条判词臂的数值，但**发现归属是全体层不是 L6**（见 ② 的修正框）。
- 新测两条评审未给的数据：判词 100% 晚于结算（5156/5156）、终局措辞 2.4%（123/5156）。
- 算出一条可对外引用的干净读数（0.2259 / CI）。

**没做（不得当作已核实）**

- 没有复算 `base=0.2644`（冻结名册人群不同）。
- 没有复算评审的「纯随机理论值 0.2300」基线。

  （评审 `:570`、`:571`）——本文件不对其真伪表态。

## 5. 维护纪律

- 本页每条 file:line **随代码漂移**。改动 `p1b/sim/out/stage4-*.json` 或
  `stage5-forecast-signal-*.json` 重新生成后，**本页数字即失效**，须重新核实。
- 新增对外数字前先问三句：
  ① 真值和答案是不是同一个来源？② 这个数是不是在答案出来之后算的？
  ③ 这个数里有几成是外部服务给的？
  三问有任何一条「是」，就**不能**按成绩报。
