## 十一 · 修订：历史回填（backfill）模式【2026-09-12 队长追加，因加速计划】

> 触发：用户令「大幅加速…最好 2 天，最晚 3-4 天」。本文 §一~§八 全部基于**实时口径**（对未来出题→等未来到来），导致 22 条 pending 全卡在真实时点未到（队长实测 corpus-resolve：pending 22 / resolved 0 / fetch-fail 0，非故障）。**本次追加历史回填模式，不改 §一~§八 任何既有结论，只增补一条并行路径。**

### 11.1 历史数据可用性（队长实测，2026-09-12）

| 源 | 历史窗口 | 可用量 | 批次/日实测 |
|---|---|---|---|
| Open-Meteo archive | 2015-01-01~2024-12-31 | **3653/3653 天全有值** | 2024-09-15 上海 max=32℃ 秒回 |
| cwl 双色球 | 近 30 期 | **30 期已开奖**（最新 2026105：red 02,04,13,14,15,30 / blue 08） | findDrawNotice?issueCount=30 直给 |
| DBnomics ECB/EXR/M.USD.EUR.SP00.A | 1999-01→2026-08 | **332 个月值** | 全序列实抓 |

### 11.2 与实时模式的差异（逐条对照）

| 维度 | 实时模式（§八 Top1-3） | **历史回填模式（本节）** |
|---|---|---|
| 题面时点 | 未来（T+1 / 下月 / 未开奖） | 过去（2015-2024 / 已开奖期） |
| cutoff | ingest 时点（真实今天） | **事件发生前一天**（问 09-15 天气→cutoff=09-14T23:59+08:00） |
| 真值可得性 | 需等待 | **立即可得**（archive 已入库） |
| resolve 延迟 | T+1 ~ 2.5 个月 | **零**（灌完即解） |
| 主要用途 | G2「连续 2 月吞吐」 | **存量池厚度 / 可判定率 / 校准曲线样本** |

### 11.3 质量红线（四条，与实时模式同严，加速不降标准）

1. **Q0-2 cutoff 严格早于事件**：backfill 题 cutoff 必须=事件前一天并在 statement 写明。**禁止用「今天」当 cutoff 问历史事件**（=泄漏，同 §〇 拒收门）。
2. **Q0-3 基率落在 (0.15, 0.85)**：每个（源×城市×月×阈值）组合先算历史基率，越界不产题。**已实测反例：上海 9 月 >35℃ 基率 0.01（3/300 天）→ 拒收**；故**禁止一套阈值灌十年**，须按城市/月份逐组合标定（照 §6.4 阈值重标定纪律）。
3. **prob = 该组合历史基率**（严格比较口径，脚本内现算），非拍脑袋。
4. **诚实标注**：statement 前缀 `【backfill】`，evidence[0].note 注明批次；引用其结论恒挂「含历史回填样本，非实时预测能力」。

### 11.4 与 G2 判据的衔接（**关键，见审计器 design §4.1 修订 R3**）

- **可判定率 / 判据争议率：计入**。
- **月 resolve 吞吐：不计入「连续 2 个月」达标判定**——该指标测持续产出能力，一次性回填不构成能力证据。月报须分列 realtime / backfill 两窗。
- **单批上限**：≤ 该 layer 现有题量 3 倍且总量 ≤500，超出需重新预注册。
- **L5 Goodhart 配额**（§6.1#5「单一 layer 月占比 ≤60%」）：**backfill 与 realtime 双窗分别独立计算**，禁止跨窗稀释。

### 11.5 执行件

脚本=p1b/scripts/corpus-backfill.cjs（默认 dry-run，--confirm 写库）；报告=p1b/sim/out/corpus-backfill.out；排程与红线详见 docs/specs/语料库历史回填-加速计划-20260912.md。
