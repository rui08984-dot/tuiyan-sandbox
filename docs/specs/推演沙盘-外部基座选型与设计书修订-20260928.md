## 1. 核心发现：官方已经给出了分工线

【事实】Anthropic 官方对照（skills-explained）：

> "MCP connects Claude to data; **Skills teach Claude what to do with that data.**"

| | Skills | Subagents | MCP |
|---|---|---|---|
| 提供什么 | **流程知识** | 任务委派 | **工具连接** |
| 何时加载 | 按需（动态） | 调用时 | 始终可用 |
| 最适合 | **专业能力** | 专项任务 | 数据访问 |

【事实】一个更好用的判定法（Developers Digest）：

> "Ask: does this thing change when the world changes, or when our process changes?
> Your ticket system's current open issues change when the world changes. **That is MCP.**
> Your team's rules for triaging a ticket change when your process changes. **That is a Skill.**"

**套到你身上：**

| 你的东西 | 随什么变 | 归属 |
|---|---|---|
| 判定器 / 权限记号 R·F·W·N / 门禁规则 / 「什么问题不能问」/ 六层判据 / n<30 纪律 | 随**流程**变 | **Skill** |
| 「当前账本里有什么」/「这条记录现在什么状态」/「这道题到期了没」 | 随**世界**变 | **MCP tool** |
| 18 条 CLI 命令表 + 544 行 | 两者都有 | **唯一真源，两个都投影它** |

**⇒ 你的资产大约 90% 是流程知识，天然属于 Skill 的领地。**

## 2. Context7 类比为什么只有 3/10

【事实】当日 live pull：upstash/context7 **62,491 stars** / 3,034 forks；@upstash/context7-mcp 近 30 天 **3,278,546** 下载；ctx7（CLI）145,061。

【事实】**它自己已经是双模**，README 原文：

> *Works in two modes:*
> - **CLI + Skills** — installs a skill that guides your agent to fetch docs using ctx7 CLI commands (**no MCP required**)
> - **MCP** — registers a Context7 MCP server

**⇒ 连 MCP 的标杆产品都已经把 CLI + Skill 当作一等公民。这是这条路被真金白银验证过的最强信号。**

【推断】类比逐条拆解：

| 维度 | Context7 | 本项目 | 像不像 |
|---|---|---|---|
| 能力类型 | **检索型**（答案在外部，必须运行时拉） | **判定型**（答案就是自己的知识） | ❌ 完全不同 |
| 护城河 | 可免费无限供给的公共语料 | 不可从公共语料重建的判据 | ❌ 完全不同 |
| 免费额度意义 | **有意义**（成本真实，需限流） | **无意义**（纯函数、零网络、成本≈0） | ❌ 反向 |
| CLI+Skill 双模 | 已是 | CLI 已有、命令表纯数据 | ✅ 像 |
| MCP 是漏斗不是产品 | 验证成立 | **未验证**（你没有后端资产） | ⚠️ 你是要自己造那个后端资产 |

**⚠️ 一条必须加的警告**：Context7 的 npm 下载量在 **2026-04 见顶 4,565,449，2026-09 回落到 2,701,425（26 天）**——但 **MCP 客户端会自动更新/重装同一个包，npm 下载量严重放大重复计数，不能当用户数用。**

**⇒ 结论：形态可以借鉴，商业结构不能照抄。** 照抄会死——它的免费额度是因为有 Upstash 补贴；你的纯函数 server 免费无限调用**是最优策略**（成本为零，限流只会赶走用户）。

## 3. 修订后的执行顺序（本文最重要的一节）

    第 1 天    写 SKILL.md（零依赖、零协议债、已列入 46 个客户端官方 showcase）
               └─ references/ 用官方示例同款命名：finance.md / legal.md
                  → 你这里就是 forecast.md / gate.md / leak.md / dueof.md
    第 2–4 天  手写 stdio MCP 适配层（可随时扔掉）
    第 1 周    发 npm 包 + 提官方 registry + 写 llms.txt + README
    第 2 周起  建付费资产：团队策略 / 私有账本 / 审计留痕导出
    持续       MCP 层可弃；Skill 层与判定器为唯一真源

### 为什么 SKILL.md 排第一

【事实】**Agent Skills 规范已从 Anthropic 仓库迁到中立站点 agentskills.io**。anthropics/skills 的 spec 文件现在只写一句指向它。**这是刻意中立化**（类比 MCP 从 Anthropic 迁到 Linux Foundation）。

【事实】格式极简：目录 + SKILL.md（必需：YAML frontmatter + Markdown 指令）+ scripts/ references/ assets/（均可选）

【事实】**渐进披露三档**：
1. **Discovery** — 启动只加载 name + description，**约 100 tokens**
2. **Activation** — 命中时加载完整正文，**建议 < 5000 tokens / < 500 行**
3. **Execution** — scripts/references/assets 按需

【事实】**客户端覆盖 46 个**（agentskills.io/clients）：Junie、Gemini CLI、OpenCode、OpenHands、Cursor、**GitHub Copilot、VS Code、Claude Code、Claude、ChatGPT & Codex**、Letta、Goose、Roo Code、Cline 系、Spring AI、Snowflake Cortex Code、Databricks Genie Code、Factory、TRAE、Kiro、Tabnine、Pulumi Neo、Deep Code、Autohand、Mistral AI Vibe 等。

【事实】**references/ 的官方示例直接点名领域文件**："Domain-specific files ( finance.md, legal.md, etc. )"
**⇒ 这一条对你的项目是直接的模板命中。**

【推断】**你的 Skill 正文该写什么**（这是第 1 天唯一要决定的事）：
- 权限记号 R·F·W·N 的含义，以及 **W 档必须由人类在终端执行**
- **退出码 3 = 门禁不过，且这是判定结果不是崩溃，agent 绝不能重试**
- **「未覆盖必须显式计数」——不能断言「没有泄漏」而不同时报 unverifiable 数量**
- **n<30 只记方向不出结论；p=null 绝不显示成 0**
- 什么题不能问（Q0 三问的通俗版）
- 每类题该怎么写（题面 + cutoff + 阈值 + 真值锚）

**估算：SKILL.md 正文 300–400 行（正好在 500 行上限内），references 4 个文件各 100–200 行。第 1 天完全够。**

## 4. R2 修订：MCP 规范已变，405 行要上修

【事实】**MCP 规范当前修订版 2026-07-28**，相对早期版本是**破坏性变更**：

**移除**：initialize / notifications/initialized 握手、Mcp-Session-Id、protocol 级 session、ping、logging/setLevel、notifications/roots/list_changed、SSE 断流续传

**新增（强制）**：server/discover（SEP-2575，**MUST 实现**）、所有结果必带 resultType、MRTR（InputRequiredResult）、subscriptions/listen、ttlMs/cacheScope、Streamable HTTP 必带 Mcp-Method/Mcp-Name 头

【事实】官方给了缓冲："Clients MUST treat results from earlier-protocol servers that omit the field as 'complete'"，且 deprecation policy 承诺**至少 12 个月**窗口。

【事实】**MCP 18 个月里做了两次破坏性变更**（2025-03-26 废弃 HTTP+SSE 引入 Streamable HTTP；2026-07-28 上述）。

**⇒ 对设计书 §1.2/§1.3 的修订：**

| 原估 | 修订后 |
|---|---|
| 「只需实现 5 个方法」 | **initialize/ping 已被移除；须实现 server/discover（强制）+ tools/list（必须确定性顺序、结果带 ttlMs/cacheScope/resultType）+ tools/call + _meta 协议版本回写** |
| 405 行（techdd 估，含 CLI 适配层） | 协议部分约 **250–400 行**（独立估算）+ CLI 适配层 85 行 + exitMap 60 行 |
| 「M0 第 0 步：人工拉取 schema 核对」 | **从可选项升级为必做项**——原估算基于旧规范，不核对就会写错 |

【事实】另一个长期风险信号：官方 roadmap 有一条 **"HTTP-native transport unification"**，原文提到要覆盖 "including local servers speaking Streamable HTTP over stdio"。
**⇒ 手写 stdio-only 迟早要再实现一次 HTTP。** 这是手写路线必须接受的长期账。

### 官方 SDK 的代价（实测，比设计书估的更极端）

【事实】@modelcontextprotocol/sdk@1.30.1 有 **16 个直接依赖**：ajv、zod、cors、hono、jose、express、raw-body、ajv-formats、cross-spawn、eventsource、content-type、pkce-challenge、@hono/node-server、json-schema-typed、eventsource-parser、express-rate-limit、zod-to-json-schema。

【事实】**对整个依赖图做 BFS 闭包遍历 = 89 个包（含 SDK 自身），即新增 88 个包。**

【推断】其中对纯 stdio server **完全是死重**的：express 全家桶（约 30 个包）、jose（OAuth/JWT）、ajv + ajv-formats + json-schema-traverse、pkce-challenge、cross-spawn、eventsource。

**⇒ 装官方 SDK = 直接违反零依赖铁律，且其中大部分是你 stdio server 永远执行不到的死代码。这验证了手写的决定。**

**裁决（不变，但理由要换）**：手写。决定性理由不是「省 2–3 人日」，是 **+88 个依赖直接违反铁律**；代价是**协议债自己扛（约 0.5–1 人日/次 breaking change）**。两边都要付钱，只是币种不同。

## 5. 三处补强（不推翻，但必须加进设计书）

### B1. ★ stdio 传输是**安全优势**，不是将就

【事实】2026-09 的一份威胁分析记录了三天内三份 advisory 的共同模式：
- **2026-09-11** PyPI mysql-mcp-server —— SSE 传输**既不校验 Host 也不校验 Origin**，默认绑 **0.0.0.0**，**没有任何路由要求认证**
- **2026-09-15** npm @zereight/mcp-gitlab —— 本地 Streamable HTTP 端点 **DNS rebinding 可达** + 出站请求 **SSRF**

【事实】原文："The specification requires Streamable HTTP servers to validate the Origin header ... at the **MUST** level, and it names DNS rebinding attacks directly as the reason. **The official SDKs include this protection, but it is off by default at the transport level.**"

**⇒ 对本项目的直接含义：选 stdio 反而免费绕开了上面全部三个漏洞类别**（无监听端口 ⇒ 无 Origin/DNS rebinding 面；判定器零网络 ⇒ 无 SSRF 面）。

**这一条比设计书里「不新增网络暴露面」的理由强得多**——它不是「少一个面」，是**你刚修完 P0-2，而这三个漏洞类别正是 P0-2 的同类**。

### B2. ★ 分发层的结局：Smithery 被收购

【事实】**Smithery —— 最大的 MCP registry + 托管平台，2026-08-05 被 Arcade.dev 收购**。联合创始人加入 Arcade。公告里 Arcade 自己说："our ToolBench benchmark shows **growth has outpaced quality**"，并把叙事从「agent 的新互联网」拉回**「企业治理」**。

**⇒ 两条结论**：
1. **做分发层的没跑出来**。Smithery 演示了这条路的确切结局——被并进执行/治理层。
2. **把 server 托管在 Smithery/Arcade 这类平台 = 把托管权交出去**。这是设计书 §5.6 之外的第二条锁定风险。

【事实】JS/npm 同期：zod 1,068,834,557｜@modelcontextprotocol/sdk 204,541,524｜@anthropic-ai/sdk 148,400,536｜@anthropic-ai/claude-code 52,821,260｜@langchain/langgraph 12,375,862｜@openai/agents 6,557,236｜@mastra/core 5,868,462｜crewai（占位包）274

**⇒ 对你的意义：你的判定器是纯函数、零网络，你不需要编排、不需要 LLM 客户端、不需要多 agent。引入任何框架都是纯负债。**

### B4. 「不存在垂直领域 agent 开源基座，而且不应该去找」

【事实】2026 年 MCP 市场实际有四种架构模式（Proxy/wrapper、Workflow/action、Unified-API、Warehouse-first），**没有一种是「垂直领域 agent 基座」**——它们都是**连接层**的形态。

【推断】**诚实的答案：不存在成熟的「垂直领域 agent」开源基座，而且不应该去找。** 因为垂直性的价值恰恰在于**不可复用**——如果你的判定逻辑能被某个通用基座覆盖，它就不构成护城河了。可复用的只有**分发壳**：

| 可当基座的东西 | 是什么 | 依赖成本 |
|---|---|---|
| **Agent Skills 的 SKILL.md** | 纯 Markdown + frontmatter | **0** |
| **llms.txt** | 纯文本文件 | **0** |
| MCP 协议 | 需要运行时 | 低（stdio）/ 高（HTTP+SDK） |
| Claude Code plugin manifest | 私有 JSON | 0，但**锁死** |

## 6. 商业修订：MCP 本体收费没有先例

【事实】逐一实抓定价页：

| 公司 | MCP 收费？ | 钱从哪来 |
|---|---|---|
| **Exa** | ❌ MCP 属 Free plan | Search $7/1k；Agent $0.012–$1.00/run |
| **Tavily** | ❌ 免费 | $0.008/credit PAYG |
| **Firecrawl** | ❌ 免费 | Hobby $16 / Standard $83 / Growth $333 / Scale $599 每月 |
| **高德地图** | ❌ 免费远程 MCP | key 走开放平台配额制，导流到 LBS API 付费 |
| **Context7** | ❌ 免费层 | 私有库解析 $5/1M tokens + 席位 + 企业合规 |
| **BlockRun** | ✅ **x402 USDC 按次付费** | 直接按调用收 crypto |

**⇒「MCP server 本体收费」基本没有跑通的先例。跑通的是「MCP 免费做漏斗，收费点在 MCP 背后的资产」。** 唯一例外是 x402，但受众是 crypto-native agent，不适合你。

【事实】**Context7 2026-01 把免费额度砍 92%（500 次/月）引发反弹，之后回调到 1,000。**
【推断】**免费层的规模效应主要是获客，不是成本控制。** 对你的含义：免费层无限是对的，因为限流既无成本理由，又会赶走用户。

### 定价修订

| 原建议 | 修订 |
|---|---|
| $29–49/席位/月 | **$10/seat/月（Context7 已验证的心理价位）**；中国团队可考虑 **¥49–¥99/人/月** |
| 免费层不设限 | **不变，且更明确**——纯函数成本≈0，限流没有任何成本理由 |
| 付费点在「托管版+审计导出+合规报告」 | **不变**，且要补一句：**你现在还没有这个后端资产。先做分发，后做资产——顺序反了会死在「20K server、41% 采用」的长尾里** |

### slogan 修订

**原推荐 B：「把判断力做成契约，让任何 agent 都无法替你下结论。」**

【推断】**这条仍然成立，但不能用「像 Context7」来解释它。** 因为：
- Context7 的价值主张是「**更准**」（给你最新版的真文档）⇒ 可比
- 本项目的价值主张是「**更受限**」（告诉你这道题不能问）⇒ 不可比

**建议改为**：

> **定位**：一个把「什么问题可以问」变成可机检契约的判定层。
> **形态**：SKILL.md 教 agent 怎么用，MCP server 让它能问，CLI 是唯一真源。
> **证据**：闸门不过时给的不是「没有答案」，是**带原因的拒绝**——pass / no_anchor / leak / leak_unverified / tautology / unverifiable，六个枚举，一个都不合并成「通过」。

**最后这句是整个产品最锋利的一句，而且它是可当场验证的。**

## 8. ❌ 明确点名：看起来最酷但会被锁死的做法

### 第一名：把 Claude Code plugin 目录当主战场

【事实】2026-09-25（3 天前）Anthropic 公告原文：
> "Plugins package MCP connectors, Agent Skills, or both, and are the **main way** to build third-party extensions for Claude."
> "Over the coming weeks, **one discovery experience will roll out** across Claude and Claude Code. Skills and MCP connectors **stay as building blocks**..."

【推断】**发现入口被平台方统一收口；独立条目被降级为零件；plugin manifest 是私有格式，提交 portal 三天前才开。** 一旦格式变更，你的 plugin 层投资归零，且无法迁移。

### 第二名：把 server 托管在 Smithery/Arcade

【事实】Smithery 2026-08-05 被收购。托管你的 server 意味着托管权易手。

## 9. 三个方案的裁决

### 方案 A（推荐）：**Skill 优先，MCP 作为可抛弃的适配层，CLI 保持唯一真源**

**做法**：① 第 1 天写 SKILL.md（+ references/forecast.md、gate.md、leak.md、dueof.md）② 第 2–4 天手写 stdio MCP 适配层 ③ 免费层不设限 ④ 付费点建在团队/私有账本/审计留痕

**代价**：手写协议约 300 行；每轮 breaking change 约 0.5–1 人日；MCP 工具列表扁平时会被塞进 prompt
**收益**：零新依赖（铁律保住）；同时出现在 46 个客户端里；两端都能用；**核心资产（判定器 + 门禁）一行都不用改**

### 方案 B（最小可行）：**只做 Agent Skill + 现成 CLI，完全不做 MCP**

**做法**：一个 SKILL.md + references/*.md，指令 agent 通过 npx your-cli 调用你已有的 CLI

**代价**：需要客户端有本地执行权限；无法被「没有 shell 的 agent」使用；不进 MCP 生态的流量池
**收益**：**零协议债、零依赖、零维护**
**★ 关键**：**这正是 Context7 自己的第一模式**（"CLI + Skills — no MCP required"）——标杆产品已用真金白银验证过这条路

### 方案 C：官方 MCP SDK 全量

**代价**：**+88 个传递依赖**，直接违反铁律
**适用场景**：如果你愿意为了「省 2–3 人日 + 长期跟 spec」而放弃铁律

## 附：一句话回答创始人的核心问题

> **一个垂直领域的项目该以什么形态、什么基座暴露给 LLM？**
>
> **以「零依赖的格式」为基座（SKILL.md / llms.txt / CLI），而不是以「框架」为基座。** 框架（LangGraph / CrewAI / AutoGen / Mastra / PydanticAI / MCP SDK）解决的是**编排和连接**，而你的核心价值——「我不给答案，我告诉你这个问题能不能问、该怎么问、有什么坑」——是**流程知识**，属于 Skill 的领地。
>
> MCP 只在你需要连接「外部活的状态」（当前账本、当前记录状态）时才必要，**而且要把它写成可随时删掉的 300 行适配器**。
>
> **商业上：MCP 是漏斗，Context7、Exa、Tavily、Firecrawl、高德全都这么做。收费点在 MCP 背后的资产。你现在没有那个资产——先做分发，别先做收费。**
