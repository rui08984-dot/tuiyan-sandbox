## 零、spec 模板六项（Phase 1 硬要求，补齐）

### 0.1 Objective 目标
把**后端已有但前端从未端出**的能力（算数、真值口径、单题回看、判词离散度）呈现为一条**人能用**的产品链：
**出题 → 算数 → 等揭晓 → 归档 → 能修正**。
用户是记录者本人（单用户）。成功 = 上面五个环节在界面上都找得到、看得懂、等的时候有交代。

### 0.4 Code Style（一个真实片段，其余照此）
```ts
// 约定：中文注释写「为什么」不写「是什么」；每个非显然的取舍都注明依据与实测数字。
export function SpecimenStrip({ cells, onPick }: { cells: Specimen[]; onPick?: (s: Specimen) => void }) {
  // ★筛不掉的格**保留占位**不删除：否则「筛掉了 22 格」会被误读成「数据没了 22 格」，
  //   而这正是本产品最要防的那类误读。
  return cells.map((c) => <Cell key={c.id} dimmed={isFilteredOut(c)} onPick={onPick} />);
}
```
- 命名：模块 kebab-case（`anchor-voice`）／组件 PascalCase／变量 camelCase
- 注释：**中文**，写约束与理由，不复述代码
- 禁词：界面与注释**均不得出现「预测」**（铁律②，有禁词扫描闸）

### 0.5 Testing Strategy
| 层级 | 工具 | 位置 | 覆盖什么 |
|---|---|---|---|
| 后端单测 | `node:test` | `p1b/test/*.test.cjs` | 契约、不可变守卫、拒收门、到期口径 |
| 前端单测 | `node:test` | `p1b/web/src/**/*.test.mjs` | 组件行为 + **产品纪律闸**（禁词、诚实线、判据不减） |
| dist 扫描 | 同上 | `p1b/web/dist.test.mjs` | 产物不得含禁词 |
| 端到端 | 浏览器实证 | 手工 | 每个模块的「怎么用」逐条走 |

★**纪律闸比功能闸更重要**：本项目多数测试锁的是「不许退化」（判据不减、n<30 必标注、禁词、样品不落仓库），不是「功能能用」。

### 0.6 Boundaries 三档
- **Always（永远做）**：改动前先读盘上最新代码（防并发覆盖）／写前指纹+两份快照（safe-mutation）／改判据必版本递进／注释写理由不写复述
- **Ask first（先问）**：改 PREREG 冻结件／改账本不可变语义／加任何新依赖／动 `tokens.css` 之外的设计真源
- **Never（永不做）**：提交 key／为「好看」引入 UI 库／删测试闸／把 n<30 的格子画成 0／给推荐式引导

## 二、核心链条与现状（实测，非观感）

链条：**出题 → 算数 → 等揭晓 → 归档 → 能修正**

| 环节 | 后端 | 前端 | 断点 |
|---|---|---|---|
| 出题 | ✅ | ⚠️ | 选项是引擎英文（`binance_daily_close`） |
| **算数** | ✅ | ❌ | ★**数算得出来，界面完全没有**——主循环断在这里 |
| 等揭晓 | ✅ | ❠️ | 无等待反馈 |
| **揭晓** | ✅ | ⚠️ | 「待落定」页假设你手填 60 个答案，而守护进程**已自动结 1700 条**⇒ 界面是倒退的 |
| **归档** | ✅ | ❌ | 无单题端点，导不出、查不了单题 |
| **修正** | ⚠️ | ❌ | 409 文案叫你「另开修正记录」，但**全库 grep amend 零命中**⇒ 死胡同 |

★**后端与你说的一致**：它是一套「能算、口径不漂移、不骗自己」的机器（六层引擎 + `evidence/` 单一真源 + 到期口径 + 拒收门 + 不可变守卫）。缺的**不是后端能力，是前端没把能力端给人看**。「像后台维护」锅在前端。

## 三、模块设计（每个含「做什么/怎么用/依赖什么」）

### M1 `anchor-voice` 真值锚人话化
- **做什么**：52 个引擎 kind → 按**领域分组**的人话选项，每项写明「到期去哪里查」
- **怎么用**：`<optgroup>` 按领域（行情/天气/彩票/汇率/文献/能源/太空/交通 ≥8 组）
- **依赖**：无（只读现有 `g2-contract-frozen-r4.json`）
- **边界**：底层 52 个 kind **一个不少**，只重组 + 加中文名；界面上**不出现裸英文标识**
- **示例**：`binance_daily_close` → 「比特币以太坊每日收盘价 · 到 Binance 查」

### M2 `answer-reveal` ★算数露头（本轮核心 · 两段式）
- **做什么**：选来源后给出**两个数**——先历史频率（立即），再引擎基率（紧接着），中间给一句结论
- **怎么用**：
  1. 写题面 → 选来源
  2. ◌ **转圈**（见 M5），分两段，文案不同：
     - 第 1 段：「在数同类题的历史样本…」→ **立即出历史频率**
     - 第 2 段：「在按这道题的条件算基率…」→ **补上引擎基率**
  3. 两个数并排 + 结论：
     > 你的判断 **55%**　｜　同类历史 **40%**（120 次里对 48 次）　｜　本题基率 **43%**
     > **你比基率更乐观。**
- **★你拍板「两者都要（先后给）」**，故设计为两段式：
  | 段 | 数从哪来 | 技术 | 等待 |
  |---|---|---|---|
  | 1 | 同类已结算题真实频率 | 一条 SQL 聚合（只读） | 秒级，立即出 |
  | 2 | 引擎针对本题算 | `l2Baseline(spec, evidence)` 纯函数，同步调用 | 亚秒级，紧随 |
  ⇒ **两段都是同步的，不存在真排队**；转圈主要覆盖「网络往返 + 聚合」，文案要说清在数什么。
- **依赖**：`anchor-voice`
- **后端改动**：
  - `disclosure.js` 的 lookup 分支加 `base_rate`（同源 SQL，只读、零写）
  - 加**基率预计算端点**（复用 `l2Baseline`，只读），供第 2 段取数
- **诚实纪律**：
  - 样本 <30 ⇒ 历史频率标「只记方向，别当结论」
  - 引擎基率若因参数不足算不出 ⇒ **明说算不出**，不编一个数（沿用 `insufficient_data` 既有口径）

### M3 `auto-reveal` 揭晓分流（三类 · 你拍板）
- **做什么**：把「待落定」按**真相**分三类，不让任何一类默默卡着
- **怎么用**：
  | 类 | 内容 | 交互 |
  |---|---|---|
  | **已自动揭晓** | 守护进程已结的（实测已结 1700 条） | 折叠成一行，显示结果 + 判分，**不问** |
  | **待你确认** | 真值机器拿不到的（彩票等未开奖、判定歧义） | 突出显示，每条附**为什么没落定**，三个键：真发生了/没发生/判定不清 |
  | **永远结不了** | 永久卡住（如接口 403 地域封禁、赔率真值过期） | 说清原因，**不给假按钮**（点不动比点了没反应诚实） |
- **依赖**：`answer-reveal`
- **★推翻说明**：上一轮「待落定」页（60 条 × 三键手填）是**倒退设计**——它假设你要手填，而守护进程已自动结 1700 条。本轮按三类重做。
- **数据来源**：`corpus-resolve-daemon.cjs` 的结算日志（`pending` / `fetch-fail` / `prescreen` 都有计数）→ 需要一个能区分三类的只读端点

### M4 `life-of-question` 一道题的一生（归档环）
- **做什么**：单题完整回看——题面 → 你的数 → 引擎的数 → 真值 → 判分 → 现在的看法；并标注**是否因真值口径缺陷被排除统计**
- **怎么用**：`/question/:id`；从「我在哪儿偏了」点任一条可进
- **依赖**：`answer-reveal`、`auto-reveal`
- **后端改动**：加**只读**单题端点（`/api/predictions/:id`），返回题面/两个数/真值/判分/判词条数/真值口径排除标记
- **数据已核实现成**：`statement`、`assigned_prob`、`outcome`、`resolved_at`、`evidence.baseRate`、`baseRateNote`、`verdicts` 条数、`truthBasis` 排除判定

### M5 `wait-states` 全链路等待态（横切）
- **做什么**：所有异步等待都有交代，不许白屏/静默
- **怎么用**：
  | 场景 | 表现 |
  |---|---|
  | <400ms | **不闪**（真快就别晃眼） |
  | >400ms | 细环转圈 + **说明在等什么**（如「在数同类题的历史样本…」） |
  | >1.5s | 补「样本多，稍等」 |
  | 完成 | 环收 ✓，回执从下方展开 |
  | 失败 | 环变 ✗ + 具体原因 + **可重试** |
- **依赖**：无
- **横切页面**：记一笔 / 待落定 / 我在哪儿偏了 / 入口页
- ★**关键**：转圈时那行字就是产品的解释——等待不是空白，是回答的一部分

### M6 `verdict-spread-view` 判词离散度（你勾了要接，排在最后）
- **做什么**：展示「同一道题、不同问法/温度，答案能从 98% 摆到 45%」——测的是**重测信度**，不是预测力
- **怎么用**：在「一道题的一生」里当一节
- **依赖**：`life-of-question`
- **后端**：`/api/disclosure/verdict-spread` **已存在**，只缺界面
- **诚实纪律**：必须同屏写明「**这是单时刻横截面（3 变体 × 3 温度 = 9 路），不是时间序列**」

### M7 `amend-copy` 修正环文案（不碰后端）
- **做什么**：把 409 那句「如需纠错请另开修正记录」改成**诚实的现状说明**
- **为什么**：`grep amend` 全库零命中 ⇒ 那条路不存在 ⇒ 留着是死胡同
- **新文案**：「这道题已落定，账本不可改（这是它可信的原因）。目前**没有**修正入口——想要修正需要单独立项。」
- **依赖**：无

## 四、构建顺序（依赖驱动，非重要性驱动）

```
M1 anchor-voice ──→ M2 answer-reveal ──→ M3 auto-reveal ──→ M4 life-of-question ──→ M6 verdict-spread
                              │                                   │
                              └─────── M5 wait-states（横切，早做早受益）
                                                                  
M7 amend-copy（独立，随时可做）
```

| 序 | 模块 | 依赖 | 能独立验证吗 |
|---|---|---|---|
| 1 | `M7` 修正文案 | 无 | ✅ 改文案即可验 |
| 2 | `M5` 等待态 | 无 | ✅ 四个页面各验一次 |
| 3 | `M1` 真值锚人话 | 无 | ✅ 下拉无英文标识 |
| 4 | `M2` **算数露头** | M1 | ✅ 能拿到数 + 样本量 |
| 5 | `M3` 揭晓分流 | M2 | ✅ 自动/待问两类分开 |
| 6 | `M4` 单题视图 | M2 M3 | ✅ 能查到一道题的一生 |
| 7 | `M6` 判词离散度 | M4 | ✅ 横截面口径写明 |

★`M6` 放最后不是因为不重要，而是它**依赖单题视图**（作为其中一节），且它本身后端已就绪、前端是纯增量。

## 六、残余假设（我没问、但我按这个推进；不对就说）

1. **领域分组由我定**（行情/天气/彩票/汇率/文献/能源/太空/交通）——依据 52 个 kind 的前缀聚类，可改
2. **等待阈值 400ms / 1.5s**——经验值，可改
3. **单题端点只读**，不写任何东西
4. **M2 的数来自「同类已结算题的真实频率」**，不是引擎跑出来的基率——因为引擎跑一次要等，而历史频率现成。若你要「引擎针对这道题算」，那是另一条链路（需接引擎，更慢）
5. **自动揭晓的分界线**：能自动查到真值的（天气/币安/文献…）自动；查不到的（彩票要等开奖公告、部分源 403）问你
