## §1 目的与非目的

### 1.1 目的（在"等不起"的领域验证方法）
- U6 原话：「长期的要做出产品肯定要用大量历史数据」「解题不会预先知道结果，而是通过我们设计的流程得出真正的解」（讨论汇总:46-47）。
- 目的＝把「等数月才可验」的长 horizon 验证，换成「历史真值已在库」的即时验证：cutoff 设历史时点 → 只用该时点前数据出题 → 算 prob → 用库内真值核对（讨论汇总:72-73）。
- 产出三类**过程证据**：①管道可用（能出题/能算/能结算）；②隔离有效（§2-§3 判据全过）；③分层读数齐备（§4）。**均非能力宣称**。

### 1.2 非目的（硬性五条）
1. **不凑数**：回测题不得充 G2 ③长 horizon 下限、不得计入「月 resolve 吞吐」达标判定（design:149、:188），不得充任何能力门分子。
2. **不宣称实时能力**：所有回测数字恒挂「历史回测·非实时能力」（§5）；回测分数≠实时预测能力证据。
3. **不替代前瞻样本**：前瞻批 0/901 未解（R1:80）是真实空白，回测不填这个洞。
4. **不改既有判据**：三件 PREREG 的题源选择键 `checklist_hash` 冻结不动（§8）；D2 不重算、不借用其 verdicts 行。
5. **不进被预测系统**：输出不公开给被预测域（反身性门）；不接 8787、不碰 key、不写 `p1a.db` 生产表（D2 只读题面视图）。

### 1.3 三道门（B-泼冷水）与 P6 作为本文硬约束
- **平凡基线门**：任何读数先给无脑基线（常数预测器 Brier≈b(1−b)）；无增量即报负结果（B-泼冷水:195）。
- **双盲足样本门**：n<30 单元只记方向、不下结论；噪声带 ±0.06（PREREG-RB §三；design:153）。
- **公开性-反身性门**：回测域须弱自反；输出不公开给被预测者；公开即触发分布漂移（B-泼冷水:42、:195）。
- **P6 分辨率**：校准好≠有用。Brier 必须分解并报 resolution 项（Brier = reliability − resolution + uncertainty；B-泼冷水:56）。只报 ECE/Brier 而不报 resolution 的报表，不算通过本文 §4。

## §2 cutoff 纪律与技术强制

### 2.1 纪律（写死的三条）
- **C1 严格早于事件**：`cutoff_at` 必须严格早于事件窗口起点；禁止用「今天」当 cutoff 问历史事件（勘察 §11.3-1 原文）。
- **C2 只用 cutoff 前信息**：题面与证据只允许 cutoff 前可观测的字段/事件；结算事件、计票、终局、真值字段一律不得进入。
- **C3 逐题可核**：`cutoff_at` 落库非空，且出题脚本校验 = 事件前一天 23:59（该域时区，默认 Asia/Shanghai）。

### 2.2 技术强制（三层，缺一层即视为无隔离）
1. **进程角色层**：先落「进程角色表」——participant／scorer／resolver 三态；回测进程角色=participant，只允许读题面只读视图（R2:81、:164）。
2. **库层**：题面库无 `outcome`/`truth_preview` 列；真值在 `truth_vault`（物理分库或 ATTACH 只读视图过渡）；回测进程的连接不得 attach vault。
3. **脚本层**：回测脚本源码不得出现 `truth_vault`／`outcome`／`truth_preview` 字面（grep 门=0）；运行期用 sqlite authorizer/只读句柄兜底。

### 2.3 防作弊复测判据（唯一硬判据）
在**回测进程**里执行以下断言，全部通过才算隔离成立；任一失败＝D2 停跑：
- A1 `SELECT outcome FROM predictions` → 失败（no such column）。
- A2 `SELECT * FROM truth_vault LIMIT 1` → 失败（no such table / denied）。
- A3 源码字面扫描 `truth_vault|outcome|truth_preview` → 0 命中（排除注释与本文档引用）。
- A4 抽样 10% 题人工复算 cutoff：evidence 事件时间全 < `cutoff_at`，零结算事件。

## §3 防泄漏判据 · 自检 · 与 F4 分库的接口

### 3.1 F4 接口（三分表，按 R2:76 定稿语义）
| 库 | 内容 | 可读者 |
|---|---|---|
| `predictions`（题面库） | 题面+`cutoff_at`+锚 id+`resolution_spec_id` | participant（含回测引擎）只读 |
| `resolution_spec` | resolve 参数（date/threshold/cmp/url_template） | resolver/daemon 可读 |
| `truth_vault` | `outcome`+`truth_preview` | 仅 resolver+scorer |

最小可逆序（R2:164）：①角色表 → ②回测引擎以 ATTACH 只读题面视图运行 → ③验收=回测进程 SELECT `truth_vault` 必须失败 → ④再谈物理分库。

### 3.2 硬门（开跑前置，**未落地不得开跑**）
- **G-D2-0**：F4 接口第 ①②③ 步（角色表+只读题面视图+SELECT 失败验收）**未全部落地 → D2 不得开跑**；不得用「先跑再隔离」的任何变形。
- 理由（R2:88）：F4 未修时，回测分数与要证的结论**循环污染且不可逆**——一旦发布污染口径的数字，后续再难洗白。
- 放行证据：角色表落盘 + A1/A2 断言实跑输出 + 源码扫描输出，三者哈希随首批报告落盘。

### 3.3 泄漏自检清单（每批跑前必跑，脚本化留痕）
1. A1/A2 盲跑断言（§2.3）。
2. 源码字面扫描（A3）。
3. evidence 时点扫描：全部事件时间 < `cutoff_at`，结算事件计数=0。
4. 题面库 schema 断言：`PRAGMA table_info(predictions)` 无 `outcome`/`truth_preview`。
5. 10% 抽样人工复算 cutoff（记录抽样 id 与结论）。
6. 自检结果 JSON+hash 落报告；泄漏率必须=**0**。

### 3.4 泄漏处置
发现任一泄漏 → 立即停跑、该批**整体作废**（不得只删可疑行）、记 `.dshwolf/buglog.json` 与变更留痕；修复后重跑须全量重出自检证据。

## §4 分层报告口径（horizon × layer × 难度）

### 4.1 三个正交维度（全部**分别报、禁混算**）
- **horizon**（resolve 目标日 − 出题日）：短 ≤7 天／中 8–30 天／长 >30 天（design:149）。
- **layer**：L1–L6 六层，按 `万物分类清单-v2` 归属；跨层只可并列展示，不可合并。
- **难度（外生）**：用该题历史基率 b 的**基线 Brier 下限 b(1−b)** 分档——
  | 档 | 判据（b(1−b)） | 等价基率 b |
  |---|---|---|
  | 最难 | ≥0.21 | 0.35–0.65 |
  | 中 | 0.16–0.21 | 0.20–0.35 或 0.65–0.80 |
  | 近 | 0.09–0.16 | 0.10–0.20 或 0.80–0.90 |
  | 极 | <0.09 | <0.10 或 >0.90 |
- **禁我方填值**：b 必须由该题所属（源×域×窗）历史样本独立算出，禁用 `assigned_prob`、判词输出或人工填值充当难度（修 R1-F7 循环度量）。

### 4.2 单元必报列（缺一列即报表作废）
每个 `horizon×layer×难度` 单元必须同表给出：n ／ 基率 b ／ **外生基线 b(1−b)** ／ 模型 Brier ／ Δ=Brier−b(1−b) ／ **resolution 项** ／ reliability(ECE，仅记账) ／ 覆盖率 ／ impute 行数 ／ 泄漏自检结果。

### 4.3 禁混算条款（逐条可机检）
1. **禁全库汇总当结论**：任何「总体 Brier/ECE」只能作附录，不得作结论；结论只许落在单元层。
2. **禁跨基率比 Brier**：期望 Brier＝b(1−b)，Brier 跨单元不可比（二期笔记-Pitfalls:13）；比较一律用 Δ 或 resolution。
3. **禁 n<30 出结论**：标「样本不足·仅方向」，噪声带 ±0.06（PREREG-RB §三）；不得由单一单元外推全批。
4. **禁 median 顶替单路**：主判据用单路读数，median 只作记账列（PREREG v1 §五）。
5. **禁 horizon/难度交叉合并**：同一题不得同时充长 horizon 与最难档两条下限（design:155-⑦）。

## §5 诚实标注义务（恒挂）

- **数字级**：所有回测数字（表头、图题、单值）恒挂「**历史回测·非实时能力**」；statement 前缀 `【backfill】` 或 `【回测】`（design §4.1 修订 R3）。
- **报告级**：报告首页必须写明「本报告为历史回测，不构成实时预测能力证据；不得计入 G2 月 resolve 吞吐（design:188）；不得引用为 PREREG 判据达成证据（对齐 PREREG-判词重跑-v1:44 对 ts-rebacktest 的边界）」。
- **禁措辞**：不得写「准确率 X%」「AI 预测能力」等暗示；UI 禁「预测」字样（铁律②）。
- **必含节**：「未覆盖与不可外推」——列出未覆盖域/层/horizon、样本不足单元、已知偏差。
- **机检**：发布前脚本扫描报告标题与表头，缺标注即拒发（标注义务=可测，不是口径自觉）。

## §6 单源原型验收标准（天气 archive）

### 6.1 源与窗口
- 源：Open-Meteo archive（`archive-api.open-meteo.com/v1/archive`），**2015-01-01～2024-12-31 共 3653/3653 天全有值**（勘察 §11.1 实测）；10 年逐日。
- 边界（写进题面）：archive=ERA5 再分析格点，**非**气象台站点实测；题面禁写「实测」，否则须换 CMA 站点锚（勘察:150）。
- Q0-3：每个（城市×月×阈值）组合先算历史基率，落 (0.15,0.85) 才可出题；**禁一套阈值灌十年**（勘察 §11.3-2 反例：上海 9 月 >35℃ 基率 0.01）。

### 6.2 验收标准（A1–A7，全过才算原型成立）
| 编号 | 判据 | 阈值/证据 |
|---|---|---|
| A1 量 | 合格题（cutoff 合规+基率在域内+非 tautology） | ≥**200** 条；覆盖 ≥3 城 × ≥12 个月 × ≥2 horizon 档；单批 ≤500（勘察 §11.4） |
| A2 泄漏 | 泄漏自检 | 泄漏率=**0**（§3.3 六项全过，含 A1/A2 断言实跑输出） |
| A3 分层 | 分层报表 | horizon×layer×难度三维齐备、单元必报列无缺、无混算（§4） |
| A4 基线 | 平凡基线门 | 每单元给出 b(1−b) 与常数预测器读数；模型须 Δ<0 才算有 resolution，否则如实报「无增量」 |
| A5 样本 | 双盲足样本门 | n<30 单元只标方向；全批结论不得由单单元外推 |
| A6 标注 | 诚实标注 | 每表挂标注、前缀合规（§5 机检过） |
| A7 复现 | 可复现 | 跑批命令+题面库快照 hash+自检输出 hash 落盘 |

### 6.3 本原型的效力
只验「管道 / 隔离 / 口径」三件事，**不产出能力宣称**；跑出的分层读数是过程证据。

## §7 kill_test（最便宜的证伪检查）

> 对齐 B-泼冷水:145：把主张压成可注册预言，在免泄漏题集上与无脑基线同台双盲。D2 的 kill_test 应 ≤1 小时、零 LLM、可脚本化；**每批跑前先跑**。

- **K1 泄漏探针**：一个只连题面库的脚本，尝试读 `truth_vault`/`outcome`/`truth_preview`。能读到 → 隔离失效，**D2 停跑**（无需继续看分数）。
- **K2 平凡基线对照**：常数预测器（恒输出该单元 b）Brier 应≈b(1−b)（误差 <0.01）。若不符 → 结算/打分管线有 bug，先修管道。
- **K3 真值置换（permutation）**：把 outcome 与题随机置换后重算 Brier。分数**不变** → 分数不依赖真值（管道故障或假分数）；分数显著变化 → 键控正常。
- **K4 无增量即止**：若所有单元模型 Brier ≥ b(1−b)（Δ≥0）→ 结论「该方法在此域无增量（resolution≈0）」**直接发布负结果**，不扩量、不换口径重试。

**通过条件**：K1 失败=隔离问题；K2/K3 失败=管道问题；K4 不是失败，是允许的负结果。三种结局都要落盘留痕，禁「数字不好看就重跑」。
