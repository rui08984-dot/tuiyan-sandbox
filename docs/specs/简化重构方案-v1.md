## 一 · B1 清单（按"用户看得懂"排序）

### B1-1 读数文本 → 结构化字段（最小充分集）
- **现状**：`baseRateNote` 是一段自由文本（「回填·东京：cutoff 前 115 个臭氧日均中 <= 42.5 占 50.4%（分位 q=0.5）」），
  读数全靠**正则解析**；且解析器有 **3 份**（`l2_baseline.parseCount` / `g2-report.parseNoteN` / `l5_sources.parseCertifiedFromNote`），靠纪律保持句式一致。
- **目标**：新增**结构化字段**（写端随行落库，additive）：`evidence.baseRate = { p, n, window:{from,to}, kind:'empirical'|'certified', basis }`；
  读端**优先结构化**、文本解析退为兜底（旧行不动）。
- **收益**：参数表可自动生成；解析不再靠句式；三份解析器收敛为一份共享模块。
- **风险与对策**：写端改造=additive 迁移 + 快照纪律（与 F4 真值分库同批做，避免两次迁移）。

### B1-2 `resolve.kind` 目录表（一页看懂"系统认识哪些题"）
- **现状**：kind 散落在 resolver 源码 + 契约表 JSON + 各脚本；使用者无法一眼看到"全清单"。
- **目标**：生成 `docs/specs/kind-目录表.md`（一行一个 kind：取数源 / 必需参数 / 真值锚 / 是否有引擎 / 已用题数）；
  来源＝契约表（`g2-contract-frozen-r4.json`，已有 `g2-contract-verify.cjs` 保证与源码一致）。
- **收益**：接题/出题的人不用读代码就知道能问什么。

### B1-3 脚本命名统一 + `--help`
- **现状**：`corpus-*.cjs` / `g2-*.cjs` / `stage4-run.cjs` / `prereg-a-*.cjs` 混用；参数靠源码开头注释，没有 `--help`。
- **目标**：① 命名前缀统一（`corpus-` 取数出题 / `ledger-` 账本维护 / `report-` 报告 / `exp-` 实验）；
  ② 每个 CLI 支持 `--help`（打印用法/参数/默认值/是否写库）。
- **收益**：使用者不必读源码。

### B1-4 门读数一张看板
- **现状**：门读数分散在 `g2-report-*.json`、`stage4-run-*.json`、`audit` 路由里。
- **目标**：`p1b/scripts/board.cjs` → 一张表（G2 五门 / 五层读数 / 采信链状态 / 账本计数 / 待结算）；
  只读、可随时刷新；**不改任何既有读数文件**。
- **收益**："现在到哪了"一眼可见（本文件与通俗说明都引用它）。

### B1-5 参数集中与默认值表
- **现状**：环境变量（`P1B_LLM_MOCK` / `P1B_LLM_TIMEOUT_MS` / `P1B_LLM_REASONING_EFFORT` / `P1B_EVIDENCE_V3*`）散落各处。**[实测]**
- **目标**：① `docs/specs/参数表.md`：变量 / 作用 / 默认值 / 影响面（人话一句）；② 代码侧新增 `p1b/src/config.js` 集中读取（additive，逐处迁移）。
- **收益**：使用者不用猜。

### B1-6（新增 · 今日教训沉淀）跑批体检命令
- **现状**：判"跑批在不在跑"要手敲三件套（进程 / DB 增长 / **队列是否陈旧**）；今天两次差点误判 wedge。
- **目标**：`p1b/scripts/exp-health.cjs`：一次打印 进程在否 / 近 10 分钟行增长 / 队列陈旧度（对在队条件核 DB） / 上游小探测。
- **收益**：凌晨值班与接手会话的第一条命令。
