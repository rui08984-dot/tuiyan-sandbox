## §0 ★读法：证据分三级，别混用

本件每一条断言都标了来源级别。**Ⓐ ＝ 本轮执笔者亲手跑出来的；Ⓑ ＝ 本轮执笔者读源码/读文件核实到的；Ⓒ ＝ 车道来件自报、执笔者未复跑。**

| 级别 | 含义 | 效力 |
|---|---|---|
| Ⓐ | 本轮实跑，命令与输出在 §1 表内 | 可当场复跑 |
| Ⓑ | 本轮读过文件，行号可点 | 可当场核对 |
| Ⓒ | 来件文字，**本轮一条都没验** | 只能当「他说他跑了」 |

## §1 缺陷台账（逐条：根因 → 改法 → 现在由哪条测试锁住）

### D1 · 写端口：年度题到期日整整早一年

- **根因**（Ⓑ `p1b/src/db/predictionsStore.js:217`）：`deriveMaturesAt` 的 year 分支写的是
  `String(r.year) + '-12-31'`，输入 `2027` 得 `2027-12-31`。契约 `g2-contract-frozen-r4.json` 的
  `year/yearly` 四 kind 明写「date = **次年** 12 月 31 日」。到期日是结算通道的**选题闸门**，
  早一年＝真值尚未发布就把年度题选中。
- **改法**（Ⓑ `:217` 现值）：`(Number(r.year) + 1) + '-12-31'`。
  同时 `:198-203` 的函数头注写明「**只有 `year` 一组已逐条对齐契约**，其余四组未拍板前不要顺手改」。
- **锁定测试**（Ⓐ A6）：`p1b/test/matures-at-year.test.cjs` ① 次年 12-31、② 契约四 kind 全口径
  （**直接读冻结契约取规则，不把 `2028` 写死成魔数**）、③ 修 year 不得外扩（非四位年仍抛错）。
- **同批改的一条过期期望值**（Ⓑ `p1b/scripts/_b1-store-verify.cjs:35`）：原 `[{year:'2026'}, '2026-12-31']`，
  现 `[{year:'2026'}, '2027-12-31']`。改值未删断言——不改会拿一条与契约相悖的断言把正确实现判成 FAIL。
- **冻结件**：`g2-contract-frozen-r4.json` 只读，本轮 `git diff` 对它无输出（Ⓒ，执笔者未复跑该 diff）。

### D2 · 读端口：守护进程没有 year 分支，年度题整组饿死

- **根因**（Ⓑ `p1b/scripts/corpus-resolve-daemon.cjs:83`）：`dueOf()` 的分支表里**没有 `r.year`** ⇒
  年度题一律落 `undatable` ⇒ daemon 永不选中 ⇒ **明明有 resolver 也永不结算，且无任何告警**。
- **改法**（Ⓑ `:83`）：`if (String(r.year).length === 4 && isFinite(Number(r.year))) return { due: (Number(r.year)+1)+'-12-31', src: 'year+1y' }`。
  判据与算式**照写端口 `deriveMaturesAt` 逐字同源**（不是各写一份）。插在 `meta.expectMonth` **之后**，
  不遮蔽任何既有分支。
- **登记同步**（Ⓑ `p1b/src/evidence/dueBranches.js`）：`UNIMPLEMENTED['year/yearly']` 已删，
  原位留注释说明为何是「删」而非「留一条失效登记」（依该表自身的设计注：分支落地后登记自动失效）。
  剩 3 条：`epiweek/weekly`、`end/daily`、`week/weekly`。
- **锁定测试**（Ⓐ A6）：`matures-at-year.test.cjs` ④ 守护进程读端口同样认 year、⑤ ★写读同源
  （4 个 year kind × 3 个年份，逐一断言 `dueOf(...).due === deriveMaturesAt(...)`；kind 名从契约现取，两处不各抄一份）。
- **回归网**（Ⓒ）：`p1b/test/corpus-resolve-dueof.test.cjs` ⑧ 是「每组要么 `dueOf` 推得出、要么登记原因」的
  覆盖断言；删了登记而不补分支，`year/yearly` 会立刻变 `bare` 转红。来件报 `covered 18 | excused 4 | bare 0`
  （该文件 `:137` 自记基线是「dueOf 只覆盖 14 个」）。**本轮未复跑该覆盖统计。**

### D3 · 未收盘 K 线被当收盘价写进不可变账本

- **根因**（Ⓑ `p1b/scripts/corpus-resolve.cjs:193` 上方两行）：原实现只靠 `futureDay(r.date)` 预筛，
  而 `futureDay` 用**上海日历**去卡 **UTC 日**语义的源 ⇒ 北京时间 00:00–07:59（UTC 16:00–23:59）时
  上海日期大 1 ⇒ 预筛放行 ⇒ `j[0]` 是**当日那根还在长的** K 线 ⇒ 半日价格被当收盘价落库。
- **改法**（Ⓑ）：新增纯函数 `p1b/src/evidence/klineClosed.js`（零依赖、零 db、零网络），
  判据取**数据自报的 `closeTime <= now`**（与时区无关）。两个调用点都从它取判据：
  活路径 `corpus-resolve.cjs:193`、兜底路径 `corpus-resolve-daemon.cjs:229`
  （兜底那份抽成导出纯函数 `judgeBinanceKlines`，`:224` 定义、`:573` 导出）。
- **两处前提纠正**（Ⓒ，本轮未复跑其复刻过程，但Ⓑ已核到结论的前提条件）：
  ① 来件问的 daemon `:219-230` 是**被遮蔽的兜底**——`evalRow:349` 优先用 `BASE[k]`（从
  `corpus-resolve.cjs` 抽取的 resolver），故 daemon 的 B3 同名分支**从不执行**，只改 B3 等于没修；两处都改了。
  ② 「K 线时长 ≥ 24 小时」是**错判据**：Binance 日 K 约定 `closeTime = openTime + 24h − 1ms`，
  已收盘 K 线时长是 **86399999ms**，拿它比 `≥ 86400000` 会把**每一根**已收盘 K 线判成未收盘 ⇒ 整类题永久饿死。
  该事实已写进 `klineClosed.js` 的头注（本轮读到，Ⓑ）。
- **锁定测试**（Ⓐ A6）：`p1b/test/binance-kline-close.test.cjs` ① 活路径未收盘必落 pending、
  ② 兜底路径同款、③ 已收盘照常出真值（防过度拦截）、④ 纯门函数判据与时区无关。

### D4 · 未到期的题可以被永久落定

- **根因**（Ⓑ `p1b/src/db/predictionsStore.js:430-433`）：`resolvePrediction()` 落定前**从不做到期检查**；
  `listUnresolved()`（`:388-404`）也**零过滤**——未到期题与已到期题混在同一张「给人点的」待办清单里。
- **改法**（Ⓑ）：
  - 到期口径**单一真源**：新增 `todayShanghai()`（`:347`）＋ `maturityState(row)`（`:365`），
    判定式 `matures_at <= 上海日历日今天`（含当日），与 T6 只读端点 `disclosure.js` 逐字同款，**未另写日期算法**。
  - **写端口**（`:430-433`）：未到期 ⇒ `{ok:false, reason:'not_due', due, today, why}`，**不写**。
  - **读端口**（`:388-404`）：默认剔除未到期；`dueFilter:false` 关闭（内部诊断用）；
    回带 `due_filter` 两桶计数（`excluded_not_yet_due` / `included_no_due_date`），**不静默吞题**。
  - **三态而非两态**（`:365-376`，本轮读到全文）：`matures_at` 为空的题**照常放行**＋回带人话
    `due_note`（`:438`）——botc 程序结算题、cwl/dlt 开奖题全无日历到期日，一刀切拦死等于把整类题打死。
- **三处判断**（Ⓒ，本轮Ⓑ核到代码与之一致）：
  **A** 无到期日放行不拦、但不许静默（回带理由）。
  **B** `listUnresolved` 只剔「有到期日但没到」——`predictions.test.cjs:186` 断言一条无到期日的题
  必须出现在清单里，抹掉它们等于把整类题从待办里抹掉。
  **C** 加了 `opts.allowNotDue` 逃生口（`:431` 条件里唯一一处），**HTTP 路由一律不得透传**——透传即拆掉设防。
- **锁定测试**（Ⓐ A6）：`p1b/test/resolve-due-guard.test.cjs` ①未到期拒写（`outcome` 仍 NULL、
  `resolved_at` 仍 NULL）、②已到期放行、③边界「到期日＝今天 ⇒ 放行」、④无到期日放行＋回带理由、
  ⑤`listUnresolved` 默认剔除与两桶计数、⑥★**HTTP 端点**也写不进去（端点不写库、不回已落定行）。
- **影响面**（Ⓐ A8，只读实测，上海日历日 2026-09-28）：未落定 **294** 条 → 新清单 **29** 条，
  **265 条未到期的被移出待办**，1 条无到期日留下（28 已到期 + 1 无到期日 = 29）。
  这 265 条正是原来能被一次误点**永久落定**的题。

- **改法**（Ⓑ）：
  - `:111` 新增 `ok: split.ok`；
  - `:98-106` `counts` 换成与返回体**同源**的六键（`auto_revealed` / `ok` / `need_human` / `stuck` /

- **锁定测试**（Ⓐ A6）：`p1b/test/reveal-class.test.cjs` ★⑤ 真打 `app.inject`、三类互斥且完备

### D6 · 查历史期间界面无任何输出（死调用）

### D7 · `known:false` 时界面假装有建议

- **根因**（Ⓑ `p1b/web/src/pages/NotePage.tsx`）：取数 `.then` 里 `setAdvice({layer: sug.layer, engine: sug.engine, n: ev.total_n})`
  **无条件执行**，三个字段全 undefined 时仍是 **truthy 对象** ⇒ `{advice ? … : null}` 走「有建议」分支，
  算数面板凭空出现。对照后端：`disclosure.js` 的 `known:false` 分支返回 `{mode,kind,known:false,reason,hint}`，
  **无 `base_rate` 键**。
- **改法**（Ⓑ）：新增纯函数 `p1b/web/src/lib/noteLookup.ts`（`readLookup(j)` ＋ 两句被锁住的文案）；
  页面两个 state（`advice` + `base`）**合并成一个 `lookup`**——拆成两个就注定它们各说各话，那正是旧病根的形状；
  `known=false` ⇒ `advice` 是 **`null`（不是全 undefined 的对象）**、算数面板整体不渲染，
  改显示后端 `reason` / `hint` 原文。
- **顺手堵的洞**（Ⓒ，本轮未复跑其成因链，但Ⓑ确认旧代码首行是 `if (!alive || !j) return;`）：
  HTTP 非 2xx 时 `r.json()` 给 `null` ⇒ 旧 `.then` 永不 `setPhase('done')`、phase 卡在 `freq`。
  在 D6 把 `phase` 接进 `<Wait>` 之后，这会变成「**一个永远转下去、永远说『在数同类题历史』的圈**」——
  等于 D6 的修复自己造了一个新的假界面。故重写 `.then` 时一并收了 `!j` 分支。**这是主动扩大的一行，理由如上。**
- **锁定测试**（Ⓐ A7）：`p1b/web/src/lib/noteLookup.test.mjs` ①`known:false` ⇒ `base=null`·无层·带后端原话
  ②`advice` 必须是 `null` 而非空对象 ③`known:true` 不被误伤 ④畸形 `base_rate` 不得变 NaN·也不得反报「没有这类题」
  ★⑤坏响应（`r.json()` 给 `null`）不得被当成 `known:true` ★⑥两句文案必须不同 ⑦**接线**（去注释后扫源码）⑧禁词。

### D8 · 判据脚本越权：改写已落定行

- **根因**（Ⓑ `p1b/scripts/judge-runner.cjs`）：选题 SQL 不排除已落定行，写回是**裸写**
  `UPDATE predictions SET assigned_prob = ? WHERE id = ?` ⇒ 一条 `outcome='true'` 的行，跑批后被写上
  `assigned_prob=0.5`。**账本不可变被脚本绕过。**
- **改法**（Ⓑ）：
  - ① 选题 SQL 补硬条件 `:52` `AND pr.outcome IS NULL`——已落定行根本进不了批；
  - ② 写回改**条件更新** `:110` `WHERE id = ? AND outcome IS NULL`，`changes=0` 即拒改并计入 `skipped`（`:112`）。
    依据：选题 SQL 只是**批开始那一刻的快照**，若某行在「选题→写回」之间被别处落定（并发 resolve / 人工回填），
    光靠 ① 挡不住；条件写在同一条 SQL 里，靠 SQLite 单语句原子性关掉这个 TOCTOU 窗口。
    **② 是执行者自己加的、派单没点名**（Ⓒ 声明，Ⓑ已核代码在位）。
  - ③ `skipped` 进 `DONE` 输出 `:119`——护栏拦下的条数必须可见，恒 0 才说明这批没有并发落定。
  - ④ 来件称 `:96` 有一行 no-op 占位、「**保留未删**（派单未要求），只把注释改准」。
    **本轮在 `:90-100` 未核到该占位行**（该段实为 verdicts 只读查询 `:99-100` 与批次2-RC 注释 `:97-98`），
    故此处**不引用行号**，只登记来件说法（Ⓒ）。
- **锁定测试**（Ⓐ A6）：`p1b/test/judge-runner-immutable.test.cjs` ①已落定题拒改（跑批前后 `assigned_prob` 逐字不变）
  ②未落定题照常写回（**防过度修复**：防把护栏修成「整批打死」这种也算绿的假修）
