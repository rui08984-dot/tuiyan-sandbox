## 发现清单

**[高] F1 泄漏判据不可执行、与 D2 §3 不同构，且照 D2 先例照抄今天必然「隔离失效」**
- 位置：立项书 §四必要件③；骨架 §4-2c、§5 第 1 条、待填清单第 7 项。
- 证据：立项书原文「③**泄漏检查**（检索只许触达 cutoff 前信息；K1 式泄漏探针先行，照 `历史回测引擎-规格D2` §3 先例）」；D2 §2.3 的 A1/A2/A3 全部是**数据库列级断言**（「A1 `SELECT outcome FROM predictions` → 失败」「A2 `SELECT * FROM truth_vault LIMIT 1` → 失败」「A3 源码字面扫描」），且 D2 §11.1 明写这套验收依赖「影子题面库＋authorizer 硬验收」，并声明「实现未落地前不得据本节宣称任何验收已通过」。只读实测：`p1a.db` 的 `predictions` 列含 `outcome`（全表 1935 行、已解 1263 行）；`truth_vault` 表存在且可读（1935 行）；`process_roles` 四条角色 `enforcement` 全部为 `'contract'`（纸面契约）；全仓 grep 无任何 authorizer 实现。⇒ 以 D2 §2.3 为形状的探针在本实验开工日跑不出「通过」，且「检索进程不得读到任何 cutoff 后信息」这句话在列级断言下无处落地。
- 建议：把泄漏验收写成三层可执行件：①进程/SQL 断言（基于现有 `predictions_public` 视图或新建只读视图，明确断言清单）；②源码字面扫描（grep 门=0）；③**内容级审计**（见 F2）。把「D2 §11.1 影子视图/authorizer 是否落地」写成开工前置或替代验收，并单列一节「本实验的隔离到哪一层、残余风险是什么」（对齐 design §4.2.1 D-4 的诚实标注义务）。

**[高] F2 「检索只许触达 cutoff 前信息」没有内容级判据；最坏情形下可以用「抓真值锚」冒充「找证据」**
- 位置：立项书 §四必要件③、§三不做第 5 条；骨架 §4-2c。
- 证据：只读实测候选行 `id=473`，其 `statement` 自带「真值锚=Open-Meteo archive daily.temperature_2m_max[2024-01-01]」，`evidence[0].resolve`＝`{"kind":"openmeteo_daily_max",...}` ——resolve 指向的官方源**直接含事件日观测值**；任何由题面/resolve 派生的检索请求都能取到真值。同时，页面的抓取时间必然是「今天」（2026 年），对 2024 年的事件页来说「页面内容」天然是事后产物，「URL＋抓取时间＋原文片段」三件套**证明不了**内容时点早于 cutoff。
- 建议：写死内容级判据——每条证据须同时满足「页面发布/更新时点 < cutoff」与「片段所述事件时点 < cutoff」，两者缺一即剔除；禁止检索管线访问 resolve 的 `url_template` 主机/字段；加 canary 测试（预埋若干「cutoff 后事实」，检查其从不进入任何臂的提示词与输出）；把「full 窗」明确定义为**泄漏上界（report-only，不参与达标判定）**，否则必要件③与「full 窗各算一遍——与命题 A 同构」（骨架 §3）自相矛盾。

**[高] F3 题源池「cutoff 可回溯」与实测不符，且与 design §4.2.2-B2 的现行口径冲突**
- 位置：骨架 §3 第一句；立项书 §五第 1 项。
- 证据：骨架原文「cutoff 可回溯（`created_at`/`matures_at` 口径沿用 g2-report 现状）」；design §4.2.2-B2 原文「backfill 题的合规**必须由独立声明的 cutoff 字段**（如 `evidence[0].cutoff` 或入库时刻）判定，**禁由 `matures_at` 派生**。在该字段落地前，① 的读数须标注『backfill 半壁池的 cutoff 合规未真正检验』」。只读实测：候选池（已解＋`g2_regime='R4'`＋L2/L3）＝**783 行**（L2 302／L3 481），其中 `matures_at IS NULL` **147 行**（dbnomics 月度 backfill），**9 行无任何 cutoff 字段**，union 覆盖 774/783；statement 带「【backfill】」前缀者 676/783；示例 `id=473`：`created_at=2026-09-12` 而 `cutoff=2023-12-31T23:59:59+08:00` —— 若按 `created_at` 当 cutoff，等于放行全部事后信息。
- 建议：写死资格谓词（如 `COALESCE(json_extract(evidence_json,'$[0].cutoff'), json_extract(evidence_json,'$[0].meta.cutoff'))`），校验 `cutoff < 事件日`；147 行的 `matures_at` 缺失与 9 行无字段分别写排除规则与披露计数；池 id 集合 hash（指纹）冻结。

**[高] F4 铁律④裁决：路径不完整，(b) 的代价被写成「零」但实际冲突 design §2 逐层矩阵；(a) 应升级为用户显式拍板的铁律修订**
- 位置：立项书 §二表格第 1 行与「诚实声明」；design §2 总表。
- 证据：立项书给「(b) 不新增角色，把检索证据作为『多路』角色的输入（**措辞与实现都在四角色内**）」。但 design §2 的 L2 行 LLM 角色＝「**基率**（整理/核对来源）」、禁列＝「禁无基率锚裸判」；L3 行＝「**校准**（出同化/特征代码）」、禁列＝「禁窗口外题混入（时界检验）」；而骨架 §2 的聚合规则是「证据行概率的加权平均」——即 LLM 对每条证据出概率、再由固定规则聚合，这与 L2/L3 已列角色都对不上。把它叫作「多路角色的输入」意味着给 L2/L3 的矩阵开列，这本身就是设计修订（与 (a) 同量级），除非明文声明「这是实验臂、不改变生产路由」。另：项目内部已有直接先例未被引用——`.scratch/forecast-debate/H-发散收敛架构.md` 对含「基率检索＋fact-check」的同类架构判过「✓ **无第五角色**」；立项书既未援引也未反驳。以及「诚实声明」把冲突行写成「本条**⑤**冲突」（争议行是 ④，⑤ 是 key 通道）。
- 建议：①先做**按功能**的四角色映射（给出 LLM 在该臂的输入/输出 schema 与权限：是否出概率），再决定是否真需要改铁律；②给出 (a)/(b) 的完整代价（含 design §2 矩阵是否修订、生产路由是否会因此改动）；③(a) 明写为「铁律修订：须用户显式拍板＋变更留痕索引＋design 版本递进」，不能停留在「写进 design」；④修正 ⑤→④。

**[高] F5 主判据/必要件与命题 A 非全同口径；N_min 留空存在事后定 N 的空间**
- 位置：骨架 §3（N_min）、§4-2d、§4.3；对比命题 A PREREG §2/§3/§4/§5。
- 证据：①A §2 原文「**正效应宣称的附加必要条件**＝**A vs C 也达阈**」（同一 0.02 阈值），骨架 d) 只要求「Δ_Brier(retrieval vs sham) 的 CI 下界 > 0」——弱一档；②A §3「**Murphy 分解同时必报**……主结论看 **resolution 增量**」，骨架报告项只有「分域读数、校准曲线、平均成本/题、时效」，缺 Murphy/resolution（也与 D2 §1.3 P6「只报 ECE/Brier 而不报 resolution 的报表，不算通过」相抵触）；③A §4 有「实际完成配对 n < 120……⇒ 只发方向性信号」的降级条款，骨架没有；④骨架 N_min 为「**待定**（……提案：以 Δ=0.02、**Brier 方差由本批实际估计**，取 80% 功率）」——「由本批实际估计」允许看到本批数据后再定 N。
- 建议：逐条对齐或在 PREREG 里**显式声明偏离＋理由**；N_min 必须用冻结前可得的固定方差来源（阶段 4 已落盘的 L2/L3 读数是现成来源）按公式算出**数值**并写死；写死「池不足 N_min ⇒ 只发方向性信号（照 A §4）」；把「事后按结果定 N／挑窗／换池」列为禁止项（照 A §5 原文照抄）。

**[中] F6 可复核性：阈值两处互相矛盾（100% vs <90%）、抽样框架未定、且没有原始快照要求**
- 位置：立项书 §四必要件②；骨架 §4-2b 与 §5 第 3 条；骨架 §7 冻结物清单。
- 证据：立项书「抽检 n≥20 条须 **100% 可复核**，否则判『不可复核』停下修」vs 骨架「可复核性抽检 **<90%** ⇒ 立即停跑」；骨架只要求证据含「URL＋抓取时间＋原文片段」，未要求保存**原始抓取物或其 hash**；检索侧（provider、query 模板、日期过滤、条数、爬取策略）不在 §7 冻结物清单（该清单只有「本文件 sha256 ＋ 提示词全文附件 ＋ 聚合规则代码 sha ＋ 题集指纹」）。
- 建议：统一为同一阈值（建议 100%，失败即整批作废重跑，对齐 D2 §3.4「该批**整体作废**（不得只删可疑行）」精神）；冻结物增补「检索策略全文＋原始快照（或其 Wayback id）＋快照 hash」；抽样规则（分层、seed、抽样框架、n 是每题还是全体）预注册；报告须披露「n=20 的 100% 通过不构成总体错误率保证」。

**[中] F7 证据存储路径未定义；若写进 `predictions.evidence_json` 同时踩「账本不可变」与既有读端**

- 证据：§六只有「单次调用成本按命题 A 实测外推（含检索抓取）」「烟测 1 天｜主跑 2–3 天」，无任何数字；命题 A 的实际记录是 2160 路目标只落库 914 行（42%）后经补漏才接近完成——失败率与重试开销应进成本模型；检索抓取/限速未计。「显著优于」既无阈值也未指 CI 口径。
- 建议：给「每题每臂调用数 × 单次成本 × 失败重试系数 ＋ 抓取费用/限速预算」的公式、单价与上限，写入冻结件；「显著优于」改为与主判据同结构的「Δ 与 CI」写法（建议直接对齐 A 的阈值口径）。

**[低] F15 骨架 §3 窗口措辞错误：「题创建时点前信息」对 backfill 题是灾难性定义**
- 位置：骨架 §3 第 2 行「`cutoff`（**题创建时点前信息**）」。
- 证据：backfill 题的 `created_at`＝入库时点（如 `id=473`：2026-09-12），晚于事件日（2024-01-01）——照字面实现等于允许取用全部事后信息。同句「与命题 A 同构」也不成立：命题 A 的 cutoff 窗是「只用 cutoff 前事件」，full 窗是含终局的已知泄漏窗，两者在 A 里都是**实验内条件**；本实验的「full 窗」若放开检索就是纯泄漏。
- 建议：改为「该题 `cutoff_at` 之前可得的信息」；对 backfill 用独立 cutoff 字段（见 F3）；full 窗按 F2 改 report-only 上界。

**[低] F16 两条决策的依赖关系未写明：若信号路线选 (b)（前瞻数值信号），铁律④裁决将失去对象**
- 位置：立项书 §二与 §三并列存在。
- 建议：写明「(a) 检索式证据 ⇒ 触发 §二裁决；(b) 非 LLM 路线 ⇒ §二裁决为 no-op（仍须记录）」；同时注意 (b) 的源（如历史预报存档）要给出可得性证据，否则「泄漏面最小」只是断言。

## 七问逐条结论

1. **铁律④裁决路径**：不完整。它只给「二选一」的菜单，没给裁决标准（按功能还是按措辞）、没写 (b) 的代价、没引项目内部直接先例（H-发散收敛架构已判过同类架构「无第五角色」），且「诚实声明」把 ④ 写成 ⑤。**(a) 属于改铁律**，必须升级为「用户显式拍板的铁律修订＋变更留痕索引＋design 版本递进」；立项书目前只有「重大变更须留痕」的流程性表述，未写明用户拍板是硬条件（文末「由用户拍板后方可写代码」是笼统授权，不能替代对 (a) 的显式选择）。此外 (b) 不是零代价：它需要 design §2 为 L2/L3 开列「多路」，否则就是措辞绕过。
2. **与命题 A 是否真同口径**：外壳同（Δ 定义、配对 bootstrap B=1000/seed=987654321、0.02 阈值、cutoff/full 双窗框架），内里有三处不齐——sham 必要件（A 要求「A vs C 也达阈」，骨架只要 CI>0）、缺 Murphy/resolution 必报（A §3 明文）、缺 n 不足的降级条款。N_min 留空在**未冻结的骨架阶段**可接受，但「方差由本批实际估计」必须替换为冻结前固定的方差来源（阶段 4 读数现成），否则确有「事后按结果定 N」的空间；写死方式＝数值＋公式＋池不足时的降级规则＋禁止事后调 N。另外 0.02 的出处（A 的 n≈1080、b≈0.30 下容差≈0.011 的 1.8 倍）不自动适用于本池，应附本池 b 分布下的容差复算，否则「能直接对比」只在口径层面成立、功效层面不成立。
3. **泄漏面**：不可操作。现在只有一句「检索只许触达 cutoff 前信息」＋「K1 式探针」，而 D2 §3 的 A1/A2/A3 是 DB 列级断言，且其依赖的影子库/authorizer 未落地（只读实测：`predictions` 含 `outcome`、`truth_vault` 可读、`process_roles.enforcement='contract'`、全仓无 authorizer 实现）——照 D2 先例照抄，今天必挂。遗漏通道至少三条：**检索内容自身的事件时点**（live web 天然含未来；resolve 源直接给真值，`id=473` 即例）、**LLM 训练记忆**（题源是 2024–2026 已解题）、**full 窗**（若放开检索则整窗泄漏）。需新增内容级判据、canary、禁抓 resolve 源、full 窗改 report-only，并披露残余风险。
4. **Goodhart / sham**：sham（空/无关、同长度）在原理上能把「检索内容增量」与「LLM 先验换说法」分开，前提是长度度量写死（token 还是字符？「同 token 预算」是 A 的原文口径）、管线冻结、且三个对比各有明确身份：主判据 retrieval−base、必要件 retrieval−sham、**报告项 sham−base**。当前骨架缺 sham−base 对照与阈值对齐，且「空/无关」把「任何文本入 context 的效果」与「相关证据的效果」混在一起；预算允许时建议加「陈旧但相关」的梯度对照臂（注意：双差数学上就等于 retrieval−sham，真正缺的是 sham−base）。
5. **停止规则**：大体写死，但有四处可被放宽——100% vs <90% 的不一致（F6）；没有 A 的「禁止择优重跑／工程故障重跑≤2 次／第 3 次即停」；「预算触顶暂停」无数值与恢复规则；「重新从冻结件起跑」只覆盖泄漏/可复核失败，未覆盖「冻结后改提示词/聚合规则」。与命题 A 的实操要正视差异：A 在首轮负读数后仍补齐了预注册样本（v1.1 先验约定先于补漏数据到达），所以本 PREREG 应把「跑满预注册 N 后再判、期间不做任何中检」写成明文，否则同样动作会被后人读成「补样换显著性」。
6. **与 intake／D2 的边界**：原则不混线（本实验不新增题、不碰 `intake_questions`（现 0 行）、不产生 D2 回测题、不动 `metric_version`/`backtest_batch`、不借 R-A/R-B/R-C 的 `checklist_hash`）。真正的问题在**写库路径**：立项书「检索证据只作 evidence」没写存哪；若写 `predictions.evidence_json` 就同时违反 handoff 铁律 5「账本不可变」并打乱 `evidence[0]` 的既有读端（G2 ④ 的 `baseRateNote`、契约表的 `resolve`，以及计划中的 `evidence.baseRate`）。读侧可以走已存在的 `predictions_public`（已去 `outcome`），但注意它暴露 `resolve_spec`——正好是 F2 的「抓真值锚」入口，必须在管线里禁掉。
7. **收益/成本与可复核性**：「每题检索证据抽检 20 条 100% 可复核」在当前设计下不现实——没有原始快照要求，网页会漂移/404/改版，且抓取时间是 2026 年（对历史题页本来就是事后内容，可复核 ≠ cutoff 合规）；n 到底是每题 20 条还是全体 20 条也未定。成本估算没有依据数字：§六只有「按命题 A 实测外推」，而 A 的实际失败率（914/2160 落库）与补漏天数说明重试开销不可忽略，检索抓取/限速另计。建议：快照＋hash、抽样规则预注册、报告总体错误率上界；成本给出公式、单价、失败系数与上限并写入冻结件。
