# 万物可预测性审计器 · 架构设计 v1.0（Q 棒 · 2026-09-11）

> 设计先行，零检索代码（G2 裁决对齐：docs/sandbox/upgrade-review-20260909/00-终审方案.md §二⑦「未过 G2 不写一行检索代码」）。用户 0910 原始规格：可预测性六层分类 × 分层专用引擎 × 统一 Brier 账本（HANDOFF-2026-09-08.md §六 L67 原文）。数据来源=已获批的全拟真模拟管线（docs/specs/2026-09-11-全拟真模拟-design.md）。科学依据=A-学术调研.md 六问+无免费午餐定理。

## §0 裁决对齐（本设计必须服从的既有裁定）
1. **G2 门槛未过前本审计器不产生任何「检索式预测」**——审计器的 MVP 职责=分类+记账+过程仪表，这是「轨B 数据积累」的一部分，不违 §八「不做」清单。
2. **「无真值锚禁入」**：六层分类的第一道产出就是「该题有没有可机检真值锚」——无锚题在分类阶段即拒绝（比终审裁决更前置：拒之门在分类层，不进账本）。
3. **校准数据不跨域迁移**：六层=显式分层声明；跨层只携带 schema/判据写作技能/记录习惯（终审 §七），报表永远按 layer 分层。
4. **LLM 四角色铁律**：聚合/基率/多路/校准——审计器每一层的 LLM 用途只允许落在这四角色内（§2 逐层标注）。
5. **G-合并三裁定继承**：R-a LLM 出逻辑不出数字；R-b 高温=发散候选必经收敛层；R-c 玄学=对照臂永不入账。
6. **与全拟真管线的关系**：sim 局产生的预测题（如「M1 批量局中 X 号会被投票出局」）是审计器最先批量的题源——其真值=程序结算，天然有锚，layer 归属按题面判定而非按数据来源。

## §1 六层分类的判据操作化

### §1.1 分类入口与拒收门
候选题进入分类器后**先过拒收门（Gate-Anchor）**，两问都答「是」才进六层判定：
- Q0-1「resolve 时点是否存在可机检或第三方可复核的真值锚？」（是=继续；否=拒收，记 reason=no_anchor——执行「无真值锚禁入」）
- Q0-2「cutoff（判据冻结）时间点是否早于事件决定性时点？」（是=继续；否=拒收，reason=leak——防事后诸葛）
拒收不是失败：拒收率本身进 G2 过程指标（见 §4），「万物」不等于「全收」。

### §1.2 判定顺序（决策树，从最特殊到最一般）
依次测试 L5 → L6 → L1 → L3 → L2 → L4；每层给「全通过=归入该层」的清单；任何一层命中后停止（取最特殊层），混合题记 secondary_layer。判定者=人按 checklist 填表（MVP 无自动分类器，见 §6 砍件），每题留 checklist_hash（清单版本号）。

### §1.3 L5 不可约随机层（检查清单）
1. 结果是否由认证随机源产生（认证 RNG/彩票物理抽奖/量子源，有可查的机制说明）？
2. 是否不存在任何公开渠道的信息优势路径（无人能比均匀分布猜得更好）？
3. 题面是否不涉及任何可学习的统计偏倚（如骰子的物理磨损可测则归 L2 不归 L5）？
全过 → L5。示例：NIST 随机数发生器下一位、官方抽奖机摇出的号码。
引擎姿态：**只给系综**（均匀分布或认证源的公布分布），禁止一切「模型能做得更好」的宣称——本层的 Brier 下限=分布熵，任何显著低于它的历史表现本身就是异常信号（提示泄漏而非本事）。
LLM 角色：**无**（零角色，纯账本记录）。

### §1.4 L6 对抗层
1. 结果是否由**利益相反的智慧主体**的决策直接产生（人或以人为目标训练的 agent）？
2. 对手是否能观测到我方历史预测/策略模式并调整（存在学习与反制通道）？
3. 策略空间是否开放（不可枚举所有打法，纯基率会因对手适应而失效）？
4. 是否存在「声称/伪装/欺骗」结构（公开陈述与真实意图可分离）？
全过 → L6。示例：狼人杀/Avalon 对局、竞技对抗细节、（远期）市场博弈位。
引擎姿态：**③结构推断路线**——账本矛盾检测特征+belief 统计+多路判词跨模型聚合（与②类校准线同构，见 §5）。LLM 角色：**多路（跨模型判词）+校准**；基率以「账本内历史基率+对位统计」形式进 prompt（G-合并 7.2 freeze values 纪律）。

### §1.5 L1 决定论层
1. 状态空间是否有限且完全可枚举（棋盘/规则系统的全部合法局面可写下来）？
2. 转移规则是否完全已知且**无隐藏随机源**（同一状态必得同一后继）？
3. 任一观察者能否仅凭公开状态推演出结果（信息完全，无暗信息）？
4. resolve 是否=程序可复算（引擎跑一遍即出真值，无裁判裁量）？
全过 → L1。示例：给定残局的象棋胜负、给定输入的确定性函数输出、已封版规则的锦标赛对阵结果。
引擎姿态：**程序计算**（LLM 零概率角色；允许 R-a 低温件「LLM 写计算代码，执行器跑数」）。账本记 0/1 与计算正确性，Brier 在本层语义=计算错误率，不与概率层混比。
LLM 角色：仅「聚合」之外的代码生成（R-a 件），**不出概率**。

### §1.6 L3 短窗混沌层
1. 是否存在已知的（或可近似的）演化机制/模型（物理方程、规则模拟、统计动力学）？
2. 预测窗口是否**显著短于**系统的可预测时界（判据操作化：历史上「同型方法在窗口 w1 的命中率」与「窗口 2×w1 的命中率」之差显著——若无历史数据此条记未知，则不得归 L3，降 L2）？
3. 是否有**实时观测流**可在窗口内同化（数据不断进来更新状态估计）？
4. resolve 是否落在窗口内（cutoff 到 resolve 的时长 < 可预测时界）？
全过 → L3。示例：48 小时天气、24 小时内某直播在线人数走势。
引擎姿态：**基率+短窗校准**（K 8.4 两件套：ACI 外环 γ=0.005 × 滚动窗/0.99^衰减内环）；数值模拟=程序件可选。LLM 角色：**校准**（出数据同化/特征代码，R-a 件）。

### §1.7 L2 系综层
1. 题面是否定义于一个**稳定可重复的总体**上（同分布假设可被清晰陈述并写进判据）？
2. 是否存在 ≥30 条同类历史结果可查（K 线 F13：n≈102 才到 ±0.05 波动带，30 只是准入）？
3. 单事件是否不可由现有信息决定性推出（但频率稳定）？
4. 是否存在外部统计源可作基率锚（官方统计/历史数据库）？
全过 → L2。示例：骰子序列、某类用户转化率、某地月降水天数。
引擎姿态：**统计基率**（历史频率+Wilson 置信区间；不做机制模型）。LLM 角色：**基率**（整理/核对基率来源，freeze values 入 prompt）。

### §1.8 L4 自反层
1. 结果是否由**人类决策**直接产生，且决策者**可能接触**到本预测或同类预测？（子判据：本预测是否计划公开——私有预测自反性弱，标注 reflexivity_exposure=low/high）
2. 是否存在反馈回路（预测→行为→结果→后续预测）的历史证据或机制描述？
3. 是否无法用 L1-L3/L5 清单归层（自反性通常叠加在其他层上）？
全过 → L4（**叠加层语义**：L4 可以与 L2/L6 叠加，primary=底层，secondary=L4）。示例：公开发布的市场点位预测、民调发布后的选举。
引擎姿态：**禁公开+反馈建模**——预测默认私有（铁律级：公开=把预测变成系统的输入，污染后续所有数据）；反馈建模=「预测公开后分布移位」审查清单+历史自反案例标注。LLM 角色：**聚合**（私有多路判词）。

### §1.9 判定清单示例（回报用，一条走通）
题：「2026-09-12 上海最高气温 > 35°C 的概率？」
拒收门：真值锚=气象台官方日数据（是）；cutoff=判据冻结早于事件决定性时点（是）→ 进入六层判定。
L5 否（非认证随机源）→ L6 否（无对抗主体）→ L1 否（大气不是有限枚举状态）→ **L3 检查**：①演化机制存在（数值天气预报模式）是；②短窗判据：历史上 24h 温度预报命中率远高于 7 天预报（可查气候统计）是；③实时观测流存在（地面站逐时数据）是；④resolve 在窗口内是 → **归 L3（primary）**。
账本记录：layer=L3, secondary_layer=null, engine=stat_baseline+aci, gate=descriptive（G2 未过）, checklist_hash=v1。

## §2 分层引擎映射 × LLM 四角色总表

| 层 | 引擎/基线 | 校准件 | LLM 角色（铁律内） | 禁止事项 |
|---|---|---|---|---|
| L1 决定论 | 程序计算（引擎跑数即真值） | 不适用（记计算错误率） | 代码生成（R-a 件），不出概率 | 禁概率话术；禁把 L1 题混入 Brier 曲线 |
| L2 系综 | 统计基率+Wilson 区间 | 全池 ECE+debiased 减偏（K F60） | 基率（整理/核对来源） | 禁无基率锚裸判 |
| L3 短窗混沌 | 基率+短窗校准（ACI×滚动窗，K 8.4） | conformal 区间+分层 SSC | 校准（出同化/特征代码） | 禁窗口外题混入（时界检验） |
| L4 自反 | 反馈建模清单+私有多路 | 私有池校准（公开历史不混入） | 聚合（私有多路判词） | **禁公开预测**；禁与已公开预测对账 |
| L5 不可约 | 认证源公布分布 | 不适用（熵下限） | 无 | 禁一切「模型更好」宣称 |
| L6 对抗 | ③结构推断（矛盾特征+belief 统计+多路聚合） | 分层校准（②类件复用） | 多路+校准 | 禁跨层迁移校准数字 |

通用纪律：每层「禁列」为硬约束；引擎缺位时（如 L3 数值模拟未建）该层只分类记账不预测——**分类与预测解耦**是本审计器与「预测万物」幻想的根本区别。

## §3 统一 Brier 账本对接

复用 predictions 表（statement 自由文本已通用，resolve/void 机制已运行）。**新增字段（一次迁移，向后兼容）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| layer | TEXT | L1-L6 或 unknown；拒收题不入 predictions（留痕于拒收日志） |
| secondary_layer | TEXT NULL | 叠加层（L4 叠加语义） |
| engine | TEXT | 引擎 id（stat_baseline/aci/proc_calc/structural/none） |
| baseline_brier | REAL | 该题所属分层基线 Brier（跨层比较禁令的技术实现：报表必须成对出示 layer_brier 与 baseline_brier 的差值） |
| public_exposure | INTEGER 0/1 | 自反暴露度（L4 必填，他层 0） |
| checklist_hash | TEXT | 判据清单版本哈希（清单改动=新版本号，不回填旧题） |
| gate | TEXT | descriptive/scored/blocked——对接 G2/G3 状态机（G2 未过则 L3 来源题恒 descriptive） |

既有 tier 字段（Tier A 机检/Tier B 自裁）保留并与 layer 正交：Tier=真值采集方式，layer=可预测性类别。**Tier A ∧ layer∈{L2,L5} 是 G2 试点期合格题型主粮**。
报表纪律：校准曲线一律按 layer 分层出图；跨层只有「题量/可判定率/争议率」三类过程指标可比（Brier 数字跨层比较=违反终审 §七迁移禁令）。

## §4 G2 门槛设计（三过程指标）

终审裁决：G2=可判定率、判据争议率、月 resolve 吞吐三过程指标达标（Brier 仅描述性），达标才允许 L3 检索代码。精确判据与采集方式如下：

| 指标 | 精确判据 | 采集方式 | 达标线（建议值，预注册后冻结） |
|---|---|---|---|
| 可判定率 | resolved+voided 题中，判据在 cutoff 时已完整冻结且真值锚可机检/第三方可查的题数 ÷ 提交总题数 | audit 状态机：submitted→judged→resolved/voided/rejected，每状态带时间戳；可判定=judged 时 checklist 全绿+锚已登记 | **≥70%**（持续 30 天窗口） |
| 判据争议率 | resolve 时点判据被质疑并导致改判或 void 的题数 ÷ 已 resolve 题数 | void/rejudge 记录表（复用 G3 三率仪表的 void 枚举+rejudged 标记） | **≤20%**（对齐终审 L2-gate void 红警线） |
| 月 resolve 吞吐 | 自然月内 resolved 题数（按 resolved_at 计） | 月报 SQL 视图（与 G3 created/resolved/void 三率仪表同一套） | **≥30/月，连续 2 个月**（n≥30 对齐 F13 准入；连续 2 月防单月偶然） |

### §4.1 修订 R3：历史回填（backfill）题的 G2 口径【2026-09-12 队长修订，因加速计划触发】

> 触发：语料库历史回填批（docs/specs/语料库历史回填-加速计划-20260912.md）一次性灌入数百条「历史事件+已存在真值」的题。**若不先定义口径，G2 三指标会被一次性灌水击穿**——这不是加速，是自欺。修订按「指标定义改动=预注册修订，checklist_hash 联动」纪律执行。

**新增字段语义（不迁移，复用既有列）**：backfill 题 statement 前缀统一 `【backfill】`，evidence[0].note 注明「历史回填批次」；实时题无此前缀。**前缀即分层键**，报表据此分窗。

| 指标 | backfill 题是否计入 | 理由 |
|---|---|---|
| 可判定率 | **计入** | 真实反映「判据能否冻结+锚能否机检」，与题何时发生无关 |
| 判据争议率 | **计入** | 同上，且 backfill 题判据更稳定，计入只会让指标更保守 |
| **月 resolve 吞吐** | **不计入「连续 2 个月」** | 该指标测的是**持续产出能力**，一次性历史回填不构成能力证据。backfill 只入「存量池厚度」单列统计 |

**防 Goodhart 补强条款（R3 新增，与 §4 原三条款并列）**：
④ **吞吐按来源分窗**：月报必须分列 `realtime_resolved` 与 `backfill_resolved`；**只有 realtime 列参与「连续 2 个月 ≥30」的达标判定**。若某月 realtime<30 而总数≥30，该月**不计入连续计数**。
⑤ **单批 backfill 上限**：单批次回填 ≤ 该 layer 现有题量的 3 倍且总量 ≤500 条，超出需重新预注册（防一次灌穿样本结构）。
⑥ **L5 Goodhart 配额扩写**（原勘察文档 §6.1#5「单一 layer 月占比 ≤60%」）：**backfill 与 realtime 两个窗口分别独立计算配额**，禁止用 realtime 窗的题去稀释 backfill 窗的彩票占比。

**诚实标注义务**：凡引用 backfill 题得出的校准结论（ECE/Brier/分辨率），报告须恒挂「含历史回填样本，非实时预测能力」标注——与 §0.3「校准数据不跨域迁移」同级别约束。

采集载体：不动 predictions 主表——过程指标全部由 gate 字段+状态时间戳的 SQL 视图产出（与 G3 仪表同代码路径，零双轨维护）。**防 Goodhart 条款**：①吞吐达标月的题目需通过 10% 随机抽检（判据质量人工复核，抽检不合格率>30% 该月不计入连续计数）；②拒收题必须记 reason（no_anchor/leak/other），拒收原因分布进月报——防止「为可判定率收垃圾题」；③指标定义改动=预注册修订（checklist_hash 联动），禁逐月改线。

### §4.2 修订 R4：G2 能力门改「样本量 + 质量分层」口径【2026-09-13 用户拍板（选项 A）】

> 触发：用户 U4/U5 质疑 + 红队 R1-F2/F3/F5 独立复核。三处证据同向：①「连续 2 月防单月偶然」统计上不成立——1000 条集中一月与分散三月证据强度相同，防偶然靠**样本量**而非月份数；②现口径实测结构性过不了——可判定率=已 resolve ÷ 提交总题数，实测上限 624/1503=41.5% < 70% 门槛，且**分母随语料主线增长而变大**（审查期 1040→1503）；③三指标无一条测预测质量（F5）——只看条数与月份时，全员填 0.5 也能满分过门。**改判据=预注册修订**；§4 原三指标与 §4.1 修订 R3 原文不删除，自本文起 G2 按 R4 执行。

**R4 能力门（新口径，全部硬判据）**

| # | 判据 | 阈值 | 与旧口径的关系 |
|---|---|---|---|
| ① | 合格题累计数（cutoff 合规 + 判据冻结且可查 + 非 tautology） | **≥60 条** | 替代「月 resolve ≥30 连续 2 月」作为能力门 |
| ② | 抽检合格率（10% 随机抽检 + 判据质量人工复核） | **≥70%** | 继承 §4 原防 Goodhart ①条，不变 |

### §4.2.1 实现口径细则（2026-09-13 · R4 落地实测后补）

> **性质声明**：本细则是**解释性**的，只钉死歧义口径；R4 的**阈值本体（≥60／≥70%／20·20·10／b(1−b)≥0.21／≥20）一字未改**。触发：`p1b/scripts/g2-report.cjs` 按 R4 重写并实跑后暴露三处歧义。

**细则 A · ③ 的 ⑦ 去重改为「披露重叠、不扣减」**
- 实测：长 horizon 21 条中 **18 条**同时是最难档（重叠率 85.7%），严格去重后独立长题仅 3 → 若严格执行，③ 判 FAIL。
- **裁定：③ 按长题总数判定（21 ≥ 10 → PASS），⑦ 降为报告项**——月报必须披露重叠数与占比。理由三条：① ③ 与 ④ 测的是两个**正交维度**（时间跨度／难度），一题同时具备两者是其价值更高，不构成重复计数；② ⑦ 的原始立意是防「同一批题充两条下限」，而该病灶在**数量门 ①**（可被灌量），不在**覆盖门 ③④**（覆盖门只要求每个维度有题、不要求题不重叠）；③ 严格去重的副作用是**激励补"容易的长题"**来满足 ③，与 ④「要难题」的立意正相冲突。
- **两种读法均已实测留档**：严格读法 ③ FAIL（独立长 3）／本细则读法 ③ PASS（长 21，重叠 18 披露）。重叠 id 样本见 `p1b/sim/out/g2-report-r4.json`。

**细则 B · ① 的 cutoff 合规判定按题源分流**
- 病象：原实现用 `created_at < 事件日` 统一判定，导致 **backfill 题天然全被排除**（其 created_at 是入库时点，晚于历史事件日）——例：b4 回填事件日在 2024–2026 上半年，入库在 2026-09-13。这不是"backfill 不合格"，是判定口径错。
- **裁定**：forward/realtime 题 → cutoffs=`created_at`（必须早于事件日）；**backfill 题 → cutoffs=`matures_at − 1 天`**（照 §4.1 修订 R3 原文「backfill 题 cutoff 必须=事件前一天」）。据此 **backfill 计入 ①**。

**细则 C · R3 ⑤「单批回填上限」按**批次**计，不按累计**
- 实测累计 backfill 701 条 > 500，被实现报为违规；但 §4.1 修订 R3 ⑤ 原文是「**单批次**回填 ≤ 该 layer 现有题量的 3 倍且总量 ≤500」——主语是单批次。
- **裁定**：按批次计。**各批实测（2026-09-13 复算，4 批）**：`wide_backfill` 280 ｜ `b4_backfill` 217 ｜ `corpus-backfill-2026-09-12` 152 ｜ `b3_backfill` 52 —— **每批均 ≤500 ✓**；累计 701 仅需在月报**披露**，不构成违规。分层 3× 上限亦全部达标（L2 303≤966／L3 374≤1098／L5 24≤252）。
> **【本小节更正 · 2026-09-13】** 本小节初版误引为「wide 280／b3 99／b4 217」：99 系把 `b3_forward` 47（**非**回填）并入了 `b3_backfill`；且漏列 `corpus-backfill-2026-09-12` 152。**C 的裁定（按批次计）不变**——各口径下最大值均 ≤500。由 g2-report 实测抓出，留痕于此。


**细则 D · ④ 的题源口径 与 ② 的抽检范围／方式**
- **D-1（④ 题源）**：R4 ④ 原文**未设题源限制**（只有 ③ 明写「长必须 realtime」），故 ④ **计入 backfill**，但必须**分列披露**：实测 808 = realtime 443 ＋ backfill 365；**仅 realtime 单列亦为 443 ≥20 → PASS**，两种口径判定一致，故不构成放水。报告须同时给出两个值。
- **D-2（② 抽检范围）**：抽检母体＝**① 合格题池**（现 1,046），抽样率 **10%**（现 n=105），**分层随机**（layer × horizon 分层；长 horizon 题必须入样，不得只抽短题）。
- **D-3（② 复核方式，三段式，须在报告披露构成）**：①**可机检段（脚本）**：resolve 的 URL／field／threshold／cmp 齐备、cutoff 合规（照细则 B）、非重言、基率落带、slug 唯一；②**判据语义段（代理复核）**：按 Q0-1／Q0-2／Q0-3 ＋「判据是否含明确对象／日期／阈值」逐题判 pass/reject 并附一句理由；③**人类校准段**：用户抽验 ≥10 题；与 ② 段一致率 **≥90%** 则采信 ② 段结果，否则按不一致率扩大人工比例。
- **D-4（诚实标注义务）**：② 的结论文本**必须写明复核构成**（机器 N 题＋代理 N 题＋用户 N 题），**不得声称"全人工复核"**；代理复核不等于独立人类审计，此残余风险随 ② 结论一并披露。

## §5 与②类校准线的关系（旁路试点，账本共用）

采纳任务书建议：**审计器是 L0-L3 阶梯的旁路试点，不是上级**。
1. 账本共用：同一 predictions 表+新增 layer 族字段；②类校准线（狼人杀判词管线）的题自动带 layer=L6；审计器不改变 L0 管线的任何既有行为（录入/结算/仪表）。
2. 引擎复用方向：**②类校准线=L6 对抗层的引擎供应方**——多路判词（W2 verdicts 表）、矛盾特征（命题 A）、分层校准件（K 8.2 流水线）全部是 L6 引擎件；审计器在 L6 层只做「把②类件挂到统一账本」的接线工作。
3. 试点次序：先导期（G2 前审计器只做三件事：分类、记账、过程仪表——零引擎建设）；L6 引擎=②类既有件直挂；L2/L5 引擎=最小统计件（基率+Wilson 区间，各半天工作量）；L1/L3/L4 引擎=分类记账但**不做预测**（引擎位=none）。
4. 前置条件不放松：G1 实测过门 + L0-L3 阶梯走完（HANDOFF L67 原文）仍是审计器进入「带引擎预测」阶段的前置；本设计只定义架构与 MVP 边界，不承诺提前。

## §6 失败长相与砍件条款

### §6.1 六种失败长相（pre-mortem，各配检测与处置）
1. **六层判定玄学化**：判据写得含糊，同一题不同人归不同层 → 争议率仪表首先在「分类争议」上爆。检测=分类复核抽检（10% 题双人背对背归类，一致率<80% 触发清单修订）。处置：checklist 逐条二元化（是/否/未知，禁形容词），修订走 checklist_hash 新版本。
2. **「万物」范围失控**：什么都往账本里塞 → 垃圾题淹没 Tier A 主粮。检测=分层题量占比+拒收原因分布月报。处置：拒收门 Q0-1/Q0-2 硬执行；每期只开一个「题型招募窗口」（如第一期只收天气/统计类 L2/L5）。
3. **引擎全建冲动**：六层六个引擎同时开工 = M 级工程×6，撞 R4 死法（终审 §八同款）。处置：§5.3 次序锁定——先导期引擎位=none，L2/L5 最小件先行，L1/L3/L4 永久「分类不预测」直到各自独立论证。
4. **跨层乱比复活**：有人拿 L6 的 Brier 和 L2 的 Brier 比「哪个层更可预测」→ 层间数字迁移禁令被报表口径破坏。处置：报表层间只出过程指标；任何跨层 Brier 对比在 UI/报告中由 baseline_brier 差值替代（同层内比基线）。
5. **G2 Goodhart**：为凑吞吐收简单题（如连收 30 条抛硬币）→ 过程指标达标但无信息量。处置：题型多样性下限（单一 layer 单一月占比≤60%）+抽检条款（§4）+层×Tier 交叉占比进月报。

> **【合并更正 2026-09-12】（S1 B3②裁定，批次 2-M1 落地；以上原文不改，第 2/5 条处置规则自本注记起合并执行）**
> 原 §6.1 第 2 条（「每期只开一个题型招募窗口」）与第 5 条（「单一 layer 单一月占比≤60%」）存在互斥隐患：单窗口若恰好只收一个 layer，60% 上限即被窗口定义击穿。合并为单一规则——**「窗口类型 × layer 配额联动表」**：
>
> | 窗口类型（每期只开一个） | 该窗口内 layer 配额（占当期入库量） |
> |---|---|
> | 天气/统计类窗口 | L2+L5 合计 ≤100%（本期主粮）；L6 ≤30%（防对冲主粮） |
> | 对局结构类窗口（sim/复盘） | L6 ≤60%（Goodhart 上限延续）；其余层按题源自然分布 |
> | 重言排除 | Q0-3（v2 清单）源头拒收，reason=tautology 不入配额统计 |
>
> 执行语义：窗口开型即锁定当期 layer 配额上限，两条旧规则成为同一张表的行列维度（窗口=行、layer 占比=列），不再分别独立生效；检测仍为分层题量占比+拒收原因分布月报（第 2 条）+层×Tier 交叉占比月报（第 5 条）。
6. **自反泄漏**：L4 题预测被公开后被引用/讨论，污染后续同域数据。处置：L4 默认 private_exposure=0 且 UI 禁分享按钮；若发生公开，该题记 reflexivity_breach=1 且同域后续题隔离统计。

### §6.2 砍件条款（YAGNI，与终审 §八对齐）
- 砍：自动分类器（NLP 判层）——MVP 人工 checklist 起步，题量证明需要后再议；
- 砍：L1/L3/L4 的预测引擎（只分类记账）；数值模拟/数据同化管线全部不做；
- 砍：跨层校准曲线、跨层排行榜、万物总评分——任何把六层压成一个数字的仪表；
- 砍：公开预测发布通道（L4 铁律的工程面）；
- 砍：长时域题、反事实题、无锚题（终审 §八原文，本设计的拒收门是它的工程实现）；
- 不做：月度盲抽复核等实验室级工程（终审 §八同款排除）。

## §8 开放接题与账本扩展（2026-09-13 用户拍板）

> 触发：阶段 3 转正后落地接题最小闭环（commit `ac47c19`）暴露两处**设计 ↔ schema 矛盾**。用户就两条各选 **A**。

**D-8.1 · unknown 的入账路径（选 A：暂不重建表）**
- **现状矛盾**：本设计 §3 写「layer ｜ L1-L6 **或 unknown**」，而实际 schema 为 `CHECK(layer IS NULL OR layer IN ('L1'...'L6'))` ⇒ **unknown 写不进 predictions**。
- **裁决**：**不单独重建** predictions。unknown 在**接题层**（intake）保留并留痕；报表侧以**只读归一视图**（如 `predictions_r4`）呈现（归一 NULL/历史值，**不改账本**）。
- **重建推迟并绑定**：放开 CHECK 的表重建与 **F4 真值分库三步**（D2 开跑硬门 G-D2-0）**合并为同一次计划内账本迁移**，避免在一个「不可变账本」上做两轮高风险重建。执行前必须：快照 ＋ sha256 ＋ 逐行拷贝校验 ＋ 回滚脚本。
- **未闭环声明**：本方案下红队 F13（unknown 出口）**只算半闭环**（接题层已闭环、入账层待合并迁移后闭环），**不得宣称 F13 已全闭**。

**D-8.2 · 外部题的挂载模型（选 A：新增 intake_questions）**
- **现状冲突**：`predictions.game_id INTEGER NOT NULL REFERENCES games(id)` ⇒ 外部题**没有「局」**。现有 `corpus:*` 容器局是**批次规避**、不是通用模型（且 `source` 口径已不一致：corpus 3／sim 31／real 51）。
- **裁决**：新增 `intake_questions` 表承载外部题 ——
  `id / statement / resolve_spec(JSON) / layer / secondary_layer / gate / checklist_hash / engine / created_at / resolved_at / outcome / evidence(JSON) / intake_reject_id(可空)`；
  与 predictions 以**可选外键**关联（外部题 resolve 后若确需并入统一 Brier 账本，再按**另行定义的域容器规则**落 predictions，**禁沿用隐式 corpus:* 模式**）。
- **与 §3 的关系**：predictions 既有列语义**不变**；`intake_questions` 为本节新增（additive）。

**细则 E · ② 抽检清单与池的绑定（防漂移，2026-09-13 补）**
- **池指纹**：audit 清单的 meta **必须**记录并打印池指纹 —— `pool_n` ＋ `generated_at` ＋ `regime`（现有 meta 已含 `pool_n/sample_n/sample_rate/generated_at`，报告须显式打印）。
- **失效规则**：若 ① 合格题池相对清单生成时**新增 >10%**（或题面集合发生实质变化），旧清单即视为**过期**；② 须**重抽重审**。未重抽前，报告必须标「**清单过期（池已变动 X%）**」，**不得以旧清单宣布 ② PASS**。
- **理由**：语料主线持续入库（一次批 +420 已在库），池每变一次，旧样本的抽样无偏性就不再被保证；这条护栏防的是「拿旧清单去签新池的门」。
- **现状**：清单生成时池=1046；其后语料批未再入库（池仍 1046），故当前清单**有效**。
