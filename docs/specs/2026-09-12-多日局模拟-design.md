# 多日局模拟 · 设计文档 v1.0（2026-09-12）

> 任务：响应用户「对局好多都是第一天」——现役 sim 语料全是一夜狼版型（单夜单昼一结算，sim-loop.cjs）。本设计把版型升级为 **6 人 3 天标准狼（屠边）**，账本从单日变跨天。只设计不实施：零代码、零落库、零 8787。
> 输入锚（已按序通读）：2026-09-11-全拟真模拟-design.md（现役 sim 宪法）× M-全拟真模拟方案.md（领域矩阵+门禁三条件）× p1b/sim/sim-loop.cjs（357 行现役实现，逐函数标注）× sim-templates-v2-题源设计.md（T1 N 参数/T7 跨天参数预留）× sentinel.cjs + batch-runner.cjs + prereg.json。
> 现役基线【已核】：30 局一夜狼批量实测（p1b/sim/out/batch/batch-progress.json）= 327 次调用 / 466,043 tokens → **均值 10.9 calls / 15,535 tokens/局**（min 10,742 / med 15,798 / max 19,299），llm-fail 7，wolf_win:village_win = 21:9。

## §1 版型定义（6 人 3 天标准狼）

### 1.1 配置与阵营选型：屠边（裁定）

- **配置**：狼人×2 + 预言家×1 + 女巫×1 + 平民×2（2 狼 2 神 2 民）。【推测：6 人局「2狼2神2民屠边」为线上常见口径，属玩法常识未逐平台核；下方算术为独立推导【已核】】
- **屠边**（采纳）：狼胜=神职全灭 ∨ 平民全灭；好人胜=狼全灭。
- **屠城**（否决）理由（算术【已核】）：屠城胜负=狼数≥好人数（平数即胜）。2狼4好开局，每昼夜至少 1 刀+1 逐=2 死，好人只需死 2 人即 2w2g 平数 → **最长线也只拖到第 3 日黎明，众数第 2 日终局**——与「多日」目标直接冲突。屠边下好人两类目标（神/民）分散，女巫解药价值放大，终局被推后。
- **终局条件（预注册写死，禁事后裁定）**：①狼全死→village_win；②神全灭∨民全灭→wolf_win；③days_max=3 兜底：第 3 昼结算后仍未分胜负 → 狼存活即 wolf_win（出现概率≈0，仅为杜绝无判局）。
- 局长数学下限：第 1 昼即胜存在窄路径（夜刀民+昼逐另一民），属正常分布尾——不作规则修补，靠 qc 天数分布监控（§7）。

### 1.2 夜规 / 昼规

- **夜**：狼刀 1（狼队统一决策，复用现役单调用口径 sim-loop.cjs:127-136）；预言家每晚验 1 人（狼/好人二值，结果**仅预言家私有**，不进公开事件）；女巫解药×1+毒药×1 全程各一瓶、**同夜至多一瓶**【裁定：简化结算，避免同夜救毒双判纠缠】；毒不可救；解药生效=平安夜；女巫可自救。死亡公告逐日公布死亡座次、**不公布死因**（刀毒不可分辨，保留博弈空间）。【推测：对齐真人局惯例】
- **昼**：存活者按座次升序各 1 次发言（死者无发言权，双批并行沿用 sim-loop.cjs:216-240）；全员投票放逐 1 人，平票 seeded_rng 破平（mulberry32 复用 sim-loop.cjs:42-50）；**放逐者遗言 1 条**（type=statement, phase=dusk），夜死者无遗言。

### 1.3 警长：不入 MVP（建议，给结论）

理由：①警长竞选=额外「上警发言+警票」子阶段，约 +6-8 calls/局（+15% 成本）且破平逻辑翻倍；②警长归票权加速放逐收敛，与「拉长对局」目标背反；③6 人局通常无警长【推测】。schema 侧警长本可零改动表达（发言顺序+vote 即可，无需新事件类型），二期走 variant JSON 扩展不阻塞——**结论：MVP 不做，二期看批 5 数据再议**。

### 1.4 与一夜狼差异逐条

| 维度 | 一夜狼（现役） | 多日局（本设计） |
|---|---|---|
| 轮次 | 单夜单昼一结算 | night/day 循环 ×1..3，每轮独立结算+胜负检查 |
| 夜间行动 | 仅狼刀 1 调用 | 狼刀+预言家验+女巫药 3 类调用；刀→巫串行依赖（巫见刀口），验独立 |
| 私有信息 | 角色告知即全部 | 预言家验人史/女巫刀口知情权/药剩余——prompt 私有上下文注入，账本零改动 |
| 死亡公告 | 单次（1 人） | 逐日 0/1/2 人+平安夜公告；死者出局（发言+投票权双失） |
| 遗言 | 无（一夜狼版型，sim-loop.cjs:211） | 放逐者 1 条 statement |
| 胜负 | 放逐即结算（放逐狼=好人胜，sim-loop.cjs:304） | 屠边程序判定，每夜每昼两个检查点 |
| 平票 | seed 破平 | 复用同款，逐日独立 |
| 成本 | 10.9 calls / 15.5k tokens【已核】 | ~31 calls / 60-65k tokens（§4） |

## §2 状态机扩展（night/day 循环 1→N）

### 2.1 循环结构（伪流程）

```
建局（角色混洗 cryptoShuffle，真值只进 meta）→
for day in 1..3:
  夜: 狼刀(1 call) → 预言家验(1 call, 狼存活时) → 女巫{救?毒?}(1 call, 存活时, 见刀口) → 程序结算 deaths[day]
      → 夜 system 事件 → 死亡公告（0/1/2 行 type=death, phase=day；0 死=平安夜 system）→ 胜负检查①
  昼: 存活者发言（含声称，双输出）→ 全员投票 → 计票破平 → 放逐公告(dusk death)+遗言 → 胜负检查②
终局: 屠边判定 → meta.truth 收口 → replay/truth md 逐日导出
```

### 2.3 events/claims/actions 零 schema 改动结论：**成立**（一条语义缺口如实声明）

- **events** 零改动【已核】：day INTEGER 1..3 直用；phase CHECK('night','day','dusk') 三值够用；type CHECK('statement','vote','death','claim','action_reveal','system') 六值够用（db.js:86-88）。平安夜=system 行，双死=2 行 death（对齐 templates-v2 §2 T1 的「夜死者=dawn death actor_seat」resolve 锚，无死亡行即存活，自洽）。
- **claims** 零改动【已核】：谓词 CHECK 7 种（db.js:96-98）覆盖验人/对跳/归票全部表达。
- **actions** 零改动但有缺口【已核】：枚举 CHECK 含 kill_target/poison_target/check_target/vote/abstain（db.js:107-108）——**无 save_target**，且 SQLite CHECK 不可 ADD COLUMN 式扩展（重建表=破坏性迁移，违零落库纪律）。裁定：**女巫救人禁落 actions**，落 meta.truth.night[d].saved + 平安夜公告，缺口记 deviations。
- players/games 零改动；唯一落库面=既有 additive ensureSimColumns（sim-loop.cjs:71-82），不新增任何迁移。

### 2.4 staging 改造

现役 stage1（LLM 全程）/stage2（纯本地）二分在多日局失效：stage1 墙钟约 7-9 min（夜段串行链 3×20-30s + 昼双批/日 2.5-3 min ×3），超单命令上限（现役 :215 已注 120s 痛点）。改 **per-day staging**：`--stage day --day N` 每日一段（夜+昼+checkpoint 落 meta，单段 ≤3 min），`--stage 2` 终结算+导出（纯本地秒级）。批量走 batch-runner.cjs:30-34 进程内调用**无 shell 上限不受影响**；单局手动跑每段用 600s 超时或后台。

### 3.2 cutoff 时点多日化

- 现役 C2 公式（templates-v2 §1：`seq(C2)=max{seq(e): e.phase≠dusk}`）在多日局**自动**=「终局日发言结束」——R-B 全信息判词口径直接成立，公式零改。
- 新增 **C2-N**（第 N 日发言结束）部分信息时点：`seq(C2-N)=max{seq(e): e.day≤N ∧ e.phase≠dusk}`，服务 T1/T7 的 N 参数——N 天题 cutoff 挂 C2-N 而非 C2，机器断言同款 `seq(C2-N)<seq(该日计票 dusk death)`。
- **现库 30 局一夜狼（games 8..37）不动不回填**；多日局落库后报数按版型分层（source+game_type 双分层，M 方案 §0.2 条款①同款）。

### 3.3 阈值重标定纪律落法

照 templates-v2 §6.4 既有纪律执行，不新立规矩：①多日 5 局试跑（批 3）后跑 v2 骨架 dry-run 出多日基率表；②全部模板基率落 **(0.15, 0.85)** 才冻结阈值（偏高端挂观察名单的 T4/T8/T9b 教训内化，§3 自检表先例）；③K/M/N 进题面生成器显式化，禁沿用 6 人一夜硬编码；④冻结后禁回填——要调参=预注册新一轮 batch。

## §4 成本预算（一夜狼 → 3 天局）

### 4.1 逐段估算（基线【已核】=30 局一夜狼实测 10.9 calls / 15,535 tokens/局，≈1.42k tokens/call）

| 段 | 调用构成 | calls | 单均 tokens | 小计 |
|---|---|---|---|---|
| 夜1+昼1 | 刀1+验1+巫1+发言5+票5 | 13 | ~1.5k | ~19.5k |
| 夜2+昼2 | 夜3+发言4+票4（逐 1 狼/民后存活 4） | ~11 | ~2.2k | ~24k |
| 夜3+昼3 | 夜2-3+发言2-3+票2-3 | ~7 | ~2.8k | ~19.5k |
| **合计/局** | | **~31（2.9×）** | | **~63k（4.2×；区间 45-80k）** |

单均涨因：streamText 全量重拉（sim-loop.cjs:221-222）随事件流线性增长（一夜狼 8-10 事件 → 多日 30+ 事件），发言/投票 prompt 是重放主体。

### 4.2 30 局总预算两口径

| 口径 | tokens | 墙钟 | 说明 |
|---|---|---|---|
| **串行**（MVP 裁定） | ~1.9M（1.8-2.4M 区间） | ~3.5-4.5h | 夜段串行链+昼双批并行 ≈7-9 min/局；风险最低，seed 复现纪律最干净 |

### 4.3 预算闸改值

## §7 风险与砍件

### 7.1 风险（各配检测+处置）

- **长局一致性**：LLM 无记忆（M 方案 §3.2 明砍记忆系统，prompt=全量），day3 发言只靠公开流+私有视角段——风险=预言家忘记自己验过谁、女巫忘药态 → 虚假矛盾污染 T2 类题真值分布。【推测：不注入私有摘要则遗忘率不可控】缓解：私有视角段注入「你此前的发言与声称摘要」（prompt 侧，零 schema）。
- **策略塌缩**：一夜狼已有座次异常信号（6 号位存活率 0.97，templates-v2 §2 T1 注），多日局保留座次升序发言或放大。检测：批 3 起跨局统计首验对象/首刀位/女巫首夜救率/对跳率 vs 真人家底；处置：升 prompt_version 换骨架或注入随机人设（禁回填已跑局）。
- **token 熔断**：prompt 随天数线性涨 + reasoning 模型偶发吃穿 max_tokens（现役 :144 根因注）→ per-day checkpoint 天然止损（单日超限只废当日，续跑锚恢复）；batch 三闸=总量 2.5M+单局 100k+llm-fail 0.1。
- **自嗨循环/局过短**：屠边窄路径存在第 1 昼终局。检测：qc 记每局天数，<2 天占比 >1/3 触发 prompt 检视。**备选拉长杠杆（预注册内换版型，非事后修补）**：7 人 3 狼 2 神 2 民屠边（好人胜需逐 3 狼，数学下限=第 3 昼；3 狼屠城开局即平数故必须配屠边）——版型 JSON 换参即切，账本 schema 全兼容。
- **继承护栏**：AI 腔（aidetect 抽 10%）/prompt 过拟合（预注册禁回填）/分布漂移（哨兵分层）三道对多日局原样生效，无新增豁免。
