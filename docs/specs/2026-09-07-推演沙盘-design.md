**能设计，且不是空想**：学术先例（清华 7-LLM 狼人杀涌现策略实验）、产品先例（AI 剧本杀 DM）、玄学排盘开源生态（npm 活跃库）三路证据都在。但经对抗审查后，**开发顺序被彻底重排：先一天级纸面实验验证核心价值，再写任何工程代码**。

## 2. 架构（四层，含修订）

### 2.1 状态层（对局状态账本）
结构化 JSON/SQLite：角色卡（身份/公开人设/私密信息）、事件流（时间戳、来源、**可见范围=谁知道**）、假设板（≥2 个竞争假设 + 依据链）。
**修订**：「谁知道什么」是一等公民，但它需要**供给方**——真值只有上帝视角（GM）知道，玩家视角只能记"他声称看到了"。P0 实验必须实测录入成本，达不到"单回合 ≤30 秒"就把产品定位降级为**纯复盘工具**。

### 2.2 推理层（LLM 研判循环）
观察 → 强制 ≥2 竞争假设 → 证据映射（结论必须引用事件 ID）→ 行动建议（问谁/试探什么/进退策略）。
**修订（诚实边界）**：事件 ID 校验只防"引用幻觉"（廉价机械查表），**不防推理幻觉**——LLM 可以精准引用真实事件然后推出错误结论，且带引用的结论反而更易取信（给幻觉镀金）。研判质量唯一验证方式 = 真实局盲测（见 P0 gate）。
**修订**：信念矩阵不做伪精确数字热力图；输出"嫌疑排序 + 依据 + 反方线索"，置信度只做相对强度表述。

### 2.3 玄学层（独立推演器）
- **确定层**：梅花易数起卦 = 取数 + 模运算，**自写实现**（一天级，天然可单测）；奇门遁甲接 npm 活跃库 `qimen-dunjia@3.1.0` 或 `mingpan`（MCP 多术数）——~~taobi~~（实测 2024-09 后停更，不接）~~MeihuaPredict~~（实测不在 npm 上，那是 GitHub 仓库名）。
- **断语层**：LLM 按传统方法论逐层解读（体用/旺衰/用神/应期），每条判词标注依据盘面要素。
- **映射层（降级）**：不做"占卜自动生成游戏事件"——审查判定其两头不讨好（GM 不认则不可控，全认则退化为随机数的叙事包皮）。定位 = 独立工具 + GM 手动采纳。

### 2.4 表现层（Web App，最后才动）
剧本工作台、推理面板（时间线/假设板/嫌疑排序）、玄学页、FPS 页（冻结）。
**纪律：终端版研判循环跑通之前，不写任何 React 组件。**

## 4. 技术选型（修订）

- **LLM 主力 = DeepSeek API**（质量优先）。本地轨为**待压测选项**而非前提：实测本机 Ollama 当前只有 embedding 模型、无对话模型；GPU 为 RTX 4060 Laptop 8G（可用约 7G）。若启用：先拉 Qwen3-8B 级模型跑 10-20k 真实上下文压测，单张研判卡 >30 秒则本地轨出局，全切 API。（注：旧环境笔记记过"Qwen3.5-9B 甜点"，与本次实测不符且公开 Qwen3 规格无 9B——以压测为准。）
- 前端 Vite + React；后端 Node 本地服务；SQLite 存对局档案（可回放）。
- 语音录入用 Web Speech API **只做草稿文本**——它没有说话人分离，转写结果落不进"谁知道"字段，自动建账不可行。

## 5. 对抗审查存档（泼冷水结论）

**决定：修订（accept 大部分反方）**。六大失败路径及预防 gate（全文见审查记录）：
1. 录入断供死亡 → gate：单回合 ≤30 秒实测
2. 研判卡无效死亡 → gate：3 场盲测信息增量，不过即杀引擎（不是换 UI 继续）
3. 通用 schema 吞噬死亡 → 纪律：P1 schema 禁止出现剧本杀之外的字段
4. 本地算力塌方死亡 → gate：8B + 10-20k ctx 压测 ≤30 秒/卡
5. 朋友局社交否决死亡 → gate：第一次朋友局实测先于一切功能优化
6. 热情死在表单上 → 纪律：UI 最后写

**残余风险（即使修订后仍在）**：
- LLM 对"蓄意欺骗"建模弱是训练目标的根本局限，盲测可能真不过——P0 就是花一天买这个答案；
- 玄学断语层无 ground truth，永远只能"参考"；
- 本方案事实层前提（模型可用性、库活跃度）已实测修正，但 P0 前仍可能发现新硬伤。

## 8. v2.1 第一性原理重建（2026-09-07 午后，用户授意"从根本想想"）

**丢弃的惯例假设**：①"AI 辅助的价值=读心/猜身份"（类比人类打法，无独立支撑）；②"引擎必须懂欺骗"（矛盾检测只需记忆+比对）；③"信念矩阵要数字置信度"（审查已弃，固化）。

**仅存的基本事实**：人类 10 人局记不住全量发言（工作记忆瓶颈=AI 账本的绝对主场）；LLM 强于结构化提取/比对/生成假设、弱于蓄意欺骗建模（审查实证）；矛盾检测=声称集×行动集机械比对，可单元测试；社交推理事件天然离散（规则事实）。

**重建：研判循环两层化**
- 第 1 层·机械矛盾检测（确定层）：账本拆「声称表+行动表」双表；输出每人"声称vs声称 / 声称vs行动"冲突对列表，每对引用两条事件序号、可机械复核。价值不依赖模型灵感，正面反制审查最强反方（LLM 欺骗建模弱）。
- 第 2 层·竞争假设推理（概率层）：必须先解释第 1 层矛盾清单，再出 ≥2 假设+嫌疑排序；矛盾定位为"嫌疑放大器"而非"判决书"（信息差/记错可能），prompt 明示。
- 账本 schema 相应调整为双表结构。

**残余约束**：命题抽取质量靠盲测抽查；单局样本小，只当方向信号；P0 判定仍以盲测协议为准。

## 9. v2.2 终稿：P0 盲测执行结果与 gate 判定（2026-09-07）

### 9.1 执行实况
- 测试材料：官方规则书 Example of Play（TB 11 人局）重建为公开层/真相层物理分离档案（docs/sandbox/p0-replay/）；真值={Benjamin 恶魔, Lachlan 投毒者, Sarah 绯红女人}，官方叙述实锤。
- 盲测执行 4 轮计划：昼1 exp（1104s）✓ / 昼1 base（1013s）✓ / 昼2 exp（280s，前台+压缩输出重试后成功）✓ / 昼2 base（后台约70分钟归队）✓。全部运行原始件存 runs/botc-rulebook/。base 昼2 与实验轨同判（Top-2={Julian, Marianna} 脱靶），H1 结论获基线数据确认。
- 实测工程事实：子代理单回合推理 15-18 分钟（本轮最大耗时根因，委派任务必须切小块控输出）；前台长批次会撞 run_code 60 分钟墙。

### 9.2 评分结论（详见 score-botc-rulebook.md）
- **H1（核心：命中率>基线）未证明**——两轨两日全部脱靶（exp: Abdallah+Douglas / Julian+Marianna；base: Marianna+Julian；真值={Benjamin, Lachlan, Sarah}）。
- **H2/H2'/H3（机制层）通过**——矛盾清单 4 硬+2 软全部引用真实事件对且语义冲突成立（含"Chef 候选对均不含 Abdallah"纯结构发现）；假设被新事件触发翻转且归因明确。
- 混杂因素如实记录：模型自认认得官方示例（记忆污染风险），但答案与真值相反，说明污染未进输出；本局永久失去正式判定材料资格。

### 9.3 根因 → 设计输入（本轮最有价值产出）
真相 hinges on 公开层完全不可见的私密信息（投毒）。"Julian 报 Sarah=Drunk"在公开证据上欠定（中毒假信息 vs 撒谎），实验轨选了证据上更自洽的错误支。**研判循环必须把 ST 的毒/醉"合法谎言"作为一等不确定性来源显式建模：矛盾层输出加"欠定标记"（声称冲突≠撒谎，须列无毒醉解释），否则确定层会系统性冤枉好人。**与 A 路调研结论互相印证。

### 9.4 steel-manning 审议（对"有条件通过"的最强反方）
- 最强反方：机制层三指标凑数放行是 gate 设计缺陷（H1 才是 gate）；矛盾层在本局恰好冤枉两个好人，"确定层"在毒醉环境下会稳定误导，两层可能比单层糟。
- 回应与修订：判定通过范围**收窄为机制层**，价值层明确未证明；矛盾层缺陷定位为 prompt/schema 可修问题（欠定标记），非架构否定；"停在 P0"部分采纳——**P1a 启动条件改为硬 gate：真实局复测（Lyingman S02E01 ~85% / Pandakill S1E7 ~70%，两局已重建并过知识对照探针）实验轨命中率 > 基线轨**，未过不进 P1a。失败处置三档（v3.0 对抗审查 R1 修订，替代旧的过不了即杀引擎口径）：① H1 过 → P1a 全量；② H1 不过但确定层线索质量 ≥ 基线 → 砍概率层，保留账本+机械矛盾检测（产品=复盘工具+矛盾检测器，即 v2.5 收窄主张的忠实形态）；③ 确定层也崩 → 杀项目。杀引擎仅指概率层（LLM 研判），不伤已被 P0 实证的机制层。评分规则须在复测点火前预注册（R2，见 docs/sandbox/adversarial-review-v3.md）。
- 决定：修订。残余风险：①真实局样本仍小（2 局），结论仍是方向性；②18 分钟/回合成本使复测周期长（每局双轨双日≈4 次×18 分钟）；③名局记忆混杂需做"知识对照"（先问模型该局答案，答出即换冷门局）。

## 10. v2.3 增补：实现方案（2026-09-07，用户问询后固化）

### 10.1 数据模型（SQLite 五主表）
events（事件流：day/phase/seq/type/payload/visibility）、claims（声称表：结构化命题+源事件）、actions（行动表：vote/kill/protect…+target/result）、contradictions（矛盾：事件对/欠定度/无辜解释）、hypotheses（假设板：证据事件对/状态/倾向）。

### 10.2 两层研判实现
第1层确定层：LLM 抽取自由文本→结构化命题（**回显人工确认后入账**）+ 纯代码冲突比对（可单测、可离线）；第2层概率层：账本切片+v1.2 模板→DeepSeek 强制 JSON→**代码强校验事件 ID 引用合法性**（不存在即丢弃重试）。输出=嫌疑排序+依据链，不做伪精确置信度。

### 10.3 前后端
Node+Fastify 本地服务（不暴露公网，key 只在服务端）；Vite+React+TS 四页面：对局设置 / 事件录入（快捷表单≤3击+文本语音草稿+抽取确认）/ 推理面板（三栏：时间线|假设板|研判卡，欠定度色标 高黄中灰，矛盾卡联动事件原文）/ 玄学页（断语标"参考非判决"）；另设复盘模式（带真值档案回放=P0 流程产品化）。

### 10.4 顺序与风险
Phase 0 真实局复测（进行中）→ Phase 1a 终端版（gate 过后，2-3 天）→ Phase 1b 网页工作台（1-2 周）；Phase 2 玄学并行。头号风险=录入断供：快捷表单+语音草稿+复盘导入三通道兜底；离线记账永远为主功能，研判为增值层。

## 11. v2.4 增补：玄学定位裁决 + 极简交互 + 无畏契约板块（2026-09-07 用户头脑风暴轮，待拍板）

### 11.1 玄学定位（第一性原理裁决，推荐 B 待拍板）
基本事实：①玄学消费需求真实（补偿性控制理论实证：焦虑→控制感补偿）；②AI 玄学赛道热但同质化拥挤（HIFORTUNE、zhouyi.bot 全术数覆盖、DeepSeek 算命破圈、AI 塔罗 5+ 款）；③本项目唯一差异化=账本推理管线（带真值复测）。推论：玄学当核心=弃差异化入红海。
**推荐方案 B（双板块）**：理性核（推理引擎，gate 保护）+ 玄学面升一级板块：①独立起卦占卜（梅花模块在建）②**对局玄学化呈现**——赛后自动生成"奇门复盘判词"（账本状态→玄学叙事，3 秒，社交货币，市面无此组合）。心智锚点唯一="你的对局外脑"，玄学是其叙事皮肤；断语明标娱乐。占卜师自动生成事件机制维持被枪毙状态（GM 手动采纳仅限远期）。
方案 C（All-in 占卜平台）仅在用户想转型娱乐产品时启用。

### 11.2 极简交互（快节奏局，P0 录入死因的 UI 解法）
①常驻流水账输入条（语音按住/打字→抽取→卡片浮出→3 秒无操作自动入"待核对"账）；②一键宏（跳身份/查杀/金水/自爆等预设打点）；③研判卡仅天结算时生成一次+推送式，局中零弹窗；④旁观者模式（整局零操作，赛后录音口述补账）；⑤天结算玄学彩蛋卡（方案 B 落地点）；⑥手机竖屏单手优先（线下桌游场景现实终端）。

### 14.1 定位（从 gate 实证与用户确认重推）
基本事实：①矛盾检测层有效率 100%（29/29 零虚构），嫌疑排序无增量（5:7）→ 产品核=矛盾+思路，非答案；②用户定位拍板：**参谋卡=思路发生器**——矛盾点/竞争思路/验证点三件套，明标「思路非答案」；③录入成本是唯一未实测生死线（P1a 必须实测，gate=单条 ≤30 秒）；④研判延迟 15-18 分钟 → 参谋卡仅天结算时生成一次。

### 14.2 范围（终端版，无 UI，零 React）
- **数据层**：SQLite（better-sqlite3）events/claims/actions 三主表先行；contradictions/hypotheses 参谋卡生成后回存。
- **CLI**：add（录入事件→LLM 结构化抽取→**回显人工确认**后入账）/ day（天结算→参谋卡）/ list / export。
- **参谋卡三件套**：①矛盾清单=**两层归属（红队 RD1 钉死）**：纯代码比对器只出「冲突对」（claims×claims、claims×actions 的字面冲突，机械可单测）；**欠定度/无辜解释归 LLM 侧**（对每个冲突对生成无辜解释清单，非空强校验——空则该冲突对不得展示），归代码会把毒/醉合法谎言当硬冲突系统性冤枉好人（§9.3 实证）；**golden 回归集=P0 全部 29 条矛盾**（语义有效率 ≥80% 方可发布，堵「比对器单测 100% 但语义层失守」的循环论证 YD1）；②竞争假设=LLM 生成 ≥2 套（带证据链+per-player stance 枚举字段供自洽校验，PD1）；③验证点=LLM 给「分辨 A/B 需要看什么」。
- **新增机械校验**：假设/排序自洽检查（假设内容与嫌疑人列表一致性——H1 认定 X 为好人则 X 不得入嫌疑 Top，机械可查；LY昼2 脱节实例的修复）。
- **玄学彩蛋**：meihua.js 挂 day 结算，天结算出玄学判词卡（娱乐标注恒挂）。
- **LLM 适配**：DeepSeek 云端 API（key 环境变量/本地配置文件，不入库不入 git）；强制 JSON 输出+代码校验+失败重试。
