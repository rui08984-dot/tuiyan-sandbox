# 参数与开关速查表 v1（人话版 · 任务 6 批次 2）

> 用途：**不用读代码就知道有哪些开关、默认是什么、改了会怎样**。改判据的开关**不在这里**（那些走 PREREG，禁随手改）。

## 一 · 环境变量（跑命令前设）

| 变量 | 人话作用 | 默认（未设时） | 影响面 |
|---|---|---|---|
| `P1B_LLM_MOCK=1` | 让所有 LLM 调用返回假响应（零网络、零费用） | 真跑 | 测试/演练专用 |
| `P1B_LLM_TIMEOUT_MS` | 单次 LLM 请求的超时（毫秒；防"永久挂死"） | **120000**（2 分钟） | 所有 LLM 路径 |
| `P1B_LLM_REASONING_EFFORT` | 让模型"少想一点"（`low`／`minimal`／`none`／`medium`／`high`） | 未设＝默认档 | 请求体；**实测只有 `low` 有效**（思考 −55%、延迟 −77%） |
| `P1B_EVIDENCE_V3=0` | 命题 A 消融用：证据块退回 2.0 三段式 | 未设＝3.0（含 d 段） | 仅实验（B 臂） |
| `P1B_EVIDENCE_V3_MODE=sham` | 命题 A 消融用：d 段换成"等 token 空特征" | 未设＝真实 d 段 | 仅实验（C 臂） |
| `LLM_API_KEY` / `DEEPSEEK_API_KEY` | key 兜底（正常应走 `p1a-terminal/config/providers.json`） | 无 | 兜底触发时服务端会告警一次 |
| `LLM_MODEL` / `LLM_BASE_URL` | 模型/端点覆盖（同上兜底） | 由 providers.json 决定 | 同上 |

## 二 · 命令行约定（各脚本通用）

| 开关 | 人话作用 | 默认 |
|---|---|---|
| `--db <path>` | 指定库文件 | 生产库（**测试请显式传**） |
| `--confirm` | **真写库**（缺省＝演练/只读） | 演练 |
| `--json <out>` / `--text <out>` | 把读数落成文件 | 只打印到屏幕 |
| `--audit <file>` | G2 报告去哪读②抽检件 | 无 → ② 显示 not-yet |
| `--run-prefix <prefix>` | 计分时限定批次前缀（防烟测混入） | 无 |
| `--since` / `--until` | 按生成时间分层（PREREG v1.1 用；**用空格格式** `2026-09-14 07:23:00`） | 无 |
| `--skip-state` / `--only-state` / `--reverse` | 扫尾与在跑**零重叠**并行 | 无 |
| `--limit` / `--max-calls` / `--max-cost` | 跑批上限（防跑飞） | 各脚本自定 |
| `--ping` | 体检时顺便探一下上游 | 关 |

## 三 · 常用命令（照抄即用）

```bash
# 现在到哪了（门读数 + 五层 + 账本，一页）
node p1b/scripts/board.cjs

# 跑批还活着吗（进程 / DB 增长 / 队列陈旧度）
node p1b/scripts/exp-health.cjs

# 命题 A 补漏回收（幂等；只补缺失变体）
P1B_LLM_REASONING_EFFORT=low node p1b/scripts/prereg-a-sweep.cjs --confirm

# 门读数重跑（含②采信）
node p1b/scripts/g2-report.cjs --audit p1b/sim/out/g2-audit-r4.json --text p1b/sim/out/g2-report-latest-20260914.out --json p1b/sim/out/g2-report-latest-20260914.json

# 五层读数重跑（只读）
node p1b/scripts/stage4-run.cjs --text p1b/sim/out/stage4-run-five-layers-20260914.out --json p1b/sim/out/stage4-run-five-layers-20260914.json

# 全量测试
cd p1b && node --test
```

## 四 · 三条判读纪律（今天两次差点误判，写死在 `exp-health` 输出里）

1. **零增长 ≠ 卡死**——先看队列是否**陈旧**（幂等写会吞掉"零增长"）；
2. **CPU 低 ≠ 卡死**——网络等待型循环不吃 CPU；
3. **wedge 判据**＝首个请求不回包 ＋ DB 零增长 ＋ 日志零字节（三件套齐全才算）。
