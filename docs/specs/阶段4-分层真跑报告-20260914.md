# 阶段 4「分层预测真跑」报告（2026-09-14 · L2/L5 最小引擎 × 真实账本）

> **这是一次只读真跑**：把**已有账本**逐题喂进已建的 L2/L5 最小引擎，拿已 resolve 的真值按层计分。
> 在此之前，引擎只被接题层（intake）在**新题**上调用过——从未对存量账本跑过。路线图阶段 4「真跑」指的就是这一步。

## 一句话结论

**引擎能在真实账本上跑通并出读数，但当前两层都还得不到「有增量」的结论**：
- **L2**：264 题可计分，Brier(engine)=**0.2487** vs Brier(常数 0.5)=0.2500，**Δ=−0.0013，95% 配对 bootstrap CI=[−0.0182, +0.0170]（含 0）** ⇒ **方向为正但不可声称优于**。
- **L5**：**0 题可计分**——引擎对全部 108 行如实 `unsupported`，且**即便补数据也没有可计分的真值**（开奖时点未到）。

诚实说：这是**「跑通了，且读数不骗人」**的结论，不是**「引擎有效」**的结论。

## 一 · 执行与口径

| 项 | 值 |
|---|---|
| 脚本 | `p1b/scripts/stage4-run.cjs`（**只读库**，零写） |
| 入库范围 | 行域 `g2_regime='R4'`，仅引擎已建的 **L2/L5**（design §5.3 先导期；L1/L3/L4/L6 恒 classify-only） |
| L2 引擎 | `p 统计基率（Wilson 95% CI）`，数据源 `evidence.baseRateNote`（与 `g2-report.parseBaseRate` 同源） |
| L5 引擎 | `p 认证源公布分布`；无结构化 `certifiedSource` → **unsupported，不编数** |
| 计分 | 仅 `outcome IS NOT NULL`：`Brier=(p−y)²`，`y∈{true,false}→{1,0}` |
| 统计 | 配对 bootstrap **B=1000、seed 987654321**（照项目既有口径）；**分层报，禁跨层池化**（design §4.3） |
| 确定性 | 已实测两次跑读数逐位一致 |

## 二 · L2 系综层读数

| 项 | 值 |
|---|---|
| 账本行 | 625 |
| 引擎出数 | **554**（71 行 `insufficient_data`＝`baseRateNote` 样本量 n<30，按 K F13 准入线不出 p） |
| 可计分（引擎出数 ∧ 已 resolve） | **264** |
| Brier(engine) | **0.2487** |
| Brier(常数 0.5) | 0.2500 |
| **Δ（engine − 0.5）** | **−0.0013** |
| **95% 配对 bootstrap CI** | **[−0.0182, +0.0170]** ⇒ **含 0** |
| 信号判定 | `engine_directionally_better_but_CI_includes_0` |
| 观测频率 | 0.5455 ｜ 引擎平均 p 0.4782 |

**判定：不可声称优于常数 0.5**（CI 含 0；Δ 量级 0.0013 远小于统计容差）。

**为什么这个结果是合理的（不是失败）**：L2 引擎的 p **本身就是基率**，其设计目标是「比硬币（0.5）好一点」。
实测 Δ=−0.0013 说明这一批题里**基率相对 0.5 的增量极弱**——这与项目既有认识一致
（α 层题多为 `b(1−b)≥0.21` 的高熵题，基率天然接近 0.5）。
**真正的「引擎增量」需要另一路模型作对照臂**（如 LLM 判词/机械特征），属阶段 4 后续件。

## 三 · L5 不可约层：**0 可计分**，原因已查明（两重）

| 层 | 账本行 | 引擎出数 | 可计分 |
|---|---|---|---|
| L5 | 108 | **0** | **0** |

**两重原因（都必须说清）**：

1. **契约形态缺口**：账本里认证源的组合概率**确实存在**，但写在 `baseRateNote` **文本**里
   （如「基率=组合数理论值 0.1818（6/33）」）；而引擎要求**结构化** `evidence.certifiedSource`
   （`{id, kind, n|outcomes}`）⇒ 引擎如实对 108 行全出 `unsupported:no_source`。
   **这不是引擎缺陷**（宁缺毋滥是其设计），**也不是数据缺陷**（值存在），是**写端未落结构化认证源**的形态缺口。
2. **真值时点未到**（更根本）：可解析认证值者 **84 行**，但其中**已 resolve 者 0**——全部是未开奖的前瞻彩票题。

⇒ **即便今天补上结构化 `certifiedSource`，L5 依然 0 可计分**，因为**开奖真值还没发生**。
    这是「等时间」而非「缺实现」——如实记录，不制造假的读数。

## 五之补 · ★重要更正：L2 **没有可用的对照臂**（本报告初稿的「下一步」是错的）

初稿写「下一个真问题＝给 L2 配对照臂」。落盘后我**去数据里找这个臂**，结果是**找不到**——如实更正如下：

### 实测证据

| 检查 | 结果 |
|---|---|
| L2 已 resolve 行 | 288（其中 `assigned_prob` 非空 **288/288**） |
| `assigned_prob` 是否＝`baseRateNote` 的基率 b | **一致 621 / 不一致 0 / 无法比 4**（最大偏差 **0.0005**，属四舍五入） |
| L2 行是否有 LLM 判词（verdicts） | **0**（判词只覆盖 sim 域 L1/L6，L2 无任何判词行） |

### 这意味着什么

1. **`assigned_prob` 就是基率本身**——它不是另一路模型，而是**同一个统计基率的复写**。
   ⇒ 用 `assigned_prob` 当「对照臂」＝**拿基率跟基率比**，Δ 恒为 0，**毫无信息量**。
2. **L2 没有任何独立信号源**：无判词、无机械特征、无第二路模型。
   ⇒ 「L2 引擎是否优于纯基率」这个问题，**在当前数据下不可回答**——不是引擎弱，是**根本没有第二路可比**。

### 为什么会出现这个局面（不是 bug，是设计使然）

- L2 题的 `baseRateNote` 是**写端算好并冻结**的外生基率（细则：`pct_share` 模式）；`assigned_prob` 直接抄它，是「记账时的声明值」。
- 项目**刻意**没给 L2 接 LLM 判词——判词线（R-A/R-B/R-C）明确只覆盖 **L6 对局域**，且已出负结果封存（§阶段 1）。
- 故 L2 层在本项目里**就是一个纯基率层**：「引擎读数」与「账本声明值」天然同一。

### 更正后的结论

| 原表述 | 更正后 |
|---|---|
| 「下一个真问题＝给 L2 配对照臂」 | ❌ **不可行**：数据里无独立信号，配出来的臂是基率自身 |
| —— | ✅ **真正的下一步**：要么**接受 L2 的定位**（它本就是「基率层」，其价值＝诚实记账与 Wilson 区间，不是"跑赢硬币"）；要么**引入新信号源**（外部模型/特征）——那是**新立项**，不是调引擎 |

**这与项目既有认识一致**：D-裁决/终极路线图把 L2 定位为「系综层＝统计基率+Wilson」，**从未承诺它跑赢硬币**；
`Δ=−0.0013 且 CI 含 0` 恰恰是「基率层老老实实等于基率」的正确表现。**本报告的价值正在于把这点钉死，防止后续有人把它当"引擎没做好"。**
