# Spec: readme · 根 README 与上手路径

> 能力地图模块 id `readme` · 依赖：`licensing` · 规模 0.8 人日
> 它是陌生人**看到的第一个字**，也是 `remote` 仓库的首屏。

## Objective

写一份**陌生人 2 分钟内读完并跑通**的根 `README.md`，并给陌生人两条 3 分钟演示路径。

**给谁用**：在 GitHub 上看到这个仓库、但完全不知道它是什么的人。
**成功的样子**：他读完知道「这是什么、我能拿它干什么、我能不能用」，并能跑起来。

## 为什么不放 `docs/RIGHTS.md` 的全文

8 条红线**必须**出现在 README 里（那是别人决定能不能用的依据），但**要压到可读的密度**。
`docs/RIGHTS.md` 存全文与出处，README 只放那段**可以直接复制**的对外版。

## Code Style

**首句与 npm description 用不同的句子**——它们是两个字段，一个被检索、一个被阅读：

| 位置 | 用哪句 | 理由 |
|---|---|---|
| **npm description / registry** | 「一个算 Brier 分的账本，LLM 不参与给数。」 | 关键词密度最高（Brier / ledger / LLM 都是搜索词）。registry 明确说「Capitals are legal and they change your search rank」 |
| **README 首屏 / 落地页** | 「把判断力做成契约，让任何 agent 都无法替你下结论。」 | 唯一同时说清「是什么」和「为什么是我」的句子 |
| 副标题 | 「记录你的判断，然后证明它没有说谎。」 | 唯一 **30 秒可验证**的承诺（真去改一笔试试？改不了） |

★**B 那句在 npm / MCP registry 场景下会失效**——它 15 个字里没有一个用户会在搜索框输入的词。**它赢在共鸣，输在检索。** 两处不要混用。

## Testing Strategy

1. **行数硬上限 80 行**（超了就是没删干净）
2. **承诺的命令可执行**：README 里出现的每条 `node ...` 都在测试里真跑一次，退出码 0
3. **禁词闸**：README 不含 UI 禁词（照 `web/dist.test.mjs` 的口径）
4. **反链检查**：README 引用的每个文件都真实存在
5. **反向锁**：把某条命令写成不存在的脚本名 ⇒ 该检查必须红

## Boundaries

- **Always**：8 条红线**逐条**在 README 里；不给试用倒计时；不承诺预测准确率
- **Ask first**：改红线措辞（那是 `docs/RIGHTS.md` 的事）
- **Never**：写「建议你预测 X」；写「准确率 90%」这类可被一句话击穿的数字

## ★两条 3 分钟演示路径（不是功能展示，是纪律展示）

**路径 A · 给第一次见的人 —— 核心是展示「拒绝」**
```
0:00 首页指那个大数：「这是系统里全部还没落定的题，**不是我记的**——
      这产品的规矩是先把归属分清」
0:25「三类：机器能自己查的、人才能答的、永远结不了的。
      **第三类不给按钮——给假按钮是欺负人**」
1:00 记一道题，重点讲第二栏「答案去哪里查」
1:40「它给了我同类题历史频率 12%，样本 34 条。
      **它没替我说『我觉得会跌』——那是我填的 40%**」
2:40「只有 1 道题，所以什么都不显示。
      **它不会拿 1 道题给我画个『你偏乐观』的结论——这才是我信它的原因**」
3:00「这页是死假设，每条挂 PREREG 的 sha16。**这是整个项目最贵的东西**」
```

**路径 B · 给要给他人看的人 —— 核心是纪律的可展示性**
```
0:00 node p1b/cli 体检 泄漏「一条命令全库扫」
0:40 node p1b/cli 门禁 锚点「**候选 0 条时它 exit 3，不是 exit 0。
      空集不许被读成通过。这是整个项目最重要的一行设计。**」
1:20 演示 exit 3 → isError:false ＋ verdict.gate='FAIL'
2:00 任意一题的六段一生，指 truth_basis.excluded
3:00 docs/specs/对外口径-20260928.md「**这页是我自己的话术管制：
      三个数字我亲手删了，因为它们会被第一问击穿**」
```

★**两条路径的核心都不是功能展示。** A 是「它会拒绝」，B 是「我亲手删掉自己的漂亮数字」。

## Success Criteria

- [ ] 根 `README.md` **≤80 行**
- [ ] 8 条红线**逐条**在 README 里
- [ ] README 里每条 `node ...` 命令在测试里真跑过、退出码 0
- [ ] 平台支持表**只写已验过的**（本轮 win-x64）
- [ ] 两条演示路径写进 README 或独立文件并被引用
- [ ] 禁词闸通过；引用的每个文件真实存在
- [ ] **反向锁**：把某条命令改成不存在的脚本名 ⇒ 该检查红
- [ ] 无试用倒计时、无准确率承诺
- [ ] 四道闸门 exit 0
