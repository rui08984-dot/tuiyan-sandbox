## 一、根因更正（实测推翻交接件表述）

交接件与 p19 锚写「judge 走宿主 env 绑死 glm，llmChat 走 providers.json ⇒ 双链分裂」。**实测不成立**：

| 检查 | 结果 |
|---|---|
| 宿主 env（LLM_MODEL/LLM_API_KEY/LLM_BASE_URL/DEEPSEEK_API_KEY） | **全部 unset**（node 实测） |
| verdicts.js:381 | 早已 `resolveLlmOptions({store})` → 读 providers.json |
| providers vs env 优先级（探针 scenario1） | providers=A 时 env=B 被忽略，model 取 providers |

| preregA-repair.cmd | 只设 `P1B_LLM_TIMEOUT_MS`，不设任何 LLM env |

⇒ 配置管道本身是通的。**真实缺陷两条**（这才是"切换不生效"的真因）：

1. **可观测性缺口**：`verdicts.model` 只是编排器写死的标签（`prereg-a-run.cjs:38` MODEL 默认
   `'tokenrhythm/glm-5.3-flash'`），与真正生效的 provider/model 脱钩 ⇒ 用户验收标准③
   「实测行 model 字段验证」**结构上无法成立**——换 provider 后行标签不变，看起来"没生效"。
2. **cards.model 过期覆盖**（UI 切模型不生效的真根因）：UI「参谋卡模型」留空的语义
   =「与抽取模型相同」，但 `upsert` 此前在留空时**保留旧 cards.model**；而下游取值优先级是
   `cards.model → extraction.model` ⇒ 只改抽取模型时，过期 cards.model 继续生效（界面已改、实际没改）。
