## §2 判词层三态的语义与实现（派单点名：逐条说明为什么是三态而不是两态）

### 2.1 三个取值落在哪、代码是什么

`p1b/src/db/verdictsStore.js:69-73` 定义，`:175-204` 是判定纯函数 `leakState`：

```js
const LEAK_STATES = ['clean', 'legacy_post_settlement', 'quarantined'];
// verdictsStore.js:70
```

### 2.2 ★为什么是三态而不是两态（逐条）

**两态（`干净 / 不干净`）会同时犯两个错，本车道的设计把它们分开了。**

| 态 | 代码 | 一句话语义（源码 `:34-40` 的自述） | 读侧待遇 |
|---|---|---|---|
| `clean` | `verdictsStore.js:180,186-190` | 判词生成时刻不晚于父题结算 | **进** `verdicts_clean` |
| `legacy_post_settlement` | `verdictsStore.js:192-198` | **明知**是结算后读数而显式豁免留存（如 R-A 读数实验整层） | 不进视图，**计入排除数并披露** |
| `quarantined` | `verdictsStore.js:38`（CHECK 白名单） | 污染方式说不清，连「只是读数」都不能断言 | 不进视图，**计入排除数并披露** |
| **NULL**（第四个落点，非枚举值） | 依赖 `ALTER TABLE ADD COLUMN` 的缺省 | 闸上线前写的行，**没核实过** | 不进视图，**计入排除数并披露** |

**① 为什么不能只有「干净 / 不干净」两态**：那一态把「**没核实**」和「**已知是读数**」读成同一件事。
前者是**我们不知道**，后者是**我们知道而且选择留下**——处置动作完全相反：
前者该去人工判定，后者该继续跑读数实验并计入排除数。合成一态 ⇒ 要么把没核实的当合规放行，
要么把明知合规豁免的行也一起拒掉。`verdictsViews.js:66-71` 因此把两桶**分开计数**，
并在 `:75-82` 的文案里分开说（"闸上线前写的历史行 N 条（未核实，不当作合规）" vs "显式豁免的结算后读数 M 条"）。

**② 为什么「历史 5156 行」落 NULL 而不是 `legacy_post_settlement`**：
把它们标成 `legacy` 等于**替 5156 行做了我们没做过的核实**——那是一次伪造。
`verdictsStore.js:30-32` 把这句写在头注里：`NULL 说的正是"没核实"，不是"合规"`。
我实测确认落点正确：副本演练后 `leak_state IS NULL = 5156`、`legacy_post_settlement = 0`（§5.3）。

**③ 为什么 `quarantined` 保留而**不是**删掉**：它是 CHECK 白名单的第三个落点，也是披露的第三个桶。
**★但我核到一件车道该说而没说清的事**：`quarantined` **本轮无任何代码路径写它**
（`verdictsStore.js:39-40` 自己写了这一点，我 grep 确认：全仓只有 `LEAK_STATES` 常量与
`verdictsViews.js:56` 的计数分支引用它，**零处赋值**）。
⇒ 它现在只是一个**预留的落点**，不是已实现的能力。列全三分桶是为了**将来出现需要人工判定的行时不必再改 CHECK**；
**但读者不许把「三个桶都在披露里」读成「三种污染方式今天都能被标注」**。

**④ 读侧必须跟着披露（这一条是本设计的核心纪律）**：
`verdictsViews.js:18-26` 头注明写「从视图里消失了这件事本身就是要告知的事实，
静默过滤等于把『这一层一半的行不能用』说成『这一层就这些行』」。
我实测：副本演练后 `verdicts_clean = 0` 行、`total_excluded = 5156`、`note` 逐字给出了这个事实。
⇒ **今天的 `verdicts_clean` 读到 0 行不是 bug，是披露纪律的正常输出**（这条进 §8-① 待拍板）。

### 2.3 ★判据：为什么不按日历日截断（964 行这一条的实际用处）

`verdictsStore.js:186` 逐字：

```js

```

**全时间戳字面比较**，不用 `predictionsStore.maturityState` 的日历日截断。
车道 A 说的复用锚我逐行核过：`p1b/src/evidence/truthBasis.js:47` 确为 `String(ra) >= String(ma)` 同一款。

## §3 leak_state 的 additive 加列做法与**零回填的证据**

### 3.1 加列是怎么做的（读源码）

`verdictsStore.js:100-109` 抽出 `addMissingColumns(conn, table, defs)`：
`PRAGMA table_info` 探测缺哪列 → 事务内逐条 `ALTER TABLE ADD COLUMN`。

**我实跑该用例为绿**（`✔ ★④c 源码锁：verdicts 层两个文件里不许出现全表回填或删除`）。
