## §4 什么信号出现时该撤

### 4.1 ⭐ 主信号：**N 个月零外部消费者**（最该盯的一条）

- **建议阈值：6 个月。** 依据（**这条是实测不是估计**）：MCP 规范的 `schema/` 目录从 2024-11-05 到 2026-07-28
  **20 个月里发布了 5 个版本**（2024-11-05 / 2025-03-26 / 2025-06-18 / 2025-11-25 / 2026-07-28，收据 §1.1 实测），
  **平均约每 5 个月一版**。一个 6 个月没人用、却要跟着每年约 2–3 次 breaking change 手工改的适配器，**是纯负债**。
  ★**「约 2–3 次/年」是我从这 5 个版本号换算的估计，不是官方承诺的节奏** —— 记下依据，别把它当硬数据引用。
- **怎么数消费者（可机械执行，不靠感觉）**：
  ```bash
  # 「有没有客户端登记过」——今天这九条全不存在，就是 0
  for f in ~/.claude.json ~/.claude/settings.json \
           ~/AppData/Roaming/Claude/claude_desktop_config.json \

           ~/AppData/Roaming/Code/User/settings.json \
           "E:/music player/.mcp.json" "E:/music player/.vscode/mcp.json" "E:/music player/.cursor/mcp.json"; do
  ```

  ★**本层刻意不记录调用方身份**（`toolTable.cjs` 与设计书红线 8），
  **所以服务端侧没有「调用次数」这个数可查** —— **消费者的唯一可数证据在客户端配置文件里**。
  **这是「默认不留痕」这条合规红线的代价：它同时让「有没有人在用」变得难查。** 记下来，别到时候忘了为什么数不出来。

### 4.4 ⠵ 维护成本超过任何真实收益

**可量化的触发条件**（任一成立）：
- 本层每半年需要动的次数 **> 它被真实调用过的次数**（今天：**前者未发生，后者 = 0**）
