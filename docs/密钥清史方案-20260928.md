## 1. 为什么必须先轮换，再清史

**清史只能擦掉记录，擦不掉已经被读走的东西。** 这个 key 从 9 月 10 日起以明文躺在
`.git/objects` 里，任何一个碰过这台机器或这个仓库副本的人都能读到。清史把门锁上，
但钥匙可能早就配出去过。所以顺序是：**先换锁，再擦门**。

### ★ 需要用户做的三步（我做不了——要登供应商后台）

1. **作废旧 key + 签发新 key**
   登 `https://tokenrhythm.studio`（自定义中转）后台，撤销以 `sk_tr_` 开头的当前 key，
   新签一把。顺手确认有没有「用量明细 / 调用日志」——如果后台能查到这把 key 被谁用过、
   用过多少，那就是外泄已发生的实锤，也是要不要追究的凭据。

2. **把新 key 写回本地配置**
   写进 `p1a-terminal/config/providers.json` 的 `providers.tokenrhythm.api_key`（该目录不入库，天然安全）。
   ⚠ 别把新 key 再粘进任何聊天窗口 / 会话记录——这条链就是这么炸的。
   顺便查一下 `odds.json` / `metaculus.json` 的两个 key 是否也在别处被复制过（本次扫描零命中，但只覆盖了 git 与本机工作区）。

3. **用新 key 冒烟验一次 + 确认旧 key 真的死了**
   跑一次实际调用，确认新 key 通；再拿旧 key 打一次，确认返回 401/403 而不是「仍然有效」。
   **第 3 步的「旧 key 已失效」是验收标准**——如果供应商后台不支持单 key 撤销、只能整账户重置，
   那就整账户重置。

### Step 3 — 改写历史（**核心，不可逆**）

```bash
cd "E:/music player"
git filter-repo --force \
  --invert-paths \
  --path .scratch/audit-3gen/_class_gen2.txt \
  --path .scratch/audit-3gen/_users_gen2-39e58053.txt
```

说明：
- `--invert-paths` = 「把列出的路径**删掉**」，而不是「只保留这些」。
- 删的是**文件**不是「含密钥的那一行」：这两个文件是会话审计的派生产物，除了密钥还有审计内容；
  但它们整个都是密钥的二次拷贝，保留价值低于泄漏风险。`PROGRESS.md`、各 `.cjs`、其余 `.jsonl`
  **不在删除范围**（已实测零命中），保留。
- tag `v0.9-l0-baseline` 会被 filter-repo 自动改指向新 commit；要撤销 tag 引用再加 `--tag-cmd`。
- **预期结果：408 个 commit 哈希全部改变。**这是不可逆点，务必在 Step 1 备份之后才跑。

### Step 4 — 清掉 6 个悬空 blob（**不做这步等于没清**）

`filter-repo` 不会自动回收「无引用的孤儿 blob」，必须显式剪枝：

```bash
cd "E:/music player"
git for-each-ref --format='delete %(refname)' refs/original/ | git update-ref --stdin   # 若 filter-repo 建了 refs/original
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

### Step 5 — 验收（三条都要绿才算清干净）

```bash
# 5a. 历史里应当零命中
git grep -I -l -E 'sk_tr_[A-Za-z0-9_-]{20,}' $(git rev-list --all) --    # 期望：无输出
# 5b. 悬空对象里应当零命中（478 → 大量减少，且无命中）
git cat-file --batch-all-objects --batch-check='%(objectname) %(objecttype)' | awk '$2=="blob"{print $1}' > /tmp/b.txt
comm -23 /tmp/b.txt <(git rev-list --all --objects | awk '{print $1}' | sort -u) | while read h; do
  git cat-file blob "$h" | grep -c -a -E 'sk_tr_[A-Za-z0-9_-]{20,}' && echo "命中: $h"
done
# 期望：无输出
# 5c. 库还是完整的
git fsck --full                                                   # 期望：no dangling / no error
git rev-list --all --count                                        # 期望：408
git log --oneline -1                                              # 期望：仍是 baseline 那句话，只是哈希变了
```

### Step 6 — 恢复方式（万一 Step 3/4 之后发现砍错了）

```bash
# 6a. 从镜像备份整库还原（最干净，把损坏的 .git 整个换掉）
rm -rf "E:/music player/.git"
git clone --mirror "E:/git-backup/music-player-pre-purge-20260928.git" tmp-restore.git
# 把 tmp-restore.git 的内容搬回 "E:/music player/.git"，然后：
git -C "E:/music player" reset --hard b178394

# 6b. 若 filter-repo 留了 refs/original/，可以不重拷，直接：
git update-ref refs/heads/master refs/original/refs/heads/master
git reflog expire --expire=now --all && git gc --prune=now
```

⚠ 恢复后**密钥又会回到历史里**——所以恢复只为「救数据」，救完必须重跑 Step 3 + 4。
