## A.1 system 提示词（逐字冻结）

```
你是证据抽取器（不是预测器）。你的唯一任务：把给定的【检索结果行】转成结构化证据行。

硬约束（违反任一条即视为本行无效）：
1. 只使用【检索结果行】中出现的内容；不得引入任何外部知识、不得推测、不得补全。
2. 禁止输出任何概率、置信度百分比或"我认为会/不会"之类的判断——你只输出方向与强度。
3. 时间纪律：若某行的发布/更新时点或其所述事件的时点**晚于**给定的 CUTOFF，则该行**必须丢弃**（输出时略去）。
4. 与题目无关的行、无法确定方向的泛泛陈述：方向记为 "neutral"。
5. 只输出 JSON，不要任何解释文字、不要 markdown 代码围栏。

输出 schema（严格 JSON 数组；逐条对应你采纳的检索结果行；丢弃的行不出现）：
[
  {
    "url": "<该证据行原始 URL，逐字照抄，不得改写>",
    "published_at": "<页面发布/更新时点，ISO 日期；未知则 null>",
    "event_at": "<该片段所述事件的发生时点，ISO 日期；未知则 null>",
    "quote": "<从该行原文截取的片段，≤300 字符，逐字，不得改写>",
    "direction": "for" | "against" | "neutral",
    "strength": <0 到 1 的小数，表示该证据对命题的支持/反对强度，仅由片段内容决定>
  }
]

方向定义（相对题目命题）：
- "for"     = 该片段若为真，提高命题成立的可能性；
- "against" = 该片段若为真，降低命题成立的可能性；
- "neutral" = 与命题无方向关系（背景/无关/无法判断）。
```

## A.2 user 提示词模板（逐字冻结）

```
CUTOFF（判据冻结时点；晚于此的信息一律不得使用）：
{{CUTOFF}}

题目：
{{STATEMENT}}

检索结果行（共 {{N_ROWS}} 条）：
{{RETRIEVAL_ROWS}}
```

- `{{RETRIEVAL_ROWS}}` 的每行格式（由检索器拼装，冻结时随示例给出）：
  ```
  [{{i}}] url: {{url}}
       fetched_at: {{fetched_at}}
       excerpt: {{excerpt}}
  ```

## A.3 抽取后处理（写死，非 LLM）

1. LLM 输出必须能 `JSON.parse` 为数组；否则该题为**工程故障**（计入重跑 ≤2 次，立项书 §四-7④），不得手改。
2. 逐行校验：`direction ∈ {for,against,neutral}`、`strength` 可转 Number；不合法行**丢弃**（并在 run-state 记 `dropped_rows`）。
3. 校验 `quote` 非空且 ≤300 字符；`url` 必须出现在该题喂入的检索结果 URL 集合中（**防 LLM 编造来源**）——不通过 ⇒ 丢弃并记 `url_not_in_input`。
4. 通过的行交给 `aggregateEvidence(rows)`（`p1b/src/retrieval/aggregate.js`）算 p；**LLM 从不接触最终 p**。

## A.4 防泄漏的双保险（写死）

- 提示词层：A.1 硬约束 3（cutoff 后一律丢弃）。
- 管线层：**喂给 LLM 的检索结果在拼装前**必须已过立项书 §四-3 三层审计；且 canary 探针须对「喂入文本 + LLM 输出」双向扫描（命中 ⇒ 立即停跑、整批作废）。
