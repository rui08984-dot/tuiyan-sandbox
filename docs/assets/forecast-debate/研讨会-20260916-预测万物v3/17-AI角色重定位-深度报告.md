## §0 执行摘要（≤300 字）

项目 AI 接入的真实图景是**三条窄通道**（判词路、证据块消费端、娱乐判词），不是 v3.0 叙事的「AI 似然估计器」。「LLM 判词无增量」负结果只覆盖「同底座×变体温度混淆×对局域 L1/L6×判词当第 6 似然路」这一个格，不覆盖全链路。2024-2026 文献水位：裸 LLM 直出概率仍显著弱于人类专家（ForecastBench），但**所有达标系统（AIA/BLF/Halawi）都是「LLM 产语言结构＋机械层管概率」的混合架构**——铁律④获得 SOTA 级外部背书，建议保留并白名单化。新角色矩阵六条，最值钱两条：**情景分支生成器**（唯一能扩容 scored=0 人口瓶颈）与 **DNA 语义提取器**（E1 已有 S 维先例、成本 S 级）。缓存结论：智谱隐式缓存≈0.5x 而非 v3.0 声称的 0.1x，中转透传未证实；判词路缓存只能防重跑，**真正的大头杠杆是 reasoning_effort=low**。

## §1 AI 现状审计：本项目 AI 接入的真实图景

### 1.1 三条窄通道（代码实证）

**通道一：判词路（唯一在役 AI 概率信号源）**。`p1b/src/routes/verdicts.js`：3 prompt 变体×3 温度（v1_evidence/0.2、v2_skeptical/0.7、v3_baserate/1.0），每路一行全量落库。LLM 唯一产出是 `verdict_text`；`implied_prob` 必须由固定末行格式「P=0.xx」**正则机械抽取**，抽取失败落 NULL 不编数（铁律④落点，verdictsStore.js 注释明言「项目两次负结果均死于 LLM 直接输出数字——temperature=0 也只是稳定地错同一个数」）。v1 臂注入证据块 3.0，v3 臂注入 LOO 基率背景行（J3/J6 教训：禁「请据此更新」式指令）。消费端 `l6_structural.js`：固定规则聚合（每变体取最新非空 implied_prob 求均值），输出带 spread[min,max]——这是纯机械层。

**通道二：证据块消费端（LLM 是读者不是作者）**。证据块 3.0＝a 事件流＋b claims 席位聚合＋c 机械特征卡＋d 机械矛盾特征（detectors/werewolf-contradictions.js W1-W6，**零 LLM、真值盲**）。整个证据侧没有任何 LLM 参与**生产**，LLM 只在判词路消费它。

**通道三：赛后娱乐判词**。`p1b/src/lib/llmChat.js`，文件头明文「禁止接入任何游戏研判功能」，无重试环、失败落 mock_fallback。

### 1.2 「LLM 判词无增量」负结果的适用边界（本轮最重要的澄清）

verdicts 表 readonly 实查的三个事实：4766 行判词只覆盖 **450/1972 题（23%）**；这 450 题全部是 L1（180）与 L6（270），**gate=scored 人口为零**；model 列 4498/4766 为单一底座 tokenrhythm/glm-5.3-flash；且 prompt_variant 与 temperature **完全一一混淆**（11 号件 §4 原判）。据此，这个负结果的严格表述是四条边界内的：

1. **域边界**：它判的是「判词对**狼人对局域** L1/L6 题的增量」。占 scored 潜在人口主力（L2/L3 已解 820 题、openmeteo/dbnomics 等数值域）的题上，**LLM 从未被上过场**——不是测了无增量，是根本没测。
2. **角色边界**：它判的是「判词作为**第 6 路似然信号**」的增量。LLM 做「不出概率的结构产出」（提取、分解、归因）的价值从未被测过。
3. **多样性边界**：单底座＋变体温度混淆下，路间分歧不可归因。多底座、解耦后的多样性价值从未被测过（11 号件已留 3×3 解耦对照实验作低成本解锁）。
4. **量纲边界**：判据是 Brier 增量。LLM 产出的**可解释性、审计性、过锚扩容**等非 Brier 价值不在此判据覆盖内。

一句话：负结果杀死的是「**判词当对局题第 6 似然路**」这一个用法，不是「LLM 在预测系统全链路的潜力」。用户「反正如果 AI……」的自我怀疑，正确答案就藏在这四条边界里。

### 1.3 成本现实（环境事实）

tokenrhythm 中转 glm-5.3-flash **强制深度思考**（关思考→HTTP 400 REASONING_REQUIRED），默认档单次判词≈7 分钟且 max_tokens 被推理 token 吃掉；`P1B_LLM_REASONING_EFFORT=low` 是唯一降压旋钮（实测思考 token 1245→562、延迟 33.5s→7.8s；minimal/none 无效）。llmOptions.js 已为全链套 120s AbortController 超时（2026-09-13 补漏跑批永久挂死事故的修复）。**成本结构的关键事实：判词 prompt 总输入仅数百 token，大头是思考型输出 token——输入侧优化（缓存）与输出侧优化（降思考档）不是同一量级的杠杆**，这个事实直接决定 §5 的结论。

## §2 最新文献盘点（2024-2026）：LLM 预测能力的真实水位

逐篇给出「对我们可用的具体机制」，每条挂已核实锚点。

### 2.1 水位线：裸 LLM 直出概率仍不达标

- **ForecastBench**（Karger et al., arXiv:2409.19839）：动态 1000 题防泄漏基准，专家人类预测者显著强于最强 LLM（p<0.001），公开排行榜持续更新。**可用机制**：①「只测揭晓后才有答案的题」是我们预注册纪律的文献同款；②排行榜按动态更新防数据污染——对我们公开验证层的直接参照。
- **Halawi et al.**（arXiv:2402.18563）：检索增强＋生成＋聚合三件套的系统**接近**竞争性人类群体，部分设定超过。**可用机制**：达标靠系统（检索+聚合），不靠裸模型——与本项目「机械引擎主干」同构。
- **Abolghasemi et al.**（DOI 10.1016/j.ijforecast.2024.07.003）：零售域 123 人 vs 5 LLM，LLM 不稳定优于人类，统计模型基座对两者都未必有益。**可用机制**：「LLM 不稳定」本身是结论——任何单点 LLM 概率都须按格披露而非全局宣称。

### 2.2 达标系统的共同架构（最重要的文献事实）

- **AIA Forecaster**（Alur et al., arXiv:2511.07678；编号勘误见诚实声明②）：三组件＝agentic search 高质量新闻源＋supervisor agent 调和同事件分歧预测＋**统计校准层反 LLM 行为偏置**。在 ForecastBench 达到与人类 superforecaster 持平；在预测市场基准上**输给市场共识**，但 AIA×市场 ensemble 胜过市场单独。**可用机制**：①概率出口必须是统计校准层——LLM 自报置信不可直接用（与我们铁律④同构，SOTA 级背书）；②「additive information」框架：AI 的价值主张是**与机械/市场基线的互补增量**，不是单打精度——这正是本报告新角色矩阵的设计轴；③supervisor 调和分歧＝我们 l6 spread 字段的文献升级版。
- **BLF**（Kevin Murphy, arXiv:2604.18576，ForecastBench SOTA）：**linguistic belief state**（半结构化「数字＋自然语言证据摘要」信念态，每步由 LLM 更新，区别于把证据无结构堆进 context）＋层级多试聚合（logit 空间均值收缩）＋层级 Platt 校准。消融：三组件均有贡献；mixed effects：**题间变异占 62% 方差**。**可用机制**：①「LLM 全程只产语言结构、概率永远在机械层」的 SOTA 实例——铁律④的正面镜像；②题难度（≈我们的 DNA）比模型微调更重要——E1/E2 路线的外部定心丸；③belief state 的「结构化证据摘要」正是 §3 角色⑤的文献形态。
- **Wisdom of the Silicon Crowd**（Schoenegger et al., DOI 10.1126/sciadv.adp1528 / arXiv:2402.19379）：12 个**异构** LLM ensemble 与 925 人人类群体统计不可分；LLM 见到人类中位数预测后精度 +17~28%，但「简单平均人类＋机器」**优于**「让 LLM 看了再更新」；LLM 有顺从偏置（均值系统性 >50%）。**可用机制**：①聚合增益靠**多源平均**不靠「信息注入再更新」——与项目 J3/J6「更新指令劣化」教训完全同向；②获取多样性必须换底座——12 个异构模型 vs 我们单底座 3 变体，第二把 key 是信息多样性刚需而非冗余。

### 2.3 三个警告

- **Prompt 工程几乎无用＋贝叶斯指令负效应**（Schoenegger et al., arXiv:2506.01578）：38 种 prompt×4 模型＋o1，多数修改增益可忽略；基率引用有微弱正效应；**鼓励模型做贝叶斯推理的指令有强负效应**。对 v3.0 直接打击：第 3 层「AI 作为似然估计器参与贝叶斯推理」的叙事若落成指令，预期是负收益。v3_baserate 微弱正效应与「基率引用微弱正效应」同向——这条已有项目内镜像。
- **同质化陷阱**（WC2026-Agents, arXiv:2607.17765）：4 个前沿 agent 在 104 场世界杯 92% 给出相同首选、无一跑赢市场 Brier。**可用机制**：同代 LLM 信号高度重叠——单底座多变体「辩论/情景/专家池」不会有信息增量（λ≈1 的文献版）。
- **市场边界**（Zemani, DOI 10.2139/ssrn.6944258）：前沿 LLM 相对市场价格几乎零信息增量，两年 scaling 未改变。**可用机制**：有认证源/市场价的题（我们 L5 层的领地）LLM 无增量是常态——L5 机械认证源的地位不可被 AI 替代。
- （如实标注：multi-agent debate 直接检验预测校准的 2024-2026 实证本轮检索轮空未检得；SWE-Debate（arXiv:2507.23348）等 debate 文献均在代码/定位任务，不外推。）

### 2.4 LLM 的比较优势在哪（分工原则的文献根据）

- **数值外推不是 LLM 的活**：LLMTime（arXiv:2310.07820）LLM 数字时间序列 zero-shot 仅「可比肩专用模型」，且 GPT-4 因分词与 RLHF 校准损伤反而不如 GPT-3；Time-LLM（DOI 10.1201/9781003616719-7）须重编程+对齐才能用。⇒ 天气/经济等数值域继续走 L2/L3 机械引擎是文献支持的安排。
- **语义→结构是 LLM 的专家级活**：Lippert et al.（DOI 10.1098/rsos.240682）GPT-4 预测行为科学实验结果与结局相关 0.89，匹配 119 名专家；AI-Augmented Predictions（DOI 10.1145/3707649）LLM 助手使人类预测精度 +24~28%。⇒ LLM 当**人机互补的语义前端**有正实证。
- **前沿方向**（Lee et al., arXiv:2507.19477，立场文）：RL 大规模训练超预测师级 LLM 是趋势，但受 noisiness-sparsity/知识截止/奖励结构三难约束——超出本项目产能，仅作 2027 复测锚点。

**分工原则（本报告的生成轴）：LLM 的比较优势＝把非结构化语义转成结构；机械系统的比较优势＝把结构转成数字。**

## §3 AI 角色矩阵重设计：六个候选的逐条裁决

每条给：输入输出／为什么是 LLM（对比人与传统算法）／判据／成本／与铁律④的关系／**与已有机械引擎的接缝（数据从哪来、结果进哪张表）**。

### 角色① DNA 八维语义提取器 —— 立项（P3 优先级）

- **输入输出**：输入＝题面 statement＋domain/kind 元数据；输出＝Ω/T/I/M/A/R/S/O 八维**枚举标签 JSON**（每维选一档，不出任何数字概率）。
- **为什么 LLM**：八维是纯语义范畴（「机制黑箱吗」「有反身性吗」），规则引擎写不出（LLMTime/Lippert 证明的语义→结构专家级任务）；人类标 1972 题不现实。为什么不是传统算法：无训练数据、无标注语料。
- **判据**：抽样 100 题人机双向一致率 ≥85%（照 E2 C1 范式，分歧格交「有无 Brier 代价」裁决）；标签 sha 冻结先于任何读数（照 PREREG 纪律）。
- **与铁律④**：完全合规——输出是结构标签不是概率。
- **接缝**：新表 `dna_tags(prediction_id, dimension, value, model, run_id, created_at)`，读侧派生、零账本写。E1 PREREG（12 号件）的 S 维操作化已有先例与口径，本角色是它的推广。**用途红线**：只作分域记账/审计（03 号件裁定），**禁止**作 DNA→配方绩效路由（撞 KK516 null）。
- **成本**：S 级。1972 题一次性＋增量，reasoning low 每题 ≈8s，全量约 4.5 小时机器时。
- **缓存潜力：高**（§5.3）——按「域×题面模板」聚簇，模板化题面（账本实查 26% 强模板复用）命中率高。

### 角色② 类比检索键构造器 —— 立项（与 O1b 绑定，S 级）

- **输入输出**：输入＝题面；输出＝结构化检索键（domain×kind×layer×变量名×获取模式），喂给 O1b「同变量异获取模式」参照类 SQL 查询。**产出不是案例本身，是查询键**——11 号件已把类比算子收紧为该子形态，本角色不越界。
- **为什么 LLM**：把「本局放逐投票最高票数≥3」对齐到 game_type=werewolf×L6 结构格需要语义对齐；规则表维护成本高于让 LLM 每题产键。
- **判据**：检索键与 domain.js 单一真源格一致率；LLM 错键即退回 SQL 默认键（fail-safe 到现役行为）。
- **与铁律④**：合规（键不是数）。
- **接缝**：读 domain.js/l2_baseline.js 的格定义；产出只进查询参数，不落新表（或落 `retrieval_keys` 日志表供审计）。
- **成本**：S。**缓存潜力：高**（同模板同键）。

### 角色③ 情景树分支生成器 —— 立项（P4，全矩阵最值钱）

- **输入输出**：输入＝已入库题面＋其 Gate-Anchor 约束；输出＝分支结构文本：「若分支 B 成立则可观察信号 Y」，每支挂靠**一个可结算子命题**（child_statement）。只出分支结构，不出概率——概率由机械引擎对每个子命题独立产出。
- **为什么 LLM**：10 号件已救活分解算子为「多路角色输入准备＋过锚扩容工具」（Least-to-Most, arXiv:2205.10625 已核实），情景分支是其推广；拆分需要世界语义（「首夜平安」可拆为「首夜无人被刀/被刀未死」），机械规则不可为。
- **判据**：**子题过锚率**（10 号件原文判据），不设 Brier 承诺；分支冻结（run_id）先于子题结算。
- **与铁律④**：合规。**接缝**：新表 `scenario_branches(parent_prediction_id, branch_text, child_statement, anchor_status, run_id)`；子题过锚后进入正常 intake→stage4 管线，与既有 scored 口径无缝。
- **战略价值**：当前账本 **scored 人口为零**是全项目最大瓶颈（11 号件 §7 实证）；本角色是六条角色里唯一能**批量扩容可结算子命题**的——直接给 E1/E2 与校准 A/B 供料，属于「产数据的角色」。
- **成本**：M 级（PREREG＋脚本＋过锚审核）。**缓存潜力：中**（父题模板复用高，但分支文本随局语境变化）。

### 角色④ 归因报告撰写者 —— 立项（S 级，零风险件）

- **输入输出**：输入＝ablation.cjs 消融输出＋g2-report/E1/E2 结果 JSON；输出＝人话版归因报告。
- **为什么 LLM**：数字归因机械层已全做完（ablation.cjs 2158 行×3 臂骨架在役），缺的只是把数字变可读文本——纯写作任务，LLM 比较优势无争议；人类做不了（一人团队产能），模板引擎做不了（数字之间的关系叙述）。
- **判据**：**零新数字校验**——报告内所有数值必须能在源 JSON 找到（引用对账脚本，防 LLM 编数），幻觉防线机械化。
- **与铁律④**：合规且是铁律④精神在写作域的延伸（数字只能来自机械层）。
- **接缝**：读 `sim/out/*.json`，写 vault 报告 markdown；零账本写。
- **成本**：S。**缓存潜力：低**（每次输入都是新结果集）。

### 角色⑤ 题面→结构化证据行扩量 —— 立项（M 级，已有范式的正确扩向）

- **输入输出**：沿用 verdicts 范式（LLM 出文本＋末行格式机械抽取），扩向不是「多出概率」而是「多出结构化证据行」：LLM 读逐日事件流产出「关键矛盾候选清单」，喂给 detectors/werewolf-contradictions.js 做**机械复核**——LLM 当候选生成器，检测器当裁判。
- **为什么 LLM**：d 段检测器 W1-W6 是确定性规则，覆盖面限于已知矛盾型；LLM 候选生成能把检测器抓不到的语义矛盾「提名」出来再交规则审。BLF 的 linguistic belief state 是文献形态。
- **判据**：候选行被机械检测器复核的确认率（提名精度）；确认行才可进证据块。
- **与铁律④**：合规（证据行是文本）。**接缝**：产出进证据块 3.0 之后的 e 段（新增段，照「只增不改」先例，可开关回退）；原始提名落 `verdicts` 同款旁路表供审计。
- **成本**：M。**缓存潜力：低-中**（逐日事件流逐局不同）。

### 角色⑥ 多智能体辩论主持协议 —— **不立项**（唯一否决）

三连否决理由：①文献轮空——2024-2026 未检得 debate 对预测校准增益的直接实证（诚实声明①），仅有的 debate 文献在代码/定位任务（arXiv:2507.23348），不可外推；②同质性——WC2026 四前沿 agent 92% 相同首选（arXiv:2607.17765）＋本项目单底座 λ≈1（03 §三），辩论输入同源，无信息差可辩；③纪律债——变体↔温度混淆的教训（11 §4）未用 3×3 解耦实验消化前，新增辩论臂只会复产混淆数据。**替代形态**：把「辩论」降格为「分歧检测器」——l6_structural.js 已输出 spread[min,max]，spread 超阈值触发人工审阅，零 LLM、零成本。若未来第二把 key 落地（异构底座 12 模型级 ensemble 有文献背书），辩论议题可重立票，但那首先是**多源聚合**问题，不是辩论协议问题。

### 3.7 铁律④裁决：保留原条文＋白名单化修订

**建议：保留，且扩写而非放宽。** 保留的三重根据：①外部——2024-2026 三个 SOTA 系统（AIA/BLF/Halawi）全部在概率出口设机械层，LLM 自报概率不可直用是文献共识（另加 Confident 笔记 LLM 自报置信 Brier 比 7.1 的内部锚）；②内部——两次负结果「temperature=0 也稳定错同一个数」；③反方证据也被覆盖——PSR 笔记「LLM 概率可塑形、Brier 型变体 information 分量最高」的正确用法正是**先机械抽取再校准**（AIA 表 E Platt 0.1140→0.1076），不构成废除理由。**修订**：原条文「LLM 出逻辑不出数字」在实践里已演化出灰色地带——末行 P=0.xx 其实是 LLM 给的数字。精确化表述：**LLM 可表达倾向，但任何进入数值列的数必须经确定性正则抽取、必须伴随可追溯 verdict_text、且只能作「证据信号」进固定规则聚合，不得作最终概率直出**。同时新增附录：LLM 允许输出 schema 白名单（结构标签／检索键／分支文本／证据行／归因文本），每类配一个确定性校验器——这是把灰色地带收进显式管理，不是放宽。

## §4 给用户的直话

用户说「是不是我说的也不准」——逐点回应 v3.0 的 AI 定位，以及「围绕 AI 接入搞」的正确姿势。

1. **「AI 作为似然估计器」（§三第 3 层）：定位词错，方向巧合对。** 错在：现状 verdicts 是 L6 聚合的**证据信号**，不是可求值的似然函数（03 号件已裁定「黑箱似然」是重包装）；且文献证明「让 LLM 像贝叶斯学派那样推理」是强负效应指令（arXiv:2506.01578）——v3.0 若把这层叙事落成 prompt，预期负收益。对在：「AI 不直接输出概率」与铁律④一致。v3.1 正确写法：AI 似然算子改称「**AI 语义算子**：产出结构化证据行与判词信号，经机械抽取进固定规则聚合」。
2. **「GLM5.3、DeepSeek 适合语言理解类算子」：举例基本合适，但暴露了真正的问题——单底座依赖。** 4498/4766 判词一个底座；文献说聚合增益靠异构多源（12-LLM ensemble 才追平人类群体）。第二把 key（providers 表已预留）不是省钱项，是**信息多样性刚需**。顺手提醒：llmChat.js 默认 model 是 deepseek-chat、默认 baseUrl 是 api.deepseek.com——与 tokenrhythm 并存说明双底座在配置层本就通了一半。
3. **「AI 似然算子＝13 算子之一」：v3.0 是在重新发明已有等价物。** 10 号件已裁定 AI 似然＝verdictsStore 多路判词收编（O3），v3.0 把它再列为新架构组件属于倒退；13 算子库已被 8 活跃＋5 封存取代，勿在 v3.1 里复活。
4. **「Prompt 缓存 0.1x 计费」（§6.3）：查证为错**（§5.1 详证）——智谱官方文档为隐式缓存≈**0.5x**，0.1x 是 DeepSeek 直连语境的数字；tokenrhythm 中转透传未证实。条款必须改写。
5. **「AI 是产品的灵魂吗？」——这句话问反了，但方向有价值。** 文献与本项目负结果同向证明：AI 当**灵魂**（出概率、当似然、当专家池）必败——ForecastBench 裸 LLM 输人类专家、单底座判词无增量、市场题零增量。AI 当**手脚＋嘴**（读语义、出结构、写归因）必赚——这正是 AIA/BLF 的 SOTA 架构，也是本项目已有资产（证据块 3.0、正则抽取、l6 固定聚合）的自然延长线。**正确姿势：机械主干当灵魂（可复现、可校准、可证伪），AI 当最勤奋的手脚（六个新角色）和唯一的嘴（归因报告）。**「围绕 AI 接入来搞」的正确翻译不是「AI 出预测」，而是「AI 把万物翻译成机械引擎能吃的结构」——预测万物的入口是语言，AI 守入口；结算万物的出口是数字，机械守出口。这恰是用户直觉里对的部分：AI 接入确实是产品差异化的关键——但差异化在**入口的翻译能力**，不在出口的概率生成。
6. **顺带纠一个任务书外的隐忧**：v3.0 参考名单里的污染项（02 号件已裁 8 项）属于 AI 叙事的一部分——AI 定位修订时须一并执行 11 号件 §5 的替换文本，勿让「AI 灵魂论」借污染引用还魂。

## §5 AI 调用的缓存命中优化设计（主持棒补充指令）

### 5.1 上游能力查证：v3.0 的 0.1x 是空头支票

实抓智谱官方文档（docs.bigmodel.cn/cn/guide/capabilities/cache.md，经 llms.txt 索引导航）：GLM 支持**隐式上下文缓存**，原文「缓存命中的 Token 按优惠价格计费（**通常为标准价格的 50%**）」——即 ≈0.5x，**不是 v3.0 §6.3 写的 0.1x**。要点：①隐式缓存无需配置，「完全相同的内容缓存命中率最高」，细微格式差异降命中率；②TTL 未公布（只写「过期后重新计算」）；③glm-5.3-flash **未被明文列出**（页面示例用 glm-5.3，功能列表写 GLM-5.2/5.1/5 系列「等」）；④官方未见显式缓存管理 API。**0.1x 的来源考据**：DeepSeek 官方缓存命中价确为 0.1x 输入价——v3.0 大概率把 DeepSeek 语境的数字错配到 GLM 语境。**两层未证实**：tokenrhythm 中转是否透传 `usage.prompt_tokens_details.cached_tokens` 与 0.5x 折扣，文档不可得；**实证途径已备**——llmChat.js 的 noteUsage 只记 prompt/completion/total 三项，加一行记录 `prompt_tokens_details.cached_tokens`（additive，S 级，零契约变化）即可在下一批判词上实测中转透传。**改写条款**：v3.1 应写「缓存命中价按上游实测为准（智谱隐式缓存 ≈0.5x；DeepSeek 直连 0.1x；中转透传待实测），0.1x 为非保证下界」——若无实测支撑，0.1x 条款在本项目＝空头支票，必须降格为「待实证项」。

### 5.2 三层缓存的现实适配（逐层：适用角色/键设计/预期命中率/失效策略）

- **结果缓存（最高优先级，S 级工程）**。项目已有先例：verdicts 幂等键 `(prediction_id, prompt_variant, temperature, COALESCE(run_id,''))` UNIQUE 索引＋INSERT OR IGNORE 保首条。泛化为**预检缓存**：判词生成**前**先查 `规范化题面哈希 norm(statement) + 证据块哈希 hash(evidence_json) + prompt 版本号 + 温度`，命中即跳过调用直接落库引用。判据：历史重跑全命中（R-A/R-B/R-C 三批、命题 A 2158 行×3 臂消融、2026-09-13 补漏跑批都发生过整批重跑）；首跑命中率诚实估计 0~10%（同 statement 不同局的证据块不同，不会命中——这是**正确行为**，防跨局信息泄漏）。失效策略：prompt 版本号递进即整代失效，旧代结果保留可审计。
- **Prompt 前缀缓存（顺手做，收益上限小）**。现状已合格：SYSTEM_HEAD＋VARIANT_ANGLE＋OUTPUT_FORMAT_RULE 是稳定 system 前缀，动态内容全部在 user 尾部——智谱隐式缓存的前提（前缀逐字节相同）天然满足。但诚实估算收益上限：判词 prompt 总输入约 500-800 token，稳定前缀约 200 token，即便 0.5x 命中，单次节省≈100 token 等效价，而单次成本大头是思考型输出 token——**前缀缓存收益 <10% 且与思考输出无关**。失效策略：SYSTEM_HEAD 属预注册契约文本，改版须 run_id 递进。
- **语义缓存（不建，明确否决）**。账本实查：1972 题 statement 高度模板化（40 字符规范化前缀重复组 45 组覆盖 506 行 ≈26%；但随机对 Jaccard>0.5 仅 4.2%；长度 p50=136/p90=176 字符）。看似高命中，实则三重否决：①**同模板不同局＝不同事件**——「本局狼人阵营胜利」在 A 局和 B 局是两个世界，v1 臂证据块含局专属事件流，语义复用＝把 A 局判词喂给 B 局，制造信息泄漏与虚假独立性；②题面短，向量检索基建（embedding+阈值+TTL）成本高于收益；③真正想抓的「同义改写」在结构化题面下极少发生。**语义缓存的正确靶点不是判词路，是 §5.3 的新角色**。

### 5.3 新角色的缓存前置设计（逐个标命中潜力）

| 角色 | 缓存潜力 | 为什么 | 键设计 |
|---|---|---|---|
| ① DNA 提取器 | **高** | 输入熵低：题面模板复用 ≈26%，八维标签与局专属证据无关，同模板必同标签 | `hash(norm(statement) 模板化) + prompt 版本`，模板化＝剥离数字/日期/座位号 |
| ② 检索键构造器 | **高** | 同模板同键；键集可先枚举缓存为查找表 | 同① |
| ③ 情景分支生成器 | **中** | 父题模板复用高，但分支文本随局语境（第几天/哪些席位活着）变化 | `父题哈希 + 局状态摘要哈希` |
| ④ 归因撰写者 | **低（≈零）** | 每次输入都是新结果集（消融/回测输出唯一） | 不设缓存，直写 |
| ⑤ 证据行扩量 | **低-中** | 逐日事件流逐局不同 | `局 id + 事件窗哈希` |
| ⑥ 辩论主持（否决） | — | 不立项 | — |

### 5.4 成本收益估算与明确结论

对照真实跑批史：命题 A 全量 2158 行×3 臂（消融重放）、D2 400 题 HB、verdicts 4766 行三批。在 reasoning low（7.8s/次）下：①**结果缓存预检**＝唯一确定收益项——重跑场景（约占历史调用 30-50% 的批次）整批免调用；首跑场景收益≈0。②**前缀缓存**＝≤10% 输入侧节省，且有中转透传未证实的折扣。③**语义缓存**＝负收益（泄漏风险＋基建成本）。④**DNA/检索键模板缓存**＝角色①②的全量成本直降约四分之一（506/1972）。**结论：值得做的是两件 S 级小事——结果缓存预检＋cached_tokens 实测打点；不值得做的是语义缓存；而比所有缓存加起来大一个量级的杠杆是 reasoning_effort=low 固化为跑批默认**（思考 token −55%、延迟 −77%，且不可被任何缓存替代——缓存只省输入，思考省的是输出）。给判据：若 cached_tokens 实测显示中转透传折扣成立，则前缀缓存升级为 P2；若不成立，缓存线在结果缓存后封盘，不再投入。

## §6 一句话总纲

AI 在本系统里的正当位置已经被它自己的负结果和 2024-2026 的 SOTA 文献同时钉死：**不出概率的语义层**——六个新角色（DNA 提取器、检索键构造器、情景分支生成器、归因撰写者、证据行扩量五个立项＋辩论主持一个否决）全部是「把万物翻译成机械引擎能吃的结构」，铁律④保留并白名单化，缓存只做结果预检与实测打点、放弃语义缓存，而真正的成本灵魂是 reasoning_effort=low——AI 是产品最勤奋的手脚和唯一的嘴，不是灵魂；灵魂是那条从 DNA 标签到 Brier 结算全程可复现的机械主干。
