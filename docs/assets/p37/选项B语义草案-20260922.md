## §2 ★语义定义（本件的核心产出）

### 2.1 `commence_utc`（赔率族）

```
字段：resolve.commence_utc（如 "2026-09-18T19:00:00Z"）
语义：比赛**开赛时刻**（UTC）
窗口起点：该时刻所在**日**（slice(0,10) ⇒ "2026-09-18"）
判据：cutoff < 窗口起点 ⇒ pass（与 gate 现有规则一致）
```

**为何用"日"而非"时刻"**：gate 现有全部规则都归到**日粒度**（`day()` 函数）。
⇒ **保持一致**（不引入新的粒度）——★**粒度议题**另有决策①覆盖（U 型题／cwl），**不在本草案范围**。

**边界**：若 `commence_utc` 为 `null`/非法 ⇒ 返回 `null`（⇒ `unverifiable`，**不猜**）。

### 2.2 `week_start`（周窗口族）

```
字段：resolve.week_start（如 "2026-08-30"）/ meta.week_start
语义：周窗口的**起点**（含）
窗口起点：该日
判据：cutoff < 窗口起点 ⇒ pass
```

### 2.3 ★★关键风险：`week_start` 与 `week_end` **语义相反**

gate **现认** `week_end` / `week`（**终点**）；本草案要加的是 `week_start`（**起点**）。

| 字段 | 语义 | 若混用 |
|---|---|---|
| `week_end` | 窗口**终点**（如 09-05）| 用终点当起点 ⇒ 判据**偏严**（cutoff 要早于终点）|
| `week_start` | 窗口**起点**（如 08-30）| 用起点当起点 ⇒ **正确** |

**实测对照**（id=930）：

```
week_start = 2026-08-30，week_end = 2026-09-05
cutoff     = 2026-08-29
用 week_start 判：08-29 < 08-30 ⇒ pass ✓（正确）
用 week_end   判：08-29 < 09-05 ⇒ pass ✓（巧合也 pass，但语义错）
```

⇒ ★**必须显式区分**：`week_start` → 起点；`week_end`/`week` → **保持现状**（gate 现有行为不动）。

**★源码依据**（本草案已核）：`corpus-thicken.cjs` L464 的 `maturesAt: c.resolve.date || c.resolve.week_end || c.resolve.week_start`
⇒ **`week_end` 被用作「到期日」（＝窗口终点）** ⇒ 证实「起点 vs 终点」的区分成立。

### 2.4 ★优先级顺序（插入位置）

gate 现有顺序（`eventWindowStart`）：
```
date → meta.date → start → epiweek → meta.epiweek → month → period → year
     → meta.eventDate → meta.expectDate → meta.expectMonth → week_end → week
```

**本草案建议插入位置**：
- `commence_utc`：**插在 `start` 之后**（都是"某日的具体时刻"类）
- `week_start`：**插在 `week_end` 之前**（同为周族，起点优先于终点）

⇒ 保持「**越具体越优先**」的既有原则。
