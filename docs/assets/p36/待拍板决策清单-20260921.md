## 决策 ①：U 型路径题的 gate 口径（是否支持「局内序列」粒度）

### 现状（盘上实测）

- 已产出 **126 条 U 型路径题**（32 局 × 平民数），全部 `prob=null`（铁律④本批只产结构）
- `anchor-gate.cjs` 的 Q0-2 用 **日期粒度**判泄漏：认的字段是 `date/start/epiweek/month/period/year/eventDate/week_end/week`
- sim 局内事件**无日期**（整局同日跑完）⇒ 126 条全判 `leak_unverified`
- **U 型机械规则已可用**：`combineNoisyOr` 与手算逐位一致（0.5716）

### 三个选项

| 选项 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）** | **维持现状**：U 型题留在产物层（已产 126 条、合成器可用），**不进 gate 判读**；等有真实读数需求时再立项 | 0 | 低——不触既有口径 |
| B | 扩 gate：新增「局内序列」口径（cutoff_seq < event_seq） | 改判据文件＝**版本递进** | **中高**：gate 是判据真源，改动影响全部既有题；且需定义「序列粒度下如何判泄漏」（尚无先例） |
| C | 给 sim 题补日期字段（用 `games.created_at`） | 小 | **高**：cutoff 与事件同日 ⇒ 仍判 leak（治不了根）；且是**伪造日期粒度**（局内本无日期） |

### 推荐 A 的理由

1. **无需求驱动**：U 型题现在**没有读数**（本批不出概率），过锚率是给「有读数的题」用的前置门；先扩 gate 是**为不存在的用例造仪器**
2. **口径变更须版本递进**：B 会改 `anchor-gate.cjs`（判据文件），按铁律⑥须走版本递进＋影响评估——而**影响面是全部既有题**（不只是 sim 族）
3. **C 是伪造**：局内本无日期，硬塞 `created_at` 会让「日期粒度」这个口径**名不副实**
4. **不阻塞**：U 型合成规则已验证可用；将来若有判词批给读数，届时再立项扩 gate 也不迟

### 若选 B 需额外拍板的三件事

1. 序列粒度的泄漏判据定义（cutoff_seq 与 event_seq 的关系式）
2. 是否对既有 sim 题（30 条已结算）追溯应用（会改变它们的 gate 结论）
3. 版本号与 PREREG 是否同步（gate 判据有对应 PREREG 吗）

## 决策 ②：被环境拦截的域（dlt 567／cta 403／elexon 403）如何处置

### 现状（盘上实测）

| 域 | 未解 | 总 | 拦截原因 | 影响门 |
|---|---|---|---|---|
| `dlt_draw_result` | **38** | 38 | HTTP 567（老问题） | 否（L5/dlt n=0） |
| `cta_daily_total_rides` | 3 | 7 | HTTP 403（本机 IP 被拦） | 否（L2/cta n=4） |
| `elexon_fuelhh_daily_mean` | 4 | 21 | HTTP 403（同上） | 否（L2/elexon n=0） |

- **加 UA 无效**（实测 Mozilla / curl 均 403）⇒ 环境层拦截，**代码无法解决**
- 每日例行结算**持续报 fail**（噪声），且到期面**不再自然收敛**
- **均不触任何门**（三域 n 均远低于 30 线，且不参与已达成的第 4 期放行门）

### 三个选项

| 选项 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）** | **维持现状**：每日 fail 如实记录，**不加特殊逻辑** | 0 | 低——但结算日志有持续噪声 |
| B | 结算统计**单独归类「环境阻塞」**（不混入 fail 计数） | 改 `corpus-resolve-daemon.cjs` 统计口径＝**版本递进** | **中**：改统计口径会让「fail 数」历史序列不可比（前后口径不同） |
| C | **出题器暂停这三域**（防继续堆积不可结题） | 改出题器配置 | **中高**：dlt 有 38 条**全部未解**（不是部分）——需先判断这 38 条是「环境拦」还是「本就该结但没结」 |

### 推荐 A 的理由

1. **不触门＝不紧急**：三域都不参与放行门（门已达成），处置的收益只是"日志干净"
2. **B 会破坏历史可比性**：fail 计数是既有序列，改口径后与历史不可比（本项目对「口径变更」一贯谨慎）
3. **C 需要先查清 dlt**：dlt 38 条**全部未解**（总 38 = 未解 38）——这不像"部分被拦"，更像**该域从未成功结过**。在查清之前暂停出题会**掩盖问题**
4. **★先做诊断再做处置**：建议**下一步先做一次 dlt 专项诊断**（查 567 的根因：是 IP 拦、接口变更、还是参数错），把根因查清后再决定 B/C

### 若选 C 的前置诊断（建议无论如何都做）

- dlt 567 首次出现的时间点（是否接口改版）
- 官方接口现状（curl 实测不同参数组合）
- 38 条是否**全部**因同一原因（还是分几类）
